### Decisions

- D1. Outcomes. `run` gives `Ok(Skipped(InvalidId))` for a `ws_id` that fails `valid_ws_id`, with no file and no tmux call. `Skipped(Logged)` means one `errors.log` line was written. `run` gives `Err` only when it must queue the snapshot and `queue_pending` fails (also logged).
- D2. Socket. The caller builds the `Multiplexer` with `tmux_socket` (AU62). Unset `tmux_socket` gives `Skipped(NoSocket)` with no tmux call.
- D3. Owner check. `run` reads `@zygo-ws` before `list-panes`. Another value: `Skipped(Logged)`. Unset: `session_exists`: `Gone` → `Skipped(Gone)`; `Exists` or `Error` → `Skipped(Logged)`.
- D4. Gone. `MuxError::Gone` from any call and `SessionAnswer::Gone` give `Skipped(Gone)`, with no write and no log line. `NoTarget` from a pane call is checked with `session_exists` after `update` returns (W§7.3 allows no other tmux call under `lock`): `Gone` → `Skipped(Gone)`; else `Skipped(Logged)`.
- D5. Shrink (AU89). Trigger: a valid stored key is missing from the read. Wait 2 s, read again; a read is used when its pane-id set equals the set of the read before it; at most 4 reads; still unstable → queue and `Pending`. `Gone` at any read → `Skipped(Gone)`.
- D6. Refused reads (one log line, no write): a line that does not parse, no line at all, a set `@zygo-pane` that fails `valid_pane_key`, or one valid key on two panes after D7. Probe 2026-11-22 (private servers, tmux 3.7c and 3.2a): `split-window` and `new-window` do not copy `@zygo-pane`.
- D7. Linked windows. Rows are sorted by window, then pane index; a row whose pane id is in an earlier row is dropped; a window with no row left gets no `windows[]` entry; then D6's key check runs.
- D8. Lost-update rule. `snapshot_seq` is kept from the first state read. A different value under `lock` → no write, release, one new whole attempt; a second difference → queue and `Pending`.
- D9. Result of `update` (review M6, round 2 M1). The closure stores its result in a captured `enum Locked { Write, Skip(SkipReason), Conflict, Closed(String), Gone, Failed(String) }` and returns `Err` for every value but `Write`. After `update`: `Ok(_)` → `Written`; `Err(StateError::Busy)` → queue (D14); `Err(StateError::Refused(_))` → the `Locked` value decides; every other `Err` (`Invalid`, `Newer`, `Io`, `OpHeld`), whether it came before or after the closure and whatever `Locked` holds → one log line and `Skipped(Logged)`. So `update` that fails never gives `Written`. Checks in the closure: `phase == down`, or `building`/`stopping` without `force` → `Skip(Phase)`; `tmux_session` changed → `Skip(Changed)`; `snapshot_seq` differs → `Conflict`.
- D10. Missing state. `Ok(None)` from the first read gives `Skipped(NoState)` before any `update`, `log_error` or tmux call. Known gap: a `forget` after the first read and before the lock lets `ensure_dir` make an empty folder with a `lock` file; nothing is written into it (D9: `Skip(Phase)`), and `state::list_all` ignores a folder with no `workspace.json` (`state.rs:575-587`).
- D11. Key assignment: private `key_pane(mux: &dyn Multiplexer, pane: &str, taken: &mut BTreeSet<String>) -> Result<(String, bool), KeyError>` (`bool`: set now), `enum KeyError { Gone, Closed, Invalid(String), Tmux(String) }`. `taken` starts with the keys of `ws.panes`, `ws.members` and this read, and gets each new key. It reads the option again under the lock, so a key set by another writer meanwhile is used (AU41).
- D12. `assign_key` (review M7, round 2 M5). Order: `^%[0-9]+$` check; `store.read()` gives a state; phase `up` or `draining`; `store.update(OP_WAIT, …)` with `key_pane`. A refusal before `update` makes no tmux call. When `key_pane` set a new key and `update` then fails, `assign_key` sets `@zygo-pane` to the empty string (finding 4) and gives `Err`. After a successful `update` it releases the lock and does the `snapshot.pending` check inline with `HOOK_WAIT`; that outcome does not change its result.
- D13. Lock wait. `HOOK_WAIT` for tmux hooks, member events and the member wrapper; `OP_WAIT` for `up` and `down`.
- D14. `snapshot.pending` (round 2 B1, B2, M2).
  - `queue_pending(paths, ws_id, force)`: `force` → `write_atomic(<dir>/snapshot.pending, b"force")`, which replaces any file in one rename; not `force` → `OpenOptions::new().write(true).create_new(true)`, which never opens a file that exists, so it never overwrites. An `AlreadyExists` error is success. So no order of writers ever turns `force` into empty.
  - `take_pending(paths, ws_id)`: renames `snapshot.pending` to `snapshot.pending.taken-<8 hex>` (no `.tmp` prefix, so `sweep_tmp` never deletes it, finding 5), reads it, deletes it. `Some(content == "force")`; `None` when the rename finds no file. A read I/O error writes one log line and gives `Some(false)`.
  - After `Busy`: `queue_pending(own_force)`, then `state::lock_file(<dir>/lock, PROBE_WAIT)` with `PROBE_WAIT = 100 ms`, never `update`. `Some(file)`: drop it at once, then `take_pending`: `None` → another writer took the file and runs it → `Pending`; `Some(taken)` → one more attempt with `force = own_force || taken`; a `Busy`, conflict or unstable result there → `queue_pending(own_force || taken)` and `Pending`. `None` from the probe → `Pending`.
- D15. `after_write`: `take_pending` → `None` gives `Skipped(NoPending)` with no tmux call; `Some(force)` gives one `run` with that `force`. So a forced pending snapshot runs in `building` and `stopping` (AU38). `run` calls `after_write` after its own write. The internal code works on a `Store` (`run` opens it from `paths`), so `assign_key`, which has no `paths`, uses the same check.
- D16. Phase gate: without `force`, `building` and `stopping` give `Skipped(Phase)`; `up` and `draining` run.
- D17. Log line: `snapshot (<event>): <text>` or `snapshot: <text>`; tmux values with `{:?}`.
- D18. `Fake`: every `Multiplexer` method answers. The five methods W6 calls answer from scripted fields; `fail` gives any of them a scripted `MuxError`; every other method records its name and gives `Err(MuxError::Failed { message: format!("fake: {name} is not scripted") })`. `show_pane_option` and `show_session_option` map an empty value to `None`, as `Tmux::show` does (`mux/tmux.rs:253-256`). `on_list(n)` runs inside `list_panes`; `n` is the call number, starting at 1. `on_set(pane, value)` runs inside `set_pane_option` before the value is stored.
- D19. Live tests hold `static LIVE: Mutex<()>` through `LIVE.lock().unwrap_or_else(|e| e.into_inner())`, start with `let Some(_) = require_tmux() else { return };`, and are `#[cfg(unix)]`. Every time bound has 2× margin.

**C8. W§7.3, replace the bullet "A snapshot that cannot get the lock in 1 s …" with:**

- A snapshot that cannot get the lock within its wait (1 s for hooks and member events, 5 s for `up` and `down`) sets `snapshot.pending` and exits 0. A snapshot with `--force` writes `force` into it with `write_atomic`, which replaces any file in one rename; a snapshot without `--force` creates an empty file only when none exists (`create_new`) and never overwrites one, so no order of writers removes a `force`. Right after, the snapshot tries `lock` once more for at most 100 ms, without reading the state; when it gets it, it releases it and takes the file: no file means another writer took it; else it runs once more, with `--force` when either it or the file had `--force`. Each writer checks `snapshot.pending` after it releases `lock`. If the file exists, the writer takes it (one rename to `snapshot.pending.taken-<hex>`, a name that the `.tmp*` sweep never matches, so only one writer gets it and the sweep never deletes it) and runs one snapshot, with `--force` when the file held `force`. `up`, `down`, `zygo ws snapshot`, the member wrapper, a hand start (`assign_key`) and verbs run it inline.

# FIX-17 — W2 state store hardening: refuse a linked state folder, cap the state read at 1 MiB

**Spec:** `docs/specs/2026-11-20-workspaces-design.md` AU84, W§7.3, W§7.1 (state dir `0700`, AU2); found by W8 implementation review round 2 (R1, R6, "New FIX node (proposed)" in `nodes/W8.md`). Defect (a): `Store::op_lock`, `Store::update` and `Store::log_error` call `ensure_dir` (`crates/zygo-workspace/src/state.rs:439`), which calls `zygo_core::session_dir::SessionDir::create`; that function runs `set_permissions(0o700)` and creates files through a symbolic link at the state folder (`crates/zygo-core/src/session_dir.rs:45-49`), so any caller on a linked `<workspaces_dir>/<id>` changes the link target (W8 red line: `forget-pane --name <id>` wrote through the link). Fix (a): the store refuses a state folder that is a symbolic link, checked with `symlink_metadata` before any create, chmod, lock or write; `op_lock`, `update` and `log_error` then create nothing, change no mode and write nothing, and `op_lock` and `update` return an error that names the path (`<path>: state folder is a link`) for their callers to report; `log_error` writes nothing. The check lives in the store; `session_dir.rs` changes only if the store cannot hold it. Defect (b): `Store::read` (`state.rs:409`, `fs::read`), `list_all` and `update` read `workspace.json` without a size cap. Fix (b): every store read takes at most 1 MiB + 1 byte (`File::take`); a larger file gives `StateError::Invalid { path, reason: "state file too large" }`, and `update` writes nothing over it. Spec text to add at this node's merge (W8 Round 2 controller text): AU84, at the end: "A `workspace.json` larger than 1 MiB is invalid with the reason `state file too large`; every reader reads at most 1 MiB + 1 byte of it, so no state read allocates more." W§7.3, after the sentence on readers ("a reader gets a whole file"): "A reader reads at most 1 MiB + 1 byte of `workspace.json`; a larger file is invalid (AU84)." W8's own checks (`admin::too_large`, `admin::read_capped`, the link checks of `admin`) stay; they agree with the store
**Files:** `crates/zygo-workspace/src/state.rs`, `crates/zygo-core/src/session_dir.rs`, `crates/zygo-workspace/tests/state.rs`
**Consumes:** `state::Store::update` (W2)
**Produces:** state store refuses linked folders and caps reads at 1 MiB
**Acceptance:** `cargo test -p zygo-workspace --locked --test state && cargo test -p zygo-core --locked` → all pass, including (unix) a state folder that is a symbolic link to a `0755` folder, on which `op_lock` and `update` return the link error, `log_error` returns, and the target folder keeps mode `0755` and gets no new file; and a 2 MiB `workspace.json` that `read`, `list_all` and `update` report as `state file too large`, with the bytes of that file unchanged after `update`

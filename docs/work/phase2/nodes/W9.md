### Decisions

- D1. Lock and sweep: `update` calls `crate::state::lock_file(&dir.activity_lock(), bound)` and, with the lock held, `crate::state::sweep_tmp(&dir.root)`, as `Store::update` does (`state.rs:424`, `:436`). Reason: both exist (finding 1); copies would drift. An error that opens the lock file is returned with the context `<activity.lock path>: open lock file`.
- D2. `read` takes no lock. Reason: every write goes through `write_atomic` (one rename), so a reader always sees a whole file; `Store::read` follows the same rule (W§7.3). `down` polls every 500 ms and must not block hooks.
- D3. One private loader, `fn load(path: &Path) -> Load` with `enum Load { Missing, ReadFailed(std::io::Error), Unparsable(serde_json::Error), Parsed(Activity) }` (`serde_json::from_slice` with `#[serde(default)]`, unknown fields dropped). `read`: `Missing` gives `Ok(Activity::default())` (W§9.1); `ReadFailed` and `Unparsable` give `Err` with the text `<activity.json path>: <error>`; `Parsed(a)` gives `Ok(a)` for any `version`, so a newer file reads its known fields. Reason: author's call M2, M3; the drain must not count a member as idle from a file it cannot read.
- D4. `update` from the loader: `Missing` and `Unparsable` start from `Activity::default()` (an unparsable file is replaced, `Ok`); `ReadFailed(e)` returns `Err` (`<path>: <e>`) and writes nothing; `Parsed(a)` with `a.version > VERSION` returns `Err` with the exact text `<activity.json path>: written by a newer zygo (version <n>)` and writes nothing; else it starts from `a`. Reason: author's call M2, M3; a hook must recover from a broken file (C6) but must not overwrite the form of a newer zygo (the rule of AU29).
- D5. `update` writes on every call: after `f` it sets `version = VERSION` and `updated_at` to Unix seconds of `SystemTime::now()`, serializes with `serde_json::to_vec`, and calls `write_atomic`. Reason: W§9.1 says `version` and `updated_at` change on every write.
- D6. When the lock stays held for all of `bound`, `update` returns `Err` with the exact text `<activity.lock path>: lock not taken within <ms> ms` and writes nothing. Reason: H1 writes that error as its one log line and exits 0 (AU56, C6).
- D7. `subagent_start` inserts or replaces `agent_id → agent_type`, also for an empty `agent_type`. `subagent_stop` removes the id only when it is in `running` and returns `true`; otherwise it returns `false` and changes nothing. Reason: AU26 rule 2 and PW7 7.5 (`pw7.txt`: 6 internal agents, stop only).
- D8. `idle` order and reasons. First an `Err` activity: `Busy` with `activity file unreadable: <error>`. Then rule 2: `subagents running: <id>, <id>` (ids in `running` key order). Then rule 3 (D9). Then rule 1. When rules 2 and 3 hold: `busy = false` gives `Idle` (rule 3 checked) or `IdleRuleSkipped` (rule 3 skipped); `busy = true` gives `TurnOpen { rule_skipped }`. Reason: AU26, PW7 7.2; W10 prints the reason of each busy member in its timeout report (W§9.3 step 6 text below), so it names the cause.
- D9. Rule 3, in this order (author's call B1, B2, M1): `status` is `Err(e)`: fails, `proxy status not read: <e>`. `requests_in_flight` is `None`: skipped (an older team server). `Some(n)` with `n > 0`: fails, `model requests in flight: <n>`, whatever `last_request_end` holds. `Some(0)` and `last_request_end` is `None`: holds (no request ended yet). Not RFC 3339: skipped. At or before `now`: fails with `last model request ended <s> s ago` (`s` = whole seconds, rounded down) while `now - end < REQUEST_QUIET`, else holds. After `now` by 10 s or less: fails, `last model request ended after the poll time` (a request that just ended, with clock skew). After `now` by more than 10 s: skipped (counts as not parseable).
- D10. `idle` holds no state and reads no clock or file: same inputs, same result. The 60 s count belongs to W10 (`down::INTERRUPTED_TURN_AFTER`), and only `TurnOpen { rule_skipped: false }` counts toward it (author's call B2; W10 contract text below).
- D11. `idle` takes `Result<&Activity, &str>` and `Result<&SessionStatus, &str>`, not an enum. Reason: the callers already hold `Result`s (`activity::read`, the proxy status call); `as_ref().map_err(String::as_str)` after `map_err(|e| format!("{e:#}"))` passes them with no new type, and the `&str` keeps `drain` free of the client's error type. "No fields" is `Ok(status)` with `requests_in_flight == None`; "read failed" is `Err`.
- D12. W§18 #57 runs two real processes (author's call B3, M7, M9). `writer_helper` is `#[ignore]` and reads its inputs from variables set only on the child `Command`. Both children wait for one start file, then make 100 updates each with `LOCK_BOUND`, count their `Ok` results and print `W9_OK <prefix> <count>`. The parent spawns both with piped output, writes the start file, and collects each with `wait_with_output` (the concurrent form of the repo's `.output()`, which would wait for the first child before the second starts), checks `1 passed`, and asserts that the running set has exactly the sum of the `Ok` counts. A timeout is allowed and counted; a lost update fails. The test is `#[cfg(unix)]`: workspaces do not exist on Windows (OP5).

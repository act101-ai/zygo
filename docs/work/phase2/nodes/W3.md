### Design decisions

- D1 Error model. Every trait operation except `session_exists` returns `Result<T, MuxError>`; `attach` returns `Result<i32, MuxError>` (M11). The first line of stderr of a non-zero exit is classified in this order:
  - `is_gone_message` gives `Gone` (D2).
  - `is_no_target_message` gives `NoTarget`: the line starts with `can't find window:`, `no such window:`, `can't find pane:` or `no such pane:`. These are not `Gone`, because the session can still exist (author's call, M4).
  - Any other text gives `Failed { message: <stderr, trimmed> }`.

  The bound gives `TimedOut`, and a spawn error gives `Spawn`. `session_exists` folds every error other than `Gone` into `SessionAnswer::Error { message }` (AU87: "any other tmux error"). Reason: the text depends on the command (finding 3). Only `has-session`, `list-panes`, `kill-session` and `new-window` print `can't find session`, while `set-option`, `set-environment` and `set-hook` print `no such session:`. So each operation must classify its own stderr; checking only `has-session` is not enough. `MuxError` implements `Display` and `std::error::Error`.
- D2 Gone texts (AU87 (1), with the AU87 change for B2 in the controller section). The first line of stderr counts as gone when it:
  - starts with `can't find session`, `no such session:` or `no server running on `;
  - equals `server exited unexpectedly`;
  - or starts with `error connecting to ` and ends with ` (No such file or directory)` or ` (Connection refused)`.

  `(Connection refused)` stays because AU87 names it. No probe produced it (M1), so only the unit test covers it.
- D3 Locale and UTF-8 (B5).
  - Every call runs with `LC_ALL=C` and passes `-u`, except two:
    - `new_session` runs with `env_clear()` and exactly `NewSession.env`, plus `-u`. A tmux server that this call starts copies the client's environment into its global environment (probe 3: `show-environment -g LC_ALL` printed `LC_ALL=C` for a server that an `LC_ALL=C` client started). Also, tmux marks each `update-environment` name that the client lacks as removed in the new session (M5).
    - `attach` keeps the caller's environment and passes no `-u`, because tmux reads the locale to decide how to draw on the user's terminal.
  - Reasons: AU87 needs the C locale only for strerror. `-u` makes the client print UTF-8 names and paths, not `_` (finding 4). The errors of `new_session` and `attach` are not matched as gone by callers (W7 checks `session_exists` first).
- D4 `PANE_FORMAT` (W§19 builder choice). The separator is `|`. The two free-text fields before the last one are read through `q:`, so a `|` in them arrives as `\|`.
  - The 13 fields, in order: `#{window_index}`, `#{q:window_name}`, `#{automatic-rename}`, `#{window_layout}`, `#{window_width}`, `#{window_height}`, `#{window_active}`, `#{window_zoomed_flag}`, `#{pane_id}`, `#{pane_index}`, `#{pane_active}`, `#{q:@zygo-pane}`, `#{pane_current_path}`.
  - `parse_pane_line` reads fields 1-12 from the left. Each field ends at the first `|` that no `\` escapes. Field 13 is the rest of the line, raw (AU99).
  - It then removes the `q:` escapes (`\X` gives `X`) from fields 2 and 12, and applies `vis_decode` to field 2 only (B3).
  - It refuses a line with fewer than 13 fields (`TooFewFields { found }`) and a typed field that does not parse (`BadField { field }`: index, size and pane-index fields are `u32`, flag fields are `0` or `1`, and `pane_id` starts with `%`).
  - `#{pane_id}` is added to the fields of W§7.4 step 2, because W6 step 4 needs a pane target for `@zygo-pane`.
  - Reasons: a control-character separator prints as `_` (6.23t). `q:` makes both fields safe for `|` (finding 5). Fields 1-12 hold no raw `|` (numbers, flags, a layout of `[0-9a-fx,{}\[\]]`, and `%N`). Taking `window_name` without `q:` is not safe, because a raw name holds `|`.
  - Deviation from the review text of B3, with evidence: `@zygo-pane` is not vis-encoded (finding 5: a raw `a\b` prints `a\b`), so decoding it would change a `\\` that the user wrote. It is only `q:`-unescaped. A valid key (AU84 `^k[a-z2-7]{8}$`) holds no backslash in either case.
- D5 `vis_decode` (B3). It turns `\\` into `\`, `\` followed by three octal digits into that byte, and `\a \b \t \n \v \f \r \0` into their control bytes. It keeps every other character unchanged and makes the bytes into a `String` with `from_utf8_lossy`. The result is the name that the user typed (tmux's `utf8_stravis` with `VIS_OCTAL|VIS_CSTYLE|VIS_TAB|VIS_NL`). On 3.7c no name can hold a control character (finding 5), so only `\\` occurs there. The octal and C-style cases are for a 3.2a server, and step 18 shows whether 3.2a accepts such a name.
- D6 Escaping lives in `Tmux`. `NewSession.start_dir`, `NewWindow.start_dir`, `NewWindow.name` and `Split.start_dir` take raw values. `Tmux` applies `format_escape` to each `-c` and `-n` value (W§13). A caller must not escape these values first: double escaping gives `##` in a name. A start directory that is not UTF-8 gives `Failed { message: "start directory is not UTF-8: <lossy path>" }` before any spawn.
- D7 Argument lists. `new_session`, `new_window` and `split_window` refuse an `argv` with fewer than 2 items (`Failed { message: "tmux needs an argument list of 2 or more items" }`, no spawn). Reason: tmux runs a single argument through `sh -c` (probe 1). Every W7 pane command `<zygo> ws run …` has 2 or more items.
- D8 Targets.
  - A session target is `=<session>:` (`session_target`), and a window target is `=<session>:<index>` (`window_target`).
  - Pane operations and `set_window_option` take a target string: a pane id `%N`, or a window target.
  - `new_session` returns the first window index (`-P -F '#{window_index}'`), `new_window` returns the new index, and `split_window` returns the new pane id (`-P -F '#{pane_id}'`). All three pass `-d`.
  - `show_pane_option` runs `show-options -p -qv`, and `show_session_option` runs `show-options -qv`. Empty output gives `None`, which means "unset or no such target" (B1, finding 6).
- D9 Runner (M2, M10). `tmux.rs` has `pub(crate) fn run_bounded(cmd: Command, limit: Duration) -> Result<Ran, MuxError>`, with `pub(crate) struct Ran { pub status: Option<ExitStatus>, pub stdout: String, pub stderr: String }` (`status` is `None` when the kernel reaped the child). Every `Tmux` call except `attach`, and `PrivateServer::run` and its `Drop`, use it with `BOUND`. The steps:
  - It sets `process_group(0)` (unix), stdin null, and stdout and stderr piped.
  - One reader thread per pipe fills a `Mutex<Vec<u8>>` and sends one message on a channel at EOF.
  - Wait for the exit, on unix by polling `exited_unreaped` every 5 ms. The first `waitid` error falls back to a `try_wait` loop, with no group kill after it.
  - At the deadline with no exit: `kill_tree`, then `TimedOut`.
  - After the exit, wait for both EOF messages until the deadline. If a pipe is still held and the child is not reaped yet, `kill_group`, then reap. If the kernel already reaped the child, send no kill.
  - Readers that are still blocked are abandoned, never joined.
  - The output is what was read, made into text with `from_utf8_lossy`.

  An exit status `None` with empty stderr counts as success. `None` with stderr is classified by D1.
- D10 Bound and attach. Each call except `attach` has `BOUND` (2 s). `attach` runs `attach-session -t =<s>:` with inherited stdin, stdout and stderr, the caller's environment, and no bound. It returns `Ok(exit code)`, or `Ok(1)` when a signal ended tmux. Reason: an attached client lives as long as the user works, so a 2 s bound would detach the user. The controller section adds this to W§13.
- D11 Private server (W§19 builder choice).
  - `PrivateServer::start()` makes `/tmp/zygo-mux-<pid>-<n>-<8 hex>` with mode 0700. The socket is `<dir>/s`.
  - It writes the wrapper `<dir>/tmux` (0755): `#!/bin/sh` and `exec '<program>' -S '<socket>' -f /dev/null "$@"`.
  - It starts no server: the first call that needs one starts it through the wrapper, which passes `-f /dev/null`.
  - `tmux()` returns `Tmux::new(wrapper, Some(socket))`. Its later `-S` names the same path, and the last `-S` wins (finding 3).
  - `Tmux::new(wrapper, None)` adds no `-S` of its own (step 7 checks it), so the wrapper's `-S` applies. A W7 test can pass the wrapper as `UpOpts.tmux` and never reach the developer's default server (M6).
  - `start()` runs `<wrapper> -V` through `run_bounded` and tries again for at most 2 s while the spawn error kind is `ExecutableFileBusy`.
  - It asserts that the socket path is 100 bytes or shorter (`sun_path` is 104 bytes on macOS).
  - It panics with `PrivateServer::start: no tmux 3.2 or later on PATH; call require_tmux first` when `require_tmux()` gives none, and also when the program path holds `'`.
  - `run` runs the real program with `-S <socket> -f /dev/null -u` and `LC_ALL=C` through `run_bounded`. Exit 0 gives `Ok(stdout with trailing white space removed)`; other results are classified by D1.
  - `kill_server` runs `kill-server`, then waits at most 5 s until `list-sessions` fails.
  - `Drop` runs `kill-server` (result ignored) and removes the directory.
- D12 Gate output. `require_tmux_at` writes `SKIP_PREFIX` + reason + `\n` with `std::io::stderr().write_all`, not `eprintln!`, because libtest captures only the print macros. `tmux_gate` returns the reason. The reasons are:
  - `<program>: cannot run: <io error>`
  - `<program>: tmux -V failed: <message>`
  - `<program>: unknown tmux version: <first line>`
  - `<program> is tmux <major>.<minor>; the minimum is 3.2`
  - `tmux not found on PATH` (`require_tmux`)
  - `tmux tests run on unix only` (non-unix)
- D13 Version. `parse_version` reads the first `<digits>.<digits>` after `tmux `: `tmux 3.2a` gives (3, 2), `tmux next-3.6` gives (3, 6), and `tmux master` gives none. Reason: AU7 cannot be checked without numbers.
- D14 Hook scope. `HookScope::Session` runs `set-hook -t =<s>: <event> <command>`. `HookScope::Window(w)` runs `set-hook -w -t =<s>:<w> <event> <command>`. W3 does not move a hook between scopes.
- D15 Windows gating (M8). CI runs `cargo test --workspace` on `windows-latest`.
  - In `mod.rs`: `testing::require_tmux`'s execute-bit check (`std::os::unix::fs::PermissionsExt`) is `#[cfg(unix)]`, and on other targets a file is enough. `tmux_gate` on `#[cfg(not(unix))]` returns `Err("tmux tests run on unix only")`, so `require_tmux_at` gives `None` there. `PrivateServer` and its `impl` are `#[cfg(unix)]`.
  - In `tmux.rs`: `process_group(0)` and `exited_unreaped` are `#[cfg(unix)]`, and the non-unix wait is the `try_wait` loop.
  - In `tests/mux.rs`: `#[cfg(unix)]` goes on `use zygo_workspace::mux::testing::PrivateServer;`, on `use std::os::unix::{fs::PermissionsExt, net::UnixListener};`, on `forks()` and `STUBS`, on `stub()`, and on every stub and tmux test. The pure tests have no gate.
- D16 Test layout. Every tmux test starts with `let Some(_) = require_tmux() else { return };`, makes its own `PrivateServer`, and holds `forks()` for its whole body. The hook path in tmux tests is `/usr/bin/true`.

## Plan

Facts from the code as it is now (checked 2026-11-21, branch with C1, W1 and X1 merged):

- `crates/zygo-workspace/src/state.rs` holds one doc line only. `crates/zygo-workspace/tests/state.rs` does not exist. `lib.rs` already has `pub mod state;`.
- `crates/zygo-workspace/Cargo.toml` `[dependencies]`: `zygo-core`, `zygo-config`, `zygo-work`, `zygo-proxy`, `anyhow`, `serde`, `serde_json`, `sha2`, `hex`, `rand`; dev: `tempfile` and the self entry with `test-hooks`. Root `Cargo.toml` `[workspace.dependencies]` has `fs4 = "1.1.0"` (`:43`), `libc = "0.2.191"` (`:48`), `time = { version = "0.3.55", features = ["formatting", "parsing"] }` (`:64`). `Cargo.lock` already holds the three packages; only the edges of `zygo-workspace` are missing.
- `fs4` 1.1.0 locks with `flock` on unix and `LockFileEx` on Windows: two handles of one file exclude each other also inside one process. So a test holds a lock with a second handle; no child process is needed. `std::fs::File` has its own `try_lock` (Rust 1.89), so every call is written `fs4::FileExt::try_lock(&f)`, as `crates/zygo-core/src/session_dir.rs:16`. `fs4::TryLockError` has `WouldBlock` and `Error(io::Error)`.
- The bounded lock pattern of this repository is `try_lock_until` (`crates/zygo-plugins/src/store.rs:356-363`, `pub(crate)`): `try_lock` in a loop, 5 ms between tries. `crates/zygo-work/src/log.rs:173` uses a blocking `fs4::FileExt::lock`, with no bound. This node writes its own loop with the 5 ms interval.
- The launcher's live check is `zygo_core::session_dir::live(dir: &Path) -> bool` (`session_dir.rs:13-17`): `token` exists and another holder has the fs4 lock on `pid`. No code checks a pid with `libc`; `crates/zygo-launch` uses `libc` for signals (`signals.rs`, `launcher.rs:712`). `state.rs` uses neither `libc` nor `time`; this node only declares them (for W10 and W9, as the contract says).
- `write_atomic` (`session_dir.rs:116-131`) makes a `tempfile::NamedTempFile` in the target's directory (file name starts with `.tmp`), sets `0600`, syncs, renames. It deletes no old `.tmp*` file. W§7.3 and W§18 #7 put that rule on the next writer of the workspace state: it is `Store::update` of this node.
- `SessionDir::new(dir).create()` (`session_dir.rs:37-52`) creates a directory and its missing parents with mode `0700` and sets `0700` on the leaf; on Windows it only creates. This node uses it for `<workspaces_dir>/<id>`.
- A test `Paths` literal with `data_dir = <tmp>/data` gives `workspaces_dir() = <tmp>/data/state/workspaces` (`paths.rs:60-75`).
- `zygo_core::Agent` serializes as `claude-code` and `opencode` (`crates/zygo-core/src/lib.rs:20-26`).

Design calls (lead log):

- (a) `Store::open` cannot fail, so each operation checks `valid_ws_id` first: `read`, `update` and `op_lock` return `StateError::Invalid`; `phase_unlocked` gives `None`; `op_lock_free` gives `true`; `log_error` and `live_launcher` do nothing. No path is built from an id that is not valid.
- (b) `update` on a missing `workspace.json` starts from `Workspace::new(id)`, whose `name` is empty. `update` validates the result before the write, so a hook write for a workspace that does not exist writes nothing (`Invalid`), and `up` creates the state when its closure sets the identity fields.
- (c) Validation (AU84) also needs `id` equal to the directory name and `version == 1`.
- (d) `tmux_socket`, `snapshot_at`, `member.program`, `member.last_run_at` are `Option`: W§8.1 step 8 writes the state before the socket (step 9), a snapshot or a start exist.
- (e) `member.overrides` is `Option<serde_json::Value>` (the whole content of `overrides.json`), so a key this zygo does not know is kept (AU78). A reader converts with `serde_json::from_value::<zygo_core::overrides::Overrides>`.
- (f) `member.compact` is the JSON string `set <w>` or `cleared` (the W§7.2 text), `<w>` as the `--compact` text.
- (g) `errors.log` line: `<unix seconds> <text>`; `\n` and `\r` of the text become a space; the text is cut to 1024 bytes. A line that would make the file larger than 64 KiB first cuts the file to its newest whole lines within 32 KiB, so a rewrite (with its `fsync`) occurs one time per 32 KiB of lines and not at each line.
- (h) `live_launcher` returns the pane key of the first live member in key order. A session id that is empty or holds a byte outside `[A-Za-z0-9]` is not looked up (no `..` reaches a path).
- (i) `list_all` skips a directory whose name is not a workspace id and a directory with no `workspace.json`; order by id.
- (j) `Store::dir()` is public: W6, W7 and W10 need `snapshot.pending`, `workspace.json.bad` and `down.log` in the same directory.
- (k) `workspace.json` is written with `serde_json::to_vec_pretty`: a verb names this file to the user on an error.
- (l) `libc` goes in `[dependencies]` (as `crates/zygo-launch/Cargo.toml:24`); the crate builds on Windows.

Not in this node: `snapshot.pending` (W6), the bound values 1 s and 5 s and the `busy; try again` text (the callers pass `bound` and print), `workspace.json.bad` (W7).

Windows: `state.rs` has one `cfg(unix)` block, in `private()` (the `0600` mode of `lock`, `op.lock`, `errors.log`). Every other item is `std`, `fs4`, `serde` and `zygo-core` code that builds on Windows. In `tests/state.rs` the tests `modes_are_0700_and_0600`, `live_launcher_reads_committed_and_pending_sessions` and their `use std::os::unix::fs::PermissionsExt` are `#[cfg(unix)]`; all other tests run on all three systems.

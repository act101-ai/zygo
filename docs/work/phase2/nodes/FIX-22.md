# FIX-22 — Session-folder readers do not wait on a FIFO: activity.json and view.json

**Spec:** `docs/specs/2026-11-20-workspaces-design.md` W-C1 (C6), AU26 (an `activity.json` that cannot be read counts as busy), AU56, W§9.1; H1 plan item C9 (2026-11-22, H1 plan review round 1, controller decision 16); operator rule of 2026-11-22: no time limit, cap or clean-up may end or delete user work. Defect: `activity::load` (`crates/zygo-workspace/src/activity.rs:86`, used by `activity::read` and `activity::update`) opens `activity.json` with `std::fs::File::open`, and `SessionView::load` (`crates/zygo-core/src/session_view.rs:129-131`) reads `view.json` with `std::fs::read`. Both follow a link and wait for a writer on a FIFO, so a FIFO at `activity.json` stops `down` (W10 reads it at each drain poll) and a FIFO at `view.json` stops every reader of the view: `session-start`, `trim`, `statusline` and the member hooks. H1 does not fix `session-start`: it keeps today's `view.json` read for launches that are not members, and membership is known only after that read. Fix: `activity::load` opens with `O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC` on unix and needs the opened handle to be a regular file; a link or any other entry is an error (`<activity.json path>: is a link` or `<activity.json path>: is not a regular file`), which the drain counts as busy (AU26), and `activity::update` returns that error and does not replace the entry. `SessionView::load` opens with `O_NONBLOCK | O_CLOEXEC` on unix and needs the opened handle to be a regular file (`<view.json path>: is not a regular file`); a link is still followed, so no launch gets a new refusal for a link, and a FIFO is an error instead of a wait. No size cap is added anywhere. `activity::update` as H1 left it is kept: it refuses a result larger than the 1 MiB read limit, and it refuses to replace an existing `activity.json` that is over that limit or does not parse, writing nothing in each case (H1 attempt-2 review round 1, F1). On other systems the opens have no flag and the handle checks stay. Then the D6 pre-check of H1 in `crates/zygo-hooks/src/workspace.rs` (the `symlink_metadata` test before each `activity::update`) is removed, and H1's hostile-input cases keep their session-log lines through the reader's own errors. After the pre-check is removed, the link and not-a-regular-file cases come back as reader errors of `activity::update` of the persistent class (the error kind `activity::Unreadable`, H1 attempt-2 review round 3) and keep the once-per-turn rule: their line is written only for `prompt`, `session` and `session-end`.
**Files:** `crates/zygo-workspace/src/activity.rs`, `crates/zygo-workspace/tests/activity.rs`, `crates/zygo-core/src/session_view.rs`, `crates/zygo-core/tests/core_basics.rs`, `crates/zygo-hooks/src/workspace.rs`, `crates/zygo-hooks/tests/workspace.rs`
**Consumes:** `activity::read` (W9), `activity::update` (W9), `workspace::run` (H1)
**Produces:** `activity::read(dir: &SessionDir) -> anyhow::Result<Activity>` and `activity::update(dir: &SessionDir, bound: Duration, f: &mut dyn FnMut(&mut Activity)) -> anyhow::Result<()>` that never wait on a FIFO and never write through a link; `SessionView::load(dir: &SessionDir) -> anyhow::Result<SessionView>` that never waits on a FIFO
**Acceptance:** `cargo test -p zygo-workspace --test activity && cargo test -p zygo-core --test core_basics && cargo test -p zygo-hooks --test workspace` → all pass, including `activity_fifo_and_link_are_errors_without_a_wait` (a FIFO at `activity.json`: `read` and `update` return `Err` within a 5 s thread bound and the FIFO stays; a link: `Err`, the link target unchanged), `session_view_load_does_not_wait_on_a_fifo` (a FIFO at `view.json`: `Err` within a 5 s thread bound; a link to a regular view still loads; a view larger than 1 MiB still loads) and H1's `hostile_inputs_change_nothing` with the D6 pre-check removed

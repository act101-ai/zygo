# FIX-28 — The first pane of a new session gets ZYGO_WORKSPACE

**Spec:** `docs/specs/2026-11-20-workspaces-design.md` W§8.1 step 9 (`:367`); `docs/specs/2026-11-21-auto-update-design.md` "When the check is skipped", the `ZYGO_WORKSPACE` bullet (`:42`). Created 2026-11-23 from M5 premise P2 (M5 plan, "Premise check"; confirmed by the controller). Problem: `up` starts the first pane of a new session in `new-session` (`crates/zygo-workspace/src/up.rs:1119`). That pane gets exactly `cleaned(vars)` (`up.rs:1104`; `crates/zygo-workspace/src/mux/tmux.rs:324`, `env_clear().envs(spec.env…)`), and `cleaned` removes `ZYGO_WORKSPACE` (`REMOVE_ALWAYS`, `crates/zygo-workspace/src/env.rs:6-20`). `up` sets `ZYGO_WORKSPACE` on the session only later, in `session_setup` (`up.rs:1166` → `:495`). So the `ws run` of that pane does not skip the update check (M5 makes `ws run` run it), and it can show the update prompt in the pane. Change: `up` gives the first pane of a new session `-e ZYGO_WORKSPACE=<id>` on `new-session`, in session scope only. Never put it in the client environment: a server that `new-session` starts copies the client environment into its global environment. tmux 3.2 (the AU7 minimum) has `new-session -e`: tmux CHANGES, section "CHANGES FROM 3.1c TO 3.2" (`CHANGES:1`), item "Add -e flag for new-session to set environment variables, like the same flag for new-window" (`CHANGES:213`); tag 3.2 `tmux.1:1211-1214` (`new-session … [-e environment]`) and `cmd-new-session.c:42` (`"Ac:dDe:EF:f:n:Ps:t:x:Xy:"`), `:258-266` (each `-e` value goes into the new session's environment, which `session_create` takes). Spec text, final form: (1) W§8.1 step 9, after "with the environment of AU64", add: "and `-e ZYGO_WORKSPACE=<id>` (session scope only). Never put it in the client environment: a server that `new-session` starts copies the client environment into its global environment, and every other session of that server would then get the id." (2) The auto-update `ZYGO_WORKSPACE` bullet becomes: "The command runs in a workspace pane (`ZYGO_WORKSPACE` is set): the workspace's `zygo up` already asked. `ws run` runs the check before it cleans its environment, so it sees `ZYGO_WORKSPACE` and skips too. `up` gives the first pane of a new session `ZYGO_WORKSPACE=<id>` with `new-session -e` (W§8.1 step 9), because that pane starts before step 10 sets the session environment."

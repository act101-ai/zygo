Library code here reads no process environment and no device: each value comes in as an input, and only the entry point (hook dispatch or cmd layer) reads the real environment, the pattern of UPD-1 `start_check` and HUD-8 `RenderEnv::from_env`: `up_all` uses the `UpOpts` input fields of W7; `admin::status` takes `ZYGO_WORKSPACE` (the workspace of this session, W§12 `zygo workspace` row) as `zygo_workspace`, and falls back to `cwd`. `up_all` passes `UpOpts.socket` to each creation; its tests and the `admin` tests use `PrivateServer::start` and its `socket`. Every `admin` function takes the tmux program (`ls` states and attached clients, `forget` refused while running) and reaches each workspace through its stored `tmux_socket` (AU62); tests pass the real `tmux` with a `PrivateServer`, or a stub script (`cfg(unix)`)

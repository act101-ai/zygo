### Contract findings (fixed above in this file)

1. `admin::list(paths)` cannot give the states `stopped (tmux gone)`, `unreachable` or the attached clients of W§12: each needs a tmux answer, and the library reads no environment. `list` takes `tmux: &Path` (D1).
2. `admin::forget(paths, name)` cannot tell "the workspace runs" (W§12): that needs `has-session` and the AU63 owner on the server of W§8.1 step 6, which `up::server` chooses from `tmux_socket` and `$TMUX`. `forget` takes `tmux` and `tmux_env` (D1, D15).
3. `admin::forget_pane` writes `workspace.json`, so it must run the W§7.3 `snapshot.pending` check after its write ("each writer checks `snapshot.pending` after it releases `lock`"), which needs a `Multiplexer`. It takes `tmux` (D19).
4. `forget` and `forget_pane` print lines and return an exit code. A function that writes to the process stdout cannot be read by an integration test; both take `out` and `err` writers (D1). `up_all` keeps the contract signature and gets `up::testing::run_all_with`, the pattern of `up::testing::run_with` (`crates/zygo-workspace/src/up.rs:139`).

6. `preflight` by name takes the first readable state of that name in id order (`up.rs:337`). Two readable states with one name would restore the first one twice. `up_all` compares the ids (D5).
7. W7 helpers that W8 uses are crate-private and not in W7's Produces: `up::member_live` (`up.rs:191`), `up::socket_is_private` (`up.rs:255`, `:293`), `up::fire` (`up.rs:151`). 11. Folders made again after a rename (D26). `Store::update`, `Store::op_lock` and `Store::log_error` call `ensure_dir` (`state.rs:453`, `:474`, `:514`; `ensure_dir` at `:439-444`), which creates the state folder when it is missing. ### Decisions

Each decision is the author's call. D2, D3, D4, D6, D8, D10, D11, D14, D16, D17, D18, D20 and D25-D30 hold the plan review's decisions (coordinator, 2026-11-22, points 1-11), recorded here as the author's call.

- D1. Signatures. `list` takes `tmux`; `forget` takes `tmux`, `tmux_env`, `out`, `err`; `forget_pane` takes `tmux`, `out`, `err` (findings 1-4). `status` keeps its contract signature: it reads only the state (W§12: name, phase, members), so it needs no tmux. The cmd layer passes the program name `tmux` (`Command` finds it on `PATH`; a missing program is a `Spawn` error, which `list`, `forget` and `up_all` handle, D4, D11, D15) and `std::env::var_os("TMUX")` (controller item C2).
- D2. `up --all` candidates (AU52). A readable state is a candidate when `down_all` is `true` (any phase) or `phase = up`. Other states are never chosen and get no tmux call. The session check of each candidate: when `tmux_socket` is set, first `socket_is_private(socket, true)` (AU62, the same `create_parent = true` as `up`, so a socket folder that a reboot removed does not stop a restore); refused → skipped. Then `server(&opts.tmux, ws.tmux_socket.as_deref(), opts.tmux_env.as_deref()).session_exists(&ws.tmux_session)`: `Gone` → chosen (a live launcher then makes `up_target` exit 1 with the AU87 text, and `up_all` adds the skip line); `Error { message }` → skipped; `Exists` → D6. A state that cannot be read (any `Err` of `list_all`: `Newer`, `Invalid`, `Io`) is skipped (AU80).
- D3. `up --all` order and lines. First one line per state that cannot be read, in id order: `zygo: workspace <id> skipped: <StateError Display>`. Then the readable candidates in (name, id) order. For each chosen state: `preflight` by name, then `up_target(.., attach = false)`; code 0 prints `zygo: <name> is up` on `out`; any other code prints `zygo: <name> skipped` on `err` after the lines of `up_target`. A skip found before `up_target` prints one line `zygo: <name> skipped: <reason>` (`tmux: <message>`, the AU62 text, or D5). A workspace whose session runs gets no line (D6). No state chosen: `zygo: up --all found no workspace to restore` on `err`. Exit 1 when any line says `skipped`, else 0. It attaches to none. The `<name>` in these lines needs no escape: a readable name passes AU84 (`^[a-z0-9-]{1,32}$`).
- D4. `up --all` refusals before any session check. `opts.name`, `opts.loadout` or `opts.reset` set: `zygo: up --all takes no workspace name, --loadout or --reset`, exit 2 (a `--reset` of every workspace would drop every saved agent session: the side that never loses work). `check_path(&opts.zygo)` fails: its AU54 text, exit 2 (once, not once per workspace). Then `tmux_check(&opts.tmux)`, the same helper and texts as `preflight` (finding 8): a missing tmux gives `zygo: workspaces need tmux; install tmux 3.2 or later`, exit 2; an old or unreadable one its `preflight` line, exit 2. So no `session_exists` runs on a tmux that `up` refuses. A later `preflight` error with code 2 also prints its line and returns 2 at once.
- D5. Two readable states with one name. `preflight` by name gives the first in id order (finding 6). When `Target.id` differs from the chosen state's id: `zygo: <name> skipped: more than one workspace state has the name <name>`. `zygo up` in that workspace's checkout still finds it by its id.
- D6. A candidate whose session exists is not restored and gets no line. `show_session_option(&ws.tmux_session, "@zygo-ws")`: another value or none → nothing changes (a session of another workspace under that name; `ls` shows `unreachable`, `up <name>` exits 1 with AU63); an error → skipped with `tmux: <e>`. Our id with `down_all = true`: the workspace is up, so `up_all` clears `down_all`: `op_lock()` (`OpHeld` → nothing changes, no line: a running `up` or `down` decides), then `session_exists` and the owner again under it (the session can have gone since the first check), and when both still hold, `update(snapshot::OP_WAIT, ..)` sets `down_all = false` when it is still `true`; a write error → `zygo: <name> skipped: <error>`. Then the `OpLock` is dropped. Our id with `down_all = false`: nothing changes.
- D7. `up_all` calls `up_target` one workspace after the other. Each `up_target` takes and releases its own `op.lock` (W7 D24), so a held lock is reported by `up_target` itself (`zygo: up or down is in progress for <name>`) and `up_all` adds `zygo: <name> skipped`.
- D8. `ls` states. Unreadable state → `Unreadable`. `phase = down` → `RepoMissing` when `main_root` or `common_dir` is not a folder, else `Down`; no tmux call. `building`, `draining`, `stopping` → that phase; the session check runs only for the clients count, and a failed or skipped call leaves the clients `-`. `phase = up`: no tmux program (D11) → `Unknown("no tmux")`; no `tmux_socket` → `Unreachable` (the server is not known); the socket in the failed set or past the deadline (D11) → `Unknown(<reason>)`; the socket's parent folder missing → `Gone` with no call (no server can listen there); AU62 refused → `Unreachable` with no call; else `session_exists`: `Exists` and `show_session_option(.., "@zygo-ws") == Ok(Some(<id>))` → `Up`; `Exists` with another value or none → `Unreachable`; an error of the option read → `Unknown(<reason>)`; `Gone` with a live launcher (AU87 (2)) → `Unreachable`; `Gone` otherwise → `RepoMissing` when the repository is missing, else `StoppedTmuxGone`; `Error` → `Unknown(<reason>)`.
- D9. `ls` agents (running/saved/detached). Running: members whose launcher is live (`member_live`). Saved: members not live, in state `running` or `resumable`, with `agent_session`, whose key is in `panes[]` (the next `up` resumes them). Detached: the same with no `panes[]` entry (W§7.5). Other members are not counted. Clients: `display("=<session>:", "#{session_attached}")` parsed as `u32`, only for a session that exists with this workspace's `@zygo-ws`; else none.
- D10. `ls` line (`impl Display for ListRow`): `<name>  <main worktree>  <state>  agents <r>/<s>/<d>  clients <n>`, fields joined by two spaces, `-` for a value that is not known (`main_root`, `agents`, `clients` of `None`). `name` and the path go through `esc` (the path as `to_string_lossy`). A state that cannot be read has `name` = its id (`ws forget <id>` then finds it, D14), `main_root`, `agents` and `clients` `None`. Rows are sorted by (name, id). The `ListState` words: `up`, `down`, `building`, `draining`, `stopping`, `stopped (tmux gone)`, `unreachable`, `repo missing`, `unreadable`, and `unknown (<reason>)` with the reasons `no tmux`, `tmux timed out`, `tmux error`.
- D11. `ls` time bound. `list(paths, tmux)` first runs `Tmux::new(tmux, None).version()`: `Err(Spawn)` sets `no_tmux` (every `phase = up` row is `Unknown("no tmux")`, the other rows keep their phase, no other call). Then `list_by(paths, no_tmux, &|s| Box::new(Tmux::new(tmux.into(), Some(s.into()))), &Instant::now)`. `list_by` has a total deadline of `LIST_DEADLINE` (4 s) from its start: before each tmux call it checks `now() + mux::BOUND <= start + LIST_DEADLINE` (a call can last up to `BOUND`); when that fails, the call is not made and the reason is `tmux timed out`. Any error of any call (`session_exists` giving `Error`, an `Err` of `show_session_option` or `display`) puts that socket into the failed set with its reason: `tmux timed out` for `MuxError::TimedOut` (or a `session_exists` message equal to `MuxError::TimedOut.to_string()`), else `tmux error`; every later row on that socket gets `Unknown(<reason>)` with no call. So `ls` makes no call past 4 s, and `/zygo:ls` stays inside the 4.5 s hook bound. `list` never fails; it always returns its rows. `admin::testing::list_by` exposes `list_by` with an injected multiplexer and clock, so the tests reach `TimedOut` and the deadline with no real wait.
- D12. `status` target. `zygo_workspace` set: it must be UTF-8 and pass `valid_ws_id`, else `Err("invalid workspace id <esc(lossy value)>")` (AU84); its state missing → `Err("no workspace with id <id>")`. Not set: `find_checkout(cwd, STATUS_GIT_BOUND)` (2 s, so the slash form fits 4.5 s), the id from `workspace_id(&checkout.common_dir)`; no checkout or no state → `Err("no workspace for this session or folder")`. A state that cannot be read → `Err` with the `StateError` `Display` (`Newer`: `workspace state is from a newer zygo; run zygo update`; `Invalid`: `<path>: <reason>`). `ZYGO_WORKSPACE` wins over `cwd`.

# UPD-1 — Auto-update: split check/install; start check at today's zygo claude / zygo opencode dispatch

**Spec:** `docs/specs/2026-11-21-auto-update-design.md` "Where" (`cmd/mod.rs:395-396`), "When the check is skipped", "Check", "Prompt", "Other sessions", "Opt-out", "Proxy", "Left to the builder". TTY detection with `std::io::IsTerminal` (no new dependency, so no `Cargo.toml`/`Cargo.lock` change); tests drive the check through an injectable `PromptIo` (TTY flag, input, output) instead of a terminal. Skip list as rewritten 2026-11-21: also skipped when `ZYGO_WORKSPACE` is set (tested with an injected environment). Honors `ZYGO_TEST_ASSUME_TTY=1` under `test-hooks` as a TTY (for subprocess tests, M5). `start_check` takes the environment as a closure and the terminal as a `PromptIo`, so tests pass both and need no `set_var`. The install path of `zygo update` is split out as `install(target, release_base, version)`: it replaces `target` (today `current_exe()` at `crates/zygo/src/cmd/update.rs:91-92`) and fetches from `release_base`; `release_base(env)` reads `ZYGO_RELEASE_BASE` through `env` under `test-hooks` (today `std::env::var` at `update.rs:132`). `start_check` gets the release base through its `env` and the binary to replace as `exe`. The entry points read the real values: `cmd/mod.rs` passes `current_exe()` (canonical) and `&|k| std::env::var_os(k)` to `start_check`, and `zygo update` (`update::run`) calls `install` with `current_exe()` and `release_base(&|k| std::env::var_os(k))`, so its behavior is unchanged. `ZYGO_TEST_ASSUME_TTY` is read where the entry point builds the real `PromptIo`. The auto-update #2 test runs in process: a temp file as `exe` and the fixture server URL as `ZYGO_RELEASE_BASE` through `env`, so the test binary is never replaced

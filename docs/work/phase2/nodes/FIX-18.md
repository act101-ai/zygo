# FIX-18 — Sessions have no idle expiry

**Spec:** `docs/specs/2026-11-18-zygo-design.md` §7.2 (Session creation, Session state, Liveness), §12.4, §12.5, and `docs/passthrough.md`, as amended 2026-11-22 by the operator ("i never asked for a ttl"); the texts are in "Spec changes for the controller" below. Defect from an operator question 2026-11-22: `IDLE_TTL` (`crates/zygo-proxy/src/session.rs:25`) made every session Gone after 24 h without an accepted request or a heartbeat (`liveness`, `session.rs:402`), so a local-mode agent pane idle 24 h, a workspace pane over a weekend, got `401 zygo_session_unknown` and had to be relaunched. The idle TTL was never requested. Fix: no session expires by idle time, local or team. `liveness` has no idle-time Gone case; `IDLE_TTL`, the expiry sweep and the delete-after-TTL of suspended sessions are removed. A session ends when its launcher deletes it at exit, local mode by stopping its proxy, or when the server restarts. The serve-mode heartbeat suspend of 5 min stays as it is
**Files:** `crates/zygo-proxy/src/session.rs`, `crates/zygo-proxy/src/routes.rs`, `crates/zygo-proxy/src/client.rs`, `crates/zygo-proxy/src/identity.rs`, `crates/zygo-proxy/tests/session_api.rs`, `crates/zygo-proxy/tests/passthrough.rs`, `crates/zygo-proxy/tests/request_path.rs`, `crates/zygo-launch/src/launcher.rs`, `crates/zygo-launch/tests/serve_client.rs`
**Consumes:** —
**Produces:** sessions have no idle expiry
**Acceptance:** `cargo test -p zygo-proxy --locked --test session_api` → all pass, including `local_session_has_no_idle_expiry` (a local session idle 25 h accepts a request; no request removes an idle local session, also after 30 days; `expires_at` empty), `team_session_with_heartbeats_idle_25h_accepts_a_request`, and `suspended_team_session_is_not_deleted_by_time` (suspended after 25 h, still mapped after 30 days and a request on another session, the next heartbeat resumes it with its compaction override)

## Plan

The fix is in `crates/zygo-proxy/src/session.rs`: `liveness` loses its Gone case, and `IDLE_TTL`, `Live.last_seen`, `Live.last_seen_utc`, `Sessions::sweep` and `retain_live` go. `routes.rs` loses the sweep middleware. `expires_at` stays on the wire, always empty. Tests that tested the idle TTL are removed or rewritten to the new rule.

Builds on: (signatures in the code now)
- `fn liveness(last_seen: Instant, last_heartbeat: Instant, team: bool, now: Instant) -> Liveness` (`session.rs:402`); callers `by_token` (`:596`), `accept` (`:608`), `heartbeat` (`:624`), `delete` (`:643`), `retain_live` (`:682`).
- `Sessions::sweep` (`session.rs:584`), called by the `sweep` middleware (`crates/zygo-proxy/src/routes.rs:49`, `:59`) on every session-API and model route; `retain_live` also ran in `Sessions::create` (`:569`).
- `SessionGrant.expires_at: String` (`session.rs:171`), `SessionStatus.expires_at: String` (`crates/zygo-proxy/src/client.rs:48`); written at `session.rs:340` and `:576`.

Plan produces:
- `fn liveness(last_heartbeat: Instant, team: bool, now: Instant) -> Liveness` with `enum Liveness { Active, Suspended }`: a team session is Suspended after `SUSPEND_AFTER` without a heartbeat, else Active; a local session is always Active.
- `Sessions::heartbeat` sets `last_heartbeat` only; `Sessions::accept` checks that the session is still mapped and active and refreshes nothing; `Sessions::delete` removes the session of the label and returns `Ok`, with no Gone case.
- `SessionGrant.expires_at` and `SessionStatus.expires_at` are always `""`, with `#[serde(default)]`.

Evidence, from the code:
- E1. Session kinds. `ProxyHandle::create_session` (`server.rs:303`) creates a local session (`team_label` `None`), held only by the launcher (`crates/zygo-launch/src/launcher.rs:339-355`, `End::Local`, stopped by `finish` at `:741`). The HTTP route `create` (`routes.rs:126-143`) needs a team label (`identity::team_label`, `identity.rs:54`), and `zygo serve` always has a `TeamAuth` (`serve.rs:113-116`). So every serve-mode session is a team session with the 60 s launcher heartbeat (`launcher.rs:401-411`).
- E2. `expires_at` readers. No code outside `zygo-proxy` reads the field: a search of `crates/` finds it only in `session.rs`, `client.rs`, and test fixtures (`crates/zygo-proxy/tests/session_api.rs`, `crates/zygo-hooks/tests/statusline_data.rs`, `crates/zygo-hooks/tests/statusline_render.rs`, `crates/zygo/src/cmd/status.rs` tests). But clients parse the two structs from a team server: `ServeClient::create_session` (`crates/zygo-launch/src/serve_client.rs:244-246`) deserializes `SessionGrant`; `SessionClient::status` (`client.rs:198`) deserializes `SessionStatus` for `zygo status` (`crates/zygo/src/cmd/status.rs:37`), the status line (`crates/zygo-hooks/src/statusline/data.rs`) and the drain rule (`crates/zygo-workspace/src/drain.rs:47`). In the code before this node both fields are a required `String` with no `#[serde(default)]`, and neither struct has `deny_unknown_fields`.

Decisions:
- D1. Operator, 2026-11-22: no idle TTL for any session; a session ends with its launcher or a server restart. The 5 min suspend of team sessions stays as it is; nothing is added.
- D2. `expires_at`: kept as a `String` field, always `""`, and `#[serde(default)]` on both structs (author's call, from E2). A client built before this node requires the field as a string: an absent field gives "missing field" and a `null` gives "invalid type: null, expected a string", so a launcher of that build against a team server of this build fails `create_session` and its `zygo status`, status line and drain fail on the status reply. An empty string parses in every build. `#[serde(default)]` lets this build read a reply without the field, so a later node can remove it once no older client is in use. No code reads the value, so empty carries no meaning to a reader.
- D3. A suspended team session is kept until its next heartbeat, its launcher's DELETE or a server restart. The launcher skips DELETE after an unreachable rows fetch (`launcher.rs:754-757`, S3), so such a session, and the session of a launcher killed without its exit step, now stays in the server's memory, suspended, until a server restart. Recorded as a finding for the controller; not changed (D1: nothing added).
- D4. Tests: `idle_ttl_24h` and `expired_sessions_swept_on_any_request` are removed (no idle TTL, no sweep); `local_session_has_no_idle_expiry` is new; `heartbeats_keep_session_past_idle_ttl` becomes `team_session_with_heartbeats_idle_25h_accepts_a_request` (1500 heartbeats, then a request; `expires_at` empty); `suspended_session_deleted_after_idle_ttl` becomes `suspended_team_session_is_not_deleted_by_time`; `refused_requests_do_not_refresh_ttl` becomes `refused_requests_leave_the_session_usable` (each refusal code on a session idle 25 h, then a request is accepted); `create_session_grant_shape` and `client_status_fields` expect `expires_at` `""` for a local and a team session. In `passthrough.rs`, `e2e_token_invalid_cases` loses its expired case and `e2e_accepted_request_refreshes_ttl` becomes `e2e_session_has_no_idle_expiry`; in `request_path.rs`, `route_accept_refreshes_ttl_and_sweeps` becomes `route_session_has_no_idle_expiry`.
- D5. Comments that named the idle TTL are corrected: `identity.rs` (`authenticate`, `model_identity`), `launcher.rs:754-755` (S3), `crates/zygo-launch/tests/serve_client.rs:1181`.
- D6. Acceptance stays `--test session_api`, as the brief sets; `passthrough.rs` and `request_path.rs` run in the full `cargo test -p zygo-proxy --locked --no-fail-fast` step.

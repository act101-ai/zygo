### Design calls

- D1. AU69 (a). `sweep::sweep(cache_root, workspace_cache, now)` keeps every rule of today's sweep and adds one case: a session folder whose `results` is a symlink is swept only when `in_workspace_cache(results, workspace_cache)` is true, (1) it is not `live`, (2) its newest change (`changed`) is `KEEP` (24 h) or more before `now`, and (3) `live()` is still false when checked again right before the removal. Then `remove_file(results)` first, and `remove_dir_all(dir)` only when that worked. The link target is never touched. `in_workspace_cache`: the cache made canonical (an error gives `false`); a link whose target exists: the canonical target `starts_with` the canonical cache; a link whose target is missing (`canonicalize` gives `NotFound`): its text (`read_link`) decides; a text with a `..` component gives `false`; any other text is joined to the canonical session folder and `existing_canonical` makes its longest existing part canonical, with the rest added back as text; `existing_canonical` gives `None` (keep) when a part on the way up is an entry that `canonicalize` cannot resolve (`symlink_metadata` succeeds there: a link whose target is missing, a link loop, an entry it cannot read; reviewer nit F7). Any other error gives `false`. Every I/O error keeps the folder. Two parts of this rule cannot make a test fail without a hook in the sweep, and this node adds no hook (plan review 2026-11-23, F8): (i) the second `live()` check: between the two checks the sweep calls only `symlink_metadata`, `canonicalize`, `read_link`, `read_dir` and `DirEntry::metadata`; none of them opens a file, so no test can make the sweep wait there, and a launcher can start between the two checks only by thread timing, which a test cannot control; (ii) the link-first order: every fault that stops the unlink of the link (a read-only session folder) also stops `remove_dir_all` of the other entries, so the outcome is the same with or without the guard. Step 3 has a test for the outcome of (ii) with this limit stated.

# FIX-19 — OpenCode plugin sends tool start and end to the member hooks

**Spec:** `docs/specs/2026-11-20-workspaces-design.md` W§9.1 (`tools_running`), AU26 (W10 round 3, running tool), AU27 (as H3 rewrites it: kinds only from `info`, the turn set); found by W10 implementation review rounds 2-3 (C24, C33 in `nodes/W10.md`); seam with H3 fixed by the H1/H3 plan review round 1 (controller, 2026-11-22). The plugin (`crates/zygo-launch/assets/opencode-plugin.js`) uses the hook names that it already uses and that the pinned OpenCode loads: `tool.execute.before` and `tool.execute.after` (`fixtures/opencode/binary-names.txt`, `load-result.json`). The existing `task` deny call stays as it is today for every session of a member, a known child included (`opencode-plugin.js:92-95`: `ws("pre-tool", { sessionID, tool_name: "Agent" })` and the throw on a deny answer); H1 never counts a `pre-tool` whose `tool_name` is `"Agent"` (H1 D5). Only the tool counting is new, and only for a member and an `input.sessionID` that is a non-empty id and not a known child of H3's `kind` map (the same population as H3's turn set: a top session or a session with no kind seen yet, never a session whose `info` showed a `parentID`): for every tool other than `task`, `tool.execute.before` queues `ws("pre-tool", { sessionID, tool_name })` with the tool's own name before the `guard` call and remembers `input.callID` in a set of counted calls. `tool.execute.after` queues `ws("tool-end", { sessionID })` first, before `trim` and `work`, exactly when `input.callID` is in that set, and then removes it from the set; it does not check the session's kind again, so a session that becomes a known child between the two calls still gets its `tool-end`, and a call that was not counted never sends one. A tool of a child whose `info` has not come yet is counted (busy, the safe side); its `tool-end` takes the count back. The plugin's `prompt` and `stop` calls (H3: the turn set becoming non-empty and empty) reset the count to 0 in H1, as `UserPromptSubmit` and `Stop` do for Claude Code; the plugin sends nothing more for them, and the `session` call does not change the count (H1). An Esc in OpenCode that ends a tool without `tool.execute.after` leaves the count up until the next `prompt` or `stop` call, the agent exit, the drain timeout or `down --now`. All calls go through the one `ws` chain, so they keep their order with `prompt` and `stop`. A `pre-tool` that denies adds nothing (H1), and a tool that the `guard` call then denies has no `tool.execute.after`: the count stays up until the turn's `stop`, the safe side.

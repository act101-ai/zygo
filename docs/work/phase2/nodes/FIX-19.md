Operator rules (2026-11-22): an open turn stays busy until Stop/StopFailure, agent exit, drain timeout or `down --now`; no timeout, TTL, cap, expiry or clean-up that can end or delete user work; there is never Claude attribution.

### Decisions

Author's calls of 2026-11-23 that fill the contract, with the plan-review decisions of the controller (2026-11-23); none adds a rule.

- D1. State: one `counted: Set<string>` per plugin instance, next to `kind` and `inTurn`. Each element is the key `` `${sessionID}\u0000${callID}` `` (plan review F4: a `callID` is unique only inside its session); D3 sends `input.sessionID` and D7 clears all, so no value per key is needed. An entry stands for one `+1` in zygo's count. It leaves the map at its `tool.execute.after` (D3), or when the plugin sends any `prompt` or `stop` call, whatever session that call names (D7), because zygo then sets the one member count to 0 and no entry stands for a `+1` any more (plan review F2 and 7(c)). Nothing else removes an entry: no cap, no expiry, no clean-up by time. An entry whose `tool.execute.after` never comes and that no `prompt` or `stop` follows stays; it can send only its own `tool-end`.
- D2. `tool.execute.before`, in this order: (a) `member` and `input.tool === "task"`: today's code, unchanged (`await ws("pre-tool", { sessionID: input.sessionID, tool_name: "Agent" })`, a deny throws); after a non-deny answer, keep the call (D1) when `isId(input.sessionID)` and `isId(input.callID)`. (b) else, `member`, `isId(input.sessionID)` and `kind.get(input.sessionID) !== "child"`: `ws("pre-tool", { sessionID: input.sessionID, tool_name: input.tool })` without `await`, then keep the call when `isId(input.callID)`. (c) the `guard` call as today. A deny answer to a non-`task` `pre-tool` is never read (H1 gives none for a name other than `"Agent"`).
- D3. `tool.execute.after`: first, when `member`, `isId(input.sessionID)`, `isId(input.callID)` and `counted` has the key of D1: `ws("tool-end", { sessionID: input.sessionID })` without `await`, then delete the key; then `trim` and `work` as today. No kind check here (a session classified as a child between the hooks still ends its call). A second `after` of the same key sends nothing.
- D4. A call whose `callID` or session id is not a non-empty string still sends its `pre-tool` (the tool runs, so the member is busy) but is not kept, so it sends no `tool-end`; the count stays up until the next `prompt` or `stop` (the safe side). The JSON fixtures and every trigger site of the 1.19.6 source give a `callID` (P1, P5); the PW4 `task` summary records no `callID` because it lists only selected keys.
- D5. A `pre-tool` call that fails, exits non-zero or is killed after 10 s answers `""`, which is not a deny, so the call is counted. If H1 did not count it (a missed lock, AU56), its `tool-end` can lower the count of another running tool by one; Claude Code has the same limit for a lost `PreToolUse`. AU27 states it as known limit (7).
- D6. Harness. The driver takes tool hooks as steps in the `events` list: an element `["tool.execute.before", input]` or `["tool.execute.after", input]` calls that hook with `input` and an output (`{ args: {} }` before, `{ title: "", output: "o", metadata: {} }` after), awaited in sequential mode, and pushes the thrown message or `null` to `res.stepThrew`; every other element is an `event` as today. The closing `task` call (`tool: true`, `callID` `"c"`) stays; it is counted and has no `after`, so the existing lists do not change. A new stub mode `hangpre` makes only `workspace` `pre-tool` calls sleep 12 s. `ws_seq` and the new `tool_seq` share one body (plan review F7).
- D7. Reset alignment (plan review F2 and 7(c), controller decisions). zygo's `prompt` and `stop` set the one member count to 0 for all sessions (`workspace.rs:214-217`, `:303-306`), so the plugin runs `counted.clear()` at the two places that queue a reset: in `leave` (`:70-72`), right after `ws("stop", { sessionID: id })`; and in `step` (`:128-130`), right after `ws("prompt", { sessionID: id })`. It runs only when that call is queued.

### Design decisions (author's calls; the spec fixes none of them)

- E-1. One output and one control folder per pane. The test writes `bin/claude` as a script: it answers `--version` with the pinned minimum, sets `ZYGO_STUB_OUT=<root>/out/$ZYGO_PANE` and `ZYGO_STUB_CONTROL=<root>/ctl/$ZYGO_PANE` when `ZYGO_PANE` is set, and `exec`s the stub. A member launcher sets `ZYGO_PANE` in the agent environment (W§8.4 last paragraph), so each pane key gets its own folders. A resumed stub of the same key continues in the same control folder: the stub skips the steps that `done` already holds (`stub.rs:232`).
- E-2. `SHELL=/bin/sh` for every stub workspace of the file (D-4). The PW11 test also runs `/bin/bash`, zsh and fish when installed. The live check runs the post-agent shell check with `/bin/sh`, with `/bin/bash`, and with the operator's login shell fish (`/usr/bin/fish` on this host).
- E-3. Every test builds its workspace with the real `zygo up` through the binary, on the harness private server reached through `$TMUX` (the M3 form, `workspace_member.rs:264-272`). Exception: #34 starts its first server through tmux's default resolution under `TMUX_TMPDIR`, as the item says. No test seeds a layout by hand.
- E-4. `down` runs as `down <name> --now --wait` (the M3 form). No E1 item tests the drain; E2 owns it.
- E-5. #37 stops `up` after the first window with a `tmux` wrapper on the harness `PATH` that holds the first `new-window` call with a bounded `exec sleep 30`. `up` has no test gate, and a new gate would change product code.
- E-6. The `/proc` reads (#17 pane environment, #21 the `sleep` process id, the PW11 signal masks) are `#[cfg(target_os = "linux")]`; the same tests check the portable part through `show-environment`, `#{pane_current_command}` and `C-c`.
- E-7. A server that `zygo up` starts reads the tmux config files (P9). So window targets come from `windows[].index` of the state or from `list-windows`, and layouts are compared with `layout_shape`: the `#{window_layout}` string without its checksum and without the pane id of each leaf cell (W§18 #20 "layout string … equal": the pane ids of a new server are not part of the saved layout's geometry). The tests also compare the pane geometry. In the live check, panes are targeted by the pane id from `list-panes`, never by a window or pane index.
- E-8. Each test has its own `Harness` (own home, own private server), so the tests run in parallel with no lock.
- E-9. The PW11 cargo test is the acceptance check (it runs in CI where tmux is present). The live runs with the real agents check what a stub cannot: an agent that put the terminal in raw mode leaves a usable shell after `/exit`. They type no prompt.

No product code change. Each hook runs `hook_command` (`crates/zygo-workspace/src/up.rs:494-525`), which snapshots the whole session with `list-panes -s`, so the window that a hook runs for does not change the result. F-1 and F-2 are tmux behaviour, recorded in the spec:

- F-1 (tmux 3.8): tmux 3.8 runs the workspace's `pane-exited`, `window-unlinked` and `window-layout-changed` hooks also when another session is current; `after-kill-pane` still runs only in the current session. So on 3.8 a closed window of shell panes is written at once.
- F-2 (tmux 3.2a): the target of `window-layout-changed` is the active pane of the window (`notify.c:253-258`, `layout.c:1049`, sent before `window_remove_pane` at `server-fn.c:189-190`). When that pane is the closed one, the hook goes to the current session (`notify.c:69-70`). So before 3.8 an active shell pane closed while another session is current waits for the next trigger, as a closed window does.
- Spec: W§7.4 (Triggers, first bullet; the PW6 known limit now covers the active-pane case and holds only before 3.8), W§7.5 rule 1, W§14 (a `window-pane-changed` hook rejected, AU90), W§17 PW6, W§18 #24 (kills the pane that is not active), #77 (checks each version), and a change-log row. `docs/premises.md` PW6: the probe sentence appended; status stays `failed`. Every fact of the old W§7.4 bullet is kept in the new text.
- Tests: #24 picks the pane of window 2 that is not active (`Row.active`, from `#{pane_active}`). #77 is renamed `w18_77_closed_shell_panes_while_another_session_is_current` (the old name `w18_77_a_closed_window_of_shells_waits_for_the_next_trigger` stays in the plan and round 1 text above, as history). It reads the version with the new helper `tmux_version` (`Harness.server` → `PrivateServer::tmux()` → `Multiplexer::version()`) and checks the rule of each version. The kill-pane comes after the 5 s check.

### Design (read before step 1)

- **No user settings write.** The temporary status line comes only through `claude --settings "$RUN/settings.json"` (`fixtures/claude-code/help.txt:227`). Flag settings take precedence over user, project and local settings, so the operator's `statusLine` (none today in `~/.claude/settings.json`) is not used during the probe and is never written. The script records `cksum` of `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/settings.json` at start and end and prints whether it is the same. The EXIT/INT/TERM/HUP trap is `live_traps` (`scripts/premises/live.sh`): it kills only the probe's driver (in `LIVE_PIDS`), its tmux session `zygo-hud-probe` (in `LIVE_TMUX`, through `tmux_own`) and removes only `$N2_SCRATCH/live-$$` (which holds `$RUN`).
- **`$RUN`** = `$N2_SCRATCH/live-$$/probe`, with `log/`, `pane/`, `fx/`. `$RUN/settings.json` = `{"statusLine": {"type": "command", "command": "python3 -I '<PREMISES_DIR>/hud_probe.py' statusline '<RUN>'", "padding": 0, "refreshInterval": 1}}`. The script stops with exit 1 if `$PREMISES_DIR` or `$RUN` holds a `'`.
- **Two Claude Code runs**, both with the operator's real environment and login, cwd = the checkout (`$REPO_DIR`):
  - **Run 1 (tmux, recorded):** own session `zygo-hud-probe`, window 120 × 45 (`resize-window` sets `window-size manual` on that window only, W-C3), attached in the operator's terminal. A driver (`hud_probe.py drive`) waits for the first status line run (bound `HUD_PROBE_WAIT`, default 180 s), then sets the phase file and captures the pane once a second with `tmux capture-pane -e -p`: `verbose` 12 s, `compact` 8 s, `wide` 10 s, `early` 10 s, `slow` 20 s, then `done`.
  - **Run 2 (plain terminal, visual):** phase `visual` (verbose OP13 bytes, then compact OP13 bytes: three rows); the operator answers four y/n questions after `/exit`.
- **Status line command output per phase** (`hud_probe.py statusline <run>`; it reads `$RUN/phase` first):

  | Phase | Reads stdin | Output |
  |---|---|---|
  | `verbose` | yes | H§6.3 verbose `printf` bytes (2 rows) |
  | `compact` | yes | H§6.3 compact `printf` bytes (1 row) |
  | `wide` | yes | 4 rows: `A|`+RULER; `B|`+10 × U+F0645+RULER; `C|`+10 × U+2702+RULER; `D|`+5 × `𝘇𝘆𝗴𝗼`+RULER |
  | `early` | **no** | `PH11 early` (exits at once) |
  | `slow` | yes | sleeps 5 s, then `PH12 slow` |
  | `done` | yes | `PROBE DONE: type /exit and press Enter` |
  | `visual` | yes | verbose bytes then compact bytes (3 rows) |

  RULER = the 30 blocks k = 1..30, each `"." * (10 - len(str(10*k))) + str(10*k)` (300 ASCII cells; the number `10k` ends at ruler column 10k).
- **Per run log** `$RUN/log/run-<time_ns>-<pid>.json`: `phase`, `tty` (`/dev/tty` opened `O_RDONLY|O_NOCTTY`, `TIOCGWINSZ` → `{"cols", "rows"}`, else `{"error": "<errno name>"}`), `env` (every name; value kept only for `COLUMNS LINES TERM TERM_PROGRAM TERM_PROGRAM_VERSION COLORTERM NO_COLOR FORCE_COLOR WT_SESSION LANG LC_ALL LC_CTYPE SHELL CLAUDECODE CLAUDE_CODE_ENTRYPOINT`; `TMUX` and `TMUX_PANE` → `"set"`; every other value → `"[omitted]"`), `stdin` (parsed JSON; `{"unparsed": "<text>"}` if not JSON; the string `"not read"` in `early`; at most 1 MiB read). Events `$RUN/log/events.jsonl`: `{"t", "pid", "phase", "event": "start"|"end"|"signal"|"stdout-error", "sig"}`; handlers for SIGTERM, SIGINT, SIGHUP, SIGPIPE write a `signal` event and exit 128 + signal.
- **Results** (`hud_probe.py analyze <run>` → `$RUN/results.tsv`, one `<id>\t<result>\t<text>` per id; SGR stripped with `\x1b\[[0-9;:]*m` before text rules; "last capture of phase P" = the highest-numbered `pane/NNNN-P.txt`; "no capture in phase P" → `failed` with that text):

  | Id | Probe action | `verified` when (else `failed`) |
  |---|---|---|
  | PH1 | Run 1 `verbose` capture with escapes; Run 2 question Q1 | The two stripe rows' SGR parameters hold `31`, `33`, `36` and `38;5;172`, and Q1 = y. Text names which are missing (`no 256-color`, `no color`) |
  | PH2 | Run 1 `verbose` capture; Q2 | Two consecutive rows start (after spaces) with `▌▌▌`, the first holds `main`, the second `ctx 196k`; and Q2 = y |
  | PH3 | Run 1 `wide` capture | The pane row after the `A|` row starts with `B|` (cut). Wrapped (that row continues RULER) → `failed` |
  | PH4 | Run 1 and Run 2 run logs; `wide` capture | `tty.cols` = 120 in Run 1 and = the terminal's `stty size` cols in Run 2; `COLUMNS` holds digits in both; usable area `2 + R_A (+1 if the row ends in …)` = 120. Text: `tty=<run1>/120,<run2>/<term> COLUMNS=<v1>,<v2> area=<n>/120 indent=<leading spaces>` |
  | PH5 | Every logged `stdin` | Each has `effort` as a string, or an object whose `level` is a string; text names the shape(s) seen; no stdin logged → `failed` |
  | PH6 | `wide` row B vs row A | c_B = (R_A − R_B) / 10 = 1 (R_X = length of the RULER prefix that row X shows after its glyphs). Text `c=<value>` |
  | PH7 | `wide` row C; Q4 | c_C = (R_A − R_C) / 10 = 1 and Q4 = y |
  | PH9 | `wide` row D; Q3 | c_D = (R_A − R_D) / 20 = 1 and Q3 = y |
  | PH11 | `early` captures and events | Every `early` capture from the 3rd on holds `PH11 early`, and ≥ 3 `early` runs each have `start` and `end` |
  | PH12 | `slow` events and captures | Always `observed`: `starts=<n> ends=<n> signals=<sig:count,…> no-end=<n> max-concurrent=<n> shown=<k>/<m> captures` |
  | PH13 | `hud_probe.py ph13 <opencode>`: `--version`, `--help`, the executable's bytes | No case-insensitive match of `status[_ -]?line` in `--help` or in the executable; text lists up to 20 unique matches with 30 bytes of context |

- **Questions** (Run 2, asked after `/exit`, read from `/dev/tty`, only `y` or `n` accepted):
  - Q1 (PH1): "Rows 1 and 2 began with three bars colored red, yellow and cyan; 'main' was blue; 'hud-work' was orange, a different color from the yellow bar. Is this what you saw? [y/n]"

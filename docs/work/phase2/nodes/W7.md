Library code here reads no process environment and no device: each value comes in as an input, and only the entry point (hook dispatch or cmd layer) reads the real environment, the pattern of UPD-1 `start_check` and HUD-8 `RenderEnv::from_env`: `UpOpts.tmux_env` is `$TMUX` (AU62 server choice, W§8.1 steps 9 and 13, W§18 #39), `zygo_session` is `ZYGO_SESSION` (AU95), and `vars` is the caller environment that `env::cleaned` (AU64) turns into the session environment; `attach` takes `$TMUX` as `tmux_env`. Tests set `tmux_env` to none (or to a value for #39), so no test reaches the live tmux server of the developer; no code in `zygo-workspace` calls `std::env::var`. `UpOpts.socket` follows the AU62 design: it only selects the server at creation (W§8.1 step 9); when set, `up` creates the session with `-S <socket>` instead of the `$TMUX` or default resolution, then stores the path it reads back as `tmux_socket` as AU62 says. Every later call for a workspace uses the stored `tmux_socket` (AU62), so `attach`, `down` and the `admin` functions need no socket override. The cmd layer (M1) passes none. Tests that start tmux use `PrivateServer::start` and pass its `socket`, so no test touches the default server (W-C3); the W§18 #39 test leaves `socket` none and sets `tmux_env` to the private server's `tmux_env`, so it tests the `$TMUX` path

# C1 — Core: workspace paths, session-dir accessors, session-view workspace field

**Spec:** `docs/specs/2026-11-20-workspaces-design.md` W§7.1, W§7.3 (`write_atomic`), W§16 zygo-core rows; AU58, AU72. Design per W§7.1 (rewritten 2026-11-21): `state_dir`, `workspaces_dir`, `workspace_cache_dir` are `Paths` methods, not fields (55 literals in 37 files lack `..`); `state_dir` is `$HOME/.local/state/zygo` when `data_dir` is `$HOME/.local/share/zygo`, else `data_dir/state`; the view gains one field `workspace` (`#[serde(default)]`). Builds on the HUD code (HUD-7): `SessionView` already has `impl Default` and every literal site ends in `..Default::default`, so no literal site changes here. `state_dir_in` holds the W§7.1 rule with `HOME` as an input; `state_dir` calls it with `HOME` from the environment, the same boundary as `Paths::from_env` in `crates/zygo-core/src/paths.rs`. The tests of both W§7.1 branches call `state_dir_in`, so no test changes `HOME`

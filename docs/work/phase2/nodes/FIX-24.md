# FIX-24 — A member whose hooks are off counts as busy

**Spec:** `docs/specs/2026-11-20-workspaces-design.md` W§9.3 step 5 (drain idle rule) and step 6 (timeout report), AU26 (its open-turn rule: busy until Stop/StopFailure, agent exit, drain timeout or `down --now`), W§9.1 (a missing `activity.json` reads as not busy), W§7.2 (`member.launch`), W§15 (§8.5 hooks row); `docs/specs/2026-11-18-zygo-design.md` §8.5 Flags (a user `disableAllHooks: true` wins and stops every hook, `zygo`'s included; FIX-21, FIX-23). Defect: `merge_settings` (`crates/zygo-launch/src/claude_code.rs:186-224`) keeps a user `--settings` key `disableAllHooks` as an ordinary key that wins, and `ClaudeCode::build` (`claude_code.rs:443-451`) writes the merged file to the member's session folder (`SessionDir::settings_json`) and passes it to Claude Code, so a member launched with `disableAllHooks: true` runs none of the member hooks of W§9.1. Its `activity.json` stays absent or at its default (`busy = false`, empty running set, `tools_running = 0`), so `drain::idle` (`crates/zygo-workspace/src/drain.rs:83-105`, called by `down` in `read_member`, `crates/zygo-workspace/src/down.rs:1118-1127`, with `activity::read` of the member's session folder) sees a working member as idle whenever its proxy is quiet for 10 s (for example during a long tool call), and `down` can stop it. Decision (controller, 2026-11-22): a member launched with merged settings that set `disableAllHooks: true` counts as busy for the drain until its agent exits (a member whose launcher is not live counts as idle, W§9.3 step 5), the drain timeout or `down --now` (AU26 open-turn rule); the user's setting is kept (no change to `merge_settings`). The signal is the merged settings file that the member's agent runs with: `<session folder>/settings.json` (the file zygo wrote) with the top-level key `disableAllHooks` equal to `true`; an OpenCode member has no such file. Second case (controller, plan review round 1 of H1/H3, minor 8, and round 2, F4, 2026-11-22): an OpenCode member that sends no member events at all also counts as busy for the drain until its agent exits, the drain timeout or `down --now`. It sends none when it was launched with `--pure` (loads no plugin, `fixtures/opencode/help.txt:38`), with `opencode run --attach <url>`, or with the subcommand `opencode attach <url>` (in both attach forms the plugin runs in a server without the member environment; known limit of W§9.1 and AU27). Where each signal comes from, verified on the live code: the only writer of `member.launch.args` is `up::fresh_member` (`crates/zygo-workspace/src/up.rs:563-576`), which stores `args::filter_from(agent, &pp.args, &pp.cwd).kept`. Neither `--pure` nor `--attach` is in the OpenCode table (`crates/zygo-workspace/src/args.rs:104-119`), so the filter keeps `--pure`, `--attach` and `--attach=<value>` as typed (`args.rs:276-278`); it removes every positional and `--` with every token after it (`args.rs:260-268`), so `run --attach <url>` is stored as `["--attach"]`, `run --attach=<url>` as `["--attach=<url>"]`, and the stored `launch.args` never hold `--`. The subcommand `attach` of `opencode attach <url>` is a positional, so the stored `launch.args` are `[]` and the record holds nothing that shows it (`Launch`, `crates/zygo-workspace/src/state.rs:141-159`, has no subcommand field; `member.program` is the agent program path). FIX-24 adds what it needs to `state::Launch` (W2; the type of `MemberRecord.launch`, which W2's Produces names through `state::MemberRecord`): a field `Launch.attach: bool` (W§7.2 key `member.launch.attach`; `#[serde(default)]` and left out of the JSON when `false`, so a file of an older zygo reads and an older zygo keeps the key in `Launch.extra`), written once at launch by `up::fresh_member` from the raw loadout arguments `pp.args`: `m.launch.attach = agent == Agent::OpenCode && args::first_positional(agent, &pp.args).as_deref() == Some("attach")`. `args::first_positional` uses the same walk as `filter`, so a flag value (for example the value of `--prompt` or `--log-level`) and a token after `--` are never the first positional. A restore keeps the saved record, so the field stays with the member. The drain check is in `drain_tick` (`down.rs:1130-1161`), where each member record `m` (and so `m.launch`) is held: for a member whose launcher is live (`live_session` gives the session folder `dir`, `down.rs:1141`), the result of `read_member(&dir)` is replaced by `Idle::Busy { reason: EVENTS_OFF, rule_skipped: false }` when `drain::events_off(&m.launch)`, else by `Idle::Busy { reason: HOOKS_OFF, rule_skipped: false }` when `drain::hooks_off(&SessionDir::new(dir))`; the running set read by `read_member` is kept for the timeout report. A member whose launcher is not live stays idle as today (`down.rs:1144-1147`). The spec text in this node's scope: AU26 (a member whose agent sends no member events counts as busy, with its reason), W§7.2 (`member.launch.attach`), W§9.3 steps 5 and 6, and the known-limit sentence of the W§9.1 OpenCode paragraph and of AU27 (as H3 writes them), which gain "such a member counts as busy for the drain until its agent exits, the drain timeout or `down --now` (AU26)". No timeout, TTL, cap or clean-up is added. Edges: H1 (`down.rs` after the `saved_for` write; `state.rs` after the `Store::update` size limit), H3 (both rewrite sections of the workspaces spec; FIX-24 edits the known-limit text H3 writes), FIX-23 (the §8.5 merge line for `disableAllHooks` comes first).

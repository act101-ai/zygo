### Decisions

- D1 (author's call; review findings 1, 2, 7). One flag, `launch.events_off`, computed from the arguments of the start that really runs. `member::record_start` always sets `kept.events_off = args::events_off(launch.kind, &launch.args)` from the arguments it gets, before the AU30 filter: the typed arguments for a hand start, the saved arguments for a `ws run` start (fresh loadout or restore). `join` keeps the saved launch at an accepted AU94 resume and still sets `rec.launch.events_off` from the typed arguments. `up::fresh_member` does not change: its record has `events_off = false` (from `MemberRecord::new`); until the `ws run` start write of that pane the member has no live launcher, so the drain counts it as idle (W§9.3 step 5) whatever the flag holds. Because the field is a named field of `Launch`, a JSON key `events_off` always reads into it and never into `Launch.extra`, and `record_start` overwrites it at every start, so a value that an older zygo kept never survives a start by this zygo. Effect on `record_start`'s D4 compare (`kept != rec.launch`): only for an OpenCode record or a Claude Code `--bare` record can the flag differ; OpenCode has no content flag (`args.rs:105-121`), and for Claude Code `dropped_flags` is then replaced by the filter's list of the same arguments, which is the rule D4 already applies when a launch changes.
- D2 (rule of `events_off`). True when, by the walk of `filter` (a flag value and a token after `--` are never a flag or a positional): Claude Code: the table flag `--bare` occurs. OpenCode: a long flag `--pure` occurs (its name before any `=`); or the first positional is `attach` (`opencode attach <url>`); or the first positional is `run` and a long flag `--attach` occurs (`opencode run --attach <url>`, `run --attach=<url>`). Not events off: a saved `["--attach"]` with no `run` (P12); `--pure-x`, `--attachx`; `--prompt attach`; any token after `--`. `--pure=false` counts as events off (the safe side; no test needs it).

The callback order: (1) the member record write, one `store.update_existing(WRAPPER_WAIT, f)` where `f` takes `ws.members.get_mut(pane)` (none → `Err` with `no member record for pane <pane>`) and runs `record_start`; it never inserts a record. (2) Only when that write gives `Ok(Some(ws))`: the results folder and link (AU16), the saved overrides from `ws.members[pane].overrides` (W§8.2 step 4), `snapshot::after_write` (W§7.3), test gate `callback` (D9), the start snapshot (W§7.4). `Ok(None)` (`ws forget` ran after the `ws run` read) and `Err` (`ws forget-pane` ran, the lock was not taken, or an I/O error) end the callback with nothing more made; the callback returns `Err` with the text (the launcher logs it, C6). - D5 (controller minor 2, 3; second review finding 8). The exit write runs only when the callback write gave `Ok(Some(_))`. It is one `store.update_existing(WRAPPER_WAIT, f)`: `f` takes the record (none → `Err`), runs `record_exit`, and gives `Err` with `unchanged` when `record_exit` gives false (so nothing is written). `record_exit` changes a record only when its `zygo_session` is this start's session or its `pending` names this session. Results: `Ok(Some(ws))` → `kept = ws.members[pane].agent_session`, then `after_write` and the exit snapshot; `Ok(None)` or `Err(Refused)` → no line, `kept = None`, no `after_write`, no exit snapshot; `Err(Busy)` or `Err(Io)` → one stderr line `zygo: could not save the exit record of pane <pane>: <error>`, `kept = None`, no `after_write`, no exit snapshot. - D15 (controller second review, finding 13).

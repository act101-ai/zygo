Tool count (W10 round 2, author's call 2026-11-22): `ClaudeCode::hooks` registers for members `PreToolUse` with matcher `*` (in place of `Agent`) running `workspace --event pre-tool`, `PostToolUse` and `PostToolUseFailure` with matcher `*` running `workspace --event tool-end`, and `SessionEnd` running `workspace --event session-end`. `pre-tool` keeps the deny of W§9.2 for `tool_name == "Agent"`; when it does not deny and the input is the main loop (no `agent_id`), it adds 1 to `Activity.tools_running` through `activity::update(dir, activity::LOCK_BOUND, ..)`. `tool-end` on the main loop takes 1 away, never below 0 (`saturating_sub`). `prompt` (main loop, also from the OpenCode plugin), `stop` (also from `StopFailure` and from the OpenCode plugin's idle event) and `session-end` set it to 0: a new prompt means the earlier tools are over; the OpenCode `session` call sets it to 0. An Esc during a tool fires no hook (P-N24-1), so only these resets end such a count. A subagent event never changes it. Each change is one `activity::update` under `activity.lock` with the hook bound; a bound that passes writes one log line and exits 0 (AU56). A lost `tool-end` leaves the member busy, the safe side: `down` then times out unless a `Stop` comes. The hook prints nothing for `tool-end` and `session-end`. State between W10 and H1 (W10 round 3, B2): W10 reads `tools_running` and nothing writes it until H1 merges, so until then every member reads 0 and a tool longer than 60 s keeps the old AU26 behaviour.

# W11 — MCP tool workspace_down behind [features] workspace_tool (AU65, PW15 fallback)

**Spec:** `docs/specs/2026-11-20-workspaces-design.md` AU65, AU18, W§9.3 step 2, W§12 (`/zygo:down [--now]` scope), W§17 PW15, W§18 #78; W§15 row §15.4. `Features.workspace_tool`: default `false`, read from the merged config only (not from the session view); a profile cannot set it (it stays out of `crates/zygo-config/src/profile.rs` `features_ok` and of `crates/zygo-proxy/src/team.rs` `profile_features`). The tool is listed (Claude Code and OpenCode) only when the toggle is on and the session view has a `workspace` marker (AU58). Input `{"now": bool}`, optional; any other key gives `InvalidParams`. A call reads `name` with `state::Store::read` for the marker's `ws_id`, runs `<zygo> down <name>` (plus `--now`) with `ZYGO_SESSION` set to this session's id (the session directory's name), stdin from `/dev/null`, stdout and stderr piped; it waits at most 5 s for the exit and for EOF and returns the output text. A non-zero exit gives `ToolError::Failed` with the text; on timeout the tool kills the process and fails with `zygo: down did not return within 5 s`. In `tools::build` the program is `std::env::current_exe()` and the paths are `Paths::from_env()` (the pattern of `crates/zygo-mcp/src/tools/work.rs:13`), so `McpCtx` does not change (its literals are in `crates/zygo-results/tests/results.rs`, owned by M1). Tests use `WorkspaceDown::new` with a stub program. Edge to H1 for `Cargo.lock`

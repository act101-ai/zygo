# OS-42 — Runner dispatch under wrappers and unseen live output

**Spec:** `docs/specs/2026-11-24-output-shaping-design.md` O§7.6 (the dispatch paragraph "A runner view is tried when…" and the row `pytest`), O-C9. The plan of this node rewrites that text as final text, with a change-log row `author's call (lead) … hides less (O§15 item 2 decision record)`. Its changes may only hide less.
**Files:** `crates/zygo-results/src/shape/runner.rs`, `crates/zygo-results/src/shape/command.rs`, `crates/zygo-results/tests/shape_runner_dispatch.rs`, `docs/specs/2026-11-24-output-shaping-design.md`
**Consumes:** `runner::view` (OS-30) and the runner order of a wrapper segment (OS-30; the wrapper list in command.rs: make test, just test, npm test, pnpm test, yarn test), `runner::pytest` (OS-31) and its live-output rule (OS-31), `runner::gotest` (OS-32)
**Produces:** a dispatch in which no runner view hides a line of the failure text of another runner, and no pytest view applies when its live-output setting cannot be seen
**Defects to fix** (found at OS-31 close, review F2 and the R2 report):

- a. Under a wrapper, `[Libtest, Pytest, Gotest]` are tried in order, and the first with a summary wins (`runner.rs:84`). A pytest run whose `FAILURES` section captured a `cargo test` run (`test x ... ok` lines and a `test result: ok.` line) gets the libtest view. The libtest failure tracking knows only `---- ` and `failures:` (`runner.rs:122`), so it hides the captured `... ok` lines inside the pytest failure section. With `pytest` as the command, the same text keeps them.
- b. Under a wrapper, the pytest flags `-s` and `--capture=…` cannot be seen, so the pytest view can hide the prints of a failing test (O-C9).
- c. Live output that the command never shows: `PYTEST_ADDOPTS` with `-s` (as a leading `NAME=value` word or in the environment), `addopts = -s` in an ini file, and `-p no:capture`.

**Acceptance:** `cargo test -p zygo-results --test shape_runner_dispatch && cargo test -p zygo-results --test shape_runner_libtest && cargo test -p zygo-results --test shape_runner_pytest` → all pass, including: (a) `make test` with the pytest-captures-cargo text keeps every captured `test … ... ok` line; (b) `make test` with pytest `-s` output where a failing test prints a progress-like line keeps that line; (c) `PYTEST_ADDOPTS=-s pytest` and `pytest -p no:capture` give no pytest view; the existing `shape_runner_libtest` and `shape_runner_pytest` suites still pass

### Decisions (author)

1. **Defect a, the section mask (O§7.6 rewrite item 3, O-C9).** `view` picks the runner `r` as now. Then it builds `keep`: one `bool` per line, the OR of `section(o, text)` for each `o` of `[Libtest, Pytest, Gotest]` other than `r`. A line with `keep` true is never hidden. `section` uses the failure sections of O§7.6:
   - Libtest: the same toggle as `libtest`. On at a line that starts with `---- `, off at a line `failures:`; the flag is the state after that line.
   - Pytest: on from the first line that matches `PY_FAILURE` to the end.
   - Go test: `go_lines(text)[i] == GoLine::Kept`.

   The mask applies only in `view`. The public `libtest`, `pytest`, `gotest` and `gotest_passed_lines` stay unmasked (they call the `_kept` form with `&[]`), so the OS-36 check (each hidden line matches `hidden_by` or is in `gotest_passed_lines`) still holds: the mask only removes hidden lines. The chosen runner still decides alone, so a masked view with nothing hidden is `None` (no change). It does not fall through to the next runner.
2. **Defect b (rewrite item 2).** In `stage`, a stage whose runners are `ALL_RUNNERS` (a wrapper) sets `acc.live_pytest`. `parse` then filters `Pytest` out of `runners` for the whole command (`command.rs:385`), so a wrapper tries `[Libtest, Gotest]`. The stored name does not change (`runner_name` is set from the stage, `command.rs:1314-1315`).
3. **Defect c, command-line forms (rewrite item 4).** `sets_pytest_addopts(words)` is true when a word starts with `PYTEST_ADDOPTS=` or `PYTEST_ADDOPTS+=`. It is checked on every stage, in every mode, at the top of `stage`, so `export …; pytest`, `env PYTEST_ADDOPTS=… pytest`, `bash -c '…'`, `env -S` and here-doc bodies count. The value is not parsed: pytest splits it with `shlex`, and any value can hold `-s` in a quoted form (O-C9: "when a shaper is unsure, … no change"). `pytest_live` also reads `-p`: in a short-option word, after the letters before the first of `kmrpcoWn`, a `p` is followed by the rest of the word or, when that is empty, by the next word. Live when that value is `no:capture`.
4. **Environment and ini: no code.** See Premises. Reading `std::env` in the hook process or reading ini files from `cwd` would be a new input that O§7.2 does not give, and it would not see the Bash shell's own environment or the rootdir that pytest picks. So it is a spec gap, not a rule of this node.

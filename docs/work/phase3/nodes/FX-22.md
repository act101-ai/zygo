### Decisions (author)

1. Keep `ref = "v2.9.2"` and re-pin it to its current commit `9d82bd97…` (option A). Do not move to `v2.9.5` (option B). Reason: option A has the least to reverse. It changes one line in each of the three pin files and one constant in each of two tests. The fixture tree, the `act-lite` digest, `act-lite` 1.2.3 and `fixtures/act-lite/languages.json` (`act_lite = "v1.2.3"`, spec §10.5) stay the same. Option B changes the fixture tree, the digest, the act-lite version and the language list. §15.9 says that "each zygo release moves the pin"; a version bump is release work, not part of this fix. Risk: the upstream tag can move again. If it does, the same line comes back, and the same re-pin fixes it.
2. The acceptance check runs as `git ls-remote https://github.com/act101-ai/act101.git 'refs/tags/v2.9.2' 'refs/tags/v2.9.2^{}'`. Pass: the peeled `^{}` line, if present, else the plain line, prints the `commit` of `marketplace.toml`. Reason: the acceptance's literal pattern `refs/tags/<ref>^{}` matches only annotated tags, and every act101 tag is lightweight (Premises bullet 2). So the literal pattern prints nothing for every possible `ref`. Its intent, "the tag resolves to the pinned commit", is what the plain line shows for a lightweight tag. The Acceptance line now states this check (author's call).
3. No new test that launches against the network. The tag-moved behavior already has network-free tests with local repositories (`crates/zygo-plugins/tests/sync.rs:856` `moved`, `crates/zygo-plugins/tests/marketplace.rs:642`). This node changes data only. Its test-first change is the pinned-commit constants. `zygo-plugins` and `zygo-config` read them offline from the checked-in data.

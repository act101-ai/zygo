### Premise check (3.1) and decisions

Live code read: MS-15 (`ops.rs`: `drop_host` asks with `drop_prompt` and the `[y/N]` + `y (--yes)` form of `cmd/mail.rs:397-410`, the model for this question), MS-17 (`cmd/mail.rs`, `tests/mail_sync_cli.rs`, `admin::named`), WD-12 (`up.rs` pool code: no forget change), WD-14 (`ws.rs`: only `launch_of`, `launch_open_code_of`; `Forget` untouched), `admin.rs` forget path.

1. **Drift: order.** S§14 put the question before W§12. The W§12 checks must come first (no question for a running workspace), and the worktree must go before the cache: `remove` (`admin.rs:764`) deletes `<workspace_cache_dir>/<id>/`, which holds `mail-sync/`; after that, git lists the worktree as `prunable` and #26 fails. Probe (git 2.56.1, scratch repository): a deleted folder leaves `… (detached HEAD) prunable` in `git worktree list`. S§14, S§7.6 rewritten (change log 2026-11-26).
2. **Drift: when to run git.** Probe (git 2.56.1): `worktree remove --force` on a registered path with no folder exits 0; on a path git never registered it exits 128 `is not a working tree`; with a missing `main_root` the spawn fails. Decision: git runs only when the worktree folder exists and `main_root` is a folder. A stale entry is harmless: the next `worktree add --force` at the same path takes it over (S§6.3 Make), and the path is the same for a new workspace of the same repository (W§5: id from the common dir, `identity.rs:17`). No stderr text matching is needed. S§6.3 rewritten.
3. **Drift: the "no" answer and stdin.** The planned `&dyn Fn(&Workspace) -> Result<(), String>` cannot say "kept" (exit 0) apart from "refused" (exit 1), and a `Fn` cannot read stdin or write the prompt without interior mutability. Now `&mut dyn FnMut(&Workspace) -> Result<bool, String>`; `admin` formats the lines with its label. No consumer names this signature (WD-15 and MS-22 Consumes do not list it); the node header is updated.
4. **Decision: the sync lock in `admin`.** A pass that runs during the removal would use, or make again, the worktree (`ensure_worktree`, `branch.rs:212`). `zygo-workspace` cannot depend on `zygo-mail-sync` (crate graph), but it owns `mail_dir` and `lock_file`, which take the same fs4 lock on `mail/sync/lock`. `forget` takes it at once, only when `mail/sync/` is a real folder (no sync folder: no sync ever ran, nothing is made), keeps it until `forget_run` returns (after `remove`), and refuses while a sync holds it. Lock order `op.lock` → sync lock → `lock`; forget never waits on the sync lock, so no cycle. S§7.6 step 1, S§15 row.
5. **Decision: the question under `op.lock`.** The question runs after the checks with `op.lock` and the sync lock held and before `lock` (the state lock that hooks wait on): `up`/`down` refuse meanwhile, as for any forget; no member is live (checked). `--yes` and the end of input never wait.
6. **Decision: a state that cannot be read.** `check_invalid` returns a probe `Workspace` (id, raw valid name, members, and `main_root` from the raw JSON when it is an absolute path, else empty), and the same step runs: its outbox is counted, and git runs only with a `main_root` folder.
7. **Decision: failure policy.** An outbox that cannot be read, or a removal that fails, refuses with nothing deleted (S§19 #20 comment at `outbox.rs:191`: unsent mail is never taken for none). A forget whose question was answered yes and then refused asks again at the next run.
8. **Bound.** `WORKTREE_REMOVE_BOUND` = 10 s: the worktree has no checkout (`--no-checkout`, S§6.3 Make), so the removal deletes a `.git` file, an index and git's entry; the S§8.2 probe has the same 10 s.
9. **Imported log.** It lives in `mail/sync/imported` under the state folder, which `remove` deletes; no extra code.
10. **Review focus.** No item names MS-21. Item 75 (no new test that spawns an agent or reads a clock) applies: no test here starts an agent, and `send` uses the fixed time `SENT` (not `SystemTime::now()`). S-C4 "never `git worktree prune`" is tested by a `prunable` user entry that stays (F1).

/// S§7.6 step 1 (MS-21): the lock of `mail/sync/lock` (the sync's lock, `SyncPaths::lock` of `zygo-mail-sync`), taken
/// at once, when `mail/sync/` is a real folder; `None` when it is not (no sync ever ran, so nothing is made). Held by
/// a sync: `zygo: a mail sync runs for <label>; try again` (exit 1).
fn sync_lock(paths: &Paths, id: &str, label: &str) -> Result<Option<fs::File>, ForgetError> {
    let dir = mail_dir(paths, id).join("sync");
    if !fs::symlink_metadata(&dir).is_ok_and(|m| m.is_dir()) {
        return Ok(None);
    }
    match lock_file(&dir.join("lock"), Duration::ZERO) {
        Ok(Some(f)) => Ok(Some(f)),
        Ok(None) => Err(ForgetError::Line(format!("zygo: a mail sync runs for {label}; try again"))),
        Err(e) => Err(ForgetError::Line(format!("zygo: cannot forget {label}: {e}"))),
    }

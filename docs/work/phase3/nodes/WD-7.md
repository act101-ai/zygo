### Where the definition is validated (WD-6 review note)

`apply_to_config` and `with_definition`, like `repository_loadout`, trust their input. A `Definition` is validated only by `repo_def::parse` (`repo_def/shape.rs:54-77`, the R§6.4 allow list; the read limits of R§6.1 step 4 come before it in `read.rs`). The only producers of a `Definition` for these calls are `check_default` (`repo_def/check.rs:26-48`, returns `Use::Approved { def, .. }` after the digest is approved) and `check_pinned` (`check.rs:59-72`, `PinnedUse::Approved { def }`). The callers (WD-11, WD-13, WD-16) pass only a `def` taken from one of those two `Approved` variants. The doc comments of both new functions say so (steps 3 and 9).

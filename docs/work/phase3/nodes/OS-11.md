### Decisions (author)

1. Bound: `parse` lexes `&cmd[..cut]`, where `cut` is the largest char boundary at or below `MAX_COMMAND_BYTES` (4096). When `cmd.len() > 4096`, the parse is unsure (O§7.1). `name`, `runners` and `reuse` still come from the prefix. A command of exactly 4096 bytes is not unsure.
2. Depth: the top-level script is depth 0. Each place that O§7.1 says to look into adds 1: `( … )`, `$( … )`, backticks, `<( … )`/`>( … )`, a `-c` string, the words after `xargs`, and each `-exec`/`-execdir` group. A depth above `MAX_DEPTH` (4) makes the parse unsure, and the lex stops there. So recursion never goes deeper than 5 frames.
3. Unsure stops the lex. This applies to an unclosed `'`, `"`, `$(`, `(` or backtick, a `)` with no open bracket, or a depth above 4. Segments that are already lexed still give `name`, `runners` and `reuse`.
4. Shell mechanics that would otherwise hide a printer. These are toward safety and are not in O§7.1's list:
   - The leading reserved words `! { } if then else elif fi do done while until` are skipped, like wrappers.
   - Redirections (`>f`, `2>&1`, `&>f`, `<<EOF`, `<<<w`) and their target word are not argv. Digits directly before `<` or `>` are an IO number.
   - `<( … )` is looked into like `$( … )`.
   - `env -S s` is parsed in turn, like `-c`.
   - A program word that holds `$` or a substitution (`$PAGER f`, `$(which cat) f`) counts as unsure.
   - Here-doc bodies are lexed as commands. This is protective: `bash <<EOF` runs them. Unbalanced text in a body gives unsure, which means no shaping and never a wrong view.
5. Wrapper options: after a wrapper, words that start with `-` are skipped, and so is `--`. The word after an option that takes an argument is skipped too. The options that take an argument are:
   - `env`: `-u -C --unset --chdir`
   - `time`: `-f -o --format --output`
   - `sudo`: `-u -g -h -p -C -D -r -t -T -U`
   - `nice`: `-n --adjustment`
   - `command`: none
6. Subcommand scan (`fn sub`), for names, runners, git printers and reuse. Walk the args after the program:
   - A word that starts with `-` or `+` is an option. Continue.
   - A word in the list is the subcommand.
   - Any other word is skipped when the word before it was an option (`git -C dir diff`). Otherwise the scan stops with no subcommand.

   The same scan with the list `["test"]` serves `make` and `just`. A false hit only adds a file printer or mislabels a stored name. Both are safe.
7. `-c` string: for program `bash`, `sh` or `zsh`, the first arg that starts with a single `-` and contains `c` (`-c`, `-lc`, `-ec`) marks the string. The string is the first later word that does not start with `-`.
8. `xargs`: skip words that start with `-`. After an exact `-I -n -P -L -d -a -E -s`, also skip the next word. The rest is a stage at depth +1. `find`: for each `-exec` or `-execdir` word, the words up to a word `;` or `+` (or the end) are a stage at depth +1. An escaped `\;` lexes to the word `;`, never to an operator.
9. Name and runners come from top-level stages only (depth 0, not nested, not xargs or find). `reuse` and `file_printer` look at every depth. `runners` is the union over top-level stages, in segment order, with no repeats.
10. Name rule (O§7.2):
    - Take the name from the first top-level stage that names a runner.
    - Else take it from the first segment whose first stage's program is in `NAMES`.
    - Else the name is `other`.

    The name is the program base name, plus ` <sub>` for the nine subcommand programs when `sub` finds a subcommand. When the runner stage's program is outside `NAMES` (`poetry run pytest`, `py.test`), the name is `other` (O-C2), with no fall-through.
11. Subcommand lists (O§15 item 1), `const` arrays in `command.rs`:
    - git: `add am apply archive bisect blame branch bundle cat-file checkout cherry-pick clean clone commit config describe diff fetch for-each-ref format-patch gc grep init log ls-files ls-remote ls-tree merge merge-base mv notes pull push range-diff rebase reflog remote reset restore rev-list rev-parse revert rm shortlog show show-ref stash status submodule switch tag worktree`

Lexer rules (outside quotes):

- Space, tab and `\r` end a word. `\n`, `;`, `&&`, `||` and a lone `&` end a segment. `|` and `|&` end a stage.
- `#` at the start of a word skips to `\n`.
- `\` followed by newline is removed. `\c` gives `c`.
- `'…'` is literal.
- In `"…"`, `\` escapes only `$`, `` ` ``, `"`, `\` and newline. `$(` and backticks nest.
- `${…}` is read to its `}` and marks the word dynamic, like `$name`.
- `(` at the start of a word, `$(`, `<(` and `>(` call `script(depth + 1, Some(')'))`. A backtick lexes the raw text up to the next unescaped backtick at depth + 1.

Runner forms (O§7.6):

| Runner | Form |
|---|---|
| `Libtest` | `cargo` with `sub == test`; a `+toolchain` word is skipped as an option |
| `Pytest` | `pytest`; `py.test`; `python` or `python3` where the word after the first `-m` is `pytest`; `uv run pytest` or `poetry run pytest` (after `run`, skip `-` words; the next word is `pytest`) |
| `Gotest` | `go` with `sub == test` |
| All three, in that order | `make test`, `just test` (scan with `["test"]`), `npm test`, `pnpm test`, `yarn test` |

Reuse forms (O§7.3):

- `git` with sub `diff` or `show`
- `git log` with a word `-p` or `--patch`
- `git format-patch` with a word `--stdout`
- program `diff`

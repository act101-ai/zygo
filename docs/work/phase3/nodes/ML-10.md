### Decisions fixed by the code and the spec

- D1. The Stop block needs `hook_event_name == "Stop"` and `stop_hook_active == false` in the input. `StopFailure` is routed to the same `--event stop` (`crates/zygo-launch/src/claude_code.rs:496`) and Claude Code ignores its output (`fixtures/claude-code/settings-schema.json:2230`): a block there would keep `busy` with no further turn. M§7.1 names only `Stop`. An OpenCode `stop` payload has neither key, so it never blocks (M§7.3 last sentence).
- D2. Blocking changes nothing in `activity.json`; every other main-loop `stop` clears as today (AU43, M§7.1 last sentence).
- D3. The prompt line is Claude Code only: the plugin drops the output of its `prompt` call (`opencode-plugin.js:45`, `:139`); OpenCode gets the line from the per-request session text (M§7.2, AU104). The AU86 block check stays first.
- D4. A mail read error (C6, M-C1, M§10): one `error_line`, the count is taken as 0, the hook goes on and returns `Ok`. No `Err` is returned, so OpenCode keeps its session text and `stop` still clears `busy`.
- D5. SessionStart parts: session text, item 8, resume note, delivery line (M§7.2: after the resume note), joined by `\n\n` as today. One line only (see the M§9 note in the report).

# DR-10 — Agent transitions: the D§6.6 rule for one record change

**Spec:** `docs/specs/2026-11-24-decision-records-design.md` D§6.6 (the agent rows; `fixed` and `superseded` final), D§6.3 ("frozen" keys: `kind`, `class`, `unit`, `round`, `role`, `id`; operator keys), D§9.4 step 9 (what a change must be), D-C4, D-C5
**Files:** `crates/zygo-work/src/lib.rs`, `crates/zygo-work/src/gate/mod.rs`, `crates/zygo-work/src/gate/transition.rs`, `crates/zygo-work/tests/decision_transition.rs`
**Consumes:** `Record` (DR-1), `Status` (DR-1), `NameKind` (DR-1), `name_kind` (DR-1)
**Produces:** `gate::transition::Version` (`Absent | Malformed | Valid(Record)`); `gate::transition::RangeCtx { pub range: BTreeSet<String>, pub superseding: BTreeSet<String> }` (full commit ids of the node range; ids named in `supersedes` by records added in the range); `gate::transition::agent_change(id: &str, old: &Version, new: &Version, ctx: &RangeCtx) -> Option<String>` (`None`: an allowed agent transition; `Some(problem)` otherwise)
**Acceptance:** `cargo test -p zygo-work --locked --test decision_transition` → all pass. One case per D§6.6 agent row allowed (none → `open`; `open` → `open` with non-frozen keys; `open` → `fixed` with `fixed_by` in the range; `open` → `superseded` named by a record added in the range; `overturned` → `fixed`; `ratified` with `promoted_to` gains `promoted_by` in the range) and one problem each for: a change of `kind`, `class`, `unit`, `round` or `role`; an agent writing `ratified` or `overturned`; an agent writing `reviewed`, `review_note`, `promoted_to` or `promotion`; `fixed_by` or `promoted_by` outside the range; `superseded` that no added record names; a change of a `fixed` or `superseded` record; a deleted record (`new = Absent`); a malformed new version; a new record created with a status other than `open` or with an operator key.

Produces (`crates/zygo-work/src/gate/transition.rs`):

```rust
/// One version of a record file in one commit (D§9.4 step 9).
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Version { Absent, Malformed, Valid(Record) }

/// The node range facts that one record change is checked against.
#[derive(Debug, Clone, Default, PartialEq, Eq)]
pub struct RangeCtx {
    /// Full commit ids of the node range R (`git rev-list <base>..<head>`).
    pub range: BTreeSet<String>,
    /// Ids that a record added in R names in `supersedes`.
    pub superseding: BTreeSet<String>,
}

/// `None`: an allowed agent transition of D§6.6. `Some(problem)`: the first fault, in the rule order below.
pub fn agent_change(id: &str, old: &Version, new: &Version, ctx: &RangeCtx) -> Option<String>
```

What DR-12 must pass (this decides the contract for its only consumer, `docs/work/phase3/nodes/DR-12.md:5`): `id` is the file stem of a path directly under `docs/decisions/`. DR-12 skips paths in subdirectories (D§6.8: not a record) before the call. A tree entry that is a link, a submodule or a blob that `parse_record` refuses is `Version::Malformed`. A path that is missing in that commit is `Version::Absent`. `agent_change` returns `None` for a name that `name_kind` gives as `Other`, so DR-12 can pass every direct child path.

### Rule order

`agent_change` returns the first problem in this order. Each problem starts with `<id>: `. Values in `<>` are filled in; `<s>`, `<from>` and `<to>` are `Status::name()`.

1. `name_kind(&format!("{id}.md"))`: `Other` → `None` (D§6.8: not a record, ignored). `Malformed` → `<id>: malformed record name` (D§9.4 step 9).
2. `new`: `Absent` with `old` also `Absent` → `None` (no change). `Absent` → `<id>: record deleted` (D-C4). `Malformed` → `<id>: malformed record` (D§9.4 step 9).
3. `old` is `Absent` or `Malformed` → the creation rules (row "none → `open`"). A malformed old version counts as no record, because `zygo decision new` writes a file that is malformed until the agent fills it (D§17 #1, D§6.8):
   1. `status` is not `open` → `<id>: new record with status <s>`.
   2. For `reviewed`, `review_note`, `promoted_to`, `promotion`, in that order, the first that is `Some` → `<id>: new record writes operator key <key>`.
   3. For `fixed_by`, `promoted_by`, in that order, the first that is `Some` → `<id>: new record writes <key>`.
   4. Else `None`.
4. `old` is `Valid(o)`, `new` is `Valid(n)`:
   1. `o == n` → `None`. (Unknown keys and comments are not in `Record`; D§6.3 keeps and ignores them.)
   2. `o.status` is `fixed` or `superseded` → `<id>: <s> is final` (D§6.6).
   3. For `kind`, `class`, `unit`, `round`, `role`, in that order, the first that differs → `<id>: frozen key <key> changed` (D§6.3). `id` needs no check: `parse_record` makes it equal the stem in both versions.
   4. `n.status` is `ratified` or `overturned` and differs from `o.status` → `<id>: agent writes status <s>` (D-C5).
   5. For `reviewed`, `review_note`, `promoted_to`, `promotion`, in that order, the first that differs → `<id>: agent writes operator key <key>` (D-C5).
   6. The transition, by `(o.status, n.status)`:
      - `(open, open)`, `(open, fixed)`, `(open, superseded)`, `(overturned, fixed)`: go on.
      - `(ratified, ratified)`: go on only when `o.promoted_to.is_some()`, `o.promoted_by.is_none()`, `n.promoted_by.is_some()`, and `n` with `promoted_by` set to `None` equals `o`. Else `<id>: an agent changes a ratified record only to add promoted_by` (D§6.6).
      - Any other pair → `<id>: not an agent transition: <from> to <to>`.
   7. `fixed_by`: when `n.fixed_by` is `Some(c)`, and either `n.fixed_by != o.fixed_by` or `n.status` is `fixed` and `o.status` is not, and `c` is not in `ctx.range` → `<id>: fixed_by <c> is not in the node range`.
   8. `promoted_by`: when `n.promoted_by` is `Some(c)`, `n.promoted_by != o.promoted_by`, and `c` is not in `ctx.range` → `<id>: promoted_by <c> is not in the node range`.
   9. `n.status` is `superseded`, `o.status` is not, and `id` is not in `ctx.superseding` → `<id>: superseded but no record added in the node range names it`.
   10. Else `None`.

D§9.4 step 9 lists the checks for an agent change: frozen keys, operator keys and statuses, `fixed_by` and `promoted_by` in R, and the `supersedes` name. D§6.6 adds the final statuses and the `ratified` rule. The plan checks these and nothing more. An `open` → `fixed` change that also edits a section passes. The "Writes" column of D§6.6 names what each row must write. It does not forbid other agent keys.

```rust
//! DR-10: one agent record change against D§6.6 (D§6.3, D§9.4 step 9, D-C4, D-C5).
use std::collections::BTreeSet;
use zygo_work::decisions::record::parse_record;
use zygo_work::gate::transition::{agent_change, RangeCtx, Version};

const ID: &str = "DDR-01JDQ2Y7Z8K4M5N6P7Q8R9S0TV";
const C40: &str = "6e7fe2f0c1d2e3f4a5b6c7d8e9f0011223344556";
/// A commit in the node range.
const IN: &str = "1111111111111111111111111111111111111111";
/// A commit outside the node range.
const OUT: &str = "2222222222222222222222222222222222222222";
const BODY: &str = "\n## Choice\n\nC.\n\n## Alternatives rejected\n\nA.\n\n## Evidence\n\nE.\n\n## Cost to reverse\n\nR.\n";

/// A valid record `ID`: an open `decision` of class `none`, then each `(key, value)` of `set` replaces or adds that key.
/// Values are TOML strings, except `round`, which is an integer.
fn rec(set: &[(&str, &str)]) -> Version {
    let mut ks: Vec<(String, String)> = [("id", ID), ("kind", "decision"), ("status", "open"), ("class", "none"),
        ("title", "Store the pane name"), ("unit", "phase-3:N12"), ("round", "2"), ("role", "code"),
        ("model", "claude-sonnet-4-5"), ("commit", C40), ("date", "2026-11-24"), ("reverse_cost", "low")]
        .iter().map(|(k, v)| (k.to_string(), v.to_string())).collect();
    for (k, v) in set { ks.retain(|(n, _)| n != k); ks.push((k.to_string(), v.to_string())); }
    let mut s = String::from("+++\ndepends_on = []\n");
    for (k, v) in &ks { s += &if k == "round" { format!("{k} = {v}\n") } else { format!("{k} = \"{v}\"\n") }; }
    s += "+++\n";
    s += BODY;
    Version::Valid(parse_record(ID, s.as_bytes()).unwrap())
}
fn open() -> Version { rec(&[]) }
fn fixed() -> Version { rec(&[("status", "fixed"), ("fixed_by", IN)]) }
fn superseded() -> Version { rec(&[("status", "superseded")]) }
fn overturned() -> Version { rec(&[("status", "overturned"), ("reviewed", "2026-11-25"), ("review_note", "Wrong layer.")]) }
const PROMOTED: [(&str, &str); 5] = [("status", "ratified"), ("reviewed", "2026-11-25"), ("review_note", ""),
                                      ("promoted_to", "rule"), ("promotion", "Add to the rules.")];
/// `ctx.range` = {IN}; `ctx.superseding` = the given ids.
fn ctx(superseding: &[&str]) -> RangeCtx {
    RangeCtx { range: BTreeSet::from([IN.to_string()]), superseding: superseding.iter().map(|s| s.to_string()).collect() }
}
fn chg(old: &Version, new: &Version) -> Option<String> { agent_change(ID, old, new, &ctx(&[])) }
fn p(s: &str) -> Option<String> { Some(format!("{ID}: {s}")) }
```

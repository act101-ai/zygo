### Author's calls

1. **Four walks, one file.** The walk grows by 19 items, and #13, #17 and #18 need their own branch history (1200
   messages, 1000 commits, a clock a year later). So the file gets three new test functions beside
   `no_mail_content_after_the_scenarios` (walk 1). Each new function has its own `file://` remotes and machines,
   and each ends with the same scans through one shared helper `scan` (step 2). The Acceptance command does not change.
   It runs 5 tests: the scanner test and the four walks.
2. **No new process-environment change.** Each walk takes the existing `hermetic()` guard (MS-22 author's call 3)
   under `SERIAL`. That guard is the file's only change of process variables, and it is restored at drop. No new
   block sets or removes a process variable. A binary child gets its variables through `Harness::zygo` (env cleared)
   and `Command::env`. A hook call gets them through the `env` closure of `run_with_sync`. No block writes a stub
   script, so nothing new runs outside `SERIAL`.
3. **The clock.** `t0()` stays the one base time. A block that needs time to pass builds an `Env` with
   `Fixed(t0() + d)` through the new `env_now`. Within one walk the clock only moves forward. Each block with a later
   clock comes last in its walk (#18 in walk 3, the #6 cache in walk 4). No result reads the wall clock, and no block
   sleeps. `watch_with` gets `poll = Duration::ZERO` and `timeout = Duration::ZERO` with mail already in `new/`, so it
   returns at its first look before any `sleep`. Its `now` closure returns one `Instant` taken once.
4. **Test-made commits go into `made`.** These are the #7 marker-less root, the #13 message commit, the #17
   `fast-import` commits and the moved tip, and the #25 `.zygo.toml` commit on `main`. Only zygo's own commits are
   held to S§6.5. Every commit's bytes are still scanned for markers.
5. **The hooks run in process.** `run_with_sync` and `session_start_with_sync` take the sync `Env`, so a counting
   spawner and a fixed clock replace `ChildSpawner` and `SystemClock`. The binary `zygo hook workspace` would start a
   real `zygo mail sync` child (`sync_env`), which only a wall-clock wait could end.

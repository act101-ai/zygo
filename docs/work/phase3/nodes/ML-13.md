## Plan

### Drift

It returns `Summary { id, from, subject }` (`store.rs:17-22`), oldest first, and moves nothing. A missing `new/` gives `Ok(vec![])` (`store.rs:104-106`); a key that is not pane-key form gives `MailError::BadKey` (`store.rs:30-35`).
2. `parse_duration` (ML-1) is `zygo_config::parse_duration` (`crates/zygo-config/src/schema.rs:718`). It takes `<n>s|m|h|d` only; `"0s"` gives `Some(Duration::ZERO)`.
3. Produces: `cmd::mail::watch` does not exist yet (no `watch` in `crates/zygo/src/cmd/mail.rs`). The signature in the contract is kept as written. Consumers ML-18 (`docs/work/phase3/nodes/ML-18.md:5`) and MS-18 (`MS-18.md:5`) name `watch (ML-13)` / `cmd::mail::watch`; neither fixes other parameters.
4. `crates/zygo/src/lib.rs:1` is `pub mod cmd;` and `cmd/mod.rs:25` is `pub mod mail;`, so `mail_cli.rs` can call `zygo::cmd::mail::watch` and name `zygo::cmd::mail::{MailArgs, MailCmd}` (as it calls `zygo::cmd::mail::verb`, `mail_cli.rs:304-306`). `clap` is a normal dependency of `zygo` (`crates/zygo/Cargo.toml:24`), so the test can use `clap::{Args, FromArgMatches}`.

### Decisions (author's call)

- A1. **Which member.** `[<name>]` resolves through `names::resolve(&ws, n, None)`, as `read --name` (ML-12 D3): a name or a pane key. With no name, the member of `ZYGO_PANE`, as `read`. Neither: `UsageError("zygo mail watch: no member for this pane; pass a name")`, exit 2 (ML-12 Open 4 rule). An unknown name: `MailError::UnknownTarget` through `finish`, exit 1 (M§10 row 1 text).
- A2. **A name with more than one target** (`all`; M§6 reserves `all`, it is not a member name). `watch` takes one key (Produces). Plan: `UsageError(format!("zygo mail watch: {n} is not one member"))`, exit 2 (`finish` escapes the whole text through `error_text`, `crates/zygo-config/src/display.rs:58-62`, so the name is not escaped twice). This is the one input rule the spec does not state; the alternative (watch only the first target) silently drops members. The lead may strike it and take `targets[0]`.
- A3. **Bad `--timeout`.** The rule and text of `zygo down --timeout` (`crates/zygo/src/cmd/down.rs:44-51`): `zygo: bad --timeout value <esc v>: use <n>s, <n>m, <n>h or <n>d` on stderr, exit 2. The field is `timeout: String` with `default_value = "25m"`, parsed in `run`, as `down`.
- A4. **Order in one round.** List first, then the clock. So mail already in `new/` returns 0 even with `--timeout 0s`, and `--timeout 0s` with no mail returns 1 at once (no wall-clock wait in the CLI tests).
- A5. **Read error.** An `Err` from `store::list` ends the watch: its `Display` (`zygo: mail: <io error>`) and `\n` on stderr through `super::print_err`, exit 1, no stdout line. This matches `read` (exit 1 on a store error, `mail.rs:96-99`).
- A6. **Poll of the CLI.** `const WATCH_POLL: Duration = Duration::from_millis(500)`, so a send is seen within 1 s (M§13 #7). Tests pass `Duration::ZERO`.
- A7. **Line.** `<esc id> <esc from> <esc subject>`, the line of `ls <name>` (`mail.rs:217`, ML-12 D4). A write error on `out` is ignored, as `print_out` (`cmd/mod.rs:52-59`).
- A8. `zygo_core::verbs::VERB_SPECS` `mail` args stay `send|read|ls …` (`crates/zygo-core/src/verbs.rs:43`): `…` covers `watch`, and `cli_surface.rs:136` pins the text. No slash form for `watch` (M§8: `/zygo:mail` lists only).

```rust
/// A clock that returns `times[i]` at its i-th call (the last value after the end) and counts its calls.
struct Clock { times: Vec<Instant>, calls: Cell<usize> }
impl Clock { fn now(&self) -> Instant { /* times[min(calls, len-1)], then calls += 1 */ } }
```

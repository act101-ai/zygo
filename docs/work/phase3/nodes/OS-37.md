### Decisions (author)

1. **Budgets** (each constant cites O§8.5; no other threshold):
   `RUNS = 200`; `STEPS_SMALL_BYTES = 64 * 1024`, `STEPS_SMALL_P95 = 5 ms`; `STEPS_LARGE_BYTES = 4 * 1024 * 1024`, `STEPS_LARGE_P95 = 100 ms`; `PROCESS_EXTRA_P95 = 50 ms` (shape on over shape off); `LOCKED_EXTRA_P95 = 50 ms` (over `HOOK_DB_BOUND`).
2. **Shaping-step input** (O§8.5 does not say which text is 64 KiB): for each case, `stdout` then `stderr` (lossy UTF-8) repeated, then cut to `n` bytes at the last char boundary ≤ `n`. `ShapeInput { parsed: Some(command::parse(meta.command)), kind: sniff(text), threshold: SessionView::default().trim_threshold_bytes }`, as `trim.rs:197-200` builds it. Only `shape::run` is timed (O§7.3 steps 1-4).
3. **Hook process** (O§8.5 does not say how the process starts; see Premises): the test binary itself, `current_exe()` with `--ignored --exact child_trim_process --nocapture --test-threads=1`, `CHILD` = a temp root set on the child `Command` only. The child does what `zygo hook trim` does (`crates/zygo/src/cmd/hook.rs:117-138`): reads all stdin, runs `guarded(|b| trim::trim_in_with(&HookInput::parse(Agent::ClaudeCode, b)?, &SessionDir::new(root/"s"), &root/"usage.db", &opts))` with `opts = TrimOpts { db_bound: HOOK_DB_BOUND, stderr_cleared: PO2_STDERR_CLEARED, shape_panic: false }` (explicit, as `shaping.rs:133-134`: `Default` reads `ZYGO_TEST_SHAPE_PANIC`). It uses `trim_in_with`, not `trim::run`, so it needs no `ZYGO_SESSION_DIR` or `HOME`. The time runs from before `spawn` to after `wait_with_output`.
4. **Largest fixture**: the case with the most `stdout.len() + stderr.len()` bytes; the test asserts it is Claude Code `PostToolUse` (today `diff/git-diff-repo`). Shape off = the session view's `shape = false`, which is how `[results] shape` reaches the hook.
5. **Write lock**: the parent opens `root/usage.db` with `rusqlite::Connection::open` and runs `BEGIN IMMEDIATE` before the 200 runs, `ROLLBACK` after; the child keeps the real bound `HOOK_DB_BOUND`.
6. **p50 / p95**: nearest rank on the sorted 200 times: `sorted[(q * n).div_ceil(100) - 1]`, i.e. index 99 and 189.
7. **Print**: `writeln!(std::io::stderr(), ...)` (not captured by libtest), one line per measured case.
8. **Serial**: each budget test holds `SERIAL` for its whole run, so the 4 tests do not share the CPU when the O§8.5 command runs them in parallel.
9. All cases are measured and printed before the test fails; the failure names every case over its budget.

### Spec gaps (reported, resolved by repo practice, not new rules)

- O§8.5 "a whole `zygo hook trim` process": a `zygo-hooks` test cannot start the `zygo` binary, and O§8.5 fixes the file in `zygo-hooks`. The child is the test binary (Decision 3). The child skips the `zygo` binary start-up (`main.rs` `install_panic_hook`, `cmd::run`, `cmd/hook.rs:92-138`, `Paths::from_env`) and adds the libtest harness start-up, so its time can be over or under that of `zygo hook trim`; OS-38 measures the real binary's budget.
- O§8.5 does not say which text the 64 KiB and 4 MiB inputs hold (Decision 2), how p95 is computed (Decision 6), whether the tests run one at a time (Decision 8), or how the numbers are shown without `--nocapture` (Decision 7).
- The child needs one variable, `CHILD`, set on the child process only (as `reinject.rs:422`).

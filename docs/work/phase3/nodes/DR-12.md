### Author's calls (spec gaps)

1. Fixed texts not in D§9.4 (step 7 `<why>` and empty proofs). DR-13 maps a missing `commit`/`reason`/`record` to `""` (the `Proof` fields are `String`). Texts: `<label>: no reason`; `<label>: no record`; `<label>: recorded with class none needs round 3 or later`; `<label>: <id> is not at head`; `<label>: <id> is not a valid record at head`; `<label>: <id> was not added in the node range`; `<label>: <id> has unit <u>, not <unit>`; `<label>: <id> has class <c>, not <class>`; `<label>: <id> of kind <k> cannot record this finding`; `<label>: <id> depends on <d>, which is not a record at head`; `<label>: <id> is <status>, not open` (class `none`); `<label>: <id> is <status>, not ratified` (stop class, status `fixed`/`superseded`); no merge base of `HEAD` and `head`: `head has no common ancestor with HEAD: give base`.
2. One `<why>` per `recorded` entry: the first failing check in D§9.4 step 7 order (later checks need the valid record).
3. Skips. Step 1 fails: steps 2, 3 still run (no read needed), 4 to 9 skipped. Step 4 fails (any of its problems, or `node range too large`): 5 to 9 skipped (R is not defined). `dispositions` absent: steps 3, 5, 6, 7 have no entries; 4, 8, 9 run.
4. Git failure: each distinct `GitFail` text is pushed once (the `--batch` process stays failed after its first error, `git.rs:200-208`); an item whose read failed is skipped; steps that need no read still run; a `log` failure skips 8 and 9.
5. Step 8 skips a record that a `recorded` entry names: step 7 already gives its stop problem, and D§8.5 step 1 gives one problem per stop item.
6. Agent commit (D§5, review focus 15): one parent and a message line that starts with `Zygo-Session:`, in any paragraph. Text with `Zygo-Session:` inside a line (body text) does not make an agent commit. Reason: D§5 says "a line"; counting every line-start reads more commits than a trailer-block rule, so the gate errs toward refusing.
7. Labels, ids and commits from the request are printed through `esc` (they reach the tool reply).
8. The git fixture helpers of `tests/decision_git.rs` are private to that test crate and that file is outside this node's Files line, so `decision_verdict.rs` copies the four it needs (`git_in`, `git`, `out`, the isolated far runner) instead of sharing a module.
9. D-C3: `check_keep` stores nothing; R, the touched records and `superseding` are computed per call.

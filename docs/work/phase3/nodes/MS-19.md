### Drift and decisions (cited)

- P1 (S§7.2 rewritten; change log 2026-11-26). S§5 and S§7.2 make `<name>@<own host>` local for every own host (S§7.5: the current host plus each host whose ack at the tip holds this identity). A send cannot know the older hosts: S§7.3 says the address check reads the member cache and never runs git, and `State.pushed` (`state.rs:235`) keeps keys of deleted acks (`sync.rs:370` only extends it; `ops.rs:116` only clears it). At send the local host is the host in force with sync on, none with sync off; `<name>@<older host>` is then remote and the cache rule refuses it, since `sync.rs:330-335` never puts a registry of this identity in the cache. The rewrite also fixes the two lines for a `to` with `@` that is not an address (S§7.2 gave none), and MS-18 shares them through `AddrError::line`.
- P2 (S§10.4 rewritten; change log 2026-11-26). The sentence "`mail_list` returns the remote addresses from the member cache" gave no key and no sync-off rule. `remote` follows the item 8 clause rule of `crates/zygo-hooks/src/mail.rs:103-111` (`remote_addresses`: config, `sync_for`, cache) and its each-address-once rule (`other_machines`, `:26-32`), with no 64 cap: the clause sends the reader to `mail_list` for all.
- P3 (Consumes). The node row named `send_remote` (MS-9); this node calls `send_remote_with` (MS-9, `outbox.rs:81`), see Consumes "Not used". It also uses `Spawner` and `TmuxWake` (MS-2) and `AddrError` (MS-4) to build the `Env` and the lines.
- D1. Only a `to` that holds `@` goes through `resolve_to`. A bare value keeps M§8/M§10 (`names::resolve`: name, pane key, `all`, `UnknownTarget` with the known names), so the ML-11 tests hold and a local send loads no config.
- D2. The config is loaded at each addressed send and each `mail_list` call with `LoadContext { paths, repo: None, team: None }`, as `tools` (`mail.rs:38`) and the hook (`zygo-hooks/src/mail.rs:104`). `repo: None` gives the same `[redaction]` and `[mail]` as the sync pass's `repo: Some(main_root)` (`sync.rs:242`): a repository file may set only `[guards]`, `[navigation]`, `[limits]`, `[work]` (`crates/zygo-config/src/layers.rs:509-519`: other tables are dropped with the line at `:517`), and `[mail]` is user only. A config that does not load: an addressed send fails with `zygo: mail sync cannot run: the config does not load` (the text of `GATE_CONFIG_LINE`, `sync.rs:90`, which is private); `mail_list` gives `remote: []`.
- D3. The sender is `ws.members[pane].valid_name()` from `workspace.json`, read at each call (AU84), not the view's `Member.name`. `send_remote_with` refuses `None` with `NoSenderName`.
- D4. `trigger(…, None, …)` runs after `send_remote_with` returns `Ok`, so the child starts after the outbox link (S§8.1 row 1); a refusal starts nothing. A failed start leaves the send `Ok` (the message is in the outbox; the next hook event or sync takes it) and writes one `errors.log` line `mail_send: cannot start the mail sync child: <io error>` through `Store::log_error` (S-C1 pattern, S-C2: no address or content).
- D5. No wake for a remote send: the M§7.3 wake is for local targets; the remote machine wakes after its import (S§10.1).
- D6. The production spawner is `ChildSpawner { zygo: zygo_program() }`, `zygo_program()` = `current_exe()` then `canonicalize`, else `current_exe()`, else an empty path (a start that then fails gives the D4 line). The MCP server runs as `zygo mcp` (`crates/zygo/src/cmd/mcp.rs:9-13`), so the current exe is `zygo`; this is the `zygo_binary` rule of `crates/zygo/src/cmd/member.rs:706`, which `zygo-mcp` cannot call (no dependency on the binary crate, MS-17 interface note).
- D7. The description sentence is unconditional: the tool list is built once per server start, and S§10.4 gives the sentence with no condition.

    let ctx = McpCtx { agent: Agent::ClaudeCode, features: Features { mail: true, ..Default::default() }, session_dir: Some(x.sd.clone()) };
    let woke = Arc::clone(&x.woke);
    mail::tools_with_sync(&ctx, x.p.clone(), MailConfig::default(), Arc::new(|| at(T0)),
        Arc::new(move |_: &Paths, _: &Workspace, k: &[String], _: &MailConfig| woke.lock().unwrap().push(k.to_vec())),
        Box::new(Spawns { sp: x.sp.clone(), seen: Arc::clone(&x.seen), fail }), policy)
}
fn tools(x: &X) -> Vec<Box<dyn Tool>> { tools_p(x, false, far()) }
fn tool<'a>(t: &'a [Box<dyn Tool>], name: &str) -> &'a dyn Tool {
    t.iter().find(|t| t.def().name == name).map(|b| b.as_ref()).unwrap_or_else(|| panic!("no tool {name}"))
}
fn send(t: &[Box<dyn Tool>], to: &str, body: &str) -> Result<Value, ToolError> {
    tool(t, "mail_send").call(json!({"to": to, "subject": SUBJECT, "body": body}))
}
fn spawns(x: &X) -> Vec<usize> { x.seen.lock().unwrap().clone() }
fn woke(x: &X) -> Vec<Vec<String>> { x.woke.lock().unwrap().clone() }
fn new_ids(p: &Paths, key: &str) -> Vec<String> {
    let Ok(rd) = fs::read_dir(mail_dir(p, ID).join(key).join("new")) else { return Vec::new() };
    let mut v: Vec<String> = rd.map(|e| e.unwrap().path().file_stem().unwrap().to_string_lossy().into_owned()).collect();
    v.sort();
    v
}

# FX-44 — `store_item` works through one folder handle

**Spec:** `docs/specs/2026-11-18-zygo-design.md` §8.6 item 8 (the stored OpenCode item 8, FX-9); `docs/specs/2026-11-24-session-text-design.md` T-C1 (C6: a hook branch that fails prints nothing that changes a decision and exits 0); graph constraints C6, the state modes and "no wall-clock test in CI" (`docs/work/phase3/graph.md` lines 1-96). Found in the FX-37 work (PR #268, review R2, `docs/work/phase3/nodes/FX-37.md` 4.2): `crates/zygo-hooks/src/session_start.rs` `store_item` (:189) checks `session-item/` with an lstat (`folder_state`, :198), then sets its mode by path (`set_permissions`, :202), opens the temp file by path (:216) and hard-links by path (`hard_link`, :229). A folder replaced by a link between the check and those calls sends the chmod, the temp file and the stored item into the link target, outside the session folder.
**Files:** `crates/zygo-hooks/src/session_start.rs`, `crates/zygo-hooks/src/pre_compact.rs` (the `at` module), `crates/zygo-hooks/tests/session_text.rs`
**Consumes:** FX-37 (`pre_compact::at`: `open_folder`, `open`, `is_regular`, `unlink`; merged from `origin/phase3/FX-37` into this branch)
**Interfaces (as they exist now, at ff24f2df + FX-37):** `zygo_hooks::session_start::fixed_item(dir: &SessionDir, agent_session: &str, build: &mut dyn FnMut() -> Option<String>) -> Option<String>`; `zygo_hooks::session_start::item_path(dir: &SessionDir, agent_session: &str) -> Option<PathBuf>`; `pre_compact::at::open_folder(path: &Path) -> io::Result<File>`; `pre_compact::at::open(folder: &File, name: &str, flags: c_int, mode: mode_t) -> io::Result<File>`; `pre_compact::at::unlink(folder: &File, name: &str) -> io::Result<()>`
**Produces:** on unix, `store_item` opens `session-item/` once with `O_DIRECTORY | O_NOFOLLOW` and does every later step through that handle: `fchmod` 0700 of the folder, `openat` of the temp file (`O_CREAT | O_EXCL | O_NOFOLLOW`, 0600), `linkat` of the temp name to the item name in the same folder, `unlinkat` of the temp name. `pre_compact::at::link(folder, old, new)` (`linkat(fd, old, fd, new, 0)`). The test seam `session_start::testing::set_after_open(folder, hook)` (feature `test-hooks`, unix): `hook` runs in `store_item` after the folder is opened and checked, before the first step through it. The FX-9 behavior is kept (temp file plus hard link, first writer wins, the stored text fixed per session, `symlink_metadata` refusal in `fixed_item`, `O_NOFOLLOW | O_NONBLOCK` reads, `MAX_ITEM`, an empty file is unusable, no log line, D6). The `cfg(not(unix))` `store_item` keeps its steps.
**Acceptance:** `cargo test -p zygo-hooks --test session_text` → all pass, including, failing first, `store_item_folder_swapped_after_open_writes_inside` (the seam replaces `session-item/` with a link to a folder of mode 0755 after the open: the call returns the built text; the link target keeps mode 0755 and its one entry; the real folder, renamed, holds the item with the text, mode 0600, at mode 0700, and no temp file); and the non-race cases `opencode_store_folder_that_is_a_link_is_not_used`, `fixed_item_stores_no_none_and_reads_no_link`, `opencode_fifo_at_the_stored_name_does_not_block`, `store_item_hard_link_at_the_item_name_is_not_written` (an empty file of mode 0644 outside the folder, hard-linked at the item name: the built text is returned, the file stays empty at mode 0644); `cargo test -p zygo-hooks` → all pass. No test has a deadline that runs in CI.

## Plan

Premises checked against the live code (ff24f2df merged with `origin/phase3/FX-37` at 1d9014f6: merge 72d21d53 on this branch):
- `session_start.rs:189-238` `store_item`: `DirBuilder::create(folder)` (0700), `folder_state(folder)` (lstat), `set_permissions(folder, 0700)` by path, `OpenOptions::open(folder.join(tmp))` with `create_new`, `O_NOFOLLOW`, 0600, by path; `hard_link(tmp, path)`; `remove_file(tmp)`.
- `pre_compact.rs` `at` (`cfg(unix)`, `pub(crate)`): `open_folder`, `open` (`openat`, adds `O_CLOEXEC`), `is_regular`, `unlink`. No `linkat`. `File::set_permissions` is `fchmod` on the handle (std), as `create_flag` uses it.
- `zygo-hooks` has the feature `test-hooks`, on for its own tests (dev-dependency on itself), as the statusline seams.

Decisions (author):
- D1. A deterministic swap test is possible: the seam `testing::set_after_open` (feature `test-hooks`, unix), keyed by the folder path so parallel tests do not meet, runs between the open of the folder and the first step through it. No wall-clock bound is used.
- D2. Failing first: the seam is first put in the old code at the same point (after `folder_state`, before `set_permissions`), with no other change; the swap test then fails (the link target gets mode 0700 and the item). Then the fix.
- D3. `at::link(folder, old, new)` = `linkat(fd, old, fd, new, 0)` (flag 0: a link at `old` is not followed; `old` is this call's own temp file). `EEXIST` is "the name is taken" (`Ok(false)`), as `hard_link` gave.
- D4. `fixed_item`'s reads (`folder_state`, `read_item` by path) are not changed: they only read, and the brief limits the node to `store_item`. Reported.
- D5. The `cfg(not(unix))` `store_item` is the old body without its `cfg(unix)` blocks (dead on that target); its steps are the same.

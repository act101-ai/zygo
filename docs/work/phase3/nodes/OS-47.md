### The pre-checks and why each is implied by its regex

Each pre-check is a necessary condition of its regex, so it only skips work whose regex would reject; where the regex result is still needed, the regex still runs.

| Change | Site | Pre-check | Why it is implied |
|---|---|---|---|
| A | `libtest_kept` `:206` | `bare.starts_with("test ")` in place of `TEST_HIDDEN.captures` | The branch runs only when `hidden_by(Libtest)` is true, so `TEST_HIDDEN` or `PROGRESS` matches. `TEST_HIDDEN` starts with `test `; `PROGRESS` starts with `[ \t]+`. They are disjoint, so `TEST_HIDDEN` matches exactly when the line starts with `test `. |
| A | `libtest_kept` `:213` | `libtest_ok`: the line is `test <n> ... ok` with `<n>` non-empty and with no `char::is_whitespace` | Given a `TEST_HIDDEN` match, `\S+` ends at the first white space, which must be the space of ` ... `; group 1 is the rest. It is `ok` exactly when the rest is `ok`, i.e. the line ends in ` ... ok` and the part between `test ` and ` ... ok` is one non-empty `\S+` run. `test a ... ignored, x ... ok` has white space in that part, so it is ignored, as now. |
| B | `view` `:152-157` | libtest: `text.contains("failures:") \|\| text.contains("---- ") \|\| TEST_FAILED_ANY.is_match(text)` | A flag needs `block` (a line that starts with `---- `), `list` (a line `failures:`) or a `TEST_FAILED` line. `TEST_FAILED_ANY` is `TEST_FAILED` with `(?m)`: `\S` and the literals cannot match `\n`, and `(?m)` `^`/`$` match at `\n` only, so it matches a text exactly when it matches one of its lines. |
| B | same | pytest: `PY_FAILURE_ANY` = `(?m)` form of `PY_FAILURE` | `on` turns on only at a `PY_FAILURE` line; same `(?m)` argument (`=+` and the literals cannot match `\n`). |
| B | same | go test: `GO_OWNER_ANY` = `(?m)^=== (RUN\|PAUSE\|CONT\|NAME)[ \t]+\S+$\|^[ \t]*--- (PASS\|FAIL\|SKIP): \S+ \(.*\)$` | `Kept` needs an owner; an owner comes only from a `GO_MARK` or `GO_RESULT` line (premise `:348-365`). The alternation is those two regexes with `(?m)`; `.` does not match `\n`. The `!cr` filter only narrows the set. |
| B | same | no remaining runner → `keep` is empty | The three views read only `keep.get(i) == Some(&true)`. |
| D | `go_lines` `:336` | first byte `o`, `F` or `?` before `GO_SUMMARY` | On one line (no `\n`), `(?m)^` matches only at offset 0, then `ok`, `FAIL` or `?`. |
| D | `go_lines` `:344` | first byte `o`, `F`, `P`, `p` or `e` before `GO_PACKAGE` | The alternatives start with `ok`, `FAIL`, `PASS`, `panic:`, `exit status `. |
| D | `go_lines` `:348` | `bare.starts_with("=== ")` before `GO_MARK.is_match`; name = after the kind word, past the blanks | `GO_MARK` starts with `^=== `. Given a match, the kind word has no blank and `[ \t]+(\S+)$` splits uniquely, so group 2 = the text after the first blank following `=== `, less its leading blanks. |
| D | `go_lines` `:351` | `rest.starts_with("--- ")` (`rest` = line less leading `' '`/`'\t'`) before `GO_RESULT.is_match`; result = `rest[4..8]`, name = `rest[10..]` up to the first `' '` | `[ \t]*` then `-`: the blank run must be all leading blanks, so `rest` starts with `--- `. `PASS`, `FAIL`, `SKIP` are 4 bytes at `rest[4..8]`, `: ` follows, the name starts at `rest[10..]`; `\S+` stops at the first white space, which the regex requires to be the `' '` before `(`. |

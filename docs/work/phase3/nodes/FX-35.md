# FX-35 — Mail wake refused in the 10 s quiet window; mail-seen and lock bounds

**Spec:** `docs/specs/2026-11-22-workspace-mail-design.md` M-G3, M§5, M§7.2, M§7.3, M§12 (found in the Phase 3 final verification stage, 2026-11-28, head b628e1ad). **M-F1 (high).** `crates/zygo-workspace/src/mail/wake.rs:104` returns `Busy` when `!probe.idle(&dir)`; `RealProbe::idle` (`wake.rs:66-77`) applies `drain::idle` (`:75`), whose rule 3 (`crates/zygo-workspace/src/drain.rs:94-96`, `REQUEST_QUIET` = 10 s at `drain.rs:14`) fails for 10 s after the last model request ended. (a) The FX-33 OpenCode turn-end wake (`crates/zygo-hooks/src/workspace.rs:308-327` `wake_after_turn`, `:337-361` `TmuxTurnWake` and `ProbeAt`) runs milliseconds after the last request, so it almost always gets `Busy`; nothing retries, and mail sent while the member was busy is never announced. (b) Any agent: mail sent in the 10 s after a member's turn ended gives the sender's wake (`after_send`, `wake.rs:201`) `Busy`, with no retry, so the member is never woken. This breaks M-G3 ("An idle member is woken"), M§7.3 (the FX-33 text "a wake that is skipped … a later turn end tries again": no later turn end comes) and M§12. The tests `opencode_turn_end_wake_that_is_not_sent_keeps_the_mail_unannounced`, `opencode_turn_end_wakes_once_for_mail_that_came_during_the_turn` and `opencode_turn_end_does_not_wake_without_new_mail` (`crates/zygo-hooks/tests/workspace.rs` near :2178, :2232, :2263) use a fake `TurnWake`. `ProbeAt(now)` applies the injected clock only to the gap: its `idle` calls `RealProbe.idle`, whose `drain::idle` call takes `RealProbe::now`, `SystemTime::now()` (`wake.rs:75`, `:79`). Constraint: no daemon, tmux is the only long-lived process (W-C2, M-G6). **M-F2.** `workspace.rs:489-496`: the `message` event calls `set_mail_seen` before it returns the line; when the plugin's 10 s timer kills the hook, or the hook exits non-zero after the write (`crates/zygo-launch/assets/opencode-plugin.js:8-34` `run`, which gives "" then; `:214-217` the `chat.message` call), the line is dropped but the ids count as announced (M§7.2, M§7.3). **M-F3.** `wake.rs:109` `lock_file(&md.join(LOCK), Duration::MAX)` and the proxy status call of `RealProbe::idle` (`wake.rs:72-74`, `STATUS_BOUND` 2 s) are reached from the OpenCode `stop` hook (`workspace.rs:481-483`); the module contract (`workspace.rs:12-13`) says "No wait here is longer than the 1 s lock bounds of AU56 and W§7.3", and M§5 says "Neither waits more than 2 s".

### Decisions (author)

1. **Wake path: a deferred retry that tmux runs (chosen).** A wake whose only failed AU26 rule is the rule 3 quiet window (`busy` false, no subagent, no tool running, no request in flight, `last_request_end` less than `REQUEST_QUIET` before the wake time or at most that much after it) returns `Outcome::Quiet(left)`, `left` = `last_request_end + REQUEST_QUIET − now`, before it takes the lock. The waker (the sender's process, the OpenCode `stop` hook, or a retry) then asks the workspace's own tmux server (`-S` socket, W-C3) for one `run-shell -b` whose shell command sleeps `ceil(left) + 1 s` and then runs `zygo hook workspace --agent claude-code --event mail-wake` for the member's session folder with `{"try":<n>}` on stdin. That hook wakes by M§7.3 steps 1-3 when there is mail to announce (Claude Code: `new/` not empty; OpenCode: an id not announced, recorded as announced only on `Woken`). A retry that again meets only the quiet window defers once more, up to try 3. Reason: it covers both M-F1 cases (the OpenCode turn end, and mail sent in the 10 s after the turn end of any member) with AU26 unchanged; nothing outlives tmux (the sleeping `sh` is a child of the tmux server and ends with its sleep); a deferral happens only when a wake met the quiet window, so an idle team starts nothing; duplicates stop at the existing wake lock, `wake_gap` and announced ids. To reverse it: remove `Quiet`, the `Defer` seam and the `mail-wake` event.
   - Rejected: **a wake that skips rule 3 right after the member's own turn-end hook.** It fixes only case (a): mail that another member sends in the 10 s after a Claude Code `Stop` still meets rule 3 at the sender, and nothing retries. It also weakens AU26 for the wake: rule 3 is the only rule that sees a model request with no hook (a turn with no `UserPromptSubmit`, a background request after `Stop`), and the wake types into the pane.
   - Rejected: **every turn end schedules one check 11 s later.** It needs no sender change, but it starts a process after every turn of every member, mail or not, and it needs an announced-id record for Claude Code too (else a member that leaves mail unread gets a wake each `wake_gap`). The chosen path defers only on demand.
   - Rejected: **the sender waits out the window.** `mail_send` and `zygo mail send` would block up to 11 s per send, and a sender killed in the wait loses the wake.
   - Rejected: **a detached sleeper process of the sender (`setsid`).** A process outside tmux that outlives its parent is the daemon that W-C2 and M-G6 forbid, and `zygo down` does not see it.
   - Rejected: **a shorter `REQUEST_QUIET` for the wake.** Any window keeps the race, and AU26 is shared with the drain.
2. **One clock (M-F1).** `wake::Probe` gains the provided method `fn ready(&self, session_dir: &Path, now: SystemTime) -> Ready` (`pub enum Ready { Idle, Busy, Quiet(Duration) }`), default `if self.idle(session_dir) { Idle } else { Busy }`, so the fakes of other crates keep their meaning. New `pub fn ready_at(session_dir: &Path, now: SystemTime, status_bound: Duration) -> Ready`: hooks off → `Busy`; `activity::read`; one status read bounded by `status_bound`; `drain::idle(…, now)` `Idle` or `IdleRuleSkipped` → `Idle`; else `drain::quiet_left(…, now)` `Some(d)` → `Quiet(d)`; else `Busy`. `RealProbe::ready` = `ready_at(dir, now, STATUS_BOUND)`; `RealProbe::idle` = `ready(dir, self.now()) == Idle`; `Clocked` and the hook probe forward `ready` with the `now` they are given. `wake` calls `probe.ready(&dir, probe.now())`, so the idle rule and the gap use one clock.
3. **`drain::quiet_left(activity, status, now) -> Option<Duration>`** (new, pure): `Some(end + REQUEST_QUIET − now)` exactly when `drain::idle` gives `Busy` and the only failed rule is the rule 3 time test (rules 1 and 2 hold, `tools_running == 0`, `requests_in_flight == Some(0)`, `last_request_end` RFC 3339 and inside the window on either side of `now`). `drain::idle` and AU26 do not change.
4. **Deferral seam.** In `wake.rs`: `pub trait Defer { fn defer(&self, ws: &Workspace, session_dir: &Path, after: Duration, try_no: u8) -> anyhow::Result<()>; }`; `pub struct TmuxDefer { pub tmux: PathBuf, pub zygo: PathBuf }`; `pub fn deferred_command(zygo: &Path, session_dir: &Path, after: Duration, try_no: u8) -> Result<String, UnsafePath>` = `sleep <s>; printf '%s' '{"try":<n>}' | ZYGO_SESSION_DIR='<dir>' '<zygo>' hook workspace --agent claude-code --event mail-wake >/dev/null 2>&1`, with both paths through `check_path`, the whole text through `format_escape`, and `<s>` in whole seconds; `pub const MAX_TRIES: u8 = 3`; `pub fn settle(store: &Store, ws: &Workspace, key: &str, out: Outcome, defer: &dyn Defer, try_no: u8) -> Outcome`: `Quiet(left)` with `try_no < MAX_TRIES` → `defer(…, ceil(left) + 1 s, try_no + 1)` → `Deferred(after)`, or `Failed` with one `errors.log` line; `Quiet` at `MAX_TRIES` stays `Quiet`; every other outcome is returned as it is. `Outcome` gains `Quiet(Duration)` and `Deferred(Duration)`. In `crates/zygo-workspace/src/mux/tmux.rs`: the inherent `Tmux::run_shell_background(&self, command: &str) -> Result<(), MuxError>` = `run-shell -b <command>` with the call bound (inherent, so no `Multiplexer` stub changes). `TmuxDefer::defer` = `Tmux::new(tmux, ws.tmux_socket).run_shell_background(&deferred_command(…)?)`.
5. **Sender path.** `after_send_with` keeps its arguments and now returns `Vec<(String, Outcome)>` (callers that end it with `;` compile as they are); it does not defer. New `pub fn after_send_at(paths, ws, tmux: &Path, keys, cfg, now)` = `after_send_with` with `RealProbe`, then `settle(…, try 1)` for each outcome with `TmuxDefer { tmux, zygo }`, `zygo` = `current_exe` canonicalized, else `current_exe` (every sender is the zygo binary: `zygo mail send`, `zygo mcp`, the sync child). `after_send` = `after_send_at(…, SystemTime::now())`. `crates/zygo-mail-sync/src/env.rs:58` (`TmuxWake`) calls `after_send_at(paths, ws, &self.tmux, keys, cfg, now)`.
6. **Hook path (`crates/zygo-hooks/src/workspace.rs`).** `TurnWake::wake` gains `try_no: u8`. New `pub fn turn_wake_with(paths, ws, key, cfg, now, mux: &dyn Multiplexer, defer: &dyn Defer, try_no: u8) -> Outcome` = `wake` with the hook probe (decision 2, status bound `HOOK_BOUND`) and lock bound `HOOK_BOUND`, then `settle`. `TmuxTurnWake { tmux, zygo }` = `turn_wake_with` with `Tmux` and `TmuxDefer`; `run_with_sync` builds it with its `zygo`. `EVENTS` gains `mail-wake` and `message-seen` (11 values). `mail-wake` (main loop, a member): nothing in phase `draining` or `stopping`; `try` from the payload must be 2 or 3, else one session-log line and nothing; OpenCode: the `wake_after_turn` body with that `try_no`; Claude Code: a wake only when `unread_mail > 0`. It starts no sync child and changes nothing in `activity.json`. The OpenCode `stop` arm calls `wake_after_turn` with try 1.
7. **Bounds (M-F3).** `wake` gains `lock_bound: Duration` (`lock_file(&md.join(LOCK), lock_bound)`; `Ok(None)` stays `Failed("wake.lock not taken")`). The sender passes `Duration::MAX` (A1, as now); the hook passes `wake::HOOK_BOUND` = 1 s (= `activity::LOCK_BOUND`), which is also the hook's status bound. The module contract (`workspace.rs:12-13`) states the waits: each lock and the proxy status read at most 1 s, each tmux call at most `mux::BOUND` (2 s).
8. **Message line (M-F2): announced only after it reached the plugin.** `message` writes the ids it announces to `mail-offered.json` in the session folder (atomic, `0600`), prints the line and writes no `mail-seen.json`. New event `message-seen` (main loop, recorded main session only): `mail-seen.json` := (announced ∪ offered) ∩ ids in `new/` now, then `mail-offered.json` is removed; a missing offered file changes nothing. The plugin, after it adds the part, queues `ws("message-seen", { sessionID })` (not awaited). A lost line or a lost `message-seen` call leaves the ids unannounced: the next message gets the line again, and the turn end gives at most one more wake; never zero lines.
9. **Spec.** M§7.2 and M§7.3 are rewritten as final text in the plan commit, with one change-log row (2026-11-28, author's call, FX-35). M§12 does not change (not in this node's Files); the rejected options are in decision 1.

### Decisions (author)

1. **Regexes** (O§7.6 row `libtest`, verbatim; O§15 item 2 is not used, so no decision record):
   - `SUMMARY` = `(?m)^test result: (ok|FAILED)\. \d+ passed; \d+ failed;` — the "Summary that confirms" form; `(?m)` lets the same regex test the whole text and one line.
   - `TEST_HIDDEN` = `^test \S+ \.\.\. (ok|ignored|ignored, .*)$` — the union of the two hidden test forms `^test \S+ \.\.\. (ok|ignored)$` and `^test \S+ \.\.\. ignored, .*$`; group 1 = `ok` counts as passed, else ignored.
   - `PROGRESS` = `^\s+(Compiling|Checking|Fresh|Downloaded|Downloading|Locking|Updating|Blocking) \S.*$` — the cargo progress form.
   Each is a `static … : LazyLock<Regex>` in `runner.rs`, as `kind_view.rs:14-16`.
2. **Lines.** `libtest` walks `text.split_inclusive('\n')`; a line's bare form is the line less one trailing `\n`. Kept lines are written verbatim (a last line with no `\n` stays so). A `\r` stays in the bare form, so `test a ... ok\r` matches no hidden form and is kept (O-C9). Count lines end in `\n`.
3. **`hidden_by(r, line)`**: `line` is one line without its `\n`. `Libtest` → `TEST_HIDDEN.is_match(line) || PROGRESS.is_match(line)`. `Pytest`, `Gotest` → `false` (no form hidden; OS-31 and OS-32 add their forms).
4. **Test binary.** A binary's hidden test lines are those after the previous `SUMMARY` line (or the text start) up to its own `SUMMARY` line (or the text end, for a binary that crashed). The count line `[zygo: <p> passed and <i> ignored test lines hidden]` goes at the place of the group's first hidden test line, with `<p>` and `<i>` the counts of that group. One `[zygo: <n> build progress lines hidden]` line goes at the place of the first hidden progress line, with `<n>` the count over the whole text. A count line is written only for a group or a total that hid at least one line, so the count lines name only what was hidden (O§7.6 "Pass and fail"). The plural wording stays as the O§7.6 forms for each `<n>` (O§15 item 5).
5. **`libtest(text)` algorithm.** `None` when `!SUMMARY.is_match(text)`. Else one pass over the lines into a list of pieces: a `TEST_HIDDEN` line opens a group piece when no group is open, then adds 1 to that group's passed or ignored count; else a `PROGRESS` line adds the build piece when it is the first one, then adds 1 to the total; else the line is a verbatim piece, and when its bare form matches `SUMMARY` the open group is closed. No group and no progress line → `None` (O§7.3 "no change"). Render the pieces in order. Steps: `PassedTestsHidden` when a group exists, then `BuildProgressHidden` when the total is > 0 (the O§7.8 order of the fixed set). The view must be strictly shorter than `text`, else `None` (O§7.3 "No step adds content"; same rule as `kind_view.rs:27`).
6. **`view(text, runners)` dispatch** (O§7.6 "the command picks the parser; the output confirms it"): the first `r` in `runners` whose summary is in `text` decides; when none has, `None`. That runner's view is the result, mapped to its `Shaper` (`Libtest` → `libtest(text)` with `Shaper::Libtest`); its `None` is the result, and later runners are not tried. A private `fn has_summary(r: Runner, text: &str) -> bool` gives `SUMMARY.is_match(text)` for `Libtest` and `false` for `Pytest` and `Gotest` (OS-31 and OS-32 add their summary forms and arms).
7. **Pipeline step 3** (O§7.3): in `shape::run`, replace the comment at `mod.rs:64` with

   ```rust
   // Step 3, runner view (O§7.6): when a segment names a runner and the text has its summary.
   let runners = input.parsed.as_ref().map_or(&[][..], |p| p.runners.as_slice());
   if let Some((t, s, k)) = runner::view(&text, runners) {
       text = t;
       steps.extend(s);
       shaper = Some(k);
   }
   ```

   It runs on the text after clean and dedup, at any size (O§7.3 puts no threshold on step 3; O§7.9 stores a shaped view below the threshold too). Step 4 then runs on the runner view, and only when that is still over the threshold (O§7.3 item 4, O§7.7). The order is thus clean, dedup, runner view, kind view, size view.

fn bare(l: &str) -> &str {

fn is_count(l: &str) -> bool {

/// The raw lines that the view removed (O§8.3 item 5). One cursor over the view lines that are not
/// count lines: a raw line equal to the line at the cursor is kept and moves the cursor; any other
/// raw line is removed. Every view line must be used, in order.
fn removed<'a>(raw: &'a str, view: &str) -> Vec<&'a str> {
    let kept: Vec<&str> = view.split_inclusive('\n').map(bare).filter(|l| !is_count(l)).collect();
    let (mut i, mut out) = (0, Vec::new());
    for l in raw.split_inclusive('\n').map(bare) {
        if kept.get(i) == Some(&l) {
            i += 1;
        } else {
            out.push(l);
        }
    }
    assert_eq!(i, kept.len(), "a view line is not a raw line in order: {:?}", kept.get(i));
    out
}

        for l in v.lines() {
            if let Some(c) = TESTS.captures(l) {
                let (a, b): (usize, usize) = (c[1].parse().unwrap(), c[2].parse().unwrap());

            }
        }
        assert_eq!((p, i, n), (ok, ign, prog));
        assert!(v.lines().filter(|l| BUILD.is_match(l)).count() <= 1);
    }
}

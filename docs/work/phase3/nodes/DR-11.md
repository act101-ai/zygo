# DR-11 — Verdict git reader: four bounded git processes behind an injectable trait

**Spec:** `docs/specs/2026-11-24-decision-records-design.md` D§9.4 (opening paragraph: one `git cat-file --batch`, one `git merge-base`, one `git rev-list`, one `git log`; 2 s per process, 10 s in all; 2,048 objects and 16 MiB; step 4 range limit 10,000; step 8 `git log` form; `cannot check: <git step> <why>`), D§6.8 (in git: a link or submodule tree entry is not a regular file), D§17 (injected git runner, no wall-clock test), D§18 PD1, D-C6
**Files:** `crates/zygo-work/src/gate/mod.rs`, `crates/zygo-work/src/gate/git.rs`, `crates/zygo-work/src/repo.rs`, `crates/zygo-work/tests/decision_git.rs`
**Consumes:** — (edge to DR-10: `crates/zygo-work/src/gate/mod.rs`, which DR-10 creates)
**Produces:** `gate::git::GitFail` (`Failed { step: &'static str, why: String } | TooMuch`; `Display` gives `cannot check: <step> <why>` and `too much to read`); `gate::git::Blob` (`Missing | NotRegular | Data(Vec<u8>)`); `gate::git::LogCommit { pub id: String, pub parents: Vec<String>, pub message: String, pub paths: Vec<(char, String)> }`; trait `gate::git::VerdictGit` with `fn commit(&mut self, rev: &str) -> Result<Option<String>, GitFail>` (full id of `<rev>^{commit}`), `fn record_blob(&mut self, rev: &str, name: &str) -> Result<Blob, GitFail>` (reads the tree `<rev>:docs/decisions` and its entry modes through `--batch`), `fn merge_base(&mut self, a: &str, b: &str) -> Result<Option<String>, GitFail>`, `fn rev_list(&mut self, base: &str, head: &str, max: usize) -> Result<Option<Vec<String>>, GitFail>` (`None` over `max`), `fn log(&mut self, base: &str, head: &str) -> Result<Vec<LogCommit>, GitFail>` (`--no-renames --name-status -z`, paths under `docs/decisions/`); `gate::git::ProcessGit::new(root: &Path) -> ProcessGit` (implements `VerdictGit`)
**Acceptance:** `cargo test -p zygo-work --locked --test decision_git` → all pass. On a fixture repository with a linked checkout, `ProcessGit` opened in the main checkout reads a commit, a record blob, the merge base, the range and the log of commits made only in the linked checkout before any merge (PD1); a record that is a symlink tree entry or a submodule gives `NotRegular`, a missing path `Missing`, a `docs/decisions` that is a blob gives `Missing`; `rev_list` over `max` gives `None`; the 2,049th object read gives `GitFail::TooMuch`, and so does a read that takes the total past 16 MiB; a git call that exits with an error (an unknown object name given to `merge_base`) gives `GitFail::Failed` naming `merge-base`. No test measures elapsed time.

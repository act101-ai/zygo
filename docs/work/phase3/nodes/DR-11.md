## Plan

### Contract drift (author's call 1, read first)

D§9.4 fixes one `git cat-file --batch` process for all object reads of a verdict, inside the four-process bound. `VerdictGit` asks for one object at a time (`commit`, `record_blob`), and DR-12 asks at steps 1, 4, 5, 7 and 9, between the `merge-base`, `rev-list` and `log` calls whose output decides the step 9 reads. A one-shot "stdin form of `run_whole`" (the Produces text, and `GitRunner::run(cmd, stdin: Option<&[u8]>, deadline)`) starts one `--batch` process per call: DR-12's Acceptance #6 case alone needs 3 `commit` and 2 `record_blob` calls, so it passes `GIT_PROCESSES` = 4 and is refused. So the one `--batch` process stays open for the life of `ProcessGit` and answers one request at a time. This changes two DR-11-only signatures (DR-12 consumes neither):

- `repo.rs` gains `run_piped` and `Piped`, a request-and-reply form of the whole-mode runner, in place of a one-shot stdin form.
- `GitRunner::run` loses `stdin`; `GitRunner::batch` is added; `BatchIo` is new. `ProcessRunner` is new, so a test can wrap the real runner with a moved clock.

`VerdictGit`, `ProcessGit`, `GitFail`, `Blob`, `LogCommit`, `GIT_STEP`, `GIT_TOTAL`, `GIT_PROCESSES`, `ProcessGit::new` and `ProcessGit::with_runner` stay as in the contract.

`name` in `record_blob` is the file name in `docs/decisions/` (for example `DDR-<26>.md`), compared byte for byte with the tree entry name. `GitFail` `Display`: `cannot check: {step} {why}` and `too much to read`. The step names are `git cat-file`, `git merge-base`, `git rev-list` and `git log`, so D§17 #9 reads `cannot check: git log timed out`.

### Rules the code follows (author's calls 2 to 9)

2. **Process budget.** Before each spawn, `ProcessGit::deadline(step)` refuses with `Failed { step, why: "more than 4 git processes" }` when `started == GIT_PROCESSES`. It refuses with `Failed { step, why: "over 10 s in all" }` when `now >= first + GIT_TOTAL`, where `first` is the `runner.now()` of the first spawn. Otherwise it adds 1 to `started` and returns `min(now + GIT_STEP, first + GIT_TOTAL)`. The `--batch` process counts once, when the first object read spawns it, and keeps the deadline it got then.
3. **Caps on what DR-11 reads.** The 2,048-object and 16 MiB caps are checked in `ProcessGit::ask`, before any stdout of the object is read. Each request counts as one object, also when the reply is `missing`. The 2,049th request is not sent. The size in the reply header is added to `bytes` before the body is read, and a header that takes `bytes` past 16,777,216 gives `TooMuch` with no body read. Then `ProcessGit` drops the process (the group is killed). This stops early, as D§9.4 needs ("reads at most"). A check after the process ends would first read the bytes the bound forbids. `Piped`'s reader thread hands 64 KiB chunks over `sync_channel(1)`, so stdout that is not asked for stays in the pipe and memory holds the asked object plus at most two chunks. `log`, `rev-list` and `merge-base` go through `run_whole` (no cap). `rev-list` is capped by `--max-count=<max+1>`. `log` is bounded only by its 2 s, as D§9.4 says (spec gap, reported).
4. **No deadlock on stdin.** Exactly one request is in flight, and each is at most 2 × 256 + 32 bytes (see 6). `cat-file --batch` flushes its reply to each request (no `--buffer`), and the reply is read before the next request is written. So stdin never holds more than one request and cannot fill a pipe buffer (4 KiB on Windows), and no writer thread is needed. A hung git shows as a `TimedOut` on the read, not as a blocked write.
5. **Exit status.** `ok` alone is never taken as success. Each stdout is checked strictly. `merge-base`: `ok` with `<id>\n` (40 or 64 lower-case hex) gives `Some`; `!ok` with empty stdout and empty stderr (exit 1, no common ancestor) gives `None`; `!ok` with stderr gives `Failed { why: "failed: <first stderr line, esc, at most 200 bytes>" }`; any other result (for example `ok` with empty stdout, which only an unknown status under ignored SIGCHLD can give) gives `Failed { why: "bad output" }`. `rev-list` and `log`: need `ok` and output that parses. The one case left open is an unknown status with empty stdout, which reads as an empty range. It needs SIGCHLD ignored in the MCP server, which no zygo code does (`grep SIGCHLD crates/*/src`). The `--batch` replies describe themselves, so no exit status is used.
6. **Argument guard (no spawn).** A rev must be 1 to 256 bytes, each in `0x21..=0x7e`, with no leading `-`. A name must be 1 to 255 bytes, with no `/`, `\n` or NUL. A bad rev gives `commit` → `Ok(None)`, `record_blob` → `Blob::Missing`, and `merge_base`/`rev_list`/`log` → `Failed { step, why: "bad revision" }`. A bad name gives `Blob::Missing` (no subdirectory is read, D§6.8).
7. **A failed `--batch` stays failed.** The first `GitFail` from the batch (spawn error, `RunError`, bad header, `TooMuch`) is stored in `self.batch`, and every later `commit`/`record_blob` returns it with no new process (D§9.4: one `--batch`).
8. **Commands.** All go through `repo::git_cmd(OsStr::new("git"), root, args)` (made `pub(crate)`) plus `GIT_NO_LAZY_FETCH=1` (no promisor fetch on a missing object): `cat-file --batch`; `merge-base <a> <b>`; `rev-list --max-count=<max+1> <base>..<head> --`; `log --no-renames --name-status -z --no-color --no-show-signature --format=%H%x00%P%x00%B <base>..<head> -- docs/decisions/`. The two `--no-*` flags are added to the D§9.4 form so that a user's `log.showSignature` or `color.ui=always` cannot change the bytes that are parsed.
9. **Real-git tests and time.** Real-git tests use `ProcessGit::with_runner(root, Box::new(Far(ProcessRunner)))`. `Far::now()` is `Instant::now() + 3600 s`, so every deadline is an hour away and machine load cannot fail a test. `ProcessGit::new` is the one-line `with_runner(root, Box::new(ProcessRunner))` and is not run in a test, because a 2 s real deadline would be a timing test (no-timing-in-CI rule). Stub tests take one `Instant::now()` as an origin and only move a stub clock from it. No test measures elapsed time. Timeout of a `Piped` read is not tested with real time (it is the same `recv_timeout` path as `run_stream`).

### Algorithms the signatures do not decide

`ProcessGit::ask(&mut self, object: &str) -> Result<Reply, GitFail>` with `enum Reply { Missing, Object { id: String, kind: String, body: Vec<u8> } }`:
get or spawn the batch (rule 2, `git cat-file`); `objects == BATCH_OBJECTS` → `TooMuch`; `objects += 1`; `send(object + "\n")`; `read_line(600)`; split on `' '`: `[_, "missing" | "ambiguous"]` → `Missing`; `[id, kind, size]` with `id` 40/64 hex and `size: u64` → `bytes + size > BATCH_BYTES` → `TooMuch`, else `bytes += size`, `body = read_exact(size)`, `read_exact(1) == b"\n"` → `Object`; anything else → `Failed { step: "git cat-file", why: "bad output" }`. A `RunError` → `Failed { step: "git cat-file", why: e.reason() }`. Every `Err` is stored (rule 7).

`commit(rev)`: `ask("<rev>^{commit}")` → `Object { id, .. }` gives `Some(id)`, `Missing` gives `None`.

`record_blob(rev, name)`: `ask("<rev>:docs/decisions")`. `Missing` or a `kind` other than `tree` → `Blob::Missing` (a `docs/decisions` that is a blob or a link). Else `find_entry(body, name, id.len() / 2)`: `None` → `Failed { why: "bad output" }`; `Some(None)` → `Missing`; mode `100644` or `100755` → `ask(<hex of raw id>)`, and a `blob` gives `Data(body)` (anything else gives `bad output`); any other mode (`120000` link, `160000` submodule, `40000` directory) → `NotRegular` with no blob read.

```rust
/// The entry `name` of a raw tree: `Some(Some((mode, raw id)))`, `Some(None)` when absent, `None` when malformed.
fn find_entry<'a>(mut t: &'a [u8], name: &[u8], id_len: usize) -> Option<Option<(&'a [u8], &'a [u8])>> {
    while !t.is_empty() {
        let sp = t.iter().position(|&b| b == b' ')?;
        let nul = sp + 1 + t[sp + 1..].iter().position(|&b| b == 0)?;
        let end = nul + 1 + id_len;
        if end > t.len() { return None; }
        if &t[sp + 1..nul] == name { return Some(Some((&t[..sp], &t[nul + 1..end]))); }
        t = &t[end..];
    }
    Some(None)
}
```

`log` output (git 2.50 seen: `<H>\0<P>\0<B>\0\n<S>\0<path>\0<S>\0<path>\0<H>\0…`; the first status of a commit has a leading `\n`, and a commit with no paths, such as a merge, is followed directly by the next id):

```rust
fn parse_log(out: &[u8]) -> Option<Vec<LogCommit>> {
    let mut t = out.split(|&b| b == 0).peekable();
    let mut v = Vec::new();
    while let Some(id) = t.next() {
        if id.is_empty() && t.peek().is_none() { break; } // the NUL that ends the output
        let id = hex_id(id)?;
        let parents = std::str::from_utf8(t.next()?).ok()?.split(' ').filter(|p| !p.is_empty())
            .map(|p| hex_id(p.as_bytes())).collect::<Option<Vec<_>>>()?;
        let message = String::from_utf8_lossy(t.next()?).into_owned();
        let mut paths = Vec::new();
        while let Some(s) = t.peek().and_then(|s| status(s)) {
            t.next();
            let p = String::from_utf8_lossy(t.next()?).into_owned();
            if p.starts_with("docs/decisions/") { paths.push((s, p)); }
        }
        v.push(LogCommit { id, parents, message, paths });
    }
    Some(v)
}
/// A name-status token: one ASCII upper-case letter, after one optional leading '\n'.
fn status(tok: &[u8]) -> Option<char> {
    match tok.strip_prefix(b"\n").unwrap_or(tok) { [c] if c.is_ascii_uppercase() => Some(*c as char), _ => None }
}
/// 40 or 64 bytes of [0-9a-f].
fn hex_id(b: &[u8]) -> Option<String>;
```

`None` from `parse_log` → `Failed { step: "git log", why: "bad output" }`. A path that is not UTF-8 is kept lossy: it can never match the record name pattern, and DR-12 treats it as a malformed name.

`Piped` (repo.rs): `run_piped` calls `spawn_piped(cmd, deadline, true, Stdio::piped())`. `spawn_piped` gains the parameter `stdin: Stdio` in place of its fixed `Stdio::null()`, and `run_bounded_out` and `run_stream` pass `Stdio::null()`. Then `run_piped` takes `child.stdin` (if it is absent: kill, reap, `Failed`), starts `drain_err`, and starts the reader thread (64 KiB `read`, `sync_channel(1)`, ends on EOF, an error or a dropped receiver). Each wait checks `Instant::now() >= deadline` first, then `recv_timeout(left)`. `Timeout` → `run.stop()`, `TimedOut`. `Disconnected` (EOF: git ended) → `Failed`. `send` does `write_all` + `flush`, and an error (EPIPE) gives `Failed`. `read_line(max)`: `Failed` when no `\n` is in the first `max + 1` bytes. Drop: the `Running` field kills the group (unix) or the tree (Windows) and reaps.

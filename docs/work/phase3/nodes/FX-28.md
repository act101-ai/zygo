### Premise (verified at `3ce003ac`)

- e1 holds. `outbox::send_remote_with` (`crates/zygo-mail-sync/src/outbox.rs`) runs the S§7.2 rules and the secret pass. Then it makes `mail/`, `mail/outbox/` and `mail/outbox/tmp/` (`ensure_mail_dir`), writes `tmp/<id>.json` (`write_synced`) and links it into `outbox/` (`publish`). It takes no lock of any kind, and it returns `Ok(id)`. Its callers report the id as sent: `zygo mail send` (`crates/zygo/src/cmd/mail.rs`, the `To::Remote` arm) and `mail_send` (`crates/zygo-mcp/src/tools/mail.rs`).
- e2 holds. `admin::forget_run` (`crates/zygo-workspace/src/admin.rs`) takes `op.lock`, then `sync_lock` (`mail/sync/lock`), then runs `before_remove`. In `zygo ws forget`, `before_remove` is `forget_mail` (`crates/zygo/src/cmd/ws.rs`). It counts with `outbox::count` and `outbox::refused_count`, asks the y/N question with no time bound, and runs `remove_sync_worktree` (git, `WORKTREE_REMOVE_BOUND` 10 s). Only after that does `mail_lock` fire the hook `forget_before_mail_lock` and take `mail/lock` exclusive (`state::take_lock(.., MAIL_LOCK_WAIT, false)`). Then `remove` renames the state folder, with `mail/outbox/` in it.
- e3 holds. No lock that a remote send takes separates the count from the rename. A send that links between them is deleted, and it is in no count that the operator saw.
- Lock order (S§7.6 step 4, M§5): `op.lock` < `mail/sync/lock` < `mail/lock` < the state lock. `MAIL_LOCK_WAIT` = 2 s (`crates/zygo-workspace/src/mail/mod.rs`). `state::lock_is_at(lock: &File, path: &Path) -> bool` is the inode check. `state::take_lock` and `state::lock_file_as` are `pub(crate)`.
- The takers of `mail/lock` shared today are `mail::Delivery::begin` and `mail::store::read_within`. `Delivery::begin` is `pub`, and it does these steps in order:
  1. It refuses a state folder that is gone with `NoWorkspace` before it makes anything.
  2. It makes `mail/` only in a state folder that exists.
  3. It takes the lock shared for at most `bound` (`Busy` when it cannot).
  4. It checks `lock_is_at` (`NoWorkspace` when the check fails).
  5. It reads `workspace.json` under the lock (`NoWorkspace` when the file is missing).
- Writers of `mail/outbox/` and `mail/outbox/refused/`:
  - `outbox::send_remote_with` adds to `outbox/` with no lock.
  - `outbox::refuse` and `sync::refuse_unread` add to `refused/`, and the pass deletes the `outbox/` files that it pushed. All three run only in a sync pass, under `mail/sync/lock`.
  - `outbox::sweep` (`zygo mail ls`, `crates/zygo/src/cmd/mail.rs`) only deletes old `refused/` and `tmp/` files. It can lower a count, but it cannot raise one.

### The rule (author's call)

Rule (B):
- The remote send holds `mail/lock` shared across its outbox write, through `Delivery::begin`.
- The forget counts `mail/outbox/` and `mail/outbox/refused/` again under `mail/lock` exclusive, right before the rename.
- When a count is higher than the count of step 2, the forget refuses (exit 1, the state stays). It does not ask again.

Reason:
- Rule (A) must hold `mail/lock` exclusive across the count and the question. The question has no time bound, and the worktree removal can take 10 s. During that time, every local delivery, read and remote send of the workspace waits 2 s and then fails with `mail is busy`. That reverses the FX-24 rule in S§7.6 step 4: "The lock comes after steps 2 and 3, so no question and no git call runs while deliveries wait for it."
- Rule (A) with `mail/sync/lock` is worse: every remote send would then wait for, or fail on, a sync pass of up to 120 s.
- Rule (B) keeps the FX-24 lock placement and the lock order. It adds one recount under a lock that the forget takes already. The send gets the same lock and the same checks as every other M§5 taker.
- A refusal leaves the state. The next sync makes the removed sync worktree again. This is the same result as the `mail is busy` refusal of step 4 today.
- To ask again, the forget would hold `mail/lock` exclusive during a question. That is the cost of rule (A), so the forget refuses.

Premise of rule (B), "every outbox writer takes `mail/lock` shared":
- `send_remote_with` takes the lock (step 4).
- The pass writers (`refuse`, `refuse_unread`, the deletes of pushed files) run only under `mail/sync/lock`. The forget holds that lock from step 1 until after the rename, so none of these writers runs between the count and the rename.
- `outbox::sweep` cannot raise a count.
- So every writer that can raise a count between the count and the rename holds `mail/lock` shared.

# FX-28 — A remote send during `ws forget` is lost uncounted

**Spec:** `docs/specs/2026-11-24-mail-sync-design.md` S§7.6 "`zygo ws forget`" (step 2: "Each command that can lose mail prints the count and asks"; it counts `mail/outbox/` and `mail/outbox/refused/` and asks before anything is deleted; step 4: `mail/lock` exclusive held across the state rename), S§8.3 (the outbox that a pass reads; the sync child that a remote send starts after its outbox write, S§8.1), M§5 "Store" (`mail/lock`, the lock order `op.lock` < `mail/sync/lock` < `mail/lock` < the state lock). Found in FX-24 review round 1 ("not caused by FX-24"). Evidence, read at the FX-24 close (branch `phase3/FX-24`):
- e1 `send_remote_with` (`crates/zygo-mail-sync/src/outbox.rs:114-125`) makes `mail/`, `mail/outbox/` and `mail/outbox/tmp/`, writes the message and links it into `mail/outbox/` with no lock: not `mail/sync/lock`, not `mail/lock`, not `op.lock`. It returns `Ok(id)`, and the caller (`zygo mail send`, `crates/zygo/src/cmd/mail.rs`; `mail_send`, `crates/zygo-mcp/src/tools/mail.rs`) tells the sender the message was sent.
- e2 the forget counts the outbox in `before_remove` (`forget_mail`, `crates/zygo/src/cmd/ws.rs:178`, `outbox::count` and `outbox::refused_count`), then asks the y/N question (no time bound), then removes the sync worktree (git up to 10 s), then `admin::forget` takes `mail/lock` exclusive and renames the state folder (S§7.6 step 4), which deletes `mail/outbox/` with it.
- e3 so a remote send that lands between e2's count and the rename (for example while the y/N question waits) is deleted with the state folder, is in no count the operator saw, and its sender was told it was sent.

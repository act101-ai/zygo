### Open for the lead

1. **Claude Code session start.** `zygo hook workspace --event session` is sent only by the OpenCode plugin (`crates/zygo-launch/assets/opencode-plugin.js:47,86`). Claude Code's `SessionStart` runs `session_start` (`workspace.rs:667-704`) and is not registered as `workspace --event session` (`crates/zygo-launch/src/claude_code.rs:491-498`). This plan follows S§8.1 as written: the four `EVENTS` of `run_with`, with nothing in `session_start`. A Claude Code member therefore starts its first sync at its first `prompt` or `tool-end`. Decide whether `session_start` also triggers.
2. **What the hook path reads.** Review focus #49 says "reads config and `last_start` only". S§8.1 says "the cost is one read of a timestamp per tool call". The trigger must load the user config (on/off and `sync_gap`, S-C6). When some `[mail.workspace.*]` table exists, it must also read `workspace.json` for the name (Drift 5). The plan reads `workspace.json` only after the config shows such a table. Accept the extra read, or put the workspace name in the view marker (another node).
3. **`last_start` in the future.** S§8.4 starts a child only when `now - last_start >= sync_gap`. A `last_start` later than `now` (clock set back, or a bad file) blocks every hook start until the clock passes it. The spec gives no rule for this. The plan applies S§8.4 literally (`due` is `false`) and adds no cap.
4. **`[features] mail` off.** ML-10 gates every mail branch of the hook on `view.mail` (`workspace.rs:240-251`). S§11 turns sync on by `[mail.workspace.<name>] sync` alone, and `sync_for` does not read features. The plan does not gate the trigger on `view.mail`.
5. **`(main loop)` scope.** S§8.1 qualifies only `session` with "main loop". The plan starts a child on `prompt`, `stop` and `tool-end` from any caller, including a subagent `tool-end` (the `agent_id` payload). The gap bounds the count either way.

### Author's calls (spec-grounded)

- **A send writes no `last_start`.** S§15 makes "the hook path that starts a sync child" the only writer of `mail/sync/last_start`. With `gap = None`, `trigger` reads and writes no `last_start` and spawns.
- **No spawn when the `last_start` write fails.** S§8.4 writes before the spawn. S§14 "Sync child does not start": one `errors.log` line, and the next trigger tries again. A failed write gives one line and no spawn, so the gap still holds.
- **A config that does not load, no `workspace.json`, or `SyncOff`** gives no child and no line. The trigger runs on every tool call, and the hook writes a persistent condition's line only on few events (`MARKER_LOG_EVENTS`, `workspace.rs:129-132`). The config error shows in `zygo config check`.
- **Log text** (S§18: left to the builder, inside S-C2): `cannot start the mail sync child: <io error>` and `cannot write mail/sync/last_start: <io error>`. In the hook they go through `elog`, so the full line is `workspace hook <event>: <text>`. No ULID, address, host, name or URL.

**Author's decisions** (the spec leaves them open; each adds no gate):
- A1. Gate (Review focus 58, M§8, AU58): `ctx.features.mail`, a `session_dir`, a view that `SessionView::load` reads, `view.mail`, and `view.workspace` `Some` (the membership marker). Any one missing lists no mail tool. Agent kind does not matter. `tools` checks the gate before it reads config, so a session that is not a member pays nothing.
- A2. `tools` loads config with `zygo_config::load(&LoadContext { paths: Paths::from_env(), repo: None, team: None })`; an error lists no mail tool (as `workspace_down` lists none when it cannot resolve).
- A3. Each call reads `workspace.json` with `Store::open(&paths, &ws_id).read()`. `Ok(None)` → `Failed("zygo: workspace <ws_id> has no state")`; `Err(e)` → `Failed("zygo: workspace <ws_id>: <e>")` (the texts of `workspace_down.rs:62-68`). A `MailError` → `Failed(e.to_string())`.
- A4. Results (JSON values):
  - `mail_send` → `{"sent":[{"id":<id>,"to":<name, else key>}],"refused":[<MailError line>…]}`. When `sent` is empty and `refused` is not, it is `Failed(<refused lines joined by "\n">)`. Then the waker runs once with the `sent` keys (none sent: not called). In `Phase::Stopping` it returns `Failed("zygo: workspace is stopping")` before `send` (M§9, AU86).
  - `mail_read` → `{"messages":[<Message as its file JSON>…]}`.
  - `mail_list` → `{"unread":<store::unread>,"messages":[{"id","from","subject"}…],"members":[{"key":<key>,"name":<name or null>}…]}` (members in key order, the sender included).
- A5. Production waker: `after_send(paths, ws, &tmux_program(), keys, cfg)`. `fn tmux_program() -> PathBuf`: the first `<entry>/tmux` over the absolute entries of `PATH` that is a file (with an execute bit on unix), else `/dev/null/tmux` (rule D2 of `crates/zygo/src/cmd/mod.rs:100-111`). Production clock: `SystemTime::now`.
- A6. Arguments. `mail_send`: `to`, `subject`, `body`, all required strings; `mail_read`: optional `max`, an integer of at least 1, default 10; `mail_list`: none. A non-object, an unknown key, a missing key or a wrong type is `InvalidParams` naming the key. Schemas are fixed in step 1.
- A7. Descriptions (C7: no context-window words; each ends with `NO_POLL`, M§8a item 2):
  - `mail_send`: `"Send mail to members of this workspace. to is a member name, a pane key, or all (every other member). Returns the message ids. " + NO_POLL`
  - `mail_read`: `"Read your new mail, oldest first: at most max messages (default 10). The messages returned are marked read. " + NO_POLL`
  - `mail_list`: `"Show the count and the subjects of your unread mail, and the current members of this workspace, without marking anything read. " + NO_POLL`

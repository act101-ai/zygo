# FX-29 — config check rejects default_loadout = "repository" that zygo up accepts

**Spec:** `docs/specs/2026-11-24-workspace-definition-design.md` R§10 `zygo up` row (the loadout: `[workspace] default_loadout` when the user config file sets it; a `repository` plan from approved files; the sentence on `zygo config check` added by WD-20 review round 1) and R§10 `zygo config check` row; `docs/specs/2026-11-20-workspaces-design.md` W§11 (the `zygo config check` rules of `crates/zygo-config/src/check.rs`: "`default_loadout` names a loadout"). Found in WD-20 review round 1 (M2). Evidence, read on `phase3/WD-20` after its merge of `origin/phase-3` at `3ce003ac`:
- e1 `loadout_violations` (`crates/zygo-config/src/check.rs:197-203`) reports `workspace.default_loadout: unknown loadout` (severity Error) for every name other than `solo` that is not a key of the user `[loadout]` tables. It has no knowledge of the `repository` loadout that approved workspace files add (`Merged::with_definition`, R§8; WD-16).
- e2 `choose` (`crates/zygo-workspace/src/up.rs`) takes a user `default_loadout = "repository"` with no user `[loadout.repository]` to the default-branch read, and plans the approved files' `repository` loadout when they hold `.zygo/workspace.toml`.
- e3 hermetic fixture (scratch HOME, hermetic git, `unshare -rn`, the build of that tree), approved files with three members, user config `[workspace] default_loadout = "repository"` and `[limits] max_members = 2`: `zygo config check` prints `error: workspace.default_loadout: unknown loadout` and exits 11; `zygo up --no-attach` prints `zygo: this repository's workspace files start 3 agents; [limits] max_members is 2; nothing started` and exits 1, which shows that it chose the repository plan. Without `max_members`, `zygo up` uses that loadout.

**Files:** `crates/zygo-config/src/check.rs`, `crates/zygo/src/cmd/config.rs`, `crates/zygo/tests/definition_surfaces.rs`, `crates/zygo-config/tests/config_layers.rs`, `docs/specs/2026-11-24-workspace-definition-design.md`, `docs/specs/2026-11-20-workspaces-design.md`, `docs/workspace-files.md`
**Consumes:** —
**Produces:** the R§10 rule by which `zygo config check` and `zygo up` agree on `[workspace] default_loadout = "repository"`.
**Contract:** `zygo config check` accepts `[workspace] default_loadout = "repository"` exactly when `zygo up` does: with a user `[loadout.repository]`, or with approved workspace files on the default branch that hold `.zygo/workspace.toml`. In every other state it keeps the error `workspace.default_loadout: unknown loadout` and exit 11. The R§10 sentence and the `docs/workspace-files.md` sentence that WD-20 review round 1 (M2) added, which state the conflict, are rewritten to the new behaviour, with a spec change-log line.
**Acceptance:** `cargo test -p zygo --locked --test definition_surfaces config_check_default_loadout_repository_follows_zygo_up` → 1 passed: with approved files that hold `.zygo/workspace.toml` and `default_loadout = "repository"`, `zygo config check` prints no `workspace.default_loadout` line and exits 0; with the same files not approved, and with profile-only approved files, it prints `error: workspace.default_loadout: unknown loadout` and exits 11. Then `cargo test -p zygo-config --locked` → all pass.

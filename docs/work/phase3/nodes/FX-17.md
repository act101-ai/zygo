# FX-17 — `zygo up` refuses a `[limits] max_members` outside 1-32 from any layer

**Spec:** `docs/specs/2026-11-24-workspace-definition-design.md` R§9.4 bullet 1 ("`[limits] max_members`, an integer 1-32, default 8. Set by the built-in, team and user layers."); finding F4 of the FX-14 review; defect source WD-11. `zygo up` never checks the range. The user config is loaded at `crates/zygo/src/cmd/up.rs:44-50` and the team value is taken at `with_team_max_members` (`up.rs:107-112`, assignment `:109`); `zygo_config::load` runs no range check, so 0 or 33 from the user or the team layer reaches `check_max` (`crates/zygo-workspace/src/up.rs:785-793`), which compares the agent count with it as is. The user layer has the same gap as the team layer. Precedent for the outcome: the `config check` rule `limits.max_members` → `must be 1-32` (`crates/zygo-config/src/check.rs:119-120`), which `zygo up` already applies to `job` and `pool` through `check_jobs` (`crates/zygo-workspace/src/up.rs:797-808`): filter `zygo_config::check` to the path, then exit 1 before any write with `zygo: <path>: <message>; nothing started` (`up.rs:805`). The contract: when the `max_members` that `zygo up` uses (user layer, or team-merged as `with_team` gives it) is outside 1-32, `zygo up` and `zygo up --all` exit 1 before any write, whatever loadout they start, with the one stderr line `zygo: limits.max_members: must be 1-32; nothing started`. The check sits in `run` (`crates/zygo/src/cmd/up.rs`), after `with_team` and before `up::up` / `up::up_all`, so it covers both forms and leaves `crates/zygo-workspace/src/up.rs` (also in FX-13) unchanged.
**Files:** `crates/zygo/src/cmd/up.rs`, `crates/zygo/tests/workspace_restore.rs`
**Consumes:** `with_team` (FX-14)
**Produces:** `zygo up` and `zygo up --all` refuse a `[limits] max_members` outside 1-32 with `zygo: limits.max_members: must be 1-32; nothing started`, exit 1, no write (`cmd::up::run(a: &UpArgs) -> i32` signature unchanged)
**Acceptance:** `cargo test -p zygo --test workspace_restore && cargo test -p zygo --lib cmd::up` → all pass, with new tests that: (1) `zygo up` with the session `team.toml` setting `[limits] max_members = 0`, and again with 33, exits 1, prints `zygo: limits.max_members: must be 1-32; nothing started` and writes no workspace record and no tmux session; (2) the same for the user config file setting 0 and 33 with no team layer; (3) 1 and 32 from the team layer and from the user layer are accepted (no such line; a repository loadout of 2 agents is refused by the R§9.4 count line with `max_members is 1`, and planned with 32); (4) with no layer setting it, `max_members` is 8 and `zygo up` prints no range line; (5) `zygo up --all` with `max_members` 0 exits 1 with the same line.

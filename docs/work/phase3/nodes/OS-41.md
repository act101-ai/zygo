### Author's calls

1. The room covers every step name once (341 bytes), not only the longest list that is reachable today (307 bytes). Every list `shape::run` can make is a subsequence of `Step::ALL`, so the bound is safe without copying the reuse and runner rules into a constant. It also covers runner steps that OS-31 and OS-32 may add, once they put them in `Step::ALL`. Cost: 34 bytes of kind view.
2. `SHAPED_MARKER_ROOM` is a literal with its arithmetic in the doc comment. The test of step 2 derives the value from the real `shaped_view` format and the real step names, so a longer name, a new step in `Step::ALL`, or a format change fails the test until the constant is updated. A `const fn` derivation would copy the format text into a second place.
3. The constant goes in `view.rs`, next to the format string it measures, and `shape/mod.rs` subtracts it at the one call site. No second "kind view cap" constant is added.
4. `Step::ALL` completeness is checked against the spec table in `step_names_are_the_spec_strings`. A new variant must be added to that table and to `ALL` together; the compiler does not enforce this.
5. Hidden-line markers (up to 43 bytes, `runner.rs:127`, `:129`) do not count against the room: they are part of the text that step 4 measures against `cap`.
6. The Files line now also names `crates/zygo-results/tests/shape_pipeline.rs` (two expectations call `kind_view` with the cap that `shape::run` uses) and `crates/zygo-hooks/tests/shaping_hook.rs` (the hook case of the acceptance).
7. The test input is a synthetic log (1000 lines `… ERROR line <i:05>`, 37,000 bytes): its old-cap log view is 8163 bytes, 29 bytes under 8 KiB, so the old final view is 8352 bytes and the new one 8016. The command `echo x` is not a file printer and not reuse, and its stored name is `other`.
8. The verification step also runs the `zygo-results` unit tests, `shape_pipeline` and `results`, because steps 1 and 8 change them.

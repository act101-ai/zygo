## Plan

**Premises (checked at 6fa80a3c; these files equal b628e1ad).** `git.rs:186-200` `batch_io` passes one deadline at spawn, and `repo.rs:297-303` `Piped` keeps it for every `fill` (`:367`). `git.rs:226-235` reads `size` bytes before any size check. `record_blob` (`git.rs:367-395`) caches trees, not blobs. `check.rs:254-263` `version` maps `Blob` to `Version`. `record.rs:12` `MAX_FILE = 65536` is private. `decision.rs:283-288` follows a `docs` link. `decision.rs:198-201` and `:267-272` drop an empty `ZYGO_SESSION_DIR`. The check order is fixed by `check.rs:71-141`: step 1 read, `merge-base`, `rev-list`, the step 5 and 7 reads, `log`, the step 8 and 9 reads; so with each whole process advancing the clock 1.5 s, the step 5 and 7 reads are at t0 + 3 s and the step 8 and 9 reads at t0 + 4.5 s (both past spawn + 2 s). git 2.56.1 probe: `git cat-file --batch-command` answers `info <obj>` with the `--batch` header only (`<id> blob <size>`, or `<obj> missing`) and `contents <obj>` exactly as `--batch` does; it exists since git 2.36 (the repository's floor is 2.50.1, `docs/premises.md`). **Outside the Files line:** `crates/zygo/tests/definition_hooks.rs:1254-1258` (h4 control) names `cat-file --batch` and the stdin line `<head>^{commit}`; they become `cat-file --batch-command` and `contents <head>^{commit}` (its predicate already judges a `--batch-command` line by its last word, `:298-300`). `record.rs:12` becomes `pub(crate)`, so `git.rs` uses the one limit.

**Design.** (D-F1) `BatchIo` gains `fn set_deadline(&mut self, deadline: Instant)`; `Piped::set_deadline(&mut self, deadline: Instant)` sets the deadline of later waits. `ProcessGit::read_deadline(&mut self) -> Result<Instant, GitFail>` gives `min(now + GIT_STEP, first + GIT_TOTAL)`, or `cannot check: git cat-file over 10 s in all` at or past the total; `read_object` calls it and `set_deadline` before each request. (D-F2) The one process is `git cat-file --batch-command`. A commit or tree read sends `contents <obj>`. A record blob sends `info <blob>` first, and `contents <blob>` only when its size is at most `MAX_FILE`; over it, `record_blob` gives the new `Blob::TooLarge` with no body read, and `check.rs` `version` maps it to `Version::Malformed`. Each request counts toward the 2,048 cap; contents bytes count toward 16 MiB. `ProcessGit.blobs: HashMap<String, Blob>` keeps the answer per blob id, so each blob is asked once per verdict. (D-F3) `decision.rs` `records_dir_absent(top: &Path) -> bool`: `lstat` of `docs`, then of `docs/decisions`, in turn; `NotFound` → absent; a directory → next part; anything else → not absent (`read_dir` reports it). (D-F4) The operator-verb guard tests `env("ZYGO_SESSION_DIR").is_some()`; `new` keeps `session_dir` for its legend. Spec: D§9.4 rewritten for `--batch-command`, the per-read bound, the request cap and the `info` size check, with one change-log line.

# FX-41 — Decision gate: git bounds, record size, verb guards

**Spec:** `docs/specs/2026-11-24-decision-records-design.md` D§9.4, D§14 (row 2 and "A file over 64 KiB"), D-C6, D§6.8, D§11.1 (found in the Phase 3 final verification stage, 2026-11-28, head b628e1ad). **D-F1.** `crates/zygo-work/src/gate/git.rs:164-175` `deadline` and `:186-200` `batch_io`: the one `--batch` process keeps the 2 s deadline it got at spawn (the first object read, step 1 head, `crates/zygo-work/src/gate/check.rs:76`); `merge-base`, `rev-list` and `log` then run (each 2 s); the reads of steps 7-9 after them must end before spawn + 2 s, so they fail with `cannot check: git cat-file …` and a correct keep is refused at `enforce`. D§9.4: "Each process has a 2 s bound, and all of them together a 10 s bound." **D-F2.** `git.rs:213-240` `read_object` reads `size` bytes (`:235`) before the 64 KiB record check (`crates/zygo-work/src/decisions/record.rs:243`, `MAX_FILE` at `:12`); there is no blob cache, so steps 7, 8 and 9 read the same blob 3 times; a 6 MiB record gives `too much to read` (the 16 MiB batch cap), not `<label>: <id> is not a valid record at head`. D§14: "A file over 64 KiB … as malformed, never opened"; D-C6. **D-F3.** `crates/zygo/src/cmd/decision.rs:282-288`: `symlink_metadata(top.join(DIR))` follows a link in a middle part (`docs`); with `docs` a dangling link, or a link to a folder without `decisions`, `ratify` and `review` print `no open records` and exit 0. D§6.8, D§14 row 2: exit 1 `zygo decision: docs/decisions is not a directory`. `crates/zygo-work/src/decisions/set.rs:39-48` `read_dir` does it right (it checks `docs` and `docs/decisions` without following a link). **D-F4.** `decision.rs:198-201` `session_dir` filters `.filter(|v| !v.is_empty())`, and the operator-verb guard (`:267-272`) uses it, so `ZYGO_SESSION_DIR` set but empty does not refuse the operator verbs. D§11.1: "refused, exit 2, when `ZYGO_SESSION_DIR` is set".

### Author's calls

1. `meta.json` written by the script: `event` = `"PostToolUse"`, `agent` = `"claude-code"`, `tool` = the first line of `<program> --version` (else the program's base name), `source` = `"<command>, run by capture-shaping.sh in <scratch dir>"` (scrubbed to `/repo`). The capturer edits `event`, `agent`, `tool` and `source` by hand when these defaults are wrong (for example `go version`); the format check enforces their value sets. Reason: O§7.12 gives OpenCode failing runs as `PostToolUse`, and runner views read pass or fail from the summary, so `PostToolUse` is a real shape for a failing run; `PostToolUseFailure` cases are the PO1 `failure` cases (OS-23).
2. `hook_input` starts from the recorded fixture of the shape (above) and replaces only the command and output fields. `PostToolUseFailure`: `error` = the case's `stdout` text; such a case has an empty `stderr` and `agent = "claude-code"` (format check). OpenCode: `output.output` and `output.metadata.output` = `stdout` then `stderr`; `metadata.exit` = `meta.exit`. OS-23 may move the failure template to the PO1 fixture.
3. `stdout` and `stderr` must be UTF-8 (format check): a hook input is JSON, so a non-UTF-8 capture cannot be a real input.
4. `must_keep` lines: the file split on `\n`, empty items dropped, `\r` kept (a CRLF raw line keeps its `\r`).
5. "Failing test" = `exit != 0`, or `stdout`+`stderr` matches `FAILING` (below): libtest `test result: FAILED.`, a pytest summary with `N failed` or `N error(s)`, go `--- FAIL:` or a `FAIL` line.
6. Size of a case = the sum of the sizes of the regular files in its folder (`view` included once it exists); folder = all regular files under `fixtures/shaping/`. Bounds 262144 and 4194304 bytes.
7. Scrub: "scratch directory" = the directory the command runs in (`$PWD` and `pwd -P`). Order: scratch (physical, then logical) → `/repo`; `$HOME` (physical, then logical) → `/home/user`; user name (`$USER`, else `id -un`) → `user`; host name (`hostname`, then its short form) → `host`. Scratch first, because a scratch directory under `$HOME` would otherwise become `/home/user/…`. A user or host name shorter than 4 characters, or `localhost`, is not replaced and gets a note on stderr (the rule of `scripts/premises/scrub.py`). The scrub uses `perl -0777 -pi` with `\Q…\E`, which keeps every other byte (no `\r` or final-newline change, unlike BSD `sed`).
8. The script writes under `${ZYGO_FIXTURES_DIR:-<repo>/fixtures/shaping}`, so the test never writes into the repository. It refuses an existing case folder (exit 1), so a new capture never erases a written `must_keep`. Names must match `[a-z0-9-]+` (else exit 2). It exits 0 when the four files are written, whatever the command's exit; the command's exit goes to `meta.exit`. The command runs with `</dev/null`, directly (`"$@"`); a pipeline is passed as `sh -c '…'`.

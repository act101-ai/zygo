# FX-34 — Keep `stub-agent` small: the real-hook stub in its own binary

**Spec:** — (found after the FX-9 merge, PR #256; CI time regression). FX-9 review F2 made the test-only binary `stub-agent` call the real hook: `real_session_start` and its `ZYGO_STUB_HOOK_PATHS` dispatch in `crates/zygo-launch/tests/stub_agent/stub.rs:268-319` call `zygo_hooks::session_start::run_member` and `zygo_core::hook::*`. So `stub-agent` links `zygo_hooks` and all its dependencies. The debug `stub-agent` grew from 9,156,632 bytes (at fe4954ef) to 258,680,392 bytes (at 757cdfe5). `crates/zygo/tests/common/workspace.rs:306-310` copies it two times (`claude`, `opencode`) into each harness home, and `crates/zygo/tests/mail_sync_no_content.rs` (`marked_files` 1117-1136, `markers_in` 1074-1076) scans every byte of the home. Evidence: CI ubuntu went from 16 min (run 46134864311) to 55 min (run 46139651831); `mail_sync_no_content` from 191 s to 2451 s. Local A/B, same test binary, only the stub swapped: `scanners_find_a_planted_marker` 18 s vs 501 s. Only the end-to-end test `opencode_transform_item_8_fixed_per_session_end_to_end` (`crates/zygo-launch/tests/opencode.rs`, `real_transform`) needs the real hook.
**Files:** `crates/zygo-launch/Cargo.toml`, `crates/zygo-launch/tests/stub_agent/stub.rs`, `crates/zygo-launch/tests/stub_hook/stub.rs`, `crates/zygo-launch/tests/opencode.rs`
**Consumes:** —
**Produces:** the test-only binary `stub-hook` (`crates/zygo-launch/tests/stub_hook/stub.rs`): `hook session-start --agent <a> [--event <e>]` with `ZYGO_STUB_HOOK_PATHS=<root>` runs the real `session-start` hook as `stub-agent` did; `stub-agent` with no reference to `zygo_hooks` or `zygo_core`
**Acceptance:** `cargo test -p zygo-launch` → all pass, including `opencode_transform_item_8_fixed_per_session_end_to_end` with `env!("CARGO_BIN_EXE_stub-hook")` and its assertions unchanged; after `cargo build -p zygo-launch --bins`, `target/debug/stub-agent` is near its 9,156,632-byte size at fe4954ef; `cargo test -p zygo --test mail_sync_no_content scanners_find_a_planted_marker -- --exact` → passes.

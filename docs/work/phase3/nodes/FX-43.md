# FX-43 — Cap the `.zygo.toml` read

**Spec:** `docs/specs/2026-11-18-zygo-design.md` §13.5 (the repository file) and its change log; `docs/specs/2026-11-24-workspace-definition-design.md` R§6.1 step 4 (the size rule of a repository file: `.zygo/workspace.toml` at most 64 KiB, above it invalid with the path and the limit; the stdout cap of a git call). Found in the FX-39 work (2026-11-28). `read_default_branch` (`crates/zygo-config/src/repo_file.rs:271-287`) reads `.zygo.toml` with `git show <branch>:.zygo.toml` through `git` (`:158-165`) and `git_out` (`:170-172`), which gives `git_out_with` no cap (`None`). So zygo reads all of a `.zygo.toml` blob on the default branch into memory, at any size. §13.5 states no size rule for the file.
**Files:** `crates/zygo-config/src/repo_file.rs`, `crates/zygo-config/tests/config_layers.rs`, `docs/specs/2026-11-18-zygo-design.md`
**Consumes:** FX-39 (`git_out_with(.., cap: Option<usize>)` and `output_larger`, `crates/zygo-config/src/repo_file.rs:174-248`; branch `origin/phase3/FX-39`, PR #265, merged into this branch)
**Produces:** `repo_file::REPO_FILE_MAX = 65536`; `read_default_branch` keeps at most 65536 bytes of the `git show` stdout; past that it stops the read, kills the call and gives `RepoFile::Invalid { branch, why: ".zygo.toml is larger than 65536 bytes" }`, so `load` warns `.zygo.toml: invalid (.zygo.toml is larger than 65536 bytes); ignored` and `zygo work` policy reports the file invalid. A file of exactly 65536 bytes is read as before.
**Acceptance:** `cargo test -p zygo-config` → all pass, including, each failing first: `repo_file_read_stops_past_the_cap` (unit test in `repo_file.rs`: a fake `git` whose `show` writes 1 MiB and then a marker file gives `Invalid` with the reason, and the marker is never written: the read stopped and the call was killed); `cargo test -p zygo-config --test config_layers -- --ignored --exact repo_file_over_the_cap_is_invalid` → passes (a real git fixture: a 65537-byte blob → `Invalid` with the reason and the `load` warning; a 65536-byte blob → `Found`); `cargo test -p zygo --test workspace_definition` → all pass.

## Decisions (author's call, FX-43)

- D1. The cap is 65536 bytes (64 KiB), as `.zygo/workspace.toml` in R§6.1 step 4. Far above a real file: four small tables.
- D2. A file above the cap is **invalid**, not unread: R§6.1 step 4 makes a repository file above its size limit invalid, with the path and the limit. Invalid is also the form that tells the user (`load` warning, `zygo work` policy status); unread counts as absent.
- D3. The size is found by the capped read itself (one byte past the cap), not by a `git cat-file -s` call first: no extra call under the 2 s budget.
- D4 (review F4). A tree at `.zygo.toml` is invalid, `.zygo.toml is not a file`, at any listing size. zygo tells it from the first line of the `git show` output, `tree <branch>:.zygo.toml` and an empty line, with no other git call; over the cap, the first `cap + 1` bytes of the stopped read are kept for this (`run_capped`, `Ran::Larger`). Not `git cat-file blob`: it would change the git messages that zygo matches to tell an absent file (`GIT_ABSENT`). No valid file starts with that line (it is not TOML).
- D5 (review F1). The test seam is a runner closure (`RunGit`: args, deadline, cap → `Ran`), not a command maker, so a CI test records the deadline of each call with no real time.

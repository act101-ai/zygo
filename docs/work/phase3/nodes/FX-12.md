# FX-12 — HUD unread count uses the store's definition (regular <ULID>.json files; missing new/ is 0)

**Spec:** — (found in the ML-14 review). The HUD count and the store's count differ. `statusline::mail::unread` (`crates/zygo-hooks/src/statusline/mail.rs:38`) counts every name that ends in `.json`, and it returns `None` when `new/` is missing (`read_dir(dir).ok()?` at mail.rs:33). The store's `ids` (`crates/zygo-workspace/src/mail/store.rs:103-121`), used by `unread` (store.rs:274), counts only regular files whose name is a valid id (`valid_id` at store.rs:25) followed by `.json`, and gives `Ok(0)` when `new/` is missing. Example: `new/` that holds `junk.json` and one symlink `<ULID>.json` gives `✉ 2` in the HUD, but `zygo workspace` shows no unread mail. M§9a (`docs/specs/2026-11-22-workspace-mail-design.md`, section "9a. Status line (HUD)", rewritten) now defines the HUD count as the store's count: regular `<ULID>.json` files, no link followed, a missing `new/` counts 0. The hook keeps its own ULID check (a copy of `valid_id`), because M§9a allows no dependency of the hook on `zygo-workspace`. The doc comment of `unread` in `crates/zygo-hooks/src/statusline/render.rs:86` ("The count of `*.json` names") must be corrected too, and so must the module doc of mail.rs (lines 1-6).
**Files:** `crates/zygo-hooks/src/statusline/mail.rs`, `crates/zygo-hooks/src/statusline/render.rs`, `crates/zygo-hooks/tests/statusline_mail.rs`
**Consumes:** —
**Produces:** `pub fn unread(paths: &Paths, view: &SessionView, deadline: Instant) -> Option<usize>` in `zygo_hooks::statusline::mail` (signature unchanged); it returns `Some(0)` for a missing `new/`, and does not count links, folders or names that are not `<ULID>.json`
**Acceptance:** `test "$(cargo test -q -p zygo-hooks --test statusline_mail -- unread_ --list 2>/dev/null | grep -c ': test$')" -ge 8 && cargo test -p zygo-hooks --test statusline_mail` → every count holds, then all pass. The tests: the 6 `unread_…` tests that exist now; new `unread_skips_links_folders_and_non_ulid_names`; new `unread_matches_the_store_count` (`junk.json`, a symlink `<ULID>.json`, a folder `<ULID>.json` and two regular `<ULID>.json` files give `Some(2)`, equal to `zygo_workspace::mail::store::unread`; the test may depend on `zygo-workspace`, because `zygo-hooks` already does); the existing missing-`new/` test (`unread_outside_a_workspace_or_without_new_is_none`) changed to expect `Some(0)` for a missing `new/`.

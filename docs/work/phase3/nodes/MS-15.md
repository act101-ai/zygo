### Drift and decisions (cited)

- P1. Step 12 has only its "write" half: `own_changes` (`sync.rs:599-634`) writes the own registry and own acks but never deletes an old own registry or an empty old ack (S§8.3 step 12, S§7.6 "Rename"). MS-15 adds the deletes there (Task 1). The MS-13 test `own_ack_follows_the_tip_across_own_hosts` (`tests/sync_pass.rs:451-470`) keeps passing: `ack/b.json` always has a file left at the tip in it.
- P2. `gate`, `take_lock`, `Ctx`, `Fail`, `stop` are private to `sync.rs` (`:97-217`). The operator commands need the same gate (S§8.3 step 1), the same lock (S§15: the lock holder is the only writer of `state.json`) and the same stop lines. Task 2 makes those `pub(crate)` and adds one `pub(crate) fn locked`; no public item of `sync.rs` changes.
- P3. `Opts` gets no new field: `tests/prune.rs:137` builds `Opts { prune: true }` without `..Default::default()`, and `tests/prune.rs` is not in this node's Files. `take_host` and `new_identity` do their own step under the lock, release it, then call `run_with(…, Mode::Cli, &Opts::default())`.
- D1. `take_host` keeps the entries of the tip's `ack/<host>.json` when that ack is valid, whatever its identity; an invalid or missing ack counts as empty (S§7.4 Validation). It writes nothing when both `registry/<host>.json` and `ack/<host>.json` already hold this identity.
- D2. The commit and push of `take_host` and `drop_host` follow S§8.3 steps 13-15: record the own blobs of the commit as `pending` before the push, as `pushed` after an accepted push (else the next pass sees a twin, `identity.rs:171-181`), no force, a moved branch fetches again, at most `MAX_ATTEMPTS`, then `MOVED_LINE`. A tip without the marker stops with `MARKER_LINE` (S§8.3 step 7). No collision or twin check runs in these two steps: `--take-host` exists to overwrite a collision; `--drop-host` touches no own file unless the operator names an own host.
- D3. `waiting_for` counts entries `<addr>/<ULID>.json` directly under each top-level tree `<addr>` whose `address::parse(addr)` host is `host`, less the ULIDs the valid `ack/<host>.json` lists (S§7.6, S§7.4). `drop_host` removes every entry directly under those folders, `registry/<host>.json` and `ack/<host>.json` when the tip lists them, in one commit.
- D4. The `host` argument of `waiting_for` and `drop_host` must pass `valid_mail_host` (the S§5 host form; every branch path is built from it); else `Err(SyncError::Stopped { line: "zygo: mail sync stopped (host); the outbox is kept".into(), check: "host" })` (the text `stop` gives, `sync.rs:122-124`), before the gate and the lock, with no `errors.log` line, and `ask` is not called.
- D5. `drop_host` asks after a `waiting_for` that releases the lock, so a person's answer never holds the sync lock; on yes it takes the lock again and deletes the files at the tip it then fetches. It always asks, also when `n` is 0 (S§7.6: "prints … and on yes deletes").
- D6. `new_identity` deletes `mail/sync/identity` (missing is fine), clears `pushed` and `pending` in `state.json` under the lock, then runs the sync; the pass makes the new identity (`make_identity`, `sync.rs:257`).
- D7. `--take-host` and `--new-identity` are flags of `zygo mail sync` (S§7.6), so each is a sync, and S§8.3 step 5 puts the S§8.2 public check at the first pass, before any fetch. `take_host` runs the pass's own `public_check` (`sync.rs:390-408`, private today; Task 2 makes it `pub(crate)`) under the lock, first, before its `fetch_tip` and push; `Verdict::Public` gives the pass's existing stop (`PUBLIC_LINE`, `sync.rs:83`, check `public`) and nothing is fetched or pushed. Its `Report` is dropped: the `run_with` that follows runs the check again at its first pass (the 1 h cache of `public.rs:147-160` answers) and adds the `Unknown` note there. `new_identity` fetches and pushes nothing before `run_with` (it deletes one local file and clears two local maps), so its first git call is the pass's, after the pass's check. `--drop-host` is a flag of `zygo mail sync` too: `waiting_for` and the deleting part of `drop_host` each run `sync::public_check(c, &mut Report::default(), deadline)?` first in their `sync::locked` closure, before their `fetch_tip`, with the same `public` stop. As `drop_host` calls `waiting_for` before `ask`, a `public` remote stops it before any fetch and before `ask` is called; the second check, in the deleting part, is answered by the 1 h cache.

    let SyncError::Stopped { line, check } = e else { panic!("{e:?}") };
    (line, check)

#[test] // S§19 #9, S§7.6 --take-host, S§14 "Moved repository, ws forget, restored backup", S-G5

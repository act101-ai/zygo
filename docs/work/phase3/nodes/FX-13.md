# FX-13 — Member record and maildir lifecycle: no maildir without a record; every record removal removes it

**Spec:** — (found in the ML-14 review). Two defects break the M§5 retention rule (`docs/specs/2026-11-22-workspace-mail-design.md`, section "5. Store", Retention bullet, rewritten): a maildir exists only for a pane key that has a member record, and every path that removes a record removes `mail/<key>/`.
(a) A stale send recreates a removed maildir. `mail::send` (`crates/zygo-workspace/src/mail/mod.rs:141-169`) resolves its targets through `names::resolve(ws, …)` (mod.rs:152) on a `&Workspace` that the caller read earlier. It takes no lock, and `store::deliver` creates the folders (`make_dirs`, `crates/zygo-workspace/src/mail/store.rs:67`). A send that read the state before `forget_pane_run` wrote the record removal (`crates/zygo-workspace/src/admin.rs:944`), and that delivers after the maildir is removed (admin.rs:981-993), recreates `mail/<key>/new/<ULID>.json`. Nothing calls `send` in production yet; ML-11 (MCP `mail_send`) and ML-12 (`zygo mail send`) add the first callers.
(b) These paths drop member records and leave `mail/<key>/` in place: `crates/zygo-workspace/src/up.rs:1138` (`--reset`), up.rs:1188 (`plan.forget`), up.rs:1367 (fresh members that were not built), up.rs:260 (`take_back_plan`, up.rs:253, called at up.rs:1217 and `crates/zygo-workspace/src/repair.rs:138`), and `crates/zygo/src/cmd/member.rs:494` (`undo_start`, member.rs:486, called at member.rs:149).
This node does not choose a mechanism. If the fix needs a lock, a refusal or any other new rule, the plan brings it to the operator as a proposed rule and waits for approval before it is built.
**Files:** `crates/zygo-workspace/src/mail/mod.rs`, `crates/zygo-workspace/src/mail/store.rs`, `crates/zygo-workspace/src/up.rs`, `crates/zygo-workspace/src/repair.rs`, `crates/zygo/src/cmd/member.rs`, `crates/zygo-workspace/tests/mail_lifecycle.rs`
**Consumes:** `zygo_workspace::mail::store::remove_pane(mail_dir: &Path, key: &str) -> std::io::Result<()>` (ML-2), `zygo_workspace::mail::mail_dir(paths: &Paths, ws_id: &str) -> PathBuf` (ML-2), `zygo_workspace::mail::send(paths: &Paths, ws: &Workspace, sender_key: Option<&str>, to: &str, subject: &str, body: &str, cfg: &MailConfig, now: SystemTime) -> Result<SendReport, MailError>` (ML-4)
**Produces:** the M§5 retention invariant holds on every path that removes a member record, and no delivery creates a maildir for a key with no record; no signature is fixed here (the plan fixes it)
**Acceptance:** `test "$(cargo test -q -p zygo-workspace --test mail_lifecycle -- lifecycle_ --list 2>/dev/null | grep -c ': test$')" -ge 6 && cargo test -p zygo-workspace --test mail_lifecycle -- --include-ignored` → every count holds, then all pass. At least 6 `lifecycle_…` tests, one each for: `up --reset`; `plan.forget`; fresh members not built; the build undo through repair (`take_back_plan`); a stale send after `forget-pane` creates no `mail/<key>/`; a send to a key with no record creates no maildir.

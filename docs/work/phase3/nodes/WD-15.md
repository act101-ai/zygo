### Author's calls (open in R§7.1 and R§17 "The text of lines this spec does not fix")

1. **Order of checks:** slash form (in `workspace::approve`); then in `run`: arguments; `ZYGO_SESSION_DIR`; checkout; read; R§7.1 steps 4, 5, 6, 7. Reason: the slash form runs inside the `prompt` hook, which reads no `.zygo/` (R-C8, R§18 item 20), so it returns before the module that reads; a usage error needs no repository.
2. **Slash reply:** `run in your shell: zygo workspace approve` for every argument list; no read, no write. Reason: the DR-3 form; a reply that repeats `--yes` would hand the agent the bypass that the R§7.1 known limit names.
3. **Arguments:** `--yes` and `--digest <hex>`, each at most once. `ctx.save` (`--save`), any other token, a repeat or a missing value: exit 2, `zygo workspace: usage: workspace approve [--yes] [--digest <hex>]`. A `--digest` value that is not 64 ASCII hex characters: exit 2, `zygo workspace: --digest takes 64 hex characters`. Upper-case hex is accepted and compared in lower case; the mismatch line shows the value as given. Reason: R§7.1 step 5 says "64 hex characters" and does not fix the case.
4. **Inside an agent session:** `ctx.session_dir.is_some()`, the rule of `plugins.rs:134` (`SessionDir::from_env` counts an empty value as unset). Reason: R§7.1 step 2 cites that rule.
5. **Checkout:** `find_checkout(&cwd, GIT_BOUND)`, the lookup of `zygo up`; the read runs at the top of its first value `co`, the checkout of the current folder (`zygo_work::repo::checkout`, the call of the launcher, `launcher.rs:890`), as the launcher reads (`launcher.rs:917`) and `zygo doctor` reads (`doctor.rs:261-263`); the id is `workspace_id(&co.common_dir)`, the launcher's id. The `folder:` line shows `co.top`. (Rewritten by WD-15 review F3: the read ran at the third value, the first listed worktree, which can be a deleted folder while the launcher reads and sends the user here.) An `Err` whose message is `up::NOT_A_REPO`: exit 2, `zygo: workspace approve needs a git repository` (`Exit.message` names `zygo up`). Any other `Err` (a bare repository with no checkout): exit 1, `zygo: workspace approve: <Exit.message, esc>` (WD-15 review F5: the reason is kept). Reason: the id that `up` and the launcher check is the id that `approve` stores.
6. **Lines of step 3:** absent `zygo: this repository has no workspace files at <full ref>` (R§7.1); unread `zygo: this repository's workspace files are unread (<why>); nothing approved`; invalid `zygo: this repository's workspace files (<full ref>) are invalid (<why>); nothing approved` (the forms of `up.rs:775-782` with this verb's ending; `<full ref>` is `full_ref.unwrap_or_default()`, as `up.rs:911`). Each value through `esc`; exit 1.
7. **User config:** read with `user_config(&ctx.paths)` (`[workspace]` is user config only, W AU22) only after steps 4 and 5. A load error: exit 1, `zygo: user config not read (<error, esc>); nothing approved`. Reason: without it the summary cannot say which members run in passthrough (R§7.1 step 6); refusing changes nothing.
8. **Store result:** `Stored::Added` → `approved <digest>` and the `to start it: …` line; `Stored::AlreadyPresent` (another `approve` stored it after this read, R§10 "Two sessions at once") → `workspace files already approved (<digest>)`; `Err(e)` → exit 1, `zygo: cannot store the approval: <e>; nothing approved`, `e` in its `Display` form (the outer context only, so a TOML error does not quote the file). With `--yes` and an `Err`, the listing is not printed (the result is the error). R§11 rows.
9. **The listing (step 6),** lines in this order (`<…>` through `esc` unless said):
   ```
   folder: <top of the current checkout>
   ref: <full ref>
   commit: <read commit>
   digest: <digest, 64 hex>
   .zygo/workspace.toml (<n> bytes):          # when present; then each line of listing(bytes) after 4 spaces
   .zygo/profiles/<name>.toml (<n> bytes):    # each profile, byte order of name; then its lines after 4 spaces
   ignored: <entry>, <entry>                   # each through shown(); `ignored: none` when empty
   summary:
     agents: <n>                                # panes of repository_loadout(def); 0 when it is None
     member <name>: kind <kind>, job <job>, profile <profile or ->, pool <true|false>, cwd <"cwd" or ->
     profile <name>: overrides <role> = "<model>", <role> = "<model>"; disabled <role>, <role>   # `overrides -`, `disabled -` when empty
     <name>, <name> run in passthrough on pool <dir>; profile <p> of <name> does not apply in passthrough
     pool <dir>: passthrough is local mode only, and [server] url is set; zygo up starts nothing   # in place of the line above when `[server] url` is set
   ```
   In the summary, `"<…>"` is free text of the files (each override's model, the `cwd`): `esc`, then `\` as `\\` and `"` as `\"`, in double quotes, so a `,` `;` `=` or space in it cannot fake the structure of the line (WD-15 review F2). Names the shape restricts to `[a-z0-9-]` (member, profile and role names) and the fixed `kind` and `job` values stay bare.
   The passthrough line only when `[workspace] pool` is set and at least one pane is a pool member by the rule of `zygo up` (`up::pool_member`: `pool = true`, `kind = "claude-code"`, no server with user info), and `zygo up` does not refuse the pool; when it does (`up::pool_refused`: `[server] url` is set), the `pool <dir>: <reason>; zygo up starts nothing` line with the reason text of `zygo up` takes its place (WD-15 review F6). The passthrough line: names in `pool::order` order; one `; profile …` clause per such pane with a profile, in the same order (the text of the `up` line, `up.rs:850-855`, without `zygo: `). `<dir>` is `pool::expand(text, pool::home().as_deref())` shown with `esc(&dir.to_string_lossy())`, or, when it fails, `<text, esc> (<reason, esc>)`. Without `--yes`: the listing, `\n`, then `approve these workspace files? [y/N] ` on `prompt`, flushed; one line read by `plugins::confirm`. With `--yes`: the listing is the first part of the result, joined to the step 7 lines with `\n`.

11. **Capability:** `judgment` stays: the approval is the R-C2 boundary, and the escaping is review focus 36.

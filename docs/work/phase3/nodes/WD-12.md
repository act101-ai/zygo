**Decisions (author's call where the spec is silent):**
- D1 A `job`/`pool` violation in a user loadout exits 1 before any write: `zygo: <path>: <message>; nothing started` (`<path>: <message>` is `Violation`'s `Display`, `check.rs:30-34`, through `esc`). A refusal, not a silent drop, as for the pool.
- D2 Check order in the pool step: expand → `[server] url` → `list`. `<dir>` is `esc` of the expanded path; when `expand` fails it is `esc` of the configured text.
- D3 Pool members: panes with `pool = true`, `kind = claude-code` and a member record (not AU98, `up.rs:703`). An unnamed pool member is named `pane <n>` in the line (`n` = 1-based pane ordinal of the plan), as `zygo doctor` does (`crates/zygo/src/cmd/doctor.rs:338-341`). Names and profiles go through `esc`.
- D4 `loadout_plan` makes the line after `choose` and its warnings; it prints on `err` only after the step 8 write succeeds (review F1: a later refusal starts nothing, so it prints no pool line). A restore prints none.
- D5 An assigned directory whose path is not UTF-8 exits 1 with reason `a directory name is not UTF-8` (`PlanPane.config_dir` is a `String`). No test: APFS refuses such names.
- D6 `[server] url` only (R§9.5 text). A pane-level `server` on a pool member is not refused here; the proxy already refuses passthrough off local mode (`crates/zygo-proxy/src/routes.rs:129`).

The launcher has no passthrough line: `launcher.rs:329-347` resolves and applies a profile with no passthrough branch and prints only `profile <n> not found`, a validation error or an apply error; the `PT_*` texts (`claude_code.rs:17-21`) are refusals for other conflicts.

# FX-25 — `zygo up` reads the definition at the current checkout; `find_checkout` keeps a git failure

**Spec:** `docs/specs/2026-11-24-workspace-definition-design.md` R§6.1 step 1 (the read and the workspace id come from the checkout), R§7.3 (each use does its own read, and applies what it checked), R§10 row `zygo up` (a loadout plan, "a `repository` plan is made after step 3, when the checkout is known"); `docs/specs/2026-11-20-workspaces-design.md` W§8.1 step 3 (find the workspace from the cwd with `zygo_work::repo::checkout` and the main worktree; "Not a repository: exit 2 (AU25)"), AU25, AU77. - f5 `zygo up` reads the definition at `t.main_root`: `crates/zygo-workspace/src/up.rs:918` `check_default(&t.main_root, …)` in `choose`. `t.main_root` is the first non-bare entry of `git worktree list` (`crates/zygo-workspace/src/identity.rs:100` `main_worktree`), which can be a first worktree whose folder was deleted. The launcher (`crates/zygo-launch/src/launcher.rs`, `zygo_work::repo::checkout`) and `zygo workspace approve` (WD-15 review F3, `crates/zygo/src/cmd/workspace_approve.rs`, `check_default(&co.top, …)`) read at the top of the current checkout, so approve can store a digest that `zygo up` does not find, or the reverse.
- f6 `find_checkout` maps every error of `worktrees` to `NOT_A_REPO` (exit 2): `crates/zygo-workspace/src/up.rs:366` (the bare-folder probe) and `:374` (the checkout's list).

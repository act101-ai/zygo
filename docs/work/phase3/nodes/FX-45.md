# FX-45 — `stub-hook` test tolerates a closed stdin (BrokenPipe flake)

**Spec:** — (found in CI). CI run 46157648977, job ubuntu-latest (PR #264), failed in `cargo test -p zygo-launch --test opencode`: `stub_hook_parses_agent_and_event_as_zygo_hook` panicked at `crates/zygo-launch/tests/opencode.rs:1380:75` with `called Result::unwrap() on an Err value: Os { code: 32, kind: BrokenPipe, message: "Broken pipe" }`. Line 1380 is `child.stdin.take().unwrap().write_all(payload…).unwrap();` in the helper `stub_hook`. The test (FX-34, PR #259) runs `stub-hook` with a bad `--agent` value; `stub-hook` then writes one `zygo hook:` line and exits without reading stdin (`crates/zygo-launch/tests/stub_hook/stub.rs` `agent_of`, as `zygo hook` `run` in `crates/zygo/src/cmd/hook.rs`). The helper's write races the child's exit; when the child exits first, the write gets EPIPE (Rust ignores SIGPIPE) and the `unwrap` panics. The product is correct, so the fix goes in the test helper. Precedent: FX-3 (`docs/work/phase3/history.md`) made `feed_stdin` (`crates/zygo/tests/common/mod.rs`) accept BrokenPipe in three zygo test helpers.
**Files:** `crates/zygo-launch/tests/opencode.rs`
**Consumes:** —
**Produces:** `feed_stdin(stdin: ChildStdin, bytes: &[u8])` in `crates/zygo-launch/tests/opencode.rs` (a BrokenPipe write is not an error; any other write error fails), used by `stub_hook`; the test `stub_hook_helper_accepts_a_child_that_exits_before_it_reads_stdin`
**Acceptance:** `cargo test -p zygo-launch --test opencode` → all pass.

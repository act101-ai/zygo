### Invariant (verified in `origin/phase-3` `d43971b6`)

- `import::candidates` (`crates/zygo-mail-sync/src/import.rs`) skips each entry whose ULID is in `own_ack` or is in `ids` (already taken this pass, over all own hosts and folders).
- `sync::pass` (`crates/zygo-mail-sync/src/sync.rs`) builds `own_ack` as the union of the `imported` lists of `own_ack(&meta, h, &identity)` for every `h` of `own_hosts`, and passes it to `import::run`.
- So an identity delivers each ULID at most once. An entry in any own host's folder whose ULID that identity acknowledged in any own host can never be delivered, whatever its sender, folder name or kind. The ack is keyed by ULID by design.

### The rules (author's call)

- **R1 ack content** (`sync::own_changes`, each own host `h`): `new_h = (old_h ∪ acked_this_pass ∪ own_ack_union) ∩ ulids_in(h's folders)`. `acked_this_pass` is `imp.acked` (any own host); `own_ack_union` is the `own_ack` set `pass` already built. A non-member entry with an acknowledged ULID is included on purpose: it can never be delivered. This also covers a duplicate that arrives in the old folder after its ULID was acked in the new host.
- **R2 old ack delete** (`h != host`): push `Change::Remove { path: "ack/<h>.json" }` when (a) no ULID entry of `h`'s folders is a message file (`prune::removable`), (b) every ULID of `h`'s folders is in `new_h` (that is, `new_h == ulids_in(h)`), and (c) `!reg_stays` (h's registry does not stay). With no entry at all, (a) and (b) hold, which is the old rule.
- **R3 prune**: no change of behaviour. `prune::run` removes each entry for which `removable(&e) && listed`. No member check, no new registry read.
- **R4 `--drop-host` count** (`ops::waiting`): only entries with `prune::removable(&e)` whose ULID the host's valid ack does not list (a missing or invalid ack lists none). Links, gitlinks and trees are not messages.
- Not defects (spec change log, same reason): a non-member file that shares an acked ULID is pruned without delivery; a ULID acked in another folder lets the ack list it; a non-member link that shares an acked ULID lets the old ack go (a link is not a message).

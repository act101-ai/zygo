# FX-27 — Acked link or gitlink entry keeps the old host's ack forever

**Spec:** `docs/specs/2026-11-24-mail-sync-design.md` S§7.6 "Rename" ("When the tip has no `*@<old>/` file and the pass deletes the old registry in the same commit, or the tip has no old registry of this identity, the pass deletes `ack/<old>.json`"), S§7.4 "Owner" (the ack holds only messages that are still on the branch), S§7.5 "Own hosts" (an old host stays an own host while its ack holds this identity), S§9 "Tree" ("Nothing else is removed"), S§13 limit 2 (what stays on the branch, and the operator's `--drop-host`). Found by MS-22 (`docs/work/phase3/nodes/MS-22.md`, "Found issues"; implementer's note to step 6). Evidence, read at the MS-22 close (`origin/phase-3` `14cd1ed2` merged):
- e1 the prune removes only regular-file blobs: `crates/zygo-mail-sync/src/prune.rs:75` (`e.kind == "blob" && matches!(e.mode.as_str(), "100644" | "100755") && listed`); MS-14 review F6, test `t16_an_acknowledged_symlink_entry_stays` (`crates/zygo-mail-sync/tests/prune.rs:538-551`): an acknowledged mode `120000` entry stays at the tip.
- e2 `own_files` (`crates/zygo-mail-sync/src/sync.rs:802-823`) counts every entry under `*@<h>/` whose name is a ULID file, of any mode, so a link (`120000`) or a gitlink (`160000`) is a file of that host.
- e3 `own_changes` deletes the ack of an old own host only when no file of that host is at the tip (`crates/zygo-mail-sync/src/sync.rs:866-871`, `at.is_empty()`).
- e4 so, after S§19 #12 entries in a renamed host's old folder (`<name>@<old>/<ULID>.json` with mode `120000` or `160000`, imported as refused and acknowledged), no prune removes them (e1), the old ack is never deleted (e2, e3), and the old host stays an own host (S§7.5) and its name stays on the branch and in `state.json` `pushed` and `pending` with no limit.

### The rule (author's call)

Option (a), with one guard. A `*@<old>/<ULID>.json` entry that no prune removes (S§9 "Tree": not a blob of mode `100644`/`100755`) does not keep `ack/<old>.json` when its ULID is in the old ack after this pass's import. The ack goes when every such entry is of that kind and listed, and S§7.6's registry condition holds. The entry stays (MS-14 review F6).

- Why (a): it is the least to reverse. It changes one condition in `own_changes`, keeps the ack's content rule (`new = (old ∪ acked) ∩ all`) and the prune unchanged, and keeps S§9 "Nothing else is removed" and S§7.4 "the only input that lets a prune remove a message".
- Why not (b): a prune that removes an entry "once its ack is gone" removes it with no ack. That breaks S§7.4 and S-C8. A prune that removes acknowledged non-regular entries reverses MS-14 F6 and D5 (a tree path cannot be removed that way). And a prune runs only when due (S§9 "When"), so the ack would stay up to 1000 commits.
- Guard "listed in the old ack": an entry that no pass acknowledged (a folder of a name this workspace does not have) still keeps the ack, as a message file does (S§13 limit 2). The test of step 6 `renamed_host_ack_stays_while_an_entry_is_not_acknowledged` holds it.
- Why the ack content keeps every entry: if `own_files` dropped non-regular entries from the ack's set, each pass would take their ULIDs out of the ack and the import would put them back (`import.rs:300-309`, the ULID is in the imported log): one commit per pass for ever.
- Twin and keys (S§7.5): the pass that deletes the ack records `pending` from the commit's own blobs (`sync.rs:482`), which no longer hold `ack/<old>.json`. At the end of the pass, `forget_old_hosts` on that commit removes `registry/<old>.json` and `ack/<old>.json` from `pushed`, as `<old>` is not an own host and no file of this identity is at those paths. No key is kept for ever. The twin check (`identity::twin`) reads only files at the tip, so a deleted file gives no twin stop. Steps 6 and 9 assert both.
- Existing condition, not changed here: the zygo-mail-sync test harness sets the process HOME, XDG_CONFIG_HOME and GIT_SSH_COMMAND once for the crate (tests/common/mod.rs).

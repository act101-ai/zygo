### Author's calls

- **Moved-from value.** `moved_from` holds the workspace id (`^[0-9a-f]{16}$`), the value the scan finds. The contract consumes no workspace-record reader, and the id needs no `workspace.json` read of the old state. The suffix text is the author's: S§7.5 says only that the line "also names that workspace".
- **Log text.** S§18 leaves `errors.log` text to the builder. The lines name the file kind, the check and the blob id, and never the path (which holds a host).
- **Non-`.json` names** under `registry/` or `ack/` are not registry or ack files: not read and not logged. A `.json` entry that is a tree, a link or a submodule is `Check("mode")` and is never read by `cat`.
- **Twin with no record.** An own file with this identity and no recorded id is a twin (S§7.5: "neither of those two"). Lost `state.json` with the identity kept gives a twin stop; `--new-identity` (MS-15) is the remedy.
- **Order.** Collision before twin; registry before ack. Both registry and ack of every own host count for the twin.
- **No entry cap.** The spec sets no limit on the number of registry or ack files, so `read_meta` adds none.
- **S§7.5 "Limit" and S-C8.** The twin is found only from blob ids at the tip, so it is found only at the first pass after the other copy writes (S§13 limit 5); no step adds a clock or any other signal. No check reads a time or config of another host (S-C8). "Imports nothing" and the exit code after a `Stop` belong to MS-13.

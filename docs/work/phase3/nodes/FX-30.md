# FX-30 — A crash-recovered delivery gets no wake and no count

**Spec:** `docs/specs/2026-11-24-mail-sync-design.md` S§8.3 step 5 ("Finish incoming", crash recovery) and step 10 ("Wake the members that got mail in step 9"), S§10.1 (the sync wakes each member that got mail), P3-4 ("Deliver and wake on the receiving machine after a fetch, with the M§7 rules"), S§19 #14 (crash seams after each step of S§8.5 "Delivery": one delivery each time). Found in FX-26 review round 2 (F-1, not caused by FX-26). Evidence, read on branch `phase3/FX-26` at `94b8c7a1`:
- e1 `sync::pass` (`crates/zygo-mail-sync/src/sync.rs`) calls `import::finish_incoming(sp, &c.store).map_err(|_| stop("incoming"))?` and drops the count it returns. `Report.delivered` adds only `imp.delivered.len()` from `import::run`, and the step 10 `wake(c, imp.read.as_ref(), &keys)` takes its keys only from `imp.delivered`. `import::finish_incoming` returns a count, not the keys that it delivered to.
- e2 after a crash at `after_incoming` or `after_log` (`import::run`), the staged file `<key>.<ULID>.json` is in `incoming/`. Step 5 of the next pass (`import::finish_incoming`) moves it into `mail/<key>/new/`, and nothing wakes `<key>` or counts the message.
- e3 after a crash at `after_new` or `after_ack`, the message is in `new/` and its ULID is in the imported log. The next pass's `import::run` finds the ULID in `seen` and only acknowledges it (`out.acked`, not `out.delivered`). The crashed run stopped at its seam before step 10, so no run wakes the member for that message.
- e4 the FX-26 reviewer's probe (`/home/kagemartin/.cache/fx26-review2/probe.rs`, test `probe_crash_recovery_delivery_gets_no_wake` in a copy of `crates/zygo/tests/mail_sync_no_content.rs`; run again for this node with `/home/kagemartin/.cache/fx26-review2/run.sh probe_crash_recovery_delivery_gets_no_wake -- --nocapture`, 1 passed): B's member is idle with a live launcher (`StubWake { idle: true }`). The control delivery (no crash) gives `delivered = 1` and `typed = [("%3", "zygo: you have mail; read it with mail_read")]`. After a crash at each point, the next `run_with` of B gives:
  - `after_incoming`: `report.delivered = 0`, in `new/`, `typed = []`;
  - `after_log`: `report.delivered = 0`, in `new/`, `typed = []`;
  - `after_new`: `report.delivered = 0`, in `new/`, `typed = []`;
  - `after_ack`: `report.delivered = 0`, in `new/`, `typed = []`.
  Each message is in `new/` once, so S§19 #14 holds, but the idle member is never woken for it and the CLI prints `0 delivered`.

**Files:** `crates/zygo-mail-sync/src/sync.rs`, `crates/zygo-mail-sync/src/import.rs`, `crates/zygo-mail-sync/src/state.rs` (only when the planner records the pending wake in the sync state), `crates/zygo-mail-sync/tests/import.rs`, `crates/zygo-mail-sync/tests/sync_pass.rs`, `crates/zygo-mail-sync/tests/crash_recovery_wake.rs`, `docs/specs/2026-11-24-mail-sync-design.md`
**Consumes:** `zygo_mail_sync::sync::run_with` (MS-14), `zygo_mail_sync::import::finish_incoming` (MS-12; FX-24 changed its second argument to `&Store`), `zygo_mail_sync::import::run` (MS-12; FX-24, FX-27)
**Produces:** the S§8.3 step 10 and S§10.1 rule by which every message that a pass or a crash recovery puts into a member's `new/` is counted in `Report.delivered` and wakes its member.
**Contract:** every message that a pass or a crash recovery puts into a member's `new/` is counted in that pass's `Report.delivered`, and its member is woken under the S§10.1 rules (idle by AU26, launcher live by AU74, the M§7.3 steps and `wake_gap`; a busy member is not woken and reads at its `Stop`). This includes the `after_new` and `after_ack` cases (e3), where the message reached `new/` in a run that never woke and the next pass only acknowledges it. How a pass finds those is the planner's call within this contract, recorded as the author's call: for example, record the pending wake in the sync state before the delivery step and clear it at step 10, or wake every member with unread mail after a recovery. `import::finish_incoming` gives the keys it delivered to (or the pass reads them another way), so step 5's deliveries join the step 10 wake. A message is counted once: a pass that counts a recovered message does not count it again in a later pass. The plan restates S§8.3 step 10 and S§10.1 as final text, with a change-log line (date, S§8.3 step 10, S§10.1, author's call, "FX-30"). The test fails on the code before the change.
**Acceptance:** `cargo test -p zygo-mail-sync --locked --test crash_recovery_wake` → all pass: for each of the four crash points `after_incoming`, `after_log`, `after_new` and `after_ack` (`import::run`), a `run_with` that the seam stops at that point is followed by a pass that reports `delivered == 1` and wakes the idle member with a live launcher exactly once (the stub wake records one `WAKE_TEXT`), and the pass after that reports `delivered == 0` and wakes no one; the message is in `new/` exactly once.

Author's calls (the spec does not decide them):
- Check names and order, first failure wins: `mode` (mode not `100644` or kind not `blob`), `name`, `size` (above `MESSAGE_MAX`), `json` (not an object, a missing or mistyped field, a duplicate key), `version`, `id`, `to`, `from` (`address::parse` gives `None`), `subject` (bytes above `SUBJECT_MAX`), `body` (bytes above `BODY_MAX`), `sent-at`. Each is a valid `state.json` check name.
- `check_message` parses into a private struct of the seven fields (unknown keys ignored, no `serde_json::Value` tree), and refuses with `json` any input whose first byte after ASCII whitespace is not `{` (serde accepts a struct from an array).
- `MESSAGE_MAX` is defined as `zygo_workspace::mail::store::FILE_MAX`: one 8 MiB limit for the reader and the importer.
- The log line of a refused candidate is `mail sync: import <ULID>: <check>`; of a failed `ls-tree` it is `mail sync: import: ls-tree`; of a failed blob read or local write it is `mail sync: import <ULID>: read` or `: write`. No path, name, host or content (S-C2).
- An entry whose name gives no ULID (`ulid_file` is `None`), or whose path is not `<folder>/<name>` with no further `/`, is not a candidate: it is skipped with no log line, no ack and no count. It has no ULID to log or acknowledge. A tree entry with a ULID name is a candidate and fails `mode`.
- A full inbox is checked with `unread` after the other checks and before step 1, so a refused message is still acked, and a full inbox leaves the message neither logged nor acked. It writes no log line (the spec gives the line only to the other checks).
- `delivered` holds `(pane key, ULID)`: the pane key is what the S§10.1 wake needs. `acked` holds each ULID once, in the order of the reading: delivered, refused and already-logged candidates.
- `left` is the count of candidates this pass saw and did not finish (full inbox, failed read, failed write), plus 1 when the reading stopped early (the 501st candidate, the deadline, an `ls-tree` error). Thus `left == 0` means no seen mail waits. The 501st candidate stops `ls` with `Flow::Stop`.
- A failed blob read (`cat` error other than the size refusal) or a failed local write leaves the candidate on the branch, not acked, for the next pass. A full `new/` at step 3 (a race after the check) leaves the staged file in `incoming/` for `finish_incoming`; the ULID is in the log, so the next pass acks it.
- `finish_incoming` passes `u32::MAX` as `max_unread` to `deliver_staged`: S§8.5 step 5 finishes a delivery whose inbox check already passed. It returns the count of files moved into `new/` (`Ok(true)`). A file whose name is not `<pane key>.<ULID>.json` is left alone; a file whose finish fails stays for the next pass, and the other files go on. `Err` only when `incoming/` or the imported log cannot be read.
- A target whose `pane_key` fails `valid_pane_key`, or whose folder `<name>@<host>` fails `address::parse` (this also checks each own host), is skipped before any git call.
- `incoming/` is made only at the first delivery, with `ensure_mail_root` on `sp.mail`, `sp.sync` and `sp.incoming` in that order (each `0700`, a link refused).

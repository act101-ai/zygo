### Decisions (author's call; text only, no rule)

- D1. Bare `zygo mail` is `zygo mail ls`. This makes the embedded fallback `zygo mail $ARGUMENTS` (`crates/zygo-plugins/src/embedded.rs:38-40`) work for `/zygo:mail`, and it gives the `slash_parity` row the same reply in both forms.
- D2. `/zygo:mail` args are `[ls [<name>]]`. Any other args give `UsageError("usage: /zygo:mail [ls [<name>]]")` (exit 2), and nothing is read. So the slash takes no send or read text (M§8, O14).
- D3. `--name` (read) and `<name>` (ls) resolve through `names::resolve(&ws, n, None)`, so a name, a pane key and `all` all work. Targets are taken in key order. `read` takes at most `max` messages in total over the targets.
- D4. Output, with each outside value through `zygo_core::esc` (S§10.5 rule, M-C2: text is printed, never logged):
  - send: one line `sent <id> to <label>` per `Sent` (`<label>` is the member's valid name, else its key).
  - read: per message, `<id> <from> <sent_at> <subject>`, then each body line as `  <line>` (two spaces). With none: `no new messages`.
  - ls: per member in key order, `<key> <name or -> <unread>` (`-` for an unread error, as `admin.rs:426-430`), or `no members`. `ls <name>`: per message `<id> <from> <subject>` (the line of ML-13 watch), or `no new messages`.
- D5. Body source: `--file <path>` reads at most `BODY_MAX + 1` bytes. More than `BODY_MAX` bytes gives `MailError::BodyTooLarge` before any write. A read error gives `zygo mail send: cannot read <esc path>: <esc error>`. Bytes that are not UTF-8 give `zygo mail send: the body is not UTF-8`. Both exit 1. `-` reads stdin the same way.
- D6. ML-1 review note 6 (checked arithmetic): ML-12 adds no arithmetic on `keep`. `parse_duration` uses `checked_mul` (`schema.rs:731`), and `store::sweep` only compares durations (`store.rs:300`).
- D7. The CLI wakes after a send (M§7.3: "After a send, the sender's process wakes…"), through `after_send` with `super::tmux_program()`. The end-to-end wake is tested in ML-18, which consumes `run` (ML-12).

Facts this plan rests on (checked at `643422cb`):
- `result_view` (`crates/zygo-mcp/src/tools/results.rs:93-112`) replies `Stored::range(first, last)`: lines `first..=last` of the stored text joined with `\n`, no final newline (`crates/zygo-results/src/store.rs:111-125`); at most 400 lines (`store.rs:104`). The MCP server wraps it as `{"content": [{"type": "text", "text": …}], "isError": …}` (`crates/zygo-mcp/src/server.rs:132`).
- The stored text is the raw tool output that the trim hook stores (`crates/zygo-hooks/src/trim.rs:235`) when it is over `results.trim_threshold_bytes` = 16384 (`zygo config show`). `seq -f 'po4-line-%03g' 1 2000` prints 2000 lines, 27001 bytes (macOS `seq`); its lines 1-400 joined are byte-equal to the judge's `view(1, 400)`. Expected reply sizes: lines 1-400 = 5199 bytes, lines 1-40 = 519 bytes.
- Tool names: Claude Code `mcp__zygo__result_view`; OpenCode `zygo_result_view` (zygo registers its MCP server as `zygo`, `crates/zygo-launch/src/opencode.rs:151`).
- `zygo claude --passthrough --yolo -- <args>`: Claude Code with its own stored login (`zygo claude --help`; `--yolo` adds `--dangerously-skip-permissions`, `crates/zygo-launch/src/claude_code.rs:630-631`); a profile does not apply in passthrough (`crates/zygo-launch/src/launcher.rs:341-342`). `claude -p … --output-format stream-json --verbose` prints one JSON event per line; a `user` event holds the `tool_result` block of each call.
- `zygo opencode --profile glm --yolo -- run -m zygo/lead --format json <prompt>`: `--yolo` puts `--auto` after `run` (`opencode.rs:506-514`); profile `glm` maps `lead` to `glm-5.3` (`zygo profile show glm`), on Z.AI (`model."glm-5.3".provider.zai.base_url`). `--format json` prints a `tool_use` event `{part}` for each finished tool part (OpenCode 1.18.16 `run`); `part.tool`, `part.callID`, `part.state.input`, `part.state.output`, `part.state.status`.
- Key: the user config `~/.config/zygo/config.toml` names the Z.AI key `"keychain:zai"` (2 lines). A run copy with `"env:ZAI_API_KEY"` instead, selected by `ZYGO_CONFIG` (`crates/zygo-core/src/paths.rs:31`), gives `zygo config check` → `config ok` and `zygo keys list` → `env:ZAI_API_KEY <unset>`; profile `glm` is in that file (`[profile.glm]`). zygo removes `ZAI_API_KEY` from the agent's environment (`crates/zygo-launch/src/env.rs:57-76`).
- Judge: the Python block of `po4_judge` (`live-shaping.sh:379-402`, 22 lines between `<<'PY'` and `PY`) reads a seen list `[{tool_use_id, request_file, is_error, tool_result_seen_by_model, text}]` (the shape of `seen_json`, `:66-104`) for lines 1-400 then 1-40, and writes per call `lines, reply_bytes, seen_bytes, reply_found, prefix, suffix, wrapper_bytes` plus the seen fields. The verdict jq (`:406-409`) prints `pass` when both replies are found and both wrappers have the same size, else `fail`, then `lines 1-400: reply <n> bytes, seen <n> bytes, reply found <yes|no>, wrapper <n> bytes; lines 1-40: …`.
- Scrub: `python3 -I scripts/premises/scrub.py <run dir> <file>` writes the scrubbed file to stdout (`scripts/premises/scrub.py:40`, `scripts/premises/lib.sh:123-125`). `scripts/check-premises.sh` has no PO ids in `IDS`/`WIDS` (`:13`, `:15`) and scans `fixtures/`.
- Row model: the PO3 row, last line of `docs/premises.md`; columns `| Id | Item | Agent | Version | Date | Result | Evidence |`; a two-agent row writes `Claude Code + OpenCode` and `<cc> + <oc>` (PM2, PM3 rows). Minimums `Claude Code: 2.1.328`, `OpenCode: 1.18.16` (`docs/premises.md:5-6`); `ver_ge` in `scripts/premises/ver.sh:5`.
- Spec record (OS-24, OS-25 R3): the O§17 item gets `Result (<version>): <result>; see the <id> row.` and `## Change log` one line. PO4 is at `docs/specs/2026-11-24-output-shaping-design.md:579`. So Part B also changes the spec, as OS-24 did (its Files list the spec).
- Consumers: O§6.4 (`spec:119-128`) counts a read-back's size as the reply's byte count; PO4 makes that count the size the model sees, within the wrapper.

# FX-36 — `zygo mail read --name all` reads every member's mail

**Spec:** `docs/specs/2026-11-22-workspace-mail-design.md` M§8, M§6 (found in the Phase 3 final verification stage, 2026-11-28, head b628e1ad). **M-F4.** The `Read` arm of `crates/zygo/src/cmd/mail.rs:148-169` resolves `--name <n>` with `names::resolve(&ws, &m, None)` (`:150`) and reads every target it gives, so `all` resolves to every member (`crates/zygo-workspace/src/mail/names.rs:29-40`) and a name that two members hold reads both. The test `read_over_members_prints_what_it_has_when_a_later_member_fails` (`crates/zygo/tests/mail_cli.rs:271-287`, `:280` runs `mail read --name all`) asserts it (ML-12 D3, an author's call). M§8: "`zygo mail read [--name <n>]` … `<n>` is a member of this machine"; M§6 reserves `all`. `zygo mail watch all` is already refused (`mail.rs:177-180`: "zygo mail watch: <n> is not one member", exit 2; tests `mail_cli.rs:450-452`, `:540-542`); `read` must refuse `all` the same way. No other test reads `all` (`crates/zygo/tests/workspace_mail.rs:256-257` sends to `all`; `:278` reads `bob`).
**Files:** `crates/zygo/src/cmd/mail.rs`, `crates/zygo/tests/mail_cli.rs`
**Consumes:** —
**Interfaces (as they exist now, confirmed at b628e1ad; existing code, not produced by a node this one depends on):** `zygo_workspace::mail::names::resolve(ws: &Workspace, to: &str, sender_key: Option<&str>) -> Result<Vec<Target>, MailError>`; `zygo::cmd::mail::run(a: MailArgs) -> i32`
**Produces:** `zygo mail read --name <n>` reads one member only: a `<n>` that resolves to other than one member (`all`, a name two members hold) is refused as `zygo mail watch` refuses it: exit 2, stderr `zygo mail read: <n> is not one member`, nothing read or moved
**Acceptance:** `cargo test -p zygo --locked --test mail_cli read_refuses_a_name_that_is_not_one_member` → 1 passed, failing first: with unread mail for `elena` and `bob`, `zygo mail read --name all` exits 2, stderr is exactly `zygo mail read: all is not one member\n`, stdout is empty and both unread counts are unchanged; the same for a name that two members hold (`twin`, stderr `zygo mail read: twin is not one member\n`); then `cargo test -p zygo --locked --test mail_cli` and `cargo test -p zygo --locked --test workspace_mail` → all pass, with `read_over_members_prints_what_it_has_when_a_later_member_fails` replaced by a one-member read whose maildir cannot be read (exit 1, the member named).

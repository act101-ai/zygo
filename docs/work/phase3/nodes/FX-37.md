# FX-37 — Session-folder file safety in pre-compact and overrides

**Spec:** `docs/specs/2026-11-24-session-text-design.md` T§9.2 item 1, T§14 item 2, T-C1, T-C6 and the state-modes constraint (found in the Phase 3 final verification stage, 2026-11-28, head b628e1ad). **SX-F1.** `crates/zygo-hooks/src/pre_compact.rs:48-67` `create_flag`: no link check on `reinject/` (`set_permissions(0700)` at `:58` follows a link to another folder); the flag is opened without `O_NOFOLLOW` or `O_NONBLOCK` (`:59-63`), so a link to a file gets chmod 0600 (`:65`) and a FIFO blocks the hook (`timeout 5 zygo hook pre-compact` → 124). Callers: `crates/zygo-hooks/src/session_start.rs:70`, `crates/zygo-hooks/src/trim.rs:281`. FIX-22 made `SessionView::load` refuse a FIFO (`crates/zygo-core/src/session_view.rs:192-229`: `O_NONBLOCK` open, `<path>: is a FIFO`, no size cap). **SX-F3.** `pre_compact.rs:34` `let out = run_in(dir)?;` returns `Err` before the flag is made when the work folder cannot be read (`open_units`, `:70-75`); T§9.2 item 1 does not make the flag depend on the units read; T§14 item 2.

## Plan

Premises checked against the live code at 6fa80a3c:
- `crates/zygo-hooks/src/pre_compact.rs:34` `let out = run_in(dir)?;` returns before the flag; `create_flag` (`:48-67`) calls `set_permissions(0700)` on `reinject/` with no link check and opens the flag with no `O_NOFOLLOW`/`O_NONBLOCK`.
- `crates/zygo-hooks/src/session_start.rs:146` `folder_state` (private) is the link-refusing folder check of `store_item`; `read_item` (`:158`) is a reader, so it does not fit the flag (a writer); its open flags are reused.
- `crates/zygo-core/src/overrides.rs:28` `Overrides::load` is `std::fs::read`. The reader of the same file in the setting verbs, `zygo_hooks::workspace::read_session_file` (`crates/zygo-hooks/src/workspace.rs:104`), opens with `O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC`, uses only a regular file and has no size cap. `zygo-core` cannot depend on `zygo-hooks`, so `load` gets the same rule in `zygo-core`.
- `libc` is a unix dependency of both crates.

Decisions (author):
- D1. `Overrides::load` follows the rule of `read_session_file`: a link is not followed (the verbs already refuse a link at `overrides.json`), a FIFO does not make the read wait, only a regular file is read; any other entry or an open or read error gives the default. No size cap, as FIX-22 and `read_session_file`.
- D2. `run_with` makes the flag whatever `run_in` gives. When `run_in` fails, its error goes to the C6 wrapper as now (no text); when the flag also fails, the two are one error, so C6 still writes one line: `<run_in error>; pre-compact: cannot create <flag>: <reason>`.
- D3. `create_flag`: after the `reinject/` create, `session_start::folder_state` must give `Usable` (made `pub(crate)`, with `Folder`); else the error `<reinject>: is a link or not a folder`. The flag is opened with `O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC` on unix (a link gives `ELOOP`, a FIFO with no reader gives `ENXIO`); an opened handle that is not a regular file is the error `<flag>: is not a regular file`, and its mode is not set.

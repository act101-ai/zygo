# OS-22 — Premise script for PO1 to PO4

**Spec:** `docs/specs/2026-11-24-output-shaping-design.md` O§17 (PO1-PO4: what each run does and records), O-C7; `docs/premises.md` "Method" (harness `scripts/premises/`, isolation, mock upstream, scrub)
**Files:** `scripts/premises/live-shaping.sh`
**Consumes:** `capture-shaping.sh` (OS-16)
**Produces:** `live-shaping.sh po1|po2|po3|po4` (runs one experiment with `scripts/premises/lib.sh` isolation and the mock upstream, saves the hook input and the next request body, scrubs them with `scripts/premises/scrub.py`, prints the paths it wrote)
**Acceptance:** `bash -n scripts/premises/live-shaping.sh && grep -c "lib.sh" scripts/premises/live-shaping.sh` → exit 0, then a count of at least 1; no test or CI step runs the script (O-C7)

## Plan

Drift from the contract (plan follows the live code):
- `capture-shaping.sh` is at `scripts/fixtures/capture-shaping.sh` (OS-16), not under `scripts/premises/`. Its interface is `ZYGO_CAPTURE_TOOL='<program> <version>' scripts/fixtures/capture-shaping.sh <shaper> <case> -- <command...>`: it runs one command and writes `stdout`, `stderr`, `must_keep` and `meta.json` under `fixtures/shaping/<shaper>/<case>/`. It captures no hook input and no request body, so `live-shaping.sh` does not call it. OS-23 uses it for `fixtures/shaping/failure/*` (its own Files line).
- The evidence paths are fixed by the consumer nodes, not by this node: OS-23 `fixtures/claude-code/hooks/PostToolUseFailure-Bash-output-main.json`; OS-24 `fixtures/claude-code/requests/po2-result.json`; OS-25 `fixtures/opencode/plugin-hooks/tool.execute.after-bash-stderr.json`; OS-26 `fixtures/claude-code/requests/po4-readback.json` and `fixtures/opencode/requests/po4-readback.json`. The script writes those exact paths.
- OS-24 checks for `err-line`, so PO2 uses the PO1 lines `out-line` and `err-line` with exit 0.

Model scripts (read, never run): `scripts/premises/run-Q4.sh` (print-mode Claude Code, `steps.py` rules, `hook_log.py` rewrite rules, tool result of the next request), `scripts/premises/run-opencode.sh` (OpenCode provider config on the mock, `opencode run`), `scripts/premises/live-mail.sh` (header text, `steps` helper, OpenCode plugin written by the script, path guards). Helpers used, all in the live code: `lib.sh` `new_run` (through `live_run`), `start_mock`, `stop_mock`, `check_abort`, `run_claude`, `hook_settings`, `scrub`, `publish_sse`, `DUMMY_KEY`, `TOOL_PATH`, `CLAUDE_BIN`, `OPENCODE_BIN`, `REPO_DIR`, `PREMISES_DIR`; `live.sh` `live_traps`, `pinned_agents`, `live_run`, `live_exec` (with `LIVE_TIMEOUT`, `LIVE_VARS`), `body_has`, `result`, `live_done`; `hook_log.py` rules `event`, `tool`, `times`, `output`, `rewrite`; `mock_upstream.py` records `rec/NNNN.json` with `body`; `scrub.py` `<run dir> <file>`.

The script is never run by a test, a CI step or an agent (O-C7). Only the operator runs it (OS-23 to OS-26). No step below runs it, `claude`, `opencode` or `zygo`.

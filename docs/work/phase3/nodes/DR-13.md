### Author's calls (spec gaps)

1. **Order in `call`** (review focus 16): (a) the size check; (b) `unit`, `round`, `verdict`, `findings` as today; (c) the `head`/`base`/`dispositions` refusals, for every verdict; (d) `discard` or `rework`: `set_verdict` as today, with no level read and no git; (e) `keep`: read `repo_root` from `SessionView::load(&session_dir)` (an error or `None` gives no root), then call `level(root)`; (f) `Monitor`: `set_verdict` as today; (g) else: problems = `vec!["cannot check: no repository root"]` without a root, or `check_keep(&req, &mut *git(root))`; (h) `Enforce` with problems: `Err(ToolError::Failed(format!("zygo: keep refused: {}", format_problems(&p))))`, before `set_verdict`; (i) `set_verdict` (no row: today's `Failed("no folded row for <unit> round <n> in this session yet")`); (j) `Notify` with problems: the reply is `recorded keep for <unit> round <n>\nzygo: dispositions: <format_problems>`. The newline is the author's call: "ends with" in D§9.3 does not name a separator.
2. **256 KiB**: the size is `serde_json::to_vec(&args)` length (compact JSON of the received object). Over `ARGS_MAX` is a refusal; exactly `ARGS_MAX` is accepted.
3. **Lengths** are counted in chars (`chars().count()`), as JSON Schema `minLength`/`maxLength` count code points.
4. **Refusals** (`ToolError::InvalidParams`, a message that names the key): a present `head`/`base` that is not a string matching `^[0-9a-f]{7,64}$`, or is `null`; a present `dispositions` that is not an array, or has more than 256 items; an item that is not an object; a missing `finding`, `class` or `disposition`; a value of the wrong type, or outside its enum, pattern or length; `commit` on an entry that is not `fixed`; `reason` on an entry that is not `rejected`; `record` on an entry that is not `recorded`. An unknown key in an entry is ignored, as an unknown top-level key is today (`work_begin`'s `future_arg` test). The patterns are checked without `regex` (`zygo-mcp` has no `regex` dependency): hex is `0-9a-f`, by hand; a record id is `DDR-` plus 26 chars of `0-9A-HJKMNP-TV-Z`, through `zygo_work::decisions::record::valid_id` (record.rs:113), which is that pattern (changed in implementation: reuse, not a copy).
5. **Entry to `Disposition`**: `class` through `Class::parse`; `fixed` gives `Proof::Fixed { commit }`, `rejected` gives `Proof::Rejected { reason }`, `recorded` gives `Proof::Recorded { record }`, with a missing proof as `""` (DR-12 call 1: `check_keep` reports it).
6. **Level**: `dispositions_level` = `hooks::session_config(paths, Some(sd), root.map(Path::to_path_buf))`, then `guards::policy(&m, sd, root.unwrap_or(&sd.root)).level(Guard::Dispositions)`. A config that does not load gives `Level::Enforce` (the D§9.3 default; a gate does not open on an error, D§9.4). The second value of `session_config` (a team-layer line) is not printed: the reply is the only output (D§9.3). It is read per keep call, so a session override made during the session applies at the next call.
7. **Git** runs in `PathBuf::from(repo_root)` (D§9.4, D§13 item 6). The `git` seam is called at most once per keep call, only at `notify`/`enforce` with a root. Production: `Box::new(|root| Box::new(ProcessGit::new(root)))`.
8. **D-C1**: the tool writes the verdict word only. The finding labels and reasons reach only the reply (problems text) and are never written to the store, a log or the session directory.
9. The `.zygo.toml` layer of the level is `zygo_config::load` with `LoadContext.repo = Some(root)`. It is tested in `zygo-config` (DR-9). The tests here inject the level, or call `dispositions_level` with `root = None`, so no test starts git.

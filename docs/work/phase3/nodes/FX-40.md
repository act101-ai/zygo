### Premises (checked on `phase3/FX-40` at `6fa80a3c`)

- S-F1 holds. `crates/zygo-mail-sync/src/public.rs:124-138` `remote_urls` runs `remote get-url -- <remote>` and `remote get-url --push -- <remote>` (no `--all`) and gives `[fetch]` or `[fetch, push]`. `public::check` (`:146`) hashes each URL for the cache and `fold` (`:180`) probes each distinct `https` form, so a longer URL list needs no change there.
- `git remote get-url --push --all` gives every `pushurl`, or every `url` when the remote has no `pushurl`: the set `git push` sends to. It applies `pushInsteadOf` as `git push` does.
- `branch::classify` (`crates/zygo-mail-sync/src/branch.rs:375-393`) takes the first ref line for the target (`find`). A push to two URLs prints one ref line per URL. With `ok = true` and lines ` ` then `!`, it gives `Pushed::Accepted`; with `ok = false` and the ` ` line first, it gives `Other("push failed")` and the pass stops after a partial push.
- S-F2 holds. `sync::pass` (`crates/zygo-mail-sync/src/sync.rs:449-543`) calls `import::run` in each round (`:486`); `Pushed::Moved` (`:535`) goes back to the fetch. `import::candidates` (`crates/zygo-mail-sync/src/import.rs:204-263`) counts `out.len() == CANDIDATE_CAP` per call. A delivered ULID is in the imported log, so a later round reads it again as `seen` (acknowledged only); a new ULID that sorts before it (an older ULID pushed by the move, or a folder read first) is delivered too, so each round can add deliveries up to its own 500.
- `own_changes` (`sync.rs:1002`) puts `acked ∪ own_ack` into each own host's ack, filtered by the ULIDs at the tip (`:1032`), so an ack carried from an earlier round never names a file that the new tip does not hold.
- `import::run` callers: `sync.rs:486` and `crates/zygo-mail-sync/tests/import.rs:213, 432, 438, 519`.

### Decisions (author's call)

- The S§8.5 count is the set of ULIDs that the pass took as candidates, kept across the rounds of the push loop. A ULID taken in an earlier round is not a candidate again (S§8.5 "the pass has not taken that ULID already"); a new ULID is read only while the set holds fewer than 500. The acks of every round of the pass go into each later round's commit, so no delivery of an earlier round loses its ack when a later round does not read it again.
- A push to several URLs: the result is `Accepted` only when git exits 0 and every ref line of the target ref has an accept flag; any ref line that is neither an accept nor a moved rejection gives `Other`; else any moved rejection gives `Moved` (S§8.3 step 15: the next attempt fetches again).

# FX-40 — Mail sync: every push URL checked, one candidate cap per pass

**Spec:** `docs/specs/2026-11-24-mail-sync-design.md` S§8.2 (step 1 and the operator rule), S§8.3 step 15, S§8.5, S§19 #13 (found in the Phase 3 final verification stage, 2026-11-28, head b628e1ad). **S-F1.** `crates/zygo-mail-sync/src/public.rs:124-138` `remote_urls` runs `git remote get-url --push -- <remote>` (`:135`) without `--all`, so it sees only the first push URL; `git push` sends to every push URL. Verified on git 2.56.1: a second push URL (a public mirror) received `refs/heads/zygo/mail`. S§8.2: "(operator) zygo refuses sync on a remote that it can see is public"; step 1: "Check each distinct URL". Also `branch::classify` (`crates/zygo-mail-sync/src/branch.rs:375-393`) takes the first matching porcelain ref line (`:378-381`); with two push URLs, one accepting and one rejecting, the pass stops after a partial push. **S-F2.** `crates/zygo-mail-sync/src/sync.rs`: the attempt loop calls `import::run` again (`:486`) after each `Pushed::Moved` (`:535-540`, `MAX_ATTEMPTS` = 5 at `:31`); `CANDIDATE_CAP` (500, `crates/zygo-mail-sync/src/import.rs:22`) is counted per call (`candidates`, `import.rs:232`). S§8.5: "Reading stops at 500 candidates in the pass"; S§19 #13. One pass can deliver up to 5 × 500.

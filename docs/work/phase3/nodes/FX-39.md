# FX-39 — Workspace definition: withdrawal check, pane folder id, listing cap

**Spec:** `docs/specs/2026-11-24-workspace-definition-design.md` R-C2, R-G1, R§6.1 step 4, R§6.2, R§7.4, R§10 (row `up`), review focus 30 (found in the Phase 3 final verification stage, 2026-11-28, head b628e1ad). **R-F1 (security).** `crates/zygo-launch/src/launcher.rs:350-357`: the R§7.4 withdrawal check runs only when `common_dir` is `Some`; it comes from `launch_checkout` (`launcher.rs:895-902`) → `zygo_work::repo::checkout` = `find_checkout(cwd, deadline).ok().flatten()` (`crates/zygo-work/src/repo.rs:492-494`), which gives `None` for a folder that git does not see as a work tree and for a git error or timeout. `crates/zygo-config/src/repo_def/shape.rs:158-194` `cwd_rule` accepts `.git`. An approved file with `cwd = ".git"` and no profile: after the user withdraws the approval, a restore or `ws run` in `<root>/.git` skips the check and starts the agent from the withdrawn definition. A git timeout in a normal checkout does the same. R-C2; R§7.4 (FX-31 bullet; its only exception is "a launch folder that is not in a git checkout"). **R-F2.** `launcher.rs:350-351` and `pinned_profile` (`:970-981`): the workspace id is computed from the pane folder's own checkout (`workspace_id(cd)`); a member whose `cwd` is a submodule or a nested repository gets another id, so every launch exits 1 with the "no longer approves" line though nothing was withdrawn. R§6.2, R§10 row `up`, R-G1. `zygo_workspace::loadout::pane_cwd` (`crates/zygo-workspace/src/loadout.rs:131-146`) does not check the repository. Author's hint: the pin can carry the approved workspace id so the check does not depend on the pane folder's checkout; the planner decides. **R-F3.** `crates/zygo-config/src/repo_file.rs:196-199` `git_out_with` reads all of stdout with no cap (stderr is capped at 64 KiB, `:203`); `crates/zygo-config/src/repo_def/read.rs:239-261` keeps every listed entry and every ignored name, and `list` (`:318`) keeps every `ls-tree` entry. R§6.1 step 4, review focus 30. Cap the listing and refuse the definition past the cap; state the cap in R§6.1 as final text with a change-log line.

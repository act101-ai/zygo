### The rule (lead's decision, ECMA-35 nF form `ESC I..I F`)

In `esc_len`, after the lone-`ESC`, CSI and OSC arms and before `Some(_)`: when the byte after `ESC` is an intermediate byte `0x20-0x2F`, count the run of intermediate bytes `0x20-0x2F` that starts at `i + 1`.

- When the run is 1 to `NF_MAX_INTERMEDIATES` (4) bytes long and the byte after it is a final byte `0x30-0x7E`: remove `ESC`, the run and the final byte (run + 2 bytes).
- Otherwise (the byte after the run is a line end, `ESC`, the first byte of `U+009B`, any other non-ASCII byte, `0x7F`, a control byte below `0x20`, or the text end; or the run is longer than 4): remove only `ESC` (1 byte); the run and what follows stay as text (O-C9). A following `ESC` or `U+009B` then starts its own sequence.

Bound 4: the longest ECMA-35 designation has 3 intermediates (a multi-byte dynamically redefinable set, `ESC $ ( SP F`); 4 keeps one spare. A longer run of `0x20-0x2F` bytes (spaces, punctuation) is more likely text than an escape, and an unbounded run would remove it with the next letter. All cut bytes are ASCII, so a cut ends on a UTF-8 boundary, and no cut takes `\n` or `\r` (neither is in `0x20-0x7E`). This arm replaces the FX-16 `Some(b'(' | b')')` arm (`(` 0x28 and `)` 0x29 are intermediate bytes). `ESC ESC`, `ESC [`, `ESC ]` and the `Some(_)` arm (other forms such as `ESC 7`, `ESC M`, `ESC c`) are unchanged.

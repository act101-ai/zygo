# RS-14 — Untranslated passthrough: the provider key never reaches the client

**Spec:** docs/specs/2026-11-25-client-model-design.md K§6.4.4 (the provider key never reaches the client, on every pair, translated or not: an untranslated non-2xx body read within `COPY_MAX` and each in-stream error event get each occurrence of the key replaced with `[REDACTED]`; an error event line over `HOLD_MAX` does not reach the client; success bytes unchanged), K§6.4.3 stream obligation 6 (the translated rule it matches); change-log line "RS-5 review F5"
**Files:** `crates/zygo-proxy/src/forward.rs`, `crates/zygo-proxy/src/tee.rs`, `crates/zygo-proxy/tests/passthrough_key.rs` (new)
**Consumes:** `ResponseCtx.lines` (RS-5)
**Produces:** on an untranslated response with `Candidate.key` set: a non-2xx body read as `read_capped` does (over `COPY_MAX` → `502 zygo_upstream_too_large`), sent with each key occurrence replaced by `[REDACTED]` (the text of `scrub`, `translate/mod.rs`), status and `content-type` kept, `content-length` of the new body; an SSE body in the tee's line mode (`Tee::arm_line_mode`), with the key replaced in the `data` lines of each `error` or `response.failed` event (read by `ResponseCtx.lines`); the tee does not pass an error event line over `HOLD_MAX` (it is the only stage that sees such a line: `tee.rs` `scan` passes it unheld), and the client body ends before it; every other byte unchanged
**Acceptance:** `CARGO_INCREMENTAL=0 cargo test -p zygo-proxy --locked --test passthrough_key -- --list | grep -q ': test$' && cargo test -p zygo-proxy --locked` → exit 0. The tests, written first and failing on the RS-5/RS-6/RS-7 tree, send through a mock upstream whose provider key is known: a Messages client to an Anthropic upstream that answers 401 with the key in its body; a Responses client to an `openai` upstream that answers 401 with the key in its body; and on each of those two pairs a 2xx SSE stream that carries an in-stream error event (`error` on the Anthropic pair, `error` and `response.failed` on the `openai` pair) with the key in its message. Each passes when the client's bytes do not contain the key and do contain `[REDACTED]`, and a 2xx event without an error passes byte for byte

# RS-14 — Untranslated passthrough: the provider key never reaches the client

**Spec:** docs/specs/2026-11-25-client-model-design.md K§6.4.4 (the provider key never reaches the client, on every pair, translated or not: an untranslated non-2xx body read within `COPY_MAX` and each in-stream error event get each occurrence of the key replaced with `[REDACTED]`; an error event line over `HOLD_MAX` does not reach the client; success bytes unchanged), K§6.4.3 stream obligation 6 (the translated rule it matches); change-log lines "RS-5 review F5" and "RS-14 premise check"
**Files:** `crates/zygo-proxy/src/forward.rs`, `crates/zygo-proxy/src/tee.rs`, `crates/zygo-proxy/tests/passthrough_key.rs` (new)
**Consumes:** `Harness::start` (RS-3) (the code it builds on predates the graph or is not a node product: see Interfaces in the plan)
**Produces:** on an untranslated response with `Candidate.key` set: a non-2xx body read as `read_capped` does (over `COPY_MAX` → `502 zygo_upstream_too_large`), sent with each key occurrence replaced by `[REDACTED]` (the text of `scrub`, `translate/mod.rs`), status and `content-type` kept, `content-length` of the new body; a 2xx SSE body in the tee's line mode (`Tee::arm_line_mode`, armed by the key whether or not the window stage armed it), with the key replaced in the `data` lines of each `error` or `response.failed` event (by `event` field; an unnamed event's line by its whole-JSON `type`, a non-JSON line fails closed); the tee does not pass an error event's `data` line over `HOLD_MAX` (it is the only stage that sees such a line: `tee.rs` `scan` passes it unheld), and the client body ends before it; every other byte unchanged
**Acceptance:** `CARGO_INCREMENTAL=0 cargo test -p zygo-proxy --locked --test passthrough_key -- --list | grep -q ': test$' && cargo test -p zygo-proxy --locked` → exit 0. The tests, written first and failing on the RS-5/RS-6/RS-7 tree, send through a mock upstream whose provider key is known: a Messages client to an Anthropic upstream that answers 401 with the key in its body; a Responses client to an `openai` upstream that answers 401 with the key in its body; and on each of those two pairs a 2xx SSE stream that carries an in-stream error event (`error` on the Anthropic pair, `error` and `response.failed` on the `openai` pair) with the key in its message. Each passes when the client's bytes do not contain the key and do contain `[REDACTED]`, and a 2xx event without an error passes byte for byte

- Holds: a passthrough candidate has no key (`passthrough.rs:231`, `Candidate { …, key: None }`), so nothing is replaced when the client's credential is forwarded.
- Holds: RS-7 added `Flow.window` (`forward.rs:1436`, set from `ctx.line_mode` at `forward.rs:640`).
- Drifted: line mode on the Messages route is armed only when the window stage arms it (`forward.rs:611-614`, `ctx.line_mode`): not for an OpenCode session or a compaction request. RS-14 arms it itself when the key is set. Today the `_` arm of `on_line` (`forward.rs:1530`) runs the line stages whenever line mode is on; RS-14 gates that arm on `window` so the line stages see exactly the lines they see today.
- Drifted: the split-error joining of `Streamed` (`Held`, `forward.rs:1262-1268`) is not reused. It turns held lines into SSE comments and re-emits a joined `data` line, which changes the bytes of an event that turns out not to be an error (K§6.4.4 (3) forbids that). It is not needed: a key holds no line break, so it never spans two `data` lines, and a per-line replacement is complete. The one scrubber is `scrub` (`translate/mod.rs:109`), wrapped for bytes by `scrub_bytes` (below).
- Drifted: an over-long line is never parsed (`tee.rs:295-307`), so "a `data` line whose JSON `type` is error" cannot decide it. K§6.4.4 (2) is rewritten as final text: an event is classed by its `event` field; in an unnamed event a whole-JSON line by its `type`, a non-JSON line fails closed; an over-long `data` line in an error or unnamed event ends the client body; the rest is read for the usage row (change-log line "RS-14 premise check").
- `ResponseCtx.lines` (the old Consumes) is not needed: the event names `error` and `response.failed` apply in both forms.

//! RS-14: on an untranslated pair (Messages → Anthropic, Responses → openai) the provider key never reaches the
//! client (K§6.4.4): a non-2xx body and each in-stream error event have the key replaced with `[REDACTED]`; an error
//! `data` line over HOLD_MAX ends the client body before it; every other byte passes. Mock upstream on 127.0.0.1.

#[path = "support/responses.rs"]
mod support;

use serde_json::{json, Value};
use support::{codex_request, Harness, MODEL};
use zygo_config::Dialect;
use zygo_core::Agent;
use zygo_proxy::tee::{COPY_MAX, HOLD_MAX};

const R: &str = "openai/v1/responses";
const M: &str = "anthropic/v1/messages";
const SSE: &str = "text/event-stream";
const JSON: &str = "application/json";
const RED: &[u8] = b"[REDACTED]";

fn contains(hay: &[u8], needle: &[u8]) -> bool {
    hay.windows(needle.len()).any(|w| w == needle)
}

/// `event: <type>\ndata: <compact json>\n\n` per event.
fn sse(evs: &[Value]) -> Vec<u8> {
    evs.iter().flat_map(|e| format!("event: {}\ndata: {e}\n\n", e["type"].as_str().unwrap()).into_bytes()).collect()
}

/// `b` with each occurrence of `key` replaced by `[REDACTED]`.
fn redacted(b: &[u8], key: &str) -> Vec<u8> {
    String::from_utf8(b.to_vec()).unwrap().replace(key, "[REDACTED]").into_bytes()
}

/// (harness, client path, client body) of the untranslated pair toward upstream `d`.
fn pair(d: Dialect, agent: Agent) -> (Harness, &'static str, Value) {
    let h = Harness::start(d, agent, "");
    match d {
        Dialect::Anthropic => (h, M, json!({"model":MODEL,"max_tokens":64,"stream":true,"messages":[{"role":"user","content":"hi"}]})),
        _ => (h, R, codex_request("turn-with-reasoning")),
    }
}

fn message_start() -> Value {
    json!({"type":"message_start","message":{"id":"msg_up","type":"message","role":"assistant","model":"up-rs","content":[],
           "stop_reason":null,"usage":{"input_tokens":7,"output_tokens":1}}})
}

fn created() -> Value {
    json!({"type":"response.created","sequence_number":0,
           "response":{"id":"resp_up","object":"response","model":"up-rs","status":"in_progress","output":[],"usage":null}})
}

/// The first event of a 2xx stream from upstream `d`.
fn first(d: Dialect) -> Value {
    if d == Dialect::Anthropic { message_start() } else { created() }
}

fn failed(message: &str) -> Value {
    json!({"type":"response.failed","sequence_number":2,"response":{"id":"resp_up","object":"response","model":"up-rs",
           "status":"failed","output":[],"error":{"code":"server_error","message":message},"usage":null}})
}

/// K§6.4.4 (1): a 401 JSON body with the key reaches the client with `[REDACTED]` in its place; status and
/// `content-type` kept; `content-length` of the new body.
#[test]
fn non_2xx_body_has_no_key() {
    for d in [Dialect::Anthropic, Dialect::Openai] {
        let (h, path, body) = pair(d, Agent::ClaudeCode);
        let k = h.provider_key().to_string();
        let up = if d == Dialect::Anthropic {
            json!({"type":"error","error":{"type":"authentication_error","message":format!("invalid x-api-key: {k}")}})
        } else {
            json!({"error":{"type":"invalid_request_error","message":format!("Incorrect API key provided: {k}"),"param":null,"code":"invalid_api_key"}})
        };
        let up = serde_json::to_vec(&up).unwrap();
        h.reply_with(401, JSON, up.clone());
        let (s, hd, b) = h.post(path, &body);
        assert_eq!(s.as_u16(), 401, "{d:?}");
        assert_eq!(hd["content-type"].to_str().unwrap(), JSON, "{d:?}");
        assert_eq!(hd["content-length"].to_str().unwrap(), b.len().to_string(), "{d:?}");
        assert!(!contains(&b, k.as_bytes()), "{d:?}");
        assert!(contains(&b, RED), "{d:?}");
        assert_eq!(&b[..], &redacted(&up, &k)[..], "{d:?}");
    }
}

/// K§6.4.4 (2): an over-long `data` line in an error or unnamed event ends the output before it, in one chunk or
/// split across chunks; later lines are read for usage only. In another event it passes.
#[test]
fn scrub_errors_cuts_an_over_long_error_line() {
    let usage = "event: message_delta\ndata: {\"type\":\"message_delta\",\"usage\":{\"output_tokens\":5}}\n\n";
    for (name, cut) in [("event: error\n", true), ("event: response.failed\n", true), ("", true), ("event: content_block_delta\n", false)] {
        for step in [usize::MAX, 1 << 20] {
            let all = format!("{name}data: {}\n\n{usage}", "x".repeat(HOLD_MAX));
            let mut t = Tee::new(true);
            t.arm_line_mode();
            t.scrub_errors(Secret::new("K3Y".to_string()));
            let mut out = Vec::new();
            for c in all.as_bytes().chunks(step) {
                out.extend_from_slice(&t.push(Bytes::copy_from_slice(c), &mut |_| {}));
            }
            out.extend_from_slice(&t.finish(&mut |_| {}));
            assert_eq!(t.cut(), cut, "{name:?} {step}");
            assert_eq!(out, if cut { name.as_bytes().to_vec() } else { all.into_bytes() }, "{name:?} {step}");
            assert_eq!(t.usage().output, 5, "{name:?} {step}");
        }
    }

# RS-16 — Messages clients: no zygo_calls_dropped key; Responses-upstream content_filter drops held calls

**Spec:** docs/specs/2026-11-25-client-model-design.md K§6.4.3 (stream obligation 5 as RS-12 leaves it: a call open at a refusal or `content_filter` is dropped, not sent with cut arguments, and the drop is recorded as `refusal_call_dropped:<n>`); RS-12 round 3 review dispositions H1, H2 (`nodes/RS-12.md`)
**Files:** `crates/zygo-proxy/src/forward.rs`, `crates/zygo-proxy/src/translate/mod.rs`, `crates/zygo-proxy/src/translate/sse.rs`, `crates/zygo-proxy/tests/refusal_calls.rs` (new)
**Consumes:** —
**Produces:** for a Messages client (Claude Code) the `zygo_calls_dropped` key never reaches the client: it is removed from a streamed `message_delta` and from a JSON Messages body before the bytes leave the proxy, and its count is recorded on the usage row as adjustment `refusal_call_dropped:<n>`. The Responses-upstream arm of `StreamMapper` (`translate/sse.rs`, Messages clients only) applies the H1 rule at `response.incomplete` with reason `content_filter`: each call still held (no `response.output_item.done`) is dropped, not closed with cut arguments, and the count goes on `message_delta` as `CALLS_DROPPED`. Every other stop and every closed call is unchanged; the Responses client path (the encoder) is unchanged.
**Acceptance:** `CARGO_INCREMENTAL=0 cargo test -p zygo-proxy --locked --test refusal_calls` → exit 0, with each test below listed `ok`, then `cargo test -p zygo-proxy --locked` → exit 0. The tests are written first and fail on the RS-12 tree (PR #202, e4c14296):
- `messages_client_chat_content_filter_streamed_has_no_dropped_key`: a streamed Messages request to a chat upstream whose answer holds a tool call open at `finish_reason` `content_filter`. It passes when the client bytes do not contain `zygo_calls_dropped`, hold no `tool_use` block for the call, end with `stop_reason` `refusal`, and the usage row holds `refusal_call_dropped:1`. On the RS-12 tree the key reaches the client and the row lacks the code.
- `messages_client_chat_content_filter_json_has_no_dropped_key`: the same answer to a non-streamed request (a JSON Messages body). It passes on the same terms.
- `messages_client_responses_upstream_content_filter_drops_open_call`: a streamed Messages request to an `openai` (Responses) upstream whose stream holds a `function_call` item with argument deltas and no `response.output_item.done`, then `response.incomplete` with reason `content_filter`. It passes when the client bytes hold no `tool_use` block or `input_json_delta` for the call, no `zygo_calls_dropped`, and the usage row holds `refusal_call_dropped:1`. On the RS-12 tree the call is closed and sent with its cut arguments.

## Planning notes

- `CALLS_DROPPED` (the `zygo_calls_dropped` key) came from RS-12's round 3 fix, not from its contract, so Consumes names no product.
- The key is written at `translate/sse.rs` (`StreamMapper::end`, `d[CALLS_DROPPED]`) and `translate/chat.rs` (the JSON body); `message_events` moves a body's key to `message_delta`; only the Responses encoder (`translate/responses_client.rs`) reads it. A Messages client gets it as sent today: Anthropic never sends that field.

### Premise check (2026-11-26)

- Holds: the chat mapper writes `d[CALLS_DROPPED]` in `StreamMapper::end` (`translate/sse.rs:431-434`); `chat::response` writes it on the body (`translate/chat.rs:147-149`); `message_events` moves it to `message_delta` (`sse.rs:467-494`); only `responses_client.rs` reads it (`:922-924`, `codes` `:907-919`). For a Messages client, `forward.rs:608` builds the mapper and `forward.rs:621-644` sends the body or `message_events` with the key; `Flow::drop` (`forward.rs:1622-1651`) adds only the encoder's codes, so no `refusal_call_dropped` reaches the row.
- Does not hold as written: "each call still held" in the Responses arm. That arm holds nothing: `response.output_item.added` with `function_call` calls `open` (`sse.rs:197-201`), and each `response.function_call_arguments.delta` calls `delta` (`sse.rs:225-229`). Both push to `out` at once, so `content_block_start` and the cut `input_json_delta` reach the client before `response.incomplete`. A drop at the end cannot take them back. So the Responses arm must hold the open `function_call` block (its start and deltas) until `response.output_item.done`. The held bytes need the `HOLD_MAX` bound (K-C2). Spec K§6.4.3 obligations 5 and 9 are rewritten to say this, with a change-log line dated 2026-11-26 (author's call).
- Closed calls stay byte-equal: the held events are the same events, sent in the same order when the block closes. `translate.rs` `res_sse_responses_events` (two `input_json_delta` events for one call), `res_sse_split_anywhere` and `res_sse_responses_done_only_and_refusal` assert this and must still pass unchanged.
- Only a Messages client reaches the Responses arm: a Responses client to an `openai` upstream is same-dialect (`translated` false, `forward.rs:526`), so no mapper runs.

#[path = "support/responses.rs"]
mod support;

use serde_json::{json, Value};
use support::{Harness, MODEL};
use zygo_config::Dialect::{self, Openai as O, OpenaiChat as C};
use zygo_core::Agent;
use zygo_proxy::tee::HOLD_MAX;

const M: &str = "anthropic/v1/messages";
const SSE: &str = "text/event-stream";
const JSON: &str = "application/json";
/// Tool arguments cut by the filter.
const CUT: &str = "{\"cmd\":";
const KEY: &[u8] = b"zygo_calls_dropped";

fn start(d: Dialect) -> Harness { Harness::start(d, Agent::ClaudeCode, "") }
fn client_body(stream: bool) -> Value {
    json!({"model":MODEL,"max_tokens":64,"stream":stream,"messages":[{"role":"user","content":"hi"}]})
}
fn contains(hay: &[u8], needle: &[u8]) -> bool { hay.windows(needle.len()).any(|w| w == needle) }
/// `event: <type>\ndata: <compact json>\n\n` per event (a Responses stream).
fn sse(evs: &[Value]) -> Vec<u8> {
    evs.iter().flat_map(|e| format!("event: {}\ndata: {e}\n\n", e["type"].as_str().unwrap()).into_bytes()).collect()
}
/// `data: <json>\n\n` per chunk, then `data: [DONE]\n\n`.
fn chat_sse(chunks: &[Value]) -> Vec<u8> {
    let mut out: Vec<u8> = chunks.iter().flat_map(|c| format!("data: {c}\n\n").into_bytes()).collect();
    out.extend_from_slice(b"data: [DONE]\n\n");
    out
}
/// The `(event, data)` pairs of an SSE body: per blank-line block, the `event:` name and the joined `data:` JSON.
fn events(b: &[u8]) -> Vec<(String, Value)> {
    String::from_utf8_lossy(b).split("\n\n").filter(|blk| !blk.trim().is_empty()).map(|blk| {
        let (mut name, mut data) = (String::new(), String::new());
        for line in blk.lines() {
            if let Some(n) = line.strip_prefix("event:") { name = n.trim().to_string(); }
            else if let Some(d) = line.strip_prefix("data:") { data.push_str(d.trim_start()); }
        }
        (name, serde_json::from_str(&data).unwrap_or_else(|_| panic!("data not JSON: {data}")))
    }).collect()
}
fn chunk(delta: Value, finish: Value) -> Value {
    json!({"id":"chatcmpl-1","object":"chat.completion.chunk","model":"up-rs","choices":[{"index":0,"delta":delta,"finish_reason":finish}]})
}
fn call() -> Value { json!({"index":0,"id":"call_1","type":"function","function":{"name":"exec_command","arguments":CUT}}) }
fn usage_raw() -> Value { json!({"prompt_tokens":120,"completion_tokens":7,"total_tokens":127}) }
/// The last usage row holds `refusal_call_dropped:1`.
fn assert_row_code(h: &Harness) {
    let rows = h.usage_rows();
    let a = &rows.last().expect("a usage row").adjustments;
    assert!(a.contains(&"refusal_call_dropped:1".to_owned()), "{a:?}");
}
/// A Messages SSE body: no key, no tool_use block, no call id, stop_reason refusal.
fn assert_stream_dropped(b: &[u8]) {
    let text = String::from_utf8_lossy(b);
    assert!(!contains(b, KEY), "{text}");
    assert!(!contains(b, b"tool_use") && !contains(b, b"input_json_delta") && !contains(b, b"call_1"), "{text}");
    let evs = events(b);
    let md = evs.iter().find(|(n, _)| n == "message_delta").expect("a message_delta");
    assert_eq!(md.1["delta"]["stop_reason"], "refusal", "{text}");
    assert_eq!(evs.last().map(|(n, _)| n.as_str()), Some("message_stop"), "{text}");
}
/// A Responses stream: a `message` item with text "hel", then a `function_call` item `call_1` with one argument
/// delta `CUT` and no `output_item.done`, then `last`.
fn responses_cut_call(last: Value) -> Vec<u8> {
    sse(&[
        json!({"type":"response.created","sequence_number":0,"response":{"id":"resp_up","object":"response","model":"up-rs","status":"in_progress","output":[],"usage":null}}),
        json!({"type":"response.output_item.added","sequence_number":1,"output_index":0,"item":{"type":"message","id":"msg_up","role":"assistant","content":[]}}),
        json!({"type":"response.content_part.added","sequence_number":2,"output_index":0,"content_index":0,"item_id":"msg_up","part":{"type":"output_text","text":""}}),
        json!({"type":"response.output_text.delta","sequence_number":3,"output_index":0,"content_index":0,"item_id":"msg_up","delta":"hel"}),
        json!({"type":"response.output_item.done","sequence_number":4,"output_index":0,"item":{"type":"message","id":"msg_up","role":"assistant","content":[{"type":"output_text","text":"hel"}]}}),
        json!({"type":"response.output_item.added","sequence_number":5,"output_index":1,"item":{"type":"function_call","id":"fc_up","call_id":"call_1","name":"exec_command","arguments":""}}),
        json!({"type":"response.function_call_arguments.delta","sequence_number":6,"output_index":1,"item_id":"fc_up","delta":CUT}),
        last,
    ])
}

fn messages_client_chat_content_filter_streamed_has_no_dropped_key() {

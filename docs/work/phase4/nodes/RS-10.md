# RS-10 — Messages events from a JSON body keep redacted_thinking and drop server-tool blocks (no empty text blocks)

**Spec:** docs/specs/2026-11-18-zygo-design.md §7.6 (translation: "Block types without a counterpart"), docs/specs/2026-11-25-client-model-design.md K§6.4.3 (stream obligations 2 and 3: a `redacted_thinking` block keeps its item; `server_tool_use` and `*_tool_result` blocks are dropped with `server_tool_dropped`)
**Files:** `crates/zygo-proxy/src/translate/sse.rs`, `crates/zygo-proxy/tests/translate.rs`, `crates/zygo-proxy/tests/responses_forward.rs`
**Consumes:** —
**Produces:** `message_events(m: &Value) -> Vec<SseEvent>` (`crates/zygo-proxy/src/translate/sse.rs:436-466` at `da0c0387`, signature unchanged) emits each block other than `text`, `thinking` and `tool_use` as one content block whose `content_block_start` carries the block as given, with no delta: a `redacted_thinking` block keeps its `data`, and `server_tool_use` / `*_tool_result` blocks keep their own type, so the encoder after it drops them with `server_tool_dropped` (the streaming path's code and channel: the usage row). It never emits an empty text block for a block that is not `text`

## Planning notes

- Found by the RS-4 planner 2026-11-26: when an upstream answers a streaming request with a JSON body, `forward.rs` turns the body into SSE with `message_events`, whose fallback arm makes every block other than `thinking` and `tool_use` an empty `text` block.
- Premise correction (RS-10 planner, 2026-11-25, live code at `da0c0387`): the defect reaches only a Responses client with an Anthropic upstream, not the Messages client. `message_events` has one caller, `forward.rs:566`, inside the translated branch (`forward.rs:537-570`, `translated = c.dialect != ctx.dialect` at `forward.rs:509`). A Messages client with an Anthropic upstream is not translated: its body passes as bytes (`forward.rs:531-532`). A Messages client with a chat or Responses upstream gets `translate_response` output, which holds only `text`, `thinking` and `tool_use` blocks (`translate/chat.rs:124-142`, `translate/responses.rs:126-155`). A Responses client with an Anthropic upstream gets the upstream Messages body itself (`forward.rs:542-547`), then `message_events` (`forward.rs:566`), then the stream encoder (`forward.rs:575-578`). Today that client gets an empty `message` item for each `redacted_thinking` and server tool block, loses the reasoning item, and no `server_tool_dropped` code is recorded.
- Channel decision (author's call): the encoder's channel, not a new one. `message_events` passes the block on with its own type; `Encoder::open_block` already drops `server_tool_use` / `*_tool_result` and sets `dropped` (`translate/responses_client.rs:1240-1243`, `is_server_tool` at `:843-845`) and keeps `redacted_thinking` as a reasoning item (`:1234`); `Encoder::adjustments` (`:1087-1089`) reaches the usage row when the stream ends (`forward.rs:1412-1414`), as on the SSE upstream path (test `anthropic_stream_returns_responses_sse_and_usage`, `tests/responses_forward.rs:246`). K§6.4.3 obligation 3 says the block "is dropped from the stream with the adjustment code `server_tool_dropped`"; the stream is the encoder's. The `x-zygo-adjustments` header is still open on this branch (headers are written at `forward.rs:605`, after `forward.rs:566`), but using it needs a second copy of obligation 3 in `sse.rs`, a changed signature and an edit of `forward.rs` (Files of RS-5 and RS-6), and it would split the encoder's codes (`reasoning_unmarked:<n>` stays row-only). Not chosen.
- Size: a block passed whole is one event of at most the body's size; the body is read to at most `COPY_MAX` = `HOLD_MAX` = 4 MiB (`tee.rs:22-23`), so the encoder's `HOLD_MAX` check (K§6.4.3 obligation 9) does not end a stream that fits `COPY_MAX`.
- No spec section drifted: K§6.4.3 obligations 2, 3 and base §7.6 hold as written; no spec edit.
- RS-4 left `non_streaming_anthropic_same_content` sending `MSG_JSON(false)` to its streamed request because of this defect (`tests/responses_forward.rs:336-337`, comment "no server tool block"); this node sends `MSG_JSON(true)` there.

  /// A Messages body with `content`, as an Anthropic upstream sends it.
  fn msg_body(content: Value) -> Value {
      json!({"id":"msg_1","type":"message","role":"assistant","model":"up","content":content,
          "stop_reason":"end_turn","stop_sequence":null,"usage":{"input_tokens":3,"output_tokens":2}})
  }

  /// `message_events` of `m` through the Responses encoder: its events and its adjustment codes.
  fn encoded(m: &Value) -> (Vec<SseEvent>, Vec<String>) {
      let bytes: Vec<u8> = message_events(m).iter().flat_map(SseEvent::to_bytes).collect();
      let mut e = Encoder::new("role-x", &tgt(), Calls::default());
      let mut out = e.push(&bytes);
      out.extend(e.finish());
      (out, e.adjustments().into_iter().map(|a| a.0).collect())
  }

  #[test] // K§6.4.3 stream obligation 2: a redacted_thinking block of a JSON body keeps its block and its item
  fn message_events_keeps_redacted_thinking() {
      let red = json!({"type":"redacted_thinking","data":"EmwKAhgB"});
      let m = msg_body(json!([red.clone(), {"type":"text","text":"hi"}]));
      let evs = message_events(&m);
      let names: Vec<&str> = evs.iter().map(|e| e.event.as_str()).collect();
      assert_eq!(names, ["message_start", "content_block_start", "content_block_stop", "content_block_start",
          "content_block_delta", "content_block_stop", "message_delta", "message_stop"]);
      assert_eq!(evs[1].data, json!({"type":"content_block_start","index":0,"content_block":red}));
      assert_eq!(evs[2].data, json!({"type":"content_block_stop","index":0}));
      assert_eq!(evs[3].data["content_block"], json!({"type":"text","text":""}));
      assert_eq!(evs[4].data["delta"], json!({"type":"text_delta","text":"hi"}));
      let (out, codes) = encoded(&m);
      let items: Vec<&Value> = out.iter().filter(|e| e.event == "response.output_item.done").map(|e| &e.data["item"]).collect();
      assert_eq!(items.len(), 2);
      assert_eq!((&items[0]["type"], &items[0]["summary"]), (&json!("reasoning"), &json!([])));
      assert_eq!(decode_thinking(items[0]["encrypted_content"].as_str().unwrap(), &tgt()), Some(red));
      assert_eq!(items[1]["type"], "message");
      assert_eq!(items[1]["content"][0]["text"], "hi");
      assert!(codes.is_empty(), "{codes:?}");
  }

  #[test] // K§6.4.3 stream obligation 3: server tool blocks of a JSON body are dropped with server_tool_dropped
  fn message_events_drops_server_tool_blocks() {
      let use_ = json!({"type":"server_tool_use","id":"srvtoolu_1","name":"web_search","input":{"query":"q"}});
      let res = json!({"type":"web_search_tool_result","tool_use_id":"srvtoolu_1","content":[]});
      let m = msg_body(json!([use_.clone(), res.clone(), {"type":"text","text":"hi"}]));
      let evs = message_events(&m);
      let starts: Vec<&Value> = evs.iter().filter(|e| e.event == "content_block_start").map(|e| &e.data["content_block"]).collect();
      assert_eq!(starts, [&use_, &res, &json!({"type":"text","text":""})]);
      let deltas: Vec<&Value> = evs.iter().filter(|e| e.event == "content_block_delta").map(|e| &e.data).collect();
      assert_eq!(deltas, [&json!({"type":"content_block_delta","index":2,"delta":{"type":"text_delta","text":"hi"}})]);
      let (out, codes) = encoded(&m);
      let items: Vec<&Value> = out.iter().filter(|e| e.event == "response.output_item.done").map(|e| &e.data["item"]).collect();
      assert_eq!(items.len(), 1);
      assert_eq!(items[0]["content"][0]["text"], "hi");
      assert!(!out.iter().any(|e| e.data.to_string().contains("srvtoolu_1")));
      assert_eq!(out.last().unwrap().event, "response.completed");
      assert_eq!(codes, ["server_tool_dropped"]);
  }

  #[test] // RS-10: a JSON 2xx to a streamed request: message_events → encoder keeps redacted_thinking, drops server tools
  fn streamed_request_json_answer_keeps_redacted_drops_server_tool() {
      let h = start(A);
      let red = json!({"type":"redacted_thinking","data":"EmwKAhgB"});
      let mut m = MSG_JSON(true);

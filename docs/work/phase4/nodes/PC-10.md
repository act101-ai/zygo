# PC-10 — Premise harness privacy: TZ=UTC for Codex runs; scrub OS in user agents and double-slash scratch paths

**Spec:** docs/specs/2026-11-25-client-model-design.md K§6.3.7 (method paragraph), K§11 item 10 (fixture scan); docs/premises.md "Method"
**Files:** `scripts/premises/lib.sh`, `scripts/premises/lib_test.sh`, `scripts/premises/scrub.py`, `scripts/premises/scrub_test.py`, `scripts/premises/mock_upstream.py`, `scripts/premises/mock_upstream_test.py`
**Consumes:** `scripts/premises/lib.sh` (PC-2), `scripts/premises/scrub.py` (PC-2)
**Produces:** `codex_env` that passes `TZ=UTC` (a constant, like TERM) to every Codex run, listed in isolation.txt's env_names; `scrub.py` that replaces OS name/version/arch inside user-agent strings (e.g. `Mac OS 27.2.1; arm64`, `Linux 6.x; x86_64`, `Windows 10.0.x`) with a fixed placeholder, and maps the harness's scratch paths to `/tmp/run` also when they contain `//` (a TMPDIR ending in `/`, e.g. `…/T//tmp.X`); `codex_env` that refuses to start Codex while a `codex app-server` runs outside the run folder (names its pid and path, never kills it) or while the per-uid daemon folder (`/private/tmp/codex-daemon-<uid>`, `/tmp/codex-daemon-<uid>`) holds a socket; `codex_record` that exits 1 and names the pid while a process whose command line holds the run folder still runs (a leftover daemon); lib.sh's Codex comment: TUI runs pass `--no-daemon`; `mock_upstream.py` whose connect.txt line for a refused absolute-URI request also names the request path (query values, userinfo and the fragment dropped; `?` when it does not parse), e.g. `127.0.0.1:57297 POST /some/path refused`; CONNECT lines stay `<host>:<port> refused`; every line ends ` refused`; `mock_upstream.py` that also accepts `MOCK_ALT_KEY` (optional, read once at start, refused when equal to `MOCK_KEY`) like `MOCK_KEY` and records `"credential": "primary"` or `"alt"` per request (never a value), any other credential still aborting; `start_mock` that hands the shell variable `MOCK_ALT_KEY` (built at run time by the part) to the mock
**Acceptance:** `python3 -I scripts/premises/scrub_test.py && sh scripts/premises/lib_test.sh && sh scripts/check-premises.sh` → every command exits 0

- The PC-3, PC-4, PC-5, PC-6 captures are re-taken after this node merges.
- CI does not run these tests.
- Scope addition (lead, author's call, 2026-11-25), found by a PC-5 real run: a Codex TUI run started `codex app-server --listen unix:// --managed-daemon` (and `daemon pid-update-loop`) that outlived the run (ppid 1) with its socket in the per-uid folder `/private/tmp/codex-daemon-501`, outside the run folder and HOME. The owner's Codex uses the same folder, so a scratch TUI run could attach to the owner's daemon (which reads the owner's `~/.codex`); the `find ~/.codex -newer` check cannot see that, and the `\.codex/packages` / `codex-pkg` process patterns miss a scratch daemon (`<run>/…/packages/app-server-daemon/…`). `codex --help` documents `--no-daemon` (`fixtures/codex/help.txt`); PC-5's session.sh passes it.
- Scope addition (lead, author's call, 2026-11-25), found by PC-6: its TUI runs POSTed to 127.0.0.1 ports other than the mock's, and connect.txt (`<host>:<port> <METHOD> refused`) cannot say what they were.
- Scope addition (lead, author's call, 2026-11-25): PC-3's PC1 needs the key-helper token distinct from `MOCK_API_KEY`, so the record proves the bearer came from the helper.
- Test hook `N2_TEST_ROOT` (lib_test.sh only): the process scans see only processes whose command line holds it, and the daemon folders are looked up under it, so a host's own Codex daemon or another session's run does not change the lib tests.

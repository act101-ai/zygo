# RS-15 — Streamed text in text_delta pieces of at most 64 KiB: the null-restore filter, message_events and the chat mapper

**Spec:** docs/specs/2026-11-25-client-model-design.md K§6.4.3 (stream obligations 8 and 9 as RS-13 leaves them). RS-15 rewrites the obligation 8 sentences that state the text limit: "a text or thinking delta ... at most that block as written in the body" (`message_events`), "a text delta is not cut and carries one upstream chunk's `content`" (the chat mapper) and "a rebuilt text block is one delta, not cut ... about 2 × `HOLD_MAX`" (the null-restore filter). Each becomes: text goes in `text_delta` pieces of at most `INPUT_DELTA_MAX` (64 KiB), cut on a character boundary, so each event line stays under 2 × 64 KiB plus framing. RS-15 also updates the obligation 9 per-path peaks that cite those limits, and adds a change-log line "RS-13 round 3 review: text deltas in 64 KiB pieces".
**Files:** `crates/zygo-proxy/src/translate/sse.rs`, `crates/zygo-proxy/src/translate/schema.rs`, `crates/zygo-proxy/tests/translate.rs`, `crates/zygo-proxy/tests/responses_forward.rs`, `docs/specs/2026-11-25-client-model-design.md`
**Consumes:** —
**Produces:** the RS-13 cutting helper in `translate/sse.rs` generalized for text: it cuts a string into pieces of at most `INPUT_DELTA_MAX` bytes on char boundaries, and each piece becomes an `input_json_delta` or a `text_delta`. Three emitters use it for text: the `text` arm of `message_events`, the chat mapper's text deltas (`translate/sse.rs`) and `RestoreFilter::rebuilt` for a rebuilt text block (`translate/schema.rs`). Signatures of `message_events` and `RestoreFilter` unchanged; the concatenated text of each block is unchanged.
**Acceptance:** `CARGO_INCREMENTAL=0 cargo test -p zygo-proxy --locked --test responses_forward -- --list | grep -q '^streamed_chat_restore_keeps_large_text: test$' && CARGO_INCREMENTAL=0 cargo test -p zygo-proxy --locked --test responses_forward -- --list | grep -q '^streamed_json_answer_keeps_large_text: test$' && CARGO_INCREMENTAL=0 cargo test -p zygo-proxy --locked --test translate -- --list | grep -q '^text_deltas_within_event_max: test$' && cargo test -p zygo-proxy --locked` → exit 0. The tests are written first and fail on the RS-13 tree:
- `streamed_chat_restore_keeps_large_text` (`tests/responses_forward.rs`): a streamed Responses request to a chat upstream, with the null-restore filter armed, whose answer holds a text block whose JSON escape passes `HOLD_MAX`. It passes when the stream ends in `response.completed` and its text equals the text of the non-streamed Response for the same upstream answer. On the RS-13 tree it ends in `response.failed` "upstream stream line too long".
- `streamed_json_answer_keeps_large_text` (`tests/responses_forward.rs`): a streamed request whose upstream answers 2xx with a JSON body near `COPY_MAX` that holds one text block. It passes when the stream ends in `response.completed` with the same text as the non-streamed Response.
- `text_deltas_within_event_max` (`tests/translate.rs`): for text made of `"` characters, every event that each of the three emitters sends is under 2 × `INPUT_DELTA_MAX` + 256 bytes, and the pieces concatenate to the original text.

## Plan

### Premise check (2026-11-25, tree 3c018348, RS-13 merged by PR #175)

- RS-13's cutting function is `input_deltas` (`crates/zygo-proxy/src/translate/sse.rs:477-486`, `pub(super)`). It has three callers: the `tool_use` arm of `message_events` (`sse.rs:458`), `StreamMapper::calls_out` (`sse.rs:342`) and `RestoreFilter::rebuilt` (`translate/schema.rs:577`, imported at `schema.rs:9`). An empty string gives no delta.
- The three text senders send one delta each, never cut:
  - the `text` arm of `message_events` (`sse.rs:463`);
  - `StreamMapper::chat` (`sse.rs:298-301`), one `text_delta` per upstream chunk with non-empty `content`;
  - `RestoreFilter::rebuilt` (`schema.rs:577`), whose `vec![json!({"type":"text_delta","text":x})]` serves both the event path (`push`, `schema.rs:606`) and the raw path (`raw_event`, `schema.rs:743`).
- `tests/translate.rs` reaches all three senders. It already imports `message_events`, `StreamMapper`, `SseEvent` (`:36-37`), `NullMap`, `RestoreFilter` and `Seg` (`:31`), and `INPUT_DELTA_MAX` (`:32`). `NullMap`'s fields are `pub` (`schema.rs:42-45`). `RestoreFilter::{new, push, finish, push_raw, finish_raw}` are `pub` (`schema.rs:542`, `:583`, `:630`, `:636`, `:678`). RS-13's tests build a `RestoreFilter` the same way (`tests/translate.rs:1775`, `:1794`).
- Thinking deltas:
  - **In scope:** the `thinking` arm of `message_events` (`sse.rs:453`). It has the same one-delta form. A body near `COPY_MAX` can hold one large thinking block. It costs one call of the same function.
  - **No thinking to cut** in the chat mapper: `chat()` reads only `content` and `tool_calls`. The restore filter holds only `tool_use` and text blocks (`RestoreFilter::start`, `schema.rs:556-567`).
  - **Out of scope:** the Responses-upstream arm of `StreamMapper` (`responses()`, `sse.rs:225`, `:229`, `:236`, `:243`). It serves only a Messages client: a Responses client to a Responses upstream is not translated (K§6.4.3, "same dialect, no pivot"). So the Responses encoder never reads its events. Each of its deltas is one upstream event, and the upstream line is bounded by `HOLD_MAX` (`StreamMapper::push`, `sse.rs:136`).
  - **Out of scope:** the `signature_delta` (`sse.rs:455`). A signature is opaque, has no cut form, and is at most as written in the body.
- **Premise that does not hold (1): `streamed_json_answer_keeps_large_text` does not fail on the RS-13 tree.** On the JSON path the body has the text escaped once, and the one `text_delta` carries it escaped once too. serde_json writes the shortest escape. So the event's `data` is the escaped text plus 79 bytes of envelope, and the body is the escaped text plus at least 54 bytes (`is_message`, `forward.rs:1421-1423`: `type` and `content`). The event is therefore within about `COPY_MAX` = `HOLD_MAX`, and the encoder's `hold` (`responses_client.rs:1167-1192`) passes it. The test stays as a regression guard that it still completes. For `message_events`, the failing-first evidence is `text_deltas_within_event_max` (its first event over the bound is a `message_events` delta). For the same reason, the RS-13 spec sentence "a whole text, thinking or other block of a JSON body near `COPY_MAX`" passes `HOLD_MAX` was not true for text or thinking. The final text of obligation 8 says this.
- **Premise that does not hold (2): `streamed_chat_restore_keeps_large_text` cannot compare against a non-streamed Response for the same upstream answer.**
  - On the RS-13 tree, the rebuilt event fails only when its escaped text passes `HOLD_MAX`. The rebuilt text is compact JSON, at most as long as the model's text. A non-streamed chat answer carries that same text escaped in `content`, read within `COPY_MAX` = `HOLD_MAX` (`read_capped`, `forward.rs:1156-1168`). So any answer big enough to fail streamed is too big to read non-streamed: `502 zygo_upstream_too_large`.
  - A non-streamed client request that gets an SSE answer is answered with SSE, not a Response object (`forward.rs:545-549`, `:576`).
  - **Author's call:** the test compares the streamed text with `json!({"b": b}).to_string()`. That is the text `NullMap::restore_message` gives on the non-streamed path (`schema.rs:67-73`, `strip_text` = compact JSON, `schema.rs:133-136`). `text_format_json_schema_route_chat` (`tests/responses_text_format.rs:221-234`) already proves that both paths give it for a small answer.
- **Premise corrected in the spec: a text piece escapes to at most 6 × 64 KiB, not 2 ×.** The contract's sentence "each event line stays under 2 × 64 KiB plus framing" holds for the restore filter (compact JSON). It does not hold for decoded text from `message_events` or the chat mapper: a control character other than `\b\f\n\r\t` escapes as `\u00XX`. The final text of obligation 8 (written at planning, change-log line dated 2026-11-25) states 384 KiB for those, which is still far under `HOLD_MAX`. The tests use `"` text, which escapes to exactly 2 ×.
- Arming the output-schema null filter on the chat route: a Responses request with `text.format` of type `json_schema` and an optional property. The OpenAI rules make the property required and nullable, and `NullMap.output` gets its path. `tests/responses_text_format.rs:221-234` shows this, with `required` sent as `["title", "note"]`.
- The encoder still completes after the cut. A JSON-body text piece adds at most its escaped bytes plus 79 to the held text, which is the body's own escape, so the sum stays within `COPY_MAX` as before. A restored chat text of 3 MiB plus one piece of at most 128 KiB is within `HOLD_MAX`.
- No review-focus line is assigned to RS-15. CI runs no clippy or fmt job.

#[test] // RS-15, K§6.4.3 stream obligation 8: text (and message_events' thinking) in pieces of at most INPUT_DELTA_MAX from each sender
fn text_deltas_within_event_max() {
    let text = "\"".repeat(300_000);
    // Every event under 2 × INPUT_DELTA_MAX + 256 bytes; the `kind` deltas: more than one, each of 1..=INPUT_DELTA_MAX
    // bytes of `key`; returns their concatenation.
    let pieces = |evs: &[SseEvent], kind: &str, key: &str| -> String {
        for e in evs {
            let n = e.to_bytes().len();
            assert!(n < 2 * INPUT_DELTA_MAX + 256, "{} {kind}: {n}", e.event);
        }
        let p: Vec<&str> = evs.iter().filter(|e| e.data["delta"]["type"] == kind).map(|e| e.data["delta"][key].as_str().unwrap()).collect();
        assert!(p.len() > 1, "{kind}: {}", p.len());
        assert!(p.iter().all(|x| !x.is_empty() && x.len() <= INPUT_DELTA_MAX), "{kind}");
        p.concat()
    };
    // message_events: a thinking block and a text block of a JSON body.
    let m = msg_body(json!([{"type":"thinking","thinking":text,"signature":"sig"},{"type":"text","text":text}]));
    let evs = message_events(&m);
    assert_eq!(pieces(&evs, "thinking_delta", "thinking"), text);
    assert_eq!(pieces(&evs, "text_delta", "text"), text);
    // The chat mapper: one upstream chunk whose `content` is the whole text.
    let sse = chat_delta(json!({"role":"assistant","content":text}), Value::Null) + &chat_delta(json!({}), json!("stop")) + DONE;
    let mut c = chat();
    let mut evs = c.push(sse.as_bytes());
    evs.extend(c.finish_events());
    assert_eq!(evs.last().unwrap().event, "message_stop");
    assert_eq!(pieces(&evs, "text_delta", "text"), text);
    // The null-restore filter: a JSON text block of the output schema with an injected null, in 60,000-byte deltas.
    let held = json!({"a":null,"b":text}).to_string();
    let want = json!({"b":text}).to_string();
    let nulls = NullMap { tools: BTreeMap::new(), output: vec![vec![Seg::Key("a".into())]] };
    let mut up = vec![msg_start("msg_1", "up"), text_start(0)];
    up.extend(held.as_bytes().chunks(60_000).map(|p| text_d(0, std::str::from_utf8(p).unwrap())));
    up.extend([block_stop(0), msg_delta("end_turn", [3, 0, 0, 2]), msg_stop()]);
    // Events path (after the chat mapper).
    let mut r = RestoreFilter::new(nulls.clone());
    let mut evs: Vec<SseEvent> = up.iter().cloned().flat_map(|e| r.push(e)).collect();
    evs.extend(r.finish());
    assert_eq!(pieces(&evs, "text_delta", "text"), want);
    // Raw path (an Anthropic upstream), in INPUT_DELTA_MAX-byte reads.
    let raw: Vec<u8> = up.iter().flat_map(SseEvent::to_bytes).collect();
    let mut r = RestoreFilter::new(nulls);
    let mut sent: Vec<u8> = raw.chunks(INPUT_DELTA_MAX).flat_map(|c| r.push_raw(c)).collect();
    sent.extend(r.finish_raw());
    assert_eq!(pieces(&events(&sent), "text_delta", "text"), want);
}

#[test] // RS-15, K§6.4.3 stream obligation 8: a restored JSON text block of a chat upstream goes out in 64 KiB pieces
fn streamed_chat_restore_keeps_large_text() {
    let h = start(C);
    // 3 MiB of `\"` in `b`: the held text is within HOLD_MAX; one rebuilt delta of it would escape to about 6 MiB.
    let b = "\"".repeat(3 << 19);
    let text = json!({"a":null,"b":b}).to_string();
    let want = json!({"b":b}).to_string();
    let mut chunks: Vec<Value> = text.as_bytes().chunks(60_000).map(|p| chunk(json!({"content":std::str::from_utf8(p).unwrap()}), Value::Null)).collect();
    chunks.push(chunk(json!({}), json!("stop")));
    h.reply_with(200, SSE, chat_sse(&chunks));
    let mut req = codex_request("first-turn");
    req["text"]["format"] = json!({"type":"json_schema","name":"out","schema":{"type":"object",
        "properties":{"a":{"type":"string"},"b":{"type":"string"}},"required":["b"],"additionalProperties":false}});
    let (s, _, body) = h.post(R, &req);
    assert_eq!(s, 200, "{}", String::from_utf8_lossy(&body[..body.len().min(512)]));
    // The null filter is armed on the output schema: `a` was made required (and nullable) upstream.
    let up = h.upstream_bodies().pop().unwrap();
    assert_eq!(up["response_format"]["json_schema"]["schema"]["required"], json!(["b", "a"]), "{}", up["response_format"]);
    let evs = events(&body);
    assert_eq!(terminals(&evs).len(), 1, "{:?}", names(&evs));
    assert_eq!(evs.last().unwrap().0, "response.completed", "{:?}", terminals(&evs));
    let items = done_items(&evs);
    let msg = items.iter().find(|i| i["type"] == "message").expect("a message item");
    assert_eq!(msg["content"][0]["text"], json!(want));
}

#[test] // RS-15, K§6.4.3 stream obligation 8: a JSON 2xx whose text is `"` as close to COPY_MAX as fits reaches a streamed request whole
fn streamed_json_answer_keeps_large_text() {
    let h = start(A);
    let body = |n: usize| {
        let mut m = MSG_JSON(false);
        m["content"] = json!([{"type":"text","text":"\"".repeat(n)}]);
        m["stop_reason"] = json!("end_turn");
        serde_json::to_vec(&m).unwrap()
    };
    let base = body(0).len();
    let n = (COPY_MAX - base) / 2;
    let up = body(n);
    assert!(up.len() <= COPY_MAX && up.len() + 2 > COPY_MAX, "{}", up.len());
    let req = codex_request("after-custom-tool-call-output");

    h.reply_with(200, JSON, up.clone());
    let (s, _, b) = h.post(R, &with_stream(req.clone(), false));
    assert_eq!(s, 200, "{}", String::from_utf8_lossy(&b[..b.len().min(512)]));
    let r: Value = serde_json::from_slice(&b).unwrap();
    let msg = r["output"].as_array().unwrap().iter().find(|i| i["type"] == "message").expect("a message item");
    let want = msg["content"][0]["text"].clone();
    assert_eq!(want.as_str().map(str::len), Some(n));

    h.reply_with(200, JSON, up);
    let (s, _, b) = h.post(R, &with_stream(req, true));
    assert_eq!(s, 200);
    let evs = events(&b);
    assert_eq!(terminals(&evs).len(), 1, "{:?}", names(&evs));
    assert_eq!(evs.last().unwrap().0, "response.completed", "{:?}", terminals(&evs));
    let items = done_items(&evs);
    let got = items.iter().find(|i| i["type"] == "message").expect("a message item");
    assert_eq!(got["content"][0]["text"], want);
}

## Planning notes

- The check per K-C7 (amended): each node is checked against its own diff, from `<parent>`, the parent of its layer (the top of the stack below it). No rule table: the `scripts/test-edit-rules/*.rules` mechanism of the first plan is dropped.
- Units: each file under `<top>/*/tests/` (`<top>` is `crates` or `tools`, round 1 F5), each file whose inner `cfg` requires `test`, each `#[cfg(test)]` item and each bare `#[test]` function of `<top>/*/src/` that exists at `<parent>` (round 1 F9). New files and new test items are not checked. A changed, added or removed non-`.rs` file under a `tests` folder, a changed doc-test block and a change to the check itself are offences too (round 1 F8, F7, F5).
- Bounds of a `#[cfg(test)]` module: a POSIX shell cannot find them reliably (nested braces, braces in strings and macros). The helper `zygo-test-edits` parses each file at `<parent>` and at `HEAD` (read with `git show`) with `syn` (already a workspace dependency from CF-1), and takes each item whose attributes hold a `cfg` predicate that names `test` (`cfg(test)`, `cfg(all(test, unix))`, `cfg(any(test, …))`). The script is a thin wrapper around `cargo run -q --locked -p zygo-test-edits -- "$@"` that maps an exit other than 0, 1 and 2 to 2 (round 1 F12).
- Test functions: each `fn` with an attribute whose last path segment is `test` (`#[test]`, `#[tokio::test(...)]`), named by its module path. Literals: every string, byte-string, char and number literal token in the unit, also inside macro token streams, a `-` directly before a number being part of it (round 1 F2); `#[doc]` attributes (doc comments) are skipped, so a comment edit passes, but a changed code block in doc text is a `doctest` offence (round 1 F7).
- Matching a unit at `HEAD`: a test file by `git diff -M` rename detection; a `#[cfg(test)]` module by its module path in any `src` file of the same crate (the moves of CC-3 and CC-9).
- Node file: the entries under its `## Test logic edits` heading, read at `HEAD` (round 1 F13). A node's acceptance passes the parent from the `Parent: <40-hex>` line that the node writes as the first line of its `## Plan` when it starts. **Review gate:** the reviewer confirms that the `Parent:` line is the base of the node's layer, `git merge-base HEAD <layer base branch>` recomputed after every merge into the node branch (round 2 D5), before reading the check's result; the check itself only requires an ancestor of `HEAD` other than `HEAD` (round 1 F4) and warns when `<parent>` is not `git merge-base HEAD origin/phase-4`. The review gate runs the parent's copy of the wrapper, which builds the parent's helper (round 2 D1).
- The test script builds repositories under `mktemp -d`, with no wall-clock wait (Global constraints). The check is not added to CI: the review gate of each P4-6 node runs it (K§11 item 24; Verification floor).

Definitions the implementer follows (author's calls, recorded in the graph Log; round 1 and round 2 changes marked):

- **Parent** (round 2 D5). `Parent:` is `git merge-base HEAD <layer base branch>` (`origin/phase-4` for a layer on the trunk), recomputed after every merge into the node branch. A commit of the node's own branch is a wrong parent: its diff misses the node's earlier commits. The wrapper prints the parent it used and, when `origin/phase-4` exists, warns on stderr when `<parent>` is not `git merge-base HEAD origin/phase-4` (a warning only: a stacked layer may use a lower layer).
- **Checker** (round 2 D1). `scripts/check-test-edits.sh` builds the helper from `<parent>`, not from `HEAD`: `git archive <parent>` into a temporary folder, `cargo build --locked -p zygo-test-edits` with `CARGO_TARGET_DIR` in the cache (`$ZYGO_TEST_EDITS_CACHE`, default `${XDG_CACHE_HOME:-$HOME/.cache}/zygo-test-edits`), the binary kept under the tree id of `tools/test-edits` at `<parent>`; then it runs that binary against this repository. - **Unit.** At `<parent>`, with `<top>` either `crates` or `tools` (round 1 F5): each test file (the whole file): a `.rs` file under `<top>/<c>/tests/`, under the root `tests/` (round 2 D2), or named by a manifest's `[[test]] path` (D2); each `.rs` file under `<top>/<c>/src/` whose inner attributes hold a `cfg` that requires `test` (the whole file, round 1 F9); and each top-level-most item of a `.rs` file under `<top>/<c>/src/` whose `cfg` predicate requires `test`, or that is a `fn` with a test attribute (a bare `#[test]`, round 1 F9) (an item inside such an item is part of it). A predicate requires `test` when it is `test`, or an `all(…)` or `any(…)` with an argument that requires `test` (round 1 F9: `any(test, …)` counts; `not(…)` never does). The check's own files (`tools/test-edits/`) are not units: a `checker` entry lists a change to them, their unit tests included (round 2). An out-of-line module is read from its body file, found by Rust's module path rules (`<dir>/x.rs` or `<dir>/x/mod.rs`) or by `#[path = "…"]`: `<dir>` is the folder of the declaring file for a crate root (`lib.rs`, `main.rs`, `build.rs`, `src/bin/*.rs`, a direct child of a crate's or the root's `tests/`, `benches/` or `examples/`, a manifest target `path`; round 2 D7), a `mod.rs` or a file loaded by `#[path]` (round 2), else the folder named after the file, then the inline modules. An out-of-line `#[cfg(test)] mod x;` is the unit `<file>::x` with its body file's items, literals and includes (round 1 F6); every out-of-line module declared inside a unit, at any depth, is merged into it as test code, its tests under their module path (round 2 D8). A body file that is a test file is a unit of its own and is not merged (the plan fix above); a merged body file is not a unit of its own. When no body file exists for an out-of-line test module, the offence line is `unreadable <file>::x — out-of-line test module`.
- **Fixture** (round 1 F8, round 2 D2, D6). A changed, added or removed file that is: a non-`.rs` file under any `tests/` folder (root included) or under the root `fixtures/`; a file named by `include_str!("…")` or `include_bytes!("…")` in a unit at `<parent>` or `HEAD` (resolved from the folder of the file that names it); or a `.rs` file in scope that does not parse at `<parent>` or at `HEAD`. Each gives `fixture <path>`.
- **Unit id.** `<file>` for a whole-file unit; `<file>::<item path>` for a `src` item (`tests`, `tests::inner`, `helper`). An item path names an impl by its type and trait, generic arguments left out: `impl<Type>` or `impl<Trait>for<Type>`; a `use`, a macro call with no name or an `extern` block is `<kind>#<n>`; a name that repeats at its level gets `#<n>` from the second on (round 2 D9).
- **Test function.** A `fn` with an attribute whose path's last segment is `test`. Its id is its module path inside the unit (`parses`, `inner::parses`); one id may hold several functions under different `cfg`s (round 2 D10). It is ignored when it has an attribute whose path's last segment is `ignore`, or a `cfg_attr(…)` whose attribute list holds such an attribute at any depth. Its gate (round 1 F3) is the set of its `cfg`, `cfg_attr` and `should_panic` attributes and of those of each module between it and its unit.
- **Gate** (round 2 D3, D4). A set of attributes, each as the token printer writes it (`#[cfg(all (test , unix))]`), so their order and layout do not matter. A unit's gate is its chain: its own `cfg` and `cfg_attr` attributes, those of each inline module around it, and its file's chain: the file's inner attributes and, for each `mod x;` that declares the file, the declaration's attributes (with the inline modules around it) and the declaring file's chain, up to the crate root.
- **Manifest** (round 2 D3). The test-relevant settings of a `Cargo.toml`: `[package] autotests`, every key of each `[[test]]`, and `test`, `doctest`, `harness` of `[lib]`, `[[bin]]`, `[[test]]`, `[[bench]]`, `[[example]]`. A changed manifest whose settings differ gives `manifest <path>`. The reader is a TOML subset: one key per line, full-line comments; a value that spans lines keeps its first line.
- **Literal.** Each string, byte-string, C-string, char, byte, integer and float literal in the unit, also inside macro calls and attribute token lists, keyed by its source text (`proc_macro2::Literal::to_string()`, so `"x"` and `r"x"` are different keys). A `-` token directly before a number literal is part of it: `-2` and `2` are different keys (round 1 F2). `true`/`false` are not literals here. A `doc` attribute (each `///`, `//!`, `#[doc = …]`) is skipped. Comments are not tokens.
- **Doc-test block** (round 1 F7). Each fenced block (```` ``` ```` or `~~~`, any info string) in the doc text of an item, impl item, trait item, field or variant of any `.rs` file read (`self` for a file's inner docs), keyed `<file>::<item path>` (impl names per round 2 D9).
- **Matching a unit at `HEAD`.** A whole-file unit: the same path, or the new path that `git diff -M --name-status <parent> HEAD` gives for it; no path → unmatched. A `src` item: first, in place: the same item path in the same file or its renamed file. Then, for the items still unmatched: among the `HEAD` items of `<top>/<c>/src/` (same crate folder) that matched nothing in place, the one with the most test-function ids in common (at least one), or, for an item with no test function, the one with the same item path; a tie is unmatched. An unmatched unit counts as empty at `HEAD`.
- **Offences.** For each unit at `<parent>` and its match: the unit's gate differing gives `ignore <unit id> (attributes …)`; per test id, the functions at `<parent>` and `HEAD` are paired, equal gates first, then in order (round 2 D10); each `<parent>` function left without a pair gives `removed <file>::<unit path>::<fn>` (a rename is a removal plus a new name); each pair whose `HEAD` function is newly ignored or whose gate differs gives `ignore <file>::<unit path>::<fn>` (round 1 F3, F14). Per `<parent>` file, the literal multiset of all its units against that of their matches gives `literals <file>: <delta>` when they differ. `<delta>`: the `+` items (count at `HEAD` above `<parent>`) sorted by key, then the `-` items sorted by key, each `<sign><key> x<n>`, joined by `, `. For a whole-file unit the `<unit path>::` part is empty. Also: `doctest <file>::<item path>` for each `<parent>` doc-test key with blocks whose blocks differ at `HEAD` (F7); `fixture <path>` (Fixture above); `manifest <path>` (Manifest above); `checker <path>` for each changed file under `tools/test-edits/` and each change to `scripts/check-test-edits.sh` or `scripts/test-check-test-edits.sh` (F5).
- **Node file.** Read at `HEAD` (round 1 F13). The section is the lines after a level 2 heading `Test logic edits` (closing hashes allowed) up to the next heading of level 1 or 2 (round 2 D11); a line inside a fenced block is never a heading (round 1). A line `None.` or a blank line is skipped. Every other line must be an entry: `- ` and one of the eight forms with a non-empty reason after ` — `; otherwise it is an offence `unreadable entry: <line>` (an indented, `*`, `+` or numbered item, plain text, a `###` heading or a fenced line included; round 1 F11, round 2 D11). A second section gives `duplicate section: ## Test logic edits` (D11). An entry clears the offence it names: `removed` clears `removed` of that id; `renamed <file>::<old> -> <new>` clears `removed` of `<old>` when `<new>` is a test function of the matched unit at `HEAD` and not at `<parent>`; `ignore` clears the ignore-kind offence of that id; `- literals <file>: …` clears that file's `literals` offence when the text after `<file>: ` starts with the printed `<delta>` followed by ` — `; `doctest`, `fixture`, `manifest` and `checker` clear the offence of the same text. An entry that clears no offence is an offence `not found: <line>` (K-C7: the list holds the exact change).

Author's calls (implementer, 2026-11-27; each where the plan left a choice open, the option with the least to reverse):

- **Unnamed items.** A `#[cfg(test)]` item with no identifier (`impl`, `use`, a macro call, an `extern` block) has the item path `<kind>#<n>`, the n-th unnamed item of that kind at its level. Reason: the Unit id needs a path; none exists at `036b92a2` with a literal or a test. Round 2 (D9): an impl is named by its type and trait instead.
- **Moved matching is one to one.** A `HEAD` item that an earlier `<parent>` item took is not a candidate for a later one. Reason: the per-file literal sums count each `HEAD` item once.
- **Line breaks in a delta.** A literal key that holds a line break prints it as `\n` (and `\r`) in `<delta>`, so each entry is one line. The multisets compare the raw keys.
- **Test file.** A path `<top>/<c>/tests/…` (the Unit definition), not any path with a `/tests/` segment (step 4's shorter wording), so `crates/<c>/src/tests/x.rs` stays a `src` file. Round 2 (D2): also the root `tests/…` and each `[[test]] path`.

Reason: `syn::visit` skips each `TokenStream` (macro bodies, attribute lists, `Verbatim` nodes), and syn 3 gives no `ToTokens` without `quote`, a dependency the plan does not list. One walk covers macros and attributes the same way.

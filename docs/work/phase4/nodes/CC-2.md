## Planning notes

- The check per K-C7 (amended): each node is checked against its own diff, from `<parent>`, the parent of its layer (the top of the stack below it). No rule table: the `scripts/test-edit-rules/*.rules` mechanism of the first plan is dropped.
- Units: each file under `<top>/*/tests/` (`<top>` is `crates` or `tools`, round 1 F5), each file whose inner `cfg` requires `test`, each `#[cfg(test)]` item and each bare `#[test]` function of `<top>/*/src/` that exists at `<parent>` (round 1 F9). New files and new test items are not checked. A changed, added or removed non-`.rs` file under a `tests` folder, a changed doc-test block and a change to the check itself are offences too (round 1 F8, F7, F5).
- Bounds of a `#[cfg(test)]` module: a POSIX shell cannot find them reliably (nested braces, braces in strings and macros). The helper `zygo-test-edits` parses each file at `<parent>` and at `HEAD` (read with `git show`) with `syn` (already a workspace dependency from CF-1), and takes each item whose attributes hold a `cfg` predicate that names `test` (`cfg(test)`, `cfg(all(test, unix))`, `cfg(any(test, …))`). The script is a thin wrapper around `cargo run -q --locked -p zygo-test-edits -- "$@"` that maps an exit other than 0, 1 and 2 to 2 (round 1 F12).
- Test functions: each `fn` with an attribute whose last path segment is `test` (`#[test]`, `#[tokio::test(...)]`), named by its module path. Literals: every string, byte-string, char and number literal token in the unit, also inside macro token streams, a `-` directly before a number being part of it (round 1 F2); `#[doc]` attributes (doc comments) are skipped, so a comment edit passes, but a changed code block in doc text is a `doctest` offence (round 1 F7).
- Matching a unit at `HEAD`: a test file by `git diff -M` rename detection; a `#[cfg(test)]` module by its module path in any `src` file of the same crate (the moves of CC-3 and CC-9).
- Node file: the entries under its `## Test logic edits` heading, read at `HEAD` (round 1 F13). A node's acceptance passes the parent from the `Parent: <40-hex>` line that the node writes as the first line of its `## Plan` when it starts. **Review gate:** the reviewer confirms that the `Parent:` line is the base of the node's layer (the top of the stack below it) before reading the check's result; the check itself only requires an ancestor of `HEAD` other than `HEAD` (round 1 F4).
- The test script builds repositories under `mktemp -d`, with no wall-clock wait (Global constraints). The check is not added to CI: the review gate of each P4-6 node runs it (K§11 item 24; Verification floor).

Definitions the implementer follows (author's calls, recorded in the graph Log; round 1 changes marked):

- **Unit.** At `<parent>`, with `<top>` either `crates` or `tools` (round 1 F5): each `.rs` file under `<top>/<c>/tests/` (the whole file); each `.rs` file under `<top>/<c>/src/` whose inner attributes hold a `cfg` that requires `test` (the whole file, round 1 F9); and each top-level-most item of a `.rs` file under `<top>/<c>/src/` whose `cfg` predicate requires `test`, or that is a `fn` with a test attribute (a bare `#[test]`, round 1 F9) (an item inside such an item is part of it). A predicate requires `test` when it is `test`, or an `all(…)` or `any(…)` with an argument that requires `test` (round 1 F9: `any(test, …)` counts; `not(…)` never does). A non-`.rs` file under a `tests` folder (fixtures, golden output) is not a unit; each change to one is a `fixture` offence (round 1 F8). An out-of-line `#[cfg(test)] mod x;` is read from its body file, found by Rust's module path rules (`<dir>/x.rs` or `<dir>/x/mod.rs`, `<dir>` the module folder of the declaring file and its inline modules) or by `#[path = "…"]`; the body file's items, literals and inner `cfg` attributes are the unit `<file>::x`, and the body file is not a unit of its own (round 1 F6). When the body file is under `<top>/<c>/tests/`, the module is not a unit: that file is a unit already (the plan fix above). When no body file exists, the offence line is `unreadable <file>::x — out-of-line test module`.
- **Unit id.** `<file>` for a whole-file unit; `<file>::<item path>` for a `src` item (`tests`, `tests::inner`, `helper`).
- **Test function.** A `fn` with an attribute whose path's last segment is `test`. Its id is its module path inside the unit (`parses`, `inner::parses`). It is ignored when it has an attribute whose path's last segment is `ignore`, or a `cfg_attr(…)` whose attribute list holds such an attribute at any depth. Its gate (round 1 F3) is the text of its `cfg`, `cfg_attr` and `should_panic` attributes and of those of each module between it and its unit; a unit's gate is the text of its own `cfg` and `cfg_attr` attributes (inner ones for a whole file, both for an out-of-line module).
- **Literal.** Each string, byte-string, C-string, char, byte, integer and float literal in the unit, also inside macro calls and attribute token lists, keyed by its source text (`proc_macro2::Literal::to_string()`, so `"x"` and `r"x"` are different keys). A `-` token directly before a number literal is part of it: `-2` and `2` are different keys (round 1 F2). `true`/`false` are not literals here. A `doc` attribute (each `///`, `//!`, `#[doc = …]`) is skipped. Comments are not tokens.
- **Doc-test block** (round 1 F7). Each fenced block (```` ``` ```` or `~~~`, any info string) in the doc text of an item, impl item, trait item, field or variant of any `.rs` file read (`self` for a file's inner docs), keyed `<file>::<item path>`.
- **Matching a unit at `HEAD`.** A whole-file unit: the same path, or the new path that `git diff -M --name-status <parent> HEAD -- crates tools` gives for it; no path → unmatched. A `src` item: first, in place: the same item path in the same file or its renamed file. Then, for the items still unmatched: among the `HEAD` items of `<top>/<c>/src/` (same crate folder) that matched nothing in place, the one with the most test-function ids in common (at least one), or, for an item with no test function, the one with the same item path; a tie is unmatched. An unmatched unit counts as empty at `HEAD`.
- **Offences.** For each unit at `<parent>` and its match: each test-function id missing at `HEAD` gives `removed <file>::<unit path>::<fn>` (a rename is a removal plus a new name); each test function ignored at `HEAD` and not at `<parent>`, or whose gate differs, gives `ignore <file>::<unit path>::<fn>` (with `(attributes `…` -> `…`)` when the gate differs); a unit whose gate differs gives `ignore <unit id> (attributes …)` (round 1 F3, F14). Per `<parent>` file, the literal multiset of all its units against that of their matches gives `literals <file>: <delta>` when they differ. `<delta>`: the `+` items (count at `HEAD` above `<parent>`) sorted by key, then the `-` items sorted by key, each `<sign><key> x<n>`, joined by `, `. For a whole-file unit the `<unit path>::` part is empty. Round 1: each `<parent>` doc-test key with blocks whose blocks differ at `HEAD` (in the renamed file, if any) gives `doctest <file>::<item path>` (F7); each changed, added or removed non-`.rs` file under a `tests` folder gives `fixture <path>` (F8); each changed file under `tools/test-edits/` and each change to `scripts/check-test-edits.sh` or `scripts/test-check-test-edits.sh` gives `checker <path>` (F5).
- **Node file.** Read at `HEAD` (round 1 F13). The lines under the `## Test logic edits` heading up to the next `## ` heading; a line inside a fenced block is never a heading (round 1). A line `None.` or a blank line is skipped. Each line that starts with `- ` must be one of the seven forms with a non-empty reason after ` — `; otherwise it is an offence `unreadable entry: <line>`. A list item in another form (indented, or with `*` or `+`) and a fenced line inside the section are also `unreadable entry` offences (round 1 F11). An entry clears the offence it names: `removed` clears `removed` of that id; `renamed <file>::<old> -> <new>` clears `removed` of `<old>` when `<new>` is a test function of the matched unit at `HEAD` and not at `<parent>`; `ignore` clears the ignore-kind offence of that id; `- literals <file>: …` clears that file's `literals` offence when the text after `<file>: ` starts with the printed `<delta>` followed by ` — `; `doctest`, `fixture` and `checker` clear the offence of the same text. An entry that clears no offence is an offence `not found: <line>` (K-C7: the list holds the exact change).

Author's calls (implementer, 2026-11-27; each where the plan left a choice open, the option with the least to reverse):

- **`renamed` entry.** `<new>` is the function's id inside the matched unit (`other_renamed`, `inner::x`), not a full id: the Offences definition reads it as "a test function of the matched unit". Reason: one form, and the file and unit are already in `<old>`.
- **Unnamed items.** A `#[cfg(test)]` item with no identifier (`impl`, `use`, a macro call, an `extern` block) has the item path `<kind>#<n>`, the n-th unnamed item of that kind at its level. Reason: the Unit id needs a path; none exists at `036b92a2` with a literal or a test.
- **Moved matching is one to one.** A `HEAD` item that an earlier `<parent>` item took is not a candidate for a later one. Reason: the per-file literal sums count each `HEAD` item once.
- **Line breaks in a delta.** A literal key that holds a line break prints it as `\n` (and `\r`) in `<delta>`, so each entry is one line. The multisets compare the raw keys.
- **Test file.** A path `<top>/<c>/tests/…` (the Unit definition), not any path with a `/tests/` segment (step 4's shorter wording), so `crates/<c>/src/tests/x.rs` stays a `src` file.
- **Literal walk.** The helper cuts each item's own token trees with syn's parse cursor and walks them (groups included, `doc` attributes skipped) instead of `syn::visit`. Reason: `syn::visit` skips each `TokenStream` (macro bodies, attribute lists, `Verbatim` nodes), and syn 3 gives no `ToTokens` without `quote`, a dependency the plan does not list. One walk covers macros and attributes the same way.
- **`Unit` has more fields** than step 4 names: `outline` and `targets` (out-of-line modules), `gate` (round 1 F3); `tests` maps each id to a `TestFn { ignored, gate }`.
- **A file that does not parse at `<parent>`** is an `unreadable <file>` offence too, as at `HEAD`; **a git failure after the argument checks** exits 2 with git's message on stderr: it is not a pass, and not an offence list.
- **Extra unit tests** (step 2 names ten): 14 more, each named for its rule; 24 in all.
- **Round 1, F3 reading of K-C7.** K-C7 fails a node "when `#[ignore]` is added". A `cfg` that can turn a test off at compile time stops it from running as `#[ignore]` does, so the check reads a changed `cfg` or `cfg_attr` attribute on a test function, on a module that holds it, on a unit item or on a test file (inner `#![cfg(…)]`) as an ignore-kind offence. `should_panic` (F14 exception) is in the same gate: adding, removing or changing it changes what the test asserts. The entry `- ignore <id>` lists either.
- **Round 1, F9 inner `cfg`.** Any inner `cfg` that requires `test` makes a `src` file a whole-file unit, not only the first inner attribute (the finding's wording). Reason: a superset; an inner `#![allow]` before `#![cfg(test)]` changes nothing about the file.
- **Round 1, F7 scope.** Every fenced block counts, whatever its info string (`text`, `ignore` and `no_run` too), in every `.rs` file read (`src` and `tests`; a binary crate's docs too). A key that has blocks at `<parent>` is checked; a new block on an item with none is a new doc test, not checked (as new tests are not). Indented (four-space) code blocks are not read (none in doc comments at `9b030436`; recorded as a limit). A `#[doc = include_str!(…)]` attribute counts as its macro text, so a changed path is seen but a changed included file is not (none at `9b030436`).
- **Round 1, fenced lines in the node file.** A heading inside a fenced block is text (the probe `entry-in-fence-elsewhere`); a fenced block inside `## Test logic edits` makes each of its lines an `unreadable entry` (fail closed).
- **Round 1, F5 self-check.** This node lists its own four checker files under `## Test logic edits`, so the check passes on this node's own diff.

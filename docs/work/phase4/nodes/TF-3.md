# TF-3 — check-premises.sh: no bash warning on a binary file in the name scan

**Spec:** none (CI and dev-host defect); found by the TF-2 round 2 implementer (author's call, 2026-11-26)
**Files:** `scripts/check-premises.sh` (`name_scan` only), `scripts/test-check-premises.sh` (the new bash cases and the optional shell argument of `run_names` only)
**Consumes:** —
**Produces:** `scripts/check-premises.sh` gives the same output under `dash`, bash 3.2 and bash ≥4.4 on a binary file in the scan scope; `scripts/test-check-premises.sh` runs the binary-file cases under `bash` too
**Acceptance:** each command run alone from the repository root, on a host where `/bin/sh` is bash ≥4.4 and `dash` is not installed (for example the dev host of 2026-11-26: `/bin/sh` → `/usr/bin/bash`, GNU bash 5.3.20, `command -v dash` fails): `bash scripts/test-check-premises.sh` → exit 0; `sh scripts/test-check-premises.sh` → exit 0; `N2_FORBIDDEN_NAMES=zzcinameq sh scripts/check-premises.sh` → exit 0; then the CI run of the node's pull request is green on ubuntu, macOS and Windows (the TF-2 premise steps run on ubuntu and macOS).

## Planning notes

- The defect (2026-11-26, `phase-4` at `4c69d718`; reproduced on the dev host, `/bin/sh` is bash 5.3.20, no `dash`): `sh scripts/test-check-premises.sh` fails case "H1: a binary file with a forbidden name" (`scripts/test-check-premises.sh:898-902`; `:915` after TF-2).
  - `scripts/check-premises.sh:431`, in `name_scan`: `hit=$( (grep -rnaiE -- "$rx" $SCOPE "$P" 2>/dev/null; printf '%s\n' "$NOTES" | grep -aiE -- "$rx") | grep -av -E -- "${4:-^\$}" | head -n 1)`. `grep -a` gives the hit line of the binary file with its NUL byte to the command substitution. Bash ≥4.4 removes the NUL and writes `scripts/check-premises.sh: line 431: warning: command substitution: ignored null byte in input` to stderr.
  - `scripts/test-check-premises.sh` `run_names` (`:112` on `phase-4`; `:128` after TF-2) runs the script with `2>&1` into `OUT`. `expect_fail` compares all of `OUT` with one line, so the warning line makes the case fail.
  - Reproduction of H1 alone (a copy tree as `mk` makes it, `printf 'a\0b alice\n' > fixtures/codex/bin.dat`, then `N2_FORBIDDEN_NAMES=alice bash scripts/check-premises.sh 2>&1`): exit 1 and two lines, the warning, then `check-premises: forbidden name from N2_FORBIDDEN_NAMES: fixtures/codex/bin.dat:1`. The same with `sh`. The result line is correct; only the warning is extra.
- CI does not see it: `ubuntu-latest` runs `sh` as `dash`, which drops the NUL with no message; `macos-latest` runs `sh` as bash 3.2, which drops it with no message. No CI step runs the scripts under bash ≥4.4.
- The other scans already change a NUL to a blank before the command substitution reads it: `scan` (`:292-293`, `tr '\000' ' '`), `cx_scan` (`:334`), `env_scan` (`:367`). `name_scan` is the only one with no `tr`. `NOTES` (`:283`) reads only the base spec and `docs/conformance.md` (text). The host-name scan (`:451`) also calls `name_scan`, so the fix covers it too.
- The fix must keep the scan result the same: a forbidden name in a binary file is still found, and the message is still `<label>: <path>:<line>` (`cut -d: -f1-2`, `:432`). The `tr` goes after the exempt filter (`grep -av -E -- "${4:-^\$}"`), so the exempt lines (`$VX`) are the same; a NUL is outside the word class of `rx`, so a hit line stays a hit line. A test of the fix in a scratch copy on 2026-11-26: with the `tr`, bash gives one line, `check-premises: forbidden name from N2_FORBIDDEN_NAMES: fixtures/codex/bin.dat:1`, exit 1; with no binary file, `N2_FORBIDDEN_NAMES=zzcinameq bash scripts/check-premises.sh` → `check-premises: ok (…)`, exit 0.
- Depends on TF-2: TF-2 changes `scripts/test-check-premises.sh` (`tick` in `run` and `run_names`) and adds the CI premise steps that run this script; TF-3 branches from the top of the stack above TF-2. The line numbers after TF-2 are given where they differ.
- The new test cases call `bash` by name, so they fail before the fix on every host with bash ≥4.4 (ubuntu CI too), not only where `/bin/sh` is bash. On macOS CI (bash 3.2) they pass before and after the fix. `bash` is on every CI runner and dev host that runs this script; a host with no `bash` fails the cases (exit 127), it does not skip them.
- No registry standard text, tier, bar exception or boundary exception list changes; no operator stop.

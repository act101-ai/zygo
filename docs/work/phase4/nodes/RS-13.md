# RS-13 — Streamed JSON answer: a tool_use input reaches the encoder in input_json_delta pieces within HOLD_MAX

**Spec:** docs/specs/2026-11-25-client-model-design.md K§6.4.3 (stream obligation 8: a streamed request answered by a JSON body gets the same content; its tool_use input in `input_json_delta` pieces of at most 64 KiB; obligation 9 bounds unchanged); change-log line "RS-10 review F3"
**Files:** `crates/zygo-proxy/src/translate/sse.rs`, `crates/zygo-proxy/tests/translate.rs`, `crates/zygo-proxy/tests/responses_forward.rs`
**Consumes:** `message_events` (RS-10)
**Produces:** `message_events(m: &Value) -> Vec<SseEvent>` (signature unchanged): a `tool_use` block gives `content_block_start` with `input: {}`, then its input serialized once as compact JSON in `input_json_delta` events of at most `INPUT_DELTA_MAX` (64 KiB) of `partial_json` each, cut on a character boundary, then `content_block_stop`; other block arms as RS-10 leaves them
**Acceptance:** `CARGO_INCREMENTAL=0 cargo test -p zygo-proxy --locked --test responses_forward -- --list | grep -q '^streamed_json_answer_keeps_large_tool_input: test$' && cargo test -p zygo-proxy --locked` → exit 0. The test, written first and failing on the RS-10 tree with `response.failed` "upstream event too long", sends a streamed Responses request to an Anthropic upstream that answers 2xx with a JSON body of at most 4 MiB holding one tool_use whose input is `{"a": "\"" × 1.5 MiB}`; it passes when the stream ends in `response.completed` and the `function_call` item's `arguments` equal those of the non-streamed Response for the same body

The SSE then goes through two stages. First the key-scrub stage (`Streamed`, `forward.rs:1195-1262`): it holds event `data` up to `HOLD_MAX` and fails with `upstream event too long`. Then the encoder (`responses_client.rs:1165-1183`, `hold`).
- Input `{"a": "\"" × 1.5 MiB}`: the body holds about 3 MiB, within `COPY_MAX` = 4 MiB. One delta escapes the input a second time, so the event `data` is about 6 MiB, more than `HOLD_MAX` = 4 MiB. With 64 KiB pieces, each event is at most about 128 KiB plus framing. The encoder holds the 3 MiB compact arguments plus one event, within `HOLD_MAX`.
- A chat upstream's `arguments` string is parsed to `input` before `message_events` (`translate/chat.rs:135`, `input_of`). So RS-13 changes one arm only.
- `str::floor_char_boundary` is stable on the pinned toolchain (1.98). The crate already uses it (`session.rs:306`).
- No review-focus line is assigned to RS-13. CI runs no clippy or fmt job (`.github/workflows/ci.yml`).

#[test] // RS-13, K§6.4.3 stream obligation 8: a JSON 2xx whose tool_use input is 1.5 MiB of `"` reaches a streamed request whole
fn streamed_json_answer_keeps_large_tool_input() {
    let h = start(A);
    let mut m = MSG_JSON(false);
    m["content"] = json!([{"type":"tool_use","id":"toolu_1","name":"exec_command","input":{"a":"\"".repeat(3 << 19)}}]);
    let up = serde_json::to_vec(&m).unwrap();
    assert!(up.len() <= COPY_MAX, "{}", up.len());
    let req = codex_request("after-custom-tool-call-output");

    h.reply_with(200, JSON, up.clone());
    let (s, _, b) = h.post(R, &with_stream(req.clone(), false));
    assert_eq!(s, 200, "{}", String::from_utf8_lossy(&b[..b.len().min(512)]));
    let r: Value = serde_json::from_slice(&b).unwrap();
    let fc = r["output"].as_array().unwrap().iter().find(|i| i["type"] == "function_call").expect("a function_call item");
    let want = fc["arguments"].clone();
    assert!(want.as_str().is_some_and(|a| a.len() > 3 << 20), "{}", want.as_str().map_or(0, str::len));

    h.reply_with(200, JSON, up);
    let (s, hd, b) = h.post(R, &with_stream(req, true));
    assert_eq!(s, 200);
    assert!(hv(&hd, "content-type").starts_with(SSE), "{hd:?}");
    let evs = events(&b);
    assert_eq!(terminals(&evs).len(), 1, "{:?}", names(&evs));
    assert_eq!(evs.last().unwrap().0, "response.completed", "{:?}", terminals(&evs));
    let items = done_items(&evs);
    let got = items.iter().find(|i| i["type"] == "function_call").expect("a function_call item");
    assert_eq!(got["arguments"], want);
}

#[test] // RS-13, K§6.4.3 stream obligation 8: input_json_delta pieces of at most INPUT_DELTA_MAX, cut on a char boundary
fn message_events_cuts_tool_input_on_char_boundaries() {
    // Compact input `{"a":"` + c × n + `"}`: the first cut is the longest 6 + k·len(c) <= INPUT_DELTA_MAX.
    for (c, n, first) in [('a', 200_000, INPUT_DELTA_MAX), ('€', 50_000, INPUT_DELTA_MAX - 1), ('😀', 40_000, INPUT_DELTA_MAX - 2)] {
        let input = json!({"a": c.to_string().repeat(n)});
        let m = msg_body(json!([{"type":"tool_use","id":"toolu_1","name":"exec_command","input":input}]));
        let evs = message_events(&m);
        assert_eq!(evs[1].data, json!({"type":"content_block_start","index":0,
            "content_block":{"type":"tool_use","id":"toolu_1","name":"exec_command","input":{}}}));
        let deltas: Vec<&Value> = evs.iter().filter(|e| e.event == "content_block_delta").map(|e| &e.data).collect();
        assert!(deltas.iter().all(|d| d["index"] == 0 && d["delta"]["type"] == "input_json_delta"), "{c}");
        let pieces: Vec<&str> = deltas.iter().map(|d| d["delta"]["partial_json"].as_str().unwrap()).collect();
        assert!(pieces.len() > 1, "{c}");
        assert_eq!(pieces[0].len(), first, "{c}");
        assert!(pieces.iter().all(|p| !p.is_empty() && p.len() <= INPUT_DELTA_MAX), "{c}");
        assert!(pieces[..pieces.len() - 1].iter().all(|p| p.len() > INPUT_DELTA_MAX - 4), "{c}");
        assert_eq!(pieces.concat(), input.to_string(), "{c}");
        assert_eq!(evs[evs.len() - 3].data, json!({"type":"content_block_stop","index":0}));
    }
}

#[test] // RS-13: an empty input `{}`, and a tool_use with no input, is one input_json_delta `{}`
fn message_events_empty_tool_input_one_piece() {
    let m = msg_body(json!([{"type":"tool_use","id":"toolu_1","name":"exec_command","input":{}},
        {"type":"tool_use","id":"toolu_2","name":"exec_command"}]));

        json!({"type":"content_block_delta","index":1,"delta":{"type":"input_json_delta","partial_json":"{}"}}),
    ]);
}

#[test] // RS-13, K§6.4.3 stream obligations 8 and 9: 1.5 MiB of `"` passes the encoder; each event stays under 2 × INPUT_DELTA_MAX plus framing
fn message_events_large_tool_input_within_hold_max() {
    let input = json!({"a": "\"".repeat(3 << 19)});
    let m = msg_body(json!([{"type":"tool_use","id":"toolu_1","name":"exec_command","input":input}]));
    let evs = message_events(&m);
    let longest = evs.iter().map(|e| e.to_bytes().len()).max().unwrap();
    assert!(longest < 2 * INPUT_DELTA_MAX + 256, "{longest}");
    let (out, codes) = encoded(&m);
    assert_eq!(out.last().unwrap().event, "response.completed", "{:?}", out.last().unwrap().data);
    let items: Vec<&Value> = out.iter().filter(|e| e.event == "response.output_item.done").map(|e| &e.data["item"]).collect();
    assert_eq!(items.len(), 1);
    assert_eq!(items[0]["type"], "function_call");
    assert_eq!(items[0]["arguments"], input.to_string());
    assert!(codes.is_empty(), "{codes:?}");
}

### Decisions (author's call)

- **Flat name.** `flat_name(ns, name)` = `<ns>__<name>` when that string is 1-64 characters of `[A-Za-z0-9_-]`. Otherwise: `<ns>__<name>` with each character outside that set replaced by `_`, cut to its first 47 characters, then `_`, then the first 16 hex digits (lowercase) of SHA-256 of `<ns>` + U+0000 + `<name>` (at most 64 characters). Why: the plain form is how Codex named MCP tools before 0.172 (`mcp__<server>__<tool>`) and reads well to the model; a pure function of the pair gives a definition and a history call the same name with no proxy state (K-C1); the hashed form keeps any client string valid, bounded and distinct.
- **Reverse by table, never by parsing.** Namespace names hold `__` (`mcp__zygo`), so `mcp__zygo__compact` cannot be split. `Calls::of` builds flat → (namespace, name) from the request's `namespace` tools and its namespaced `function_call` history items; `Calls::item` looks the model's name up.
- **Collision.** A flat name equal to another sent tool's name (top-level, or another flat name: `a__b`/`c` against `a`/`b__c`) is the existing duplicate-name 400 (obligation 6). Fail closed; no capture shows one.
- **Nested types.** A nested `function` flattens. Another nested type is dropped and counted as a top-level one is (`tools_dropped:<type>:<n>`): no capture shows one, and no premise says how its call returns. A `namespace` with no string `name` → `400 "namespace tool: missing name"`; with no `tools` array → `400 "namespace tool: missing tools"`. The namespace's own `description` is not sent (no Messages place; each nested tool keeps its own).
- **History.** A `function_call` with a string `namespace` becomes a `tool_use` named `flat_name(namespace, name)`; a `namespace` that is not absent, `null` or a string → `400 "function_call: namespace must be a string"`. `function_call_output` is unchanged.
- **tool_choice.** `{"type":"function","name":n,"namespace":ns}` (string `ns`) names `flat_name(ns, n)`. With no `namespace`, `n` is matched as sent, so the flat name also works; a bare nested name is not sent → the existing 400.
- **Lead's decisions (2026-11-25, on the planner's open points).** Collision → the existing duplicate-name 400 (fail closed). `tool_choice` accepts `{type:"function", name, namespace}` and the flat name (no capture shows Codex's form). A nested tool that is not `function` is dropped and counted. Note for RS-4: RS-4 must build the encoder from `Calls::of(&client_body)` (the client's Responses body, not the translated one), or the namespace table is empty and calls return under the flat name.
- **tools_from_history.** No code change: history names are flat, so they match flat definitions. A namespaced call whose namespace is no longer sent is declared `history only` under its flat name and still maps back (the table takes it from the history item).

### Review focus

- Every site that names a tool agrees on the flat name: `tools`, the history `function_call` arm, `tool_choice`, `history_tools`, `Calls::of`; one function, `flat_name`, computes it.
- The reverse map is a table lookup; no code splits a name on `__`.
- Hostile names (non-ASCII, control characters, 10 KB names, an empty namespace) give a valid name of at most 64 characters or a 400, never a panic.
- `Calls::of` and `request` read the same fields, so an item maps back only to a pair the request sent.
- The seam with RS-3 (PR #157): in this file RS-3 changes only `cut`'s visibility (`:73`); in the spec it adds a K§6.4.3 "Candidates" paragraph and change-log lines. A merge keeps both.

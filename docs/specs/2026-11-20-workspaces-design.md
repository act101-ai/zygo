## 1. Intent

The operator runs several agents in tmux. The operator must stop them for two reasons:

1. **Reason 1:** to free resources, so that the operator can use the workstation for other work.
2. **Reason 2:** to restart the coding harness after an upgrade (for example, a new Claude Code version).

Today zygo cannot pause or resume. A zygo session is one launch of one agent (§5). At exit the launcher deletes `~/.cache/zygo/sessions/<ULID>/` except `results/` (`crates/zygo-launch/src/launcher.rs:599-624`, §8.2 step 6). zygo does not record the agent's own session id. Thus, after a stop, the operator must find each conversation again by hand and rebuild the tmux layout by hand.

With elephant-goldfish (§9), a lead agent is usually idle at its prompt while its subagents work. The operator, or an agent that the operator tells to, runs `zygo down`.

Phase 2 adds **workspaces**. `zygo down` waits until each agent of one repository has ended its turn and its subagents (the drain), then saves the state and stops the agents. `zygo up` brings back the tmux layout and resumes each agent in its own conversation, with its saved launch flags, its session overrides and its compaction override (OP12).

## 2. Goals

- **W-G1** `zygo up` creates or restores one tmux session per repository, with its layout and its agents.
- **W-G2** `zygo down` drains, then saves and stops all agents of the workspace.
- **W-G3** `zygo up` after `zygo down`, after a reboot, or after a crash of the tmux server resumes each agent in its own conversation.
- **W-G4** A loadout in user config sets the first layout and the agent panes of a workspace.
- **W-G5** CLI verbs list, attach, and forget workspaces.
- **W-G6** No daemon. tmux is the only long-lived process.

## 3. Non-goals

These items are out of scope for phase 2 **(operator)**. Reason: the scope is reduced. Elephant-goldfish subagents make a cross-agent coordination layer unnecessary for now. Each item can return in a later phase.

- A supervisor daemon.
- Messages between agents, and wake of one agent by another.
- Triggers (actions that start on an event).
- Git modes (four modes in an earlier draft) and automatic worktree management. zygo does not create, delete, or switch worktrees.
- Pools and slots of agents.
- Toasts (desktop notifications).
- Restart briefs (text that zygo writes for a fresh restart).
- Separate `pause` and `resume` verbs. `down` and `up` do this work **(operator, OP1)**.
- Workspaces on native Windows **(operator, OP5)**.
- Restore of non-agent commands. zygo never runs a saved shell command again **(operator, OP8)**.
- A change to the current work item. Today the explicit setting is shared in the git common dir (`crates/zygo-work/src/current.rs:66-67`), and detection reads the branch of the checkout that holds the cwd (`current.rs:102-107`), so detection can already differ per worktree. Phase 2 keeps both. A per-worktree setting is related work for a later phase.
- Changes to the usage store schema (§14).

## 4. Constraints

- **W-C1** The base constraints C1-C10 (§4) apply. C6 applies to every new hook: a hook never breaks the agent.
- **W-C2** No daemon (§7.1, A2, §18.3). tmux holds the processes; zygo runs only when a verb, a hook, or a pane starts it.
- **W-C3** zygo sets tmux options and hooks only on its own sessions. zygo never sets a global tmux option or a global hook.
- **W-C4** Every state write is atomic: write a temporary file, then rename it.
- **W-C5** A cloned repository cannot start an agent or a command through a workspace. Loadouts come from user config only.
- **W-C6** `zygo claude` and `zygo opencode` outside a workspace stay a clean v1 launch **(operator, OP9)**.
- **W-C7** The workspace state holds no secret and no content: no session token, no provider key, no URL user info, no prompt text, no conversation content, no subagent description, and no inline value (JSON text or URL) of an agent flag (AU30). W§7.2 lists every field.
- **W-C8** No user-controlled text reaches a tmux argument that tmux expands as a format, unescaped (AU55, AU54).
- **W-C9** zygo never resumes a conversation whose launcher is still live (AU87).

## 5. Glossary additions

§5 "Session: one launch of one agent" does not change. A resumed agent is a new zygo session with the same agent conversation.

| Term | Meaning |
|---|---|
| Workspace | One git repository, identified by its git common dir. The main checkout and all linked worktrees are one workspace **(operator, OP2)**. |
| Workspace session | The tmux session of a workspace, named `zygo-<name>`. One per workspace **(operator, OP3)**. |
| Workspace id | The first 16 hex characters of SHA-256 of the canonical common-dir path. Form: `^[0-9a-f]{16}$` (AU2, AU84). |
| Pane key | A stable id that zygo gives each pane of a workspace session: `k` plus 8 random characters of lower-case base32. Form: `^k[a-z2-7]{8}$` (AU84). It stays the same after a restore. tmux pane ids (`%N`) change. |
| Member | The agent slot of one pane key. A member runs one zygo agent session at a time; its record (`member` in W§7.2) persists across zygo sessions, so the next `up` can resume it. |
| Agent session id | The agent's own conversation id (Claude Code `session_id`, OpenCode `sessionID`). zygo uses it to resume. Not the zygo session id (ULID). |
| Live launcher | A launcher whose session directory passes `session_dir::live` (`crates/zygo-core/src/session_dir.rs:13-17`): it holds the lock on its `pid` file. |
| Loadout | A named layout plus its panes, in user config **(operator, OP10)**. "Profile" stays the model profile (§11). |
| Loadout pane | One `[[loadout.<name>.window.pane]]` entry (W§11): an agent pane or a shell pane. |
| Snapshot | The saved state of a workspace: layout, panes, cwds, and member records. |
| Drain | The wait in `zygo down` until each member's turn and its subagents end. |
| Detached member | A member record whose pane key is not in the saved layout. `up` does not recreate it (W§7.5). |
| Builder | The person or agent who implements this design. |
| Brief | The task text that started this document. W§20 lists where the repository contradicts it. |

## 6. Decided approach

### 6.1 Parts

```
 operator, or an agent the operator tells to
        │  zygo up | down | ls | attach | loadout | ws forget
        ▼
 ┌──────────────────────────────────────────────────────────────────┐
 │ zygo CLI (crates/zygo/src/cmd)                                   │
 │   └─ crates/zygo-workspace: identity, state store, lock,         │
 │      snapshot, loadout resolution, drain, Multiplexer trait      │
 │      └─ Tmux impl ── tmux -S <absolute socket path> ──┐          │
 └───────────────────────────────────────────────────────┼──────────┘
                                                         ▼
 ┌────────────────────── tmux server ───────────────────────────────┐
 │ session zygo-<name>   env ZYGO_WORKSPACE=<id>   option @zygo-ws  │
 │  hooks (this session only) ── run-shell ──▶ zygo ws snapshot     │
 │  ┌─ pane @zygo-pane=k1 ───────────┐  ┌─ pane @zygo-pane=k2 ─────┐ │
 │  │ zygo ws run (argv, no shell)   │  │ zygo ws run --shell      │ │
 │  │  └─ launcher (§8.2) + proxy    │  │  └─ exec $SHELL in cwd   │ │
 │  │      └─ claude --resume <id>   │  └──────────────────────────┘ │
 │  │          hooks: SessionStart,  │                               │
 │  │          UserPromptSubmit,     │──▶ zygo hook workspace        │
 │  │          PreToolUse Agent,     │                               │
 │  │          Stop, StopFailure,    │                               │
 │  │          SubagentStart/Stop    │                               │
 │  │  then exec $SHELL              │                               │
 │  └────────────────────────────────┘                               │
 └───────────────────────────────────────────────────────────────────┘
                                                      │ atomic writes under lock
                                                      ▼
 ~/.local/state/zygo/workspaces/<id>/workspace.json   (snapshot, members)
 ~/.cache/zygo/sessions/<ULID>/activity.json           (turn and subagent state)
 ~/.cache/zygo/sessions/<ULID>/results ──symlink──▶ ~/.cache/zygo/workspaces/<id>/results/<pane key>/
```

| AU26 | Idle rule (W§9.3 step 5). A member is idle when all three are true: (1) `busy` is `false`: a `Stop` or `StopFailure` came after the last `UserPromptSubmit`; (2) its running set (`SubagentStart`/`SubagentStop`) is empty; a `SubagentStop` with no matching `SubagentStart` (internal agents, empty `agent_type`; PW7 7.5) does not change the running set; (3) its proxy reports no model request in flight and none that ended in the last 10 s (AU91). A request in flight makes the member busy whatever `last_request_end` holds. A `last_request_end` that is 10 s or less after the poll time counts as a request that just ended. Rule 3 is skipped when the proxy status has no `requests_in_flight` field (an older team server), or when no request is in flight and `last_request_end` is not an RFC 3339 time or is more than 10 s after the poll time; `down` then prints this line once for the member: `zygo: <member>: proxy request state not usable; idle rule 3 skipped`. A proxy status that cannot be read is not a skip: the member is busy with the reason `proxy status not read: <error>`. A missing `activity.json` reads as `busy` `false` and an empty running set (W§9.1); an `activity.json` that cannot be read or parsed makes the member busy with the reason `activity file unreadable: <error>`. Running tool (W10 round 3, busy over idle): a member whose main loop has a running tool (`tools_running` above 0, W§9.1) is busy with the reason `tool running`, whatever `busy` holds and whatever time passes: a tool call sends no model request. Open turn (FIX-20, operator 2026-11-22: no invented requirement may end user work): a member whose `busy` is `true` and whose main loop runs no tool is busy at every poll, whatever time passes; no quiet time counts it as idle. Known limit: a turn ended with Esc gives no `Stop` or `StopFailure` (PW7 7.2), so `busy` stays `true`. The member then stays busy until a `Stop` or `StopFailure` comes (a `Stop` comes at the end of the turn of a next prompt, if one comes; without one the turn stays open until the drain timeout or `down --now`), until its agent exits (a member whose launcher is not live counts as idle, W§9.3 step 5), or until the drain timeout, where `down` writes `phase = up` again with no work lost, stops nothing, lists the member with `no Stop since its last prompt` and exits 1; `down --now` is the operator's explicit override. Known limit: a turn that starts with no `UserPromptSubmit` (for example, when a background task ends) and runs a tool for more than 10 s without a model request can look idle. Known limit: an Esc during a tool fires no hook (P-N24-1, `docs/live-checks.md`: an interrupted command fires neither `PostToolUse` nor `PostToolUseFailure`), so `tools_running` stays above 0. The member then stays busy until its next `UserPromptSubmit`, `Stop` or `SessionEnd`, each of which sets the count to 0; else `down` reaches its drain timeout, writes `phase = up` again with no work lost and exits 1, and `down --now` stops it. A lost `PostToolUse` (its hook did not get `activity.lock` within its bound, AU56), and a tool call that another `PreToolUse` hook denied after the count went up, do the same. Known limit: a hook that does not get `activity.lock` within its 1 s bound loses its change (AU56): a lost `SubagentStop` keeps the member busy until the drain timeout, and a lost `SubagentStart` hides that subagent from rule 2. An `activity.json` that cannot be read or parsed, or that is larger than 1 MiB, stays busy: no hook replaces it, and no hook writes a result larger than 1 MiB (AU56). Known limit: an `activity.json` that does not parse is never rewritten, so the member counts busy for the rest of the agent run: every graceful `down` waits the drain timeout and exits 1 until `down --now` or the agent exits (a session folder is never reused, so this ends with the agent). Known limit: with hostile id sizes a `Stop` or a `SubagentStart` can be refused (AU56): the member stays busy until the next accepted `Stop`, or a background subagent is not seen by rule 2. A `/zygo:` line that the prompt hook consumes as a verb never reaches the model, except when its verb panics (W§9.1 `UserPromptSubmit` row), so `workspace --event prompt` does not change `activity.json` for it (a verb line such as `/zygo:status` starts no turn); a line that the prompt hook passes to the model sets `busy = true`. Both hooks use the same rule (`prompt::consumes`). The `zygo` binary registers the dispatch before any hook runs, so every `/zygo:` line that `prompt::consumes` accepts is consumed; other lines (for example a leading space or an unknown form) pass to the model and mark the member busy. Known limit: when the `zygo hook prompt` process is killed from outside before it decides (for example by Claude Code's hook timeout), Claude Code sends the line to the model and that turn is not marked busy. ## 7. State

### 7.1 Location and files

`paths.rs` derives every directory from `$HOME` on unix and does not read `XDG_*` variables (`crates/zygo-core/src/paths.rs:27-35`). The new directories follow that rule **(author)**:

| Path | Content |
|---|---|
| `$HOME/.local/state/zygo/workspaces/<id>/workspace.json` | The snapshot and member records (W§7.2). `0600`. |
| `…/<id>/lock` | Short write lock (fs4, as `session_dir::live`). |
| `…/<id>/op.lock` | Held by an `up` or `down` process for its whole life. A free lock while `phase` is `building`, `draining` or `stopping` means that process died. |
| `…/<id>/snapshot.pending` | A snapshot that must run later. A snapshot sets it when it cannot get `lock` within its wait, when its shrink reads stay unstable (AU89), or at its second `snapshot_seq` conflict (W§7.4 step 4). It holds `force` when a forced snapshot set it, else nothing (W§7.3). |
| `…/<id>/down.log` | Output of a detached `down` (AU97). |
| `$HOME/.local/state/zygo/down-all.log` | Output of a detached `down --all` (AU97). |
| `…/<id>/errors.log` | One line per failed hook or snapshot write. At most 64 KiB. |
| `$HOME/.cache/zygo/workspaces/<id>/results/<pane key>/` | Results of a member, linked from each of its sessions (AU16). |
| `$HOME/.cache/zygo/sessions/<ULID>/activity.json` | Turn and subagent state from the workspace hook (W§9.1). |
| `$HOME/.cache/zygo/sessions/<ULID>/activity.lock` | fs4 lock for changes to `activity.json` (AU56). |

New `Paths` methods (not fields, so no `Paths` literal changes): `state_dir()`, `workspaces_dir()` = `state_dir()/workspaces`, and `workspace_cache_dir()` = `cache_dir/workspaces`. `state_dir()` is `$HOME/.local/state/zygo` when `data_dir` is `$HOME/.local/share/zygo` (as `Paths::from_env` sets it on unix), and `data_dir/state` otherwise, so a `Paths` built by a test keeps its state under its own directory. ### 7.3 Writes and the lock

- Every write reads `workspace.json`, changes it, and writes it with `write_atomic` (W-C4). `write_atomic` (`crates/zygo-core/src/session_dir.rs:107-123`, now `pub(crate)`; make it public) creates a `tempfile::NamedTempFile` in the same directory, sets mode `0600`, syncs it, and renames it over the target with `persist`. On an error the temporary file is deleted when it is dropped. Only a process that dies between create and rename leaves a `.tmp*` file; the next writer deletes `.tmp*` files in the state directory older than 1 min.
- A reader reads at most 1 MiB + 1 byte of `workspace.json`; a larger file is refused (AU84). A state folder that is a symbolic link or not a folder is refused (`<path>: state folder is a link`, `<path>: state folder is not a folder`) before any create, mode change, lock or write. No file of a state folder (`workspace.json`, `lock`, `op.lock`, `errors.log`, `snapshot.pending`) is opened through a symbolic link, and none that is not a regular file is waited on. A symbolic link at `<state dir>/workspaces` or above it is followed: a user may link the data folder. A writer refuses a result larger than 1 MiB, the same limit, and writes nothing (`<path>: the new state is <n> bytes, more than the 1048576 bytes that every reader accepts (AU84); not written`); a hook logs that line once (AU56). Known limit: a recorded id that leaves `workspace.json` near the read limit can make a later write (an `up` that copies it, `down` step 8) exceed the limit; that write is refused and logged, and the stored state stays readable. Only hostile input makes such an id.
- A writer holds `lock` only to read, merge and write the file. It runs no tmux call and waits for no process while it holds `lock`, with one exception: the key assignment of W§7.4 step 4 (one `show-options` and at most one `set-option` per new pane, each with the 2 s bound). `up` and `down` run every tmux check without `lock` (W§8.1, W§9.3).
- Wait bounds: hooks, member events and their snapshots 1 s; snapshots run by `up` and `down` 5 s; launchers and the member wrapper 5 s; `up` and `down` 5 s, then exit 1 with `zygo: workspace <name> is busy; try again`.
- A snapshot that cannot get the lock within its wait (1 s for hooks and member events, 5 s for `up` and `down`) sets `snapshot.pending` and exits 0. A snapshot with `--force` writes `force` into it with `write_atomic`, which replaces any file in one rename; a snapshot without `--force` creates an empty file only when none exists (`create_new`) and never overwrites one, so no order of writers removes a `force`. Right after, the snapshot tries `lock` once more for at most 100 ms, without reading the state; when it gets it, it releases it and takes the file: no file means another writer took it; else it runs once more, with `--force` when either it or the file had `--force`. Each writer checks `snapshot.pending` after it releases `lock`. If the file exists, the writer takes it (one rename to `snapshot.pending.taken-<hex>`, a name that the `.tmp*` sweep never matches, so only one writer gets it and the sweep never deletes it) and runs one snapshot, with `--force` when the file held `force`. The taken name holds 128 random bits. A taker sets the time of `snapshot.pending` to now just before its rename, and reads and removes the taken file before it runs the snapshot, so a taken file older than 60 s was left by a process that died. Each take first handles such files: it renames each one to `snapshot.pending.recover-<128-bit hex>` (a name that neither this scan nor the `.tmp*` sweep matches), reads its flag, removes it, sets `snapshot.pending` again with that flag (a `force` file replaces; an empty one never overwrites) and writes one line to `errors.log`. A `snapshot.pending` that is not a regular file is not opened: it is removed, one line goes to `errors.log`, and it runs as a snapshot without `--force`. At most 64 bytes of the file are read. `up`, `down`, `zygo ws snapshot`, the member wrapper, a hand start (`assign_key`) and verbs run it inline. A hook process starts it as a detached child (`setsid`, stdin, stdout and stderr to `/dev/null`) and returns, so the hook does not wait for the 2 s check of AU89; when the child cannot start, the hook sets `snapshot.pending` again with the flag it took and writes one line to `errors.log`. A pending snapshot with `--force` also runs when `phase` is `stopping` (AU38), inline or in that child; `down` does not wait for it, and when it runs after the `kill-session` of W§9.3 step 11 it finds the session gone and writes nothing, so `up` restores the last written layout.
- `op.lock` serializes `up` and `down`. Each takes it at its start, with the 200 ms retry of AU83, and holds it for its whole life.
- Two kinds of writers change different fields. `ws snapshot` changes `windows[]` and `panes[]`. Launchers, the member wrapper and agent hooks change `members{}`. Both use the same lock.

### 7.4 Snapshot

Signature (hidden): `zygo ws snapshot --ws-id <id> [--event <hook name>] [--force]`.

- `--ws-id`: the workspace id (AU44, AU84). The socket is `tmux_socket` of `workspace.json` (AU62).
- `--event`: the tmux hook that started the snapshot, for `errors.log`; none for other triggers.
- `--force`: AU38.

Steps:

1. An invalid `--ws-id`: AU84 exception. Read `workspace.json` without the lock. No file: exit 0 and create nothing. A state that fails its checks (AU84) or is from a newer zygo (AU29): one line to `errors.log`, exit 0. If `phase` is `down` or `tmux_socket` is unset, exit 0. Without `--force`, also exit 0 when `phase` is `building` or `stopping`. Keep the `snapshot_seq` value read here. If `tmux_socket` is not the socket that the multiplexer of this snapshot is bound to (`Multiplexer::socket`), exit 0 with no tmux call. This holds for every read of the state: the first one, the retry of step 4, the run after the 100 ms probe of W§7.3, and each `snapshot.pending` check.
2. Read the session option `@zygo-ws`. If it is set and is not the workspace id (AU63, AU84), or it is unset while `has-session` finds the session, write one line to `errors.log` and exit 0. Then run one `list-panes -s -t =<session> -F <format>` with window index, name, `automatic-rename`, layout, width, height, active and zoom flags, pane id, pane index, active flag, `@zygo-pane`, and the current path last (AU99). A pane that a linked window lists again is kept once, in its first window. Every tmux call has the 2 s bound. A tmux answer that the session or server is gone (AU87), from this or any later tmux call of the snapshot: exit 0 with no write and no log line. Other tmux error, a line that does not parse, no line at all, a `@zygo-pane` that is set and not valid (AU84), or one key on two panes: one line to `errors.log`, exit 0.
3. Shrink rule (AU89): if a key that `panes[]` holds is missing from the read, wait 2 s, do the `@zygo-ws` check of step 2 again, and read again, checked as in step 2, until two reads in a row show the same pane ids (at most four reads; else set `snapshot.pending` and exit 0). Use the last read.
4. Take `lock` (AU41) within the wait of W§7.3. If `phase` is now `down`, or `building` or `stopping` without `--force`, or `tmux_session` changed, or `tmux_socket` is not the socket of the multiplexer, release and exit 0 with no tmux call. If `snapshot_seq` is not the value of step 1, another snapshot wrote after this one read: release and do the whole snapshot again from step 1, once; a second time, set `snapshot.pending` and exit 0. For each pane that had no `@zygo-pane`, read `@zygo-pane` again. A valid key: use it. If another pane of this read holds that key, one line to `errors.log`, exit 0 with no write. A value that is not valid: one line to `errors.log`, exit 0 with no write. Still empty: make a new key that no `panes[]` entry, no member record and no pane of this read holds, set the tmux option, and use the key. A pane that closed meanwhile, or any other error of the pane option read or set (except a gone answer, which exits 0 at once): release; if `has-session` finds the session gone, exit 0; else one line to `errors.log` and exit 0, with no write in both cases.
5. Under the same lock: replace `windows[]` and `panes[]` by the read, set `snapshot_at`, and add 1 to `snapshot_seq`; a window keeps the unknown fields of the stored window with the same index only when one of that stored window's panes has a key that is on a pane of the window now (a new window at the index of a closed one keeps none), and a pane keeps those of the stored pane with the same key (AU78); a window with `automatic-rename` on gets no name; each pane's `kind` comes from its member record (AU53). Do not delete member records. Write. Release. A write that fails (the state cannot be read again, fails its checks, or cannot be replaced) writes one line to `errors.log`. Then do the `snapshot.pending` check of W§7.3.

Triggers **(author)**:

- tmux hooks on the workspace session only (W-C3): `after-new-window`, `after-split-window`, `window-layout-changed`, `window-renamed`, `client-detached`, and `after-kill-pane`, `pane-exited`, `window-unlinked` (a `kill-window` fires no `after-kill-pane`). No focus hooks (AU90). Each runs the fixed string of AU54. `window-unlinked` is set with `set-hook -w` on each window; tmux 3.3 and later store it on the session (PW6 6.30). Reliability (PW6, 2026-11-22): tmux runs the hook of an event whose target is gone (`after-kill-pane`, `pane-exited`, `window-unlinked`) in the session that it takes as current: the session with a client, else the most recent one. So these three fire for the workspace only when it is that session, and then they also fire for panes of other sessions (a snapshot that changes nothing). A pane closed in a window that keeps other panes always fires `window-layout-changed` on that window. An agent pane closed by hand is always recorded by the member wrapper at agent exit.
- The member wrapper at agent start and at agent exit.
- The `SessionStart` hook, and for OpenCode the plugin's `session` call, when the agent session id changes; the hook starts the snapshot as the detached child of W§7.3, one child with the pending check.
- `down`, before it stops anything (final snapshot, with `--force`).
- `up`, at the end of the build (with `--force`).

Known limit: a `cd` in a shell pane changes no tmux state, so the saved cwd is the cwd at the last trigger. `down` always takes a final snapshot. After a crash, a shell pane can come back in an older cwd. Agent panes do not change cwd.

Known limit (PW6): a whole window of shell panes that closes (`kill-window`, or its last shell exits) while the workspace session is not tmux's current session is written at the next trigger. A crash before that trigger brings the window back at `up` as shells in their saved cwd.

Known limit: `up` sets the window-scoped hooks (`window-layout-changed`, `window-renamed`, `pane-exited`, `window-unlinked`) and `remain-on-exit off` on each window that it builds. A window that the operator creates later has none of them; its changes are written at the next session hook (`after-new-window`, `after-split-window`, `client-detached`, `after-kill-pane`) or member wrapper snapshot.

### 7.5 Panes closed by hand (AU35)

1. A pane closed while the session lives (`kill-pane`, `kill-window`, an exit of `ws run --shell`'s shell) leaves the layout at the next snapshot, after the 2 s check (AU89). If it held a member record, that member is **detached**: its record stays, and `up` does not recreate it. The snapshot comes from `window-layout-changed`, from the member wrapper at agent exit, or from the W§7.4 hooks when the workspace session is tmux's current session. The known limit of W§7.4 applies to a window of shell panes.
2. Any other loss of panes (a teardown, a server death, a reboot) writes nothing: a teardown's shrinking snapshots find the session gone after 2 s (AU89), and a crash fires no hook. The members stay `resumable` (AU17), and `up` restores the last written layout.
3. For each detached member with an `agent_session` and state `resumable`, `up` prints `zygo: <kind> agent session <id> is detached (its pane was closed); resume it by hand or run zygo ws forget-pane <key>`. `zygo ws forget-pane <key>` or `up --reset` deletes the record.

## 8. `zygo up`

### 8.1 Sequence

1. On Windows: exit 2, `workspaces need tmux; run zygo in WSL` (OP5).
2. Find `tmux` on `PATH` and read `tmux -V`. No tmux: exit 2, `workspaces need tmux; install tmux 3.2 or later`. Older version: exit 2 with the found version.
3. Find the workspace: by `<name>` from the state directory (AU20), else from the cwd with `zygo_work::repo::checkout` (`repo.rs:137`) and the main worktree (AU77). Not a repository: exit 2 (AU25). A state that does not parse, or fails AU84: exit 1 naming the file (`--reset` renames it to `workspace.json.bad`). A state file larger than 1 MiB is refused, not invalid (AU84): `up` exits 1 with or without `--reset`, and the file is never renamed. By `<name>`, the readable states are matched first. Then a state that cannot be read matches when the `name` string of its JSON is `<name>`: a newer state by that alone, an invalid state only when that name passes AU2, `common_dir` and `main_root` are non-empty absolute paths, and its folder is the W§5 id of `common_dir`. One match: a newer state exits 1 with the AU29 text, an invalid one follows the rule above. Two or more: exit 1 with `zygo: more than one workspace state has the name <name>: <file>, <file>`. In the own folder of a bare repository, where `checkout` finds no work tree, `up` reads `git worktree list --porcelain` there: with a non-bare entry it takes the checkout of that main worktree; with none it exits 2 with the AU77 text.
4. Compute `id` (AU2). Check the zygo path by AU54 (exit 2 before anything changes). Take `op.lock` (AU83 retry); held: exit 1, `zygo: up or down is in progress for <name>`.
5. Repair a dead `up` or `down` (no lock needed for the read; writes under `lock`), on the server of step 6: `phase = building` → AU67 (by `build_plan` when the session is gone), only on a session whose `@zygo-ws` is the id (a session without it or with another value: exit 1, AU63; it is never adopted), after the session options and hooks of step 10 are set again; when `tmux_socket` is unset (an `up` that died before its step 9 write), the repair reads the socket with `display-message -p -t =zygo-<name> '#{socket_path}'`, checks it by AU54 and AU62, and writes it with `phase = up`; `phase = draining` → `phase = up` if the session exists, else `down`; `phase = stopping` → AU75. `repair` runs no `snapshot.pending` check after its writes; `up` and `down` call it right after `repair` returns (W§7.3). A state that does not parse or fails AU84 is not repaired: without `--reset` `up` exits 1 (W§10); with `--reset` it is renamed to `workspace.json.bad`, with no check of its socket, after the plan of step 7 passed all its checks and before the write of step 8. The repair of this step is the only write of `up` before those checks. Each repair write that sets `phase = up` removes `build_plan` and `fresh_members`.
6. Check the tmux session `zygo-<name>` on `tmux_socket` (AU62), without `lock`. If it exists and `@zygo-ws` is the id (AU63): with `--reset` or `--loadout`, exit 1 (AU37); else, when step 5 repaired it from `building`, run one snapshot with `--force` and then the `snapshot.pending` check, with the state's `tmux_socket` (as in step 12); then attach (step 13) and stop. If it exists with another `@zygo-ws`: exit 1 (AU63). If the answer is not "gone" by AU87 (an unreachable session with a live launcher, or another error): exit 1.
7. Choose the plan:
   - `--reset`, no `workspace.json`, or a state with no pane: the loadout (`--loadout`, else `[workspace] default_loadout`, else `solo`). With `--reset`, first print one line per member in state `running` or `resumable` with an agent session id (AU37). Members start fresh. A loadout pane whose `server` holds user info becomes a shell pane with no member record, and `up` prints the AU98 line.
   - Else: the saved `windows[]` and `panes[]`, windows in index order and panes in index order. A member in state `running` or `resumable`, with an `agent_session`, with its pane key in `panes[]`, and whose launcher is not live (AU87), resumes. Every other pane is a shell (OP8). A member in state `running` or `resumable` without an `agent_session` gives the W§10 line. `--loadout` without `--reset` is ignored with one line.
   - Every window name passes the control-character check and every saved size is in 1..=10000, else exit 1 before step 8 (AU96). No value that goes into a tmux command line may end with `;`, which tmux reads as the end of a command: the main worktree (`-c`), each window name and layout (from the loadout or the saved state) and each item of each pane's argument list (AU15). Such a value makes `up` exit 1 with `zygo: <what> "<value>" ends with `;`, which tmux reads as the end of a command; nothing was written`, before any write of this run except the repair of step 5 and before the `workspace.json.bad` rename; when that repair wrote, the text ends with `nothing of this plan was written`.
8. Take `lock`. Write the plan: a full `panes[]` entry for every pane (AU48), member records (for fresh loadout members: `launch` from the loadout pane, AU45), `phase = building`, `build_plan` (`loadout` or `restore`) and `fresh_members` (the keys of the fresh loadout members; empty for a restore); when `tmux_socket` is unset and step 9 will use a known server (the socket of `$TMUX`, after its AU62 check), set `tmux_socket` to it, so a later `up` and its repair ask the same server; for each resumed member, `note_pending = true`; delete the member record of each pane restored as a shell when that record, as read under `lock`, has no agent session id (`agent_session` or `pending.agent_session`) and no pending start (AU53), and keep a whole copy of it for the undo of step 9. Release `lock`. Whether this write set `tmux_socket` is decided in this write.
9. Create the session detached with the **first pane of the first window**, and tag it in the same tmux invocation: `new-session -d -s zygo-<name> -c <main worktree, # doubled> -x <width> -y <height> -- <ws run argument list> ; set-option -t =zygo-<name>: @zygo-ws <id> ; set-option -p -t =zygo-<name>: @zygo-pane <key> ; set-option -t =zygo-<name>: destroy-unattached off` (AU55, AU68, AU96), with the environment of AU64. So no session of this workspace exists without `@zygo-ws`, and a global `destroy-unattached on`, which destroys a detached session when its command list ends (tmux 3.2a and 3.7c), does not end it. Then `resize-window -t =zygo-<name>:<first window> -x <width> -y <height>` (AU96), and, when the first window has a saved or loadout name, `rename-window -t =zygo-<name>:<first window> -- <name>` with `#` doubled (AU55, AU99; `new-session` takes no name, so the first window is renamed as `new-window` renames the others). The server: the server of `$TMUX` when set, else tmux's default resolution; a restore uses `tmux_socket` (AU62). Read the socket path with `display-message -p -t =zygo-<name> '#{socket_path}'` and check it by AU54 and AU62. On a failed check: `kill-session`, then the undo, then exit 2 (or 1 for AU62). When `new-session` fails, ask the same server for `zygo-<name>` and its `@zygo-ws`: the id → `phase` stays `building`, print the error and exit 1 (the next `up` repairs it, AU67); no session → the undo, exit 1; another value or none → print the error, the undo, then exit 1 with AU63; an answer that tells neither → `phase` stays `building`, exit 1. The undo is one write under `lock`: `phase = down`; then by `build_plan` as AU67 does when the session is gone; each record that step 8 deleted is put back, whole; a `tmux_socket` that the step 8 write set is removed; `build_plan` and `fresh_members` are removed. After the write, the `snapshot.pending` check with the `tmux_socket` of the state written. A failed undo write prints `zygo: state not cleaned: <error>`. Else write `tmux_socket` under `lock`.
10. On this session only: `set-environment -r` for each name of AU64, `set-environment ZYGO_WORKSPACE <id>`, user option `@zygo-ws <id>`, `destroy-unattached off` and `remain-on-exit off` (AU68), the hooks of W§7.4 (AU54).
11. For the other panes of the first window, `split-window`. For each later window, set `default-size` (AU96), then `new-window` (with `-c` as in step 9 and `-n` with `#` doubled when it has a saved name) with its first pane, then `split-window` for the rest. Each pane gets its key (`@zygo-pane`) and its start command: the `ws run` argument list of AU15, with `--shell` for a shell pane (AU46). A failed split: AU96. Then `select-layout <layout>` per window. A layout that tmux refuses (wrong pane count) falls back to `tiled` with one warning line. Agent panes that start now write their member records under `lock` (W§7.3); they do not wait for `up`. Step 11 ends with `set-option -w -u -t =zygo-<name>:<first window> window-size` (AU96), also when it builds no pane.
12. Select the saved active window and pane; restore zoom. Wait at most 2 s, reading `list-panes` each 50 ms, until each built pane whose planned cwd is an existing folder reports that folder as `#{pane_current_path}`; then run one snapshot with `--force` (AU38) in every case. The wait keeps the snapshot from recording the start folder of a `ws run` that has not changed to its cwd yet. The snapshot merges the member records written in step 11. Take `lock`; set `phase = up`, `down_all = false`; write; release. Print the permission flags of each resumed member (AU70), one warning per dropped flag (AU30), and one line per detached member (W§7.5) and per pane not built (AU96). Release `op.lock`.
13. Attach: with `--no-attach` or `ZYGO_SESSION` set (AU95), print `zygo: <name> is up` and exit 0. Inside tmux on another server: AU100. Outside tmux, `attach-session -t =zygo-<name>`; inside tmux on the same server, `switch-client -t =zygo-<name>`.

`up --all` takes no `<name>`, `--loadout` or `--reset` (exit 2). It runs the tmux check of step 2 first (exit 2 when tmux is missing or older than 3.2), before any session check. It runs steps 3-12 for each workspace with `down_all = true`, and for each workspace left with `phase = up` and no tmux session (AU52, W-G3), one after the other in name order. The session check runs the AU62 check of the socket first. A workspace whose session exists is not restored and gets no line; when that session holds this workspace's `@zygo-ws` and `down_all = true`, `up --all` clears `down_all` under `op.lock` and `lock`, because the workspace is up, then runs the `snapshot.pending` check of W§7.3. First it reports each state that does not parse, fails AU84 or is newer: `zygo: workspace <id> skipped: <error>` (AU80). Then it prints one line per chosen workspace: `zygo: <name> is up` on stdout, or, after the lines of that `up`, `zygo: <name> skipped` on stderr; a workspace whose `op.lock` is held, whose `up` fails, whose socket fails AU62, or whose session is unreachable (AU87) is skipped. When no workspace reaches its restore (there is no candidate, or each candidate runs or is skipped before its `up`), it prints `zygo: up --all found no workspace to restore`. It attaches to none and exits 1 when it skipped one.

### 8.2 `zygo ws run` (one pane)

Signature (hidden): `zygo ws run --ws-id <id> --pane <key> [--shell]`.

1. Validate the id and the key (AU84). Clean the own environment (AU64). Read the pane's entry in `panes[]` by pane key, and its member record (no lock needed for a read). Take the cwd from the `panes[]` entry (AU48) and change to it (AU55). If the cwd does not exist: change to `main_root`; for an agent pane, do not resume (AU61): print the AU61 line and go to step 8; for a shell pane, print `zygo: <cwd> is gone`. With `--shell`, go to step 8.
2. Build `LaunchOpts` (`crates/zygo-launch/src/launcher.rs:44-67`) from `member.launch` through `launch_opts` (AU45), with the member fields (W§8.4), the saved `CLAUDE_CONFIG_DIR` and the program rule of AU61, and `LaunchOpts.member = Some(Member { ws_id, pane })` (AU102), also when `member.launch.args` hold `--settings` (AU59). Compaction: AU32.
3. Add the session argument: resume: Claude Code `--resume=<id>`, OpenCode `--session=<id>`, one token each (AU3); fresh Claude Code: `--session-id=<new UUID v4>` (W§8.3).
4. Set `LaunchOpts.resume_note` from the member record when `note_pending = true` (AU72), with `agent_session` = the id that step 3 resumes, none for a fresh start (W§9.4). Set the launcher callback (AU34). It makes the `results` symlink (AU16). When `member.overrides` is present, it writes it into the new `overrides.json`, and, when `redaction_content` is set, sends it with `PATCH /v1/zygo/sessions/{id}/settings` (the proxy session already exists when the callback runs, `launcher.rs:292`; hook-side settings are read from `overrides.json` on each hook call, §17.1). There is no `clean_stop` gate (OP12). Then it writes the member record (AU92).
5. Set SIGHUP and SIGTERM to `SIG_IGN` (AU88).
6. Run the launcher in process (`Launcher::run`, `launcher.rs:130`).
7. With `spawned = false`, delete `member.pending`; the member stays as it was (AU60, AU92). Else commit the pending start if the `SessionStart` hook has not done it, and classify (AU17, AU73). A resume **failed fast** when the launcher received no signal, no signal ended the agent, the code is non-zero, and the agent ran less than 10 s; then the member stays `resumable` and `ws run` prints `zygo: resume of <kind> session <id> failed (exit <n>); try: zygo <kind> -- --resume <id>`. Write the member record under `lock`.
8. Set `ZYGO_WORKSPACE=<id>` (AU93). Set the default handlers for SIGHUP and SIGTERM again; `exec $SHELL` (else `/bin/sh`) in the cwd.

Steps 4, 5 and 7 are the **member wrapper**. A hand-started member (AU9) runs the same wrapper from `zygo claude` or `zygo opencode`, without step 8 (it sets the default handlers again before it exits).

### 8.3 Session-id pre-assign

For Claude Code, when the arguments (after AU30 filtering, or as typed for a hand-started member) hold none of `--session-id`, `-r`/`--resume`, `-c`/`--continue`, `--fork-session`, `--from-pr`, `--cloud`, `--teleport` (the session rows of the AU30 table in `crates/zygo-workspace/src/args.rs`, read by the same parser, so a token after `--` or a flag value is not a session argument), the member wrapper passes `LaunchOpts.agent_session = Some(AgentSession::Preassign(<new UUID v4>))`, the launcher adds `--session-id=<new UUID v4>` (one token) before the user's arguments, so before any `--`, and the wrapper records the id in `member.pending` (AU3, AU9, AU92). With a session argument of the user's own, the id comes only from the `SessionStart` hook. OpenCode has no pre-assign; its id comes from the plugin (PW4).

### 8.4 Membership

A launch is a member when all these are true:

- `ZYGO_SESSION` is not set (not a launch inside an agent's tool).
- The server URL holds no user info (AU98). A user `--settings` does not change membership (AU59).
- `$TMUX_PANE` is set, and `display -p -t $TMUX_PANE '#{session_name} #{@zygo-ws}'` gives `zygo-<name>` and a valid id (AU84) equal to `ZYGO_WORKSPACE`.
- For a hand start: the pane key holds no resumable record and no live launcher (AU94).

These checks are for a hand start only; `ws run` passes `LaunchOpts.member` explicitly (AU102). The user-info check runs first, before any key or record is written. A hand-started launch (AU9) gets the key from `@zygo-pane`, or creates one by the locked path of W§7.4 step 4 (AU79). A member launcher:

- sets `ZYGO_WORKSPACE` and `ZYGO_PANE` in the child environment (§8.4 "Set");
- registers the member hooks (W§9.1);
- writes the membership marker into the session view (AU58);
- runs the member wrapper (W§8.2).

For every launch that is not a member, the launcher removes `ZYGO_WORKSPACE` and `ZYGO_PANE` from the child environment (AU58). Such a launch is a v1 launch in every other way (OP9, W-C6).

### 9.2 Dispatch and stopping blocks

While a `down` holds `op.lock` (AU83):

- `draining`, with `drain_block_dispatch = true`: the `pre-tool` event on tool `Agent` prints `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"zygo: workspace is draining for down; finish your turn"}}`.
- `stopping`: the `pre-tool` event on `Agent` denies with `zygo: workspace is stopping`, and `UserPromptSubmit` prints `{"decision":"block","reason":"zygo: workspace is stopping"}` (AU86).

The hook reads `phase` from `workspace.json` without `lock` (the file is replaced by rename). In any other case it prints nothing and does not touch `op.lock`.

### 9.3 Sequence

1. Steps 1-3 of W§8.1 (platform, tmux, workspace). With no name, the workspace of the cwd checkout; no environment value overrides it. `/zygo:down` and the `workspace_down` tool name the workspace of the session's membership marker, never the cwd; a session with no marker gets `zygo: this session is not in a workspace` (exit 1). With `--all`: every workspace (AU19, AU80).
2. Detach rule (AU18). `$TMUX_PANE` is looked up in the session of every target: a target with a saved socket only when that socket is the socket of `$TMUX`, a target with no saved socket on the server of `$TMUX` (else tmux's default). Before any tmux call on a saved socket in this step, the AU62 check runs; a socket that is not private exits 1 with the AU62 line. When it applies: the sandbox guard of AU18 first, before any session check (it reads the server pid; an unreadable pid refuses); then, when no target session exists, `down` runs in the foreground (step 3 needs no drain); else make the zygo path absolute against the cwd (the detached process runs in `/`) and check that joined path (AU54; exit 2), cut the log (AU97) and start `zygo down` again as a new session leader (`setsid`) with the same `--now` and `--timeout`, plus `--wait`, and the same target (`--all`, or `--` and the name); stdin from `/dev/null`, stdout and stderr to the log of AU97. The started process keeps no descriptor of the caller's stdin, stdout or stderr (the `workspace_down` tool waits for their end, AU65). Print `zygo: down started; end your turn` and exit 0.
3. Per workspace: take `op.lock` (AU83 retry); held: report `up or down is in progress` (with `--all`, skip; exit 1 at the end). Repair as W§8.1 step 5. Check the session without `lock`: gone by AU87 → under `lock`, `phase = down` (and `down_all = true` with `--all`; no other `down` changes `down_all`; a state already in phase `down` gets no write), report `zygo: <name> is not running`, release `op.lock`; unreachable, another `@zygo-ws` or another tmux error → exit 1. Else, under `lock`, `phase = draining`.
4. Final layout snapshot with `--force` (W§7.4, AU38). A snapshot that refuses what it read (one `errors.log` line: a `@zygo-pane` that fails AU84, a key on two panes, an unexpected tmux error) stops `down` before anything stops: `phase = up`, release `op.lock`, exit 1 (W§18 #10). An `Err` because `snapshot.pending` could not be set prints one line and `down` goes on.
5. Drain (skip with `--now`). Poll every 500 ms. For each member whose launcher is live, read `activity.json` and the proxy status (session token from its session directory; AU91), and apply the idle rule (AU26). The state is read again at each poll, so a member that joins during the drain is drained too. The status of each live member is read with a 2 s bound. Each workspace's drain time starts after its own step 4. With `--all`, a workspace that waits in step 10 does not stop the polls and timeouts of the others. A member whose launcher is not live counts as idle. Foreground progress: one line per member when it becomes idle, and a line every 30 s with the members that still run. With `--all`, every workspace drains under one timeout, and each one goes on to step 7 as soon as all its members are idle in the same poll (AU19).
6. Timeout (`--timeout`, else `drain_timeout`): for each workspace still draining, set `phase = up`, which ends the dispatch block, and release its `op.lock`. Print each busy member with its pane, its running subagents and its reason: the busy reason of the idle rule (AU26), or `no Stop since its last prompt` for a member whose turn is still open. Then print `run zygo down --now to stop at once`. Exit 1.
7. Set `phase = stopping` (AU86). From here SIGINT, SIGHUP and SIGTERM do not end `down` for this workspace, and it never goes back. One handler, installed once per `down` before its first `draining` write and restored when `down` ends, catches the three signals.
8. For each member whose launcher is live (AU74): record `closed_units` (AU31, AU76); with `--now`, record the running set as `interrupted` (ids and types); set `clean_stop = true` and `saved_for` = the ULID of that member's live zygo session (the session folder that AU74 found live). Write the state. These values are saved only here (AU42).
9. Warn about busy shell panes (AU24).
10. For each member whose launcher is live: send SIGTERM to its launcher (pid from its session directory `pid` file). The launcher forwards it to the agent (`signals.rs:94-117`) and runs `finish` (`launcher.rs:599-624`). Wait until each such member record has left `running` and its launcher is no longer live, at most 30 s; then report the ones still running and continue. No SIGKILL follows: `kill-session` in step 11 sends SIGHUP to every pane process, and a SIGKILL would cut the launcher's `finish`.
11. Check `@zygo-ws` (AU63) and run `kill-session -t =zygo-<name>`. Then, under `lock`: `phase = down`, and `down_all = true` with `--all`. Release `op.lock`. Print `zygo: <name> is down (<n> agents saved)`. A `down` that dies between the kill and the write leaves `stopping` with no session; the repair of AU75 sets `phase = down`.

`op.lock` is released on every exit path (an fs4 lock also ends with its process). SIGINT, SIGHUP or SIGTERM from before the `draining` write until the `stopping` write cancels every drain that is not stopping yet: `phase = up`, release `op.lock`, exit 128 + the signal number (130 for Ctrl+C). With `--all`, workspaces that already stopped or are stopping go on to the end. With `--all`, a signal before a workspace's step 3 leaves it and the workspaces after it untouched, and `down` exits 128 + the signal number.

### 9.4 Resume note

When `note_pending = true`, `ws run` passes the note inputs in `LaunchOpts.resume_note`, and the launcher puts them in the session view that it builds (AU72). At the first main-loop `SessionStart`, the session-start hook builds the note from them, adds it after the session text (§8.6), removes them from the session view, and clears the saved values in the member record (AU60):

- With `clean_stop = false` (crash, reboot or hand kill; AU42): `zygo did not stop this session cleanly; the list of closed units was not saved.`
- With interrupted subagents: `zygo stopped this session while subagents <type> <id>, <type> <id> were running; their results were lost; dispatch them again if still needed.`
- With closed units: `Units <unit>, <unit> were closed when zygo stopped this session; call work_begin to open them again if work continues.`

No note when `clean_stop` is `true` and both lists are empty.

The note follows the session text after one empty line, one sentence per line in the order above; with `clean_stop = false` only the first sentence is printed. An empty `<type>` prints `<id>` alone. Each type, id and unit is printed with control characters escaped. Claude Code: the hook prints the note first, then removes the inputs from the session view (also when no note is printed) and clears the member record (AU60). OpenCode: the plugin adds the session text to each model request, so the note is in the system text of every request while its inputs are in the session view. The inputs belong to one agent session: their `agent_session` is the resumed id, or none for a fresh start. A `session` call with id X (AU104): inputs with no `agent_session` get X and stay; inputs with X stay; inputs with another id are removed from the session view. The commit (AU92) never removes them.

## 10. Failure handling

| Case | Behavior |
|---|---|
| A write fails partway | The rename did not happen, so the old `workspace.json` stays whole (W§7.3). A hook writes one line to `errors.log` and exits 0 (C6). |
| `workspace.json` does not parse or fails AU84 | `up` and `down` exit 1 naming the file; `--all` skips it (AU80). `up --reset` renames it to `workspace.json.bad` and applies the loadout. Hooks and snapshots change nothing and write one line to `errors.log` (AU84, W§7.4 step 1). |
| `workspace.json` larger than 1 MiB | Refused and never changed (AU84, AU29): `up`, `up --reset`, `ws forget <id>` and `ws forget-pane` exit 1 with `zygo: <path>: state file too large; it may be from a newer zygo, so zygo does not change it`; `--all` skips it (AU80); `zygo workspace` gives that text; `ls` shows it by id as `unreadable`. Hooks and snapshots change nothing. |
| `up <name>` or `attach <name>` with no state of that name (a state that cannot be read counts when the `name` of its JSON matches) | Exit 1, `zygo: no workspace named <name>` (AU20). |
| Lock held | Bounded waits (W§7.3). An fs4 lock ends with its holder, so a lock is never stale. |
| `up` or `down` process died | `op.lock` is free while `phase` is `building`, `draining` or `stopping`. `up` and `down` repair (W§8.1 step 5, AU67, AU75). The blocks of W§9.2 end at once (AU83). |
| tmux server gone (crash, reboot, `kill-server`) | The launchers received SIGHUP or SIGTERM, so members stay `resumable` (AU17). `phase` stays `up`. `ls` shows `stopped (tmux gone)`. `up` restores the last written layout (W§7.5 rule 2). Closed units and interrupted subagents are not saved; the resume note says so (AU42). |
| tmux unreachable while launchers live (another `TMUX_TMPDIR`, a sandbox) | Not "gone": the verb exits 1 and resumes nothing (AU87, W-C9). |
| Workspace session killed by hand | As "tmux server gone" (AU89). |
| One pane closed while the session lives | Detached member (W§7.5 rule 1). |
| A split fails at `up` (no space) | The pane is not built; its member is detached and stays resumable (AU96). |
| tmux answers with an unexpected error | No change; exit 1 or one `errors.log` line (AU87). |
| No agent session id saved | The pane comes back as a shell; `up` deletes its member record when the record has no agent session id and no pending start (AU53). `up` prints `zygo: pane <key>: no agent session id saved; started a shell`. |
| Resume fails | A shell and the resume command; the next `up` tries again (AU12, W§8.2 step 7). |
| Missing cwd | AU61, W§8.2 step 1. |
| Repository moved or deleted | The common-dir path changes, so the id changes and `up` creates a new workspace. `ls` shows the old one as `repo missing`. `zygo ws forget <name>` deletes it. |
| Profile, server or binary missing at resume | The launcher's existing messages apply (`launcher.rs:204-206` for a profile; exit 13 for a missing agent); the member stays as it was (AU60, AU92). |
| Newer state version | AU29. |
| Two `up` at the same time | `op.lock`: the second exits 1 after the 200 ms retry. |

Running: members whose launcher is live; saved: members in state `running` or `resumable` with an agent session id, no live launcher and a pane in `panes[]`; detached: the same with no pane (W§7.5). Attached clients only for a session of this workspace. `ls` makes no tmux call after 4 s from its start; a socket whose call failed or timed out is not asked again in the same `ls`. Also `/zygo:ls` (OP11). |

| `zygo loadout list` / `zygo loadout show <n>` | Loadouts with their source (built-in or user); one loadout in TOML. |
| `zygo ws forget <name>` | `<name>` is matched first as a workspace id (16 hex characters, with that state directory present), then as a workspace name, then against the JSON `name` of a state from a newer zygo. Only a real directory is a state directory: a symbolic link at `<state dir>/workspaces/<id>` is never opened, locked, written or changed; `forget <id>` removes the link itself (an unlink, after one more check that it is a link) and prints `zygo: <path> was a link, not a state folder; removed the link`. For a state directory, `forget` takes `op.lock`, reads the state again, runs its checks, and takes `lock` (5 s) before it deletes anything; then, under both locks, it deletes the results cache and renames the state directory out of the workspace list, then removes it. Refused (exit 1, nothing deleted) while `op.lock` is held, while `lock` stays held past 5 s, while a member launcher is live, while the workspace's own session runs (`@zygo-ws` equal to its id; a session of another workspace under that name does not refuse it, AU63), when the socket fails AU62 (checked also when tmux is not installed), when the session check gives a tmux error, for a state from a newer zygo (AU29), and for a name that two states share (the message lists their ids). A state that does not parse or fails AU84 is checked from its raw JSON, read with the AU84 cap (name, socket, member launchers, session); when a check finds it running, or no check can run, `forget` refuses and names `zygo up --reset` as the repair. A state file larger than 1 MiB is refused by id with the AU84 text before any lock, and is not matched by name. A symbolic link at the cache path or in the state directory is removed as a link. Before its own work, `forget` removes folders that an earlier `forget` left (`.forget-*`), state directories with no `workspace.json` whose `op.lock` and `lock` are free, and results caches whose id has no state directory (none, or a link or file in its place) or a state directory with no `workspace.json` whose locks are free. `ls` removes nothing. |
| `zygo ws forget-pane <key>` | Delete one member record (detached or not) and, in the same write, set that pane's `panes[].kind` to `shell` (AU53); then the `snapshot.pending` check of W§7.3; then delete its results cache `results/<key>/`. Each part of the cache path below the workspace cache directory (`<id>`, `results`, `<key>`) is checked without following links: a link at `<id>` or `results` refuses before anything is written; a link at `<key>` is removed as a link. Refused (exit 1, nothing changed) while its launcher is live (checked under `lock`), while `op.lock` is held, while `lock` stays held past 5 s, for a key that fails AU84, and when the workspace's state directory is a symbolic link (`zygo: the state folder of workspace <id> is a link; it is not changed`). A key with no member record but a results cache only removes the cache. Run in the workspace's checkout or with `--name <name>` (a workspace id is matched first, as for `ws forget`). A state file larger than 1 MiB is refused with the AU84 text, by `--name <id>` or in its checkout, and is not matched by name. |
| `zygo ws snapshot --ws-id <id> [--event <hook name>] [--force]`, `zygo ws run --ws-id <id> --pane <key> [--shell]`, `zygo hook workspace` | Internal and hidden (AU44). No sweep for `ws` (AU71). |

Exit codes follow §8.2: `0`, `1` failure or busy, `2` usage or platform. `zygo doctor` also reports the tmux version and whether it meets the minimum. Slash forms: `/zygo:down`, `/zygo:ls`, `/zygo:workspace` (OP11); `up`, `attach`, `loadout` and `ws` are CLI-only. The slash forms run under the 4.5 s hook bound of §17.1; `/zygo:down` returns after it starts the detached process.

## 13. Multiplexer trait

`crates/zygo-workspace` defines one trait. tmux is the only phase-2 implementation (OP5). The trait has the operations of W§7.4, W§8 and W§9: check version, socket path, session exists (with the AU87 answer kinds), create session with a first pane, a start directory, a size, a cleaned environment and, in the same tmux invocation, the session options `@zygo-ws` and `destroy-unattached off` and the first pane's `@zygo-pane`, set and hide (`-r`) session environment values, set and read session options, set and unset window options, set hooks, create window with a first pane, rename window, split pane with a start command (argument list), set and read pane options, apply layout, select window and pane, zoom, list panes with fields (AU99), attach, switch client, kill session. Every call except `attach` has a 2 s bound. After creation, the tmux implementation passes `-S <tmux_socket>` to every call (AU62) and escapes `#` in every `-c` and `-n` value (AU55). Every call except `new_session` and `attach` runs under `LC_ALL=C` (AU87) with `-u`, because a client under `LC_ALL=C` without `-u` prints each non-ASCII character of a window name or a pane path as `_` (W3 review probe, tmux 3.7c). `new_session` runs with exactly the cleaned environment of AU64 and no `LC_ALL=C`, because a server that it starts copies the client's environment into the global environment of every pane, and tmux marks each `update-environment` name that the client lacks as removed in the new session. `attach` has no bound, because an attached client lasts as long as the user works, and keeps the caller's environment, because tmux reads the locale to draw on the user's terminal. Option reads use `show-options -q`, so an unset option, and also a missing target, gives an empty value. Tests use it with a private server.

## 14. Alternatives rejected

| Alternative | Why rejected |
|---|---|
| A supervisor daemon | Reduced scope **(operator)**. tmux already holds the processes, and hooks plus launchers can write the state (AU1). A daemon adds install and lifecycle work (§18.3). It may return in a later phase. |
| Messages, wake, triggers, git modes, pools, slots, toasts, restart briefs | Reduced scope **(operator)**. Elephant-goldfish subagents make cross-agent coordination unnecessary for now. They may return in a later phase. |
| Fresh restart by default | **(operator, OP4)**. The operator wants each agent to continue its conversation. A fresh restart loses the lead's plan and context. |
| A Windows Terminal backend | Windows Terminal has no scriptable layout query or session hooks to snapshot from. OP5 keeps the trait, so a later backend is possible. |
| A one-agent Windows mode | It gives a second, smaller feature set to keep in step. WSL gives the full feature. |
| Auto-tmux on `zygo claude` | Breaks OP9: a plain launch must stay a v1 launch. Only `zygo up` creates a workspace. |
| Loadouts in `.zygo.toml` | A loadout starts programs with arguments. A cloned repository must not do that (W-C5, A5). |
| Periodic-only snapshots | They lose changes made between ticks, and they need a timer process. Event hooks plus a final snapshot at `down` cover OP7 without a daemon. |
| tmux-resurrect or tmux-continuum | They run on the whole server (against W-C3), they re-run saved commands (against OP8), and they do not know agent session ids. |
| Claude Code background sessions (`--bg`, `respawn`, `fixtures/claude-code/help.txt`) | Claude Code only; the session runs outside the tmux layout, and the zygo launcher (with its proxy) is not its parent. |
| A shell string as pane command (`$SHELL -c '…; exec $SHELL'`) | Quoting differs between sh, zsh and fish. An argument list plus `exec` (AU15) needs no quoting. |
| Key members by tmux pane id (`%N`) | Pane ids change after a restore. A pane key in a user option stays the same. |
| `down` waits in the foreground when an agent runs it | It waits for its own caller's turn and kills its own pane, and an agent's Bash tool times out (AU18). |
| Refuse `down` while a shell pane runs a program | `down` can run with no person at the terminal; a refusal blocks W§1 reason 1 (AU24). |
| `up` holds the lock while it creates panes | Agent panes start during that time and must write their member records; they would wait for `up` (AU36). |
| Snapshot deletes the record of each pane that is gone | A `kill-session` closes panes one by one while the session still exists, so every member would be lost (W§7.5). |
| A stable layout with candidates and promotion; tombstones for `kill-pane` | They needed hook-order rules and extra fields. The 2 s shrink check (AU89) plus detached members give the protection with no stored history. |
| Save launch arguments unfiltered | They can hold prompt text and session arguments that clash with the added `--resume` (AU30, W-C7). |
| Strip provider keys from tmux and `ws run` | The in-process proxy of each pane's launcher reads them (`crates/zygo-proxy/src/provider.rs:19-25`); the launcher already keeps them from the agent (AU64). |
| One plugin sync per `up` (`skip_sync`) | The marketplace locks already serialize the per-launch syncs. |
| `-L <label>` and `default` server forms | A label resolves through `TMUX_TMPDIR`, which can differ between shells and sandboxes, so one workspace could look gone from one shell. One absolute path with `-S` cannot (AU62). |
| Move `results/` out at exit and back in at resume | Two moves and a signal window. A symlink to one per-member directory needs neither (AU16). |
| Save overrides and the compaction override only at `down` | A crash or reboot loses them, and `down` needs a status read. A write at each change keeps them with no read (OP12, AU105). |
| No slash commands for workspace verbs (earlier AU21) | Against O14 **(operator, OP11)**. |
| A `resume_failed` state and `--retry-failed` | A state that only blocks the next try. Every `up` tries again and prints the command (AU60). |
| Gate bypass flags on `up --all` | The flags are printed at every `up`; a gate adds a flag and a second path (AU70). |
| Drain idle rule from notifications and a quiet time | Premises PW12/PW13. The proxy request state gives the signal for model work (AU26, AU91). Tool events give one count only (`tools_running`, W10 rounds 2 and 3): a tool call sends no model request, so without the count a tool that runs while `busy` is `false` looked idle. Above 0 the member is busy whatever `busy` holds (never lose work). The cost is two `zygo hook` processes for each tool call of a member (`PreToolUse` and `PostToolUse`, `*` matcher); a launch that is not a member gets neither. |

A prerelease of a minimum (such as 1.18.16-beta) is below it and is rejected; a prerelease of a later version (such as 1.19.0-beta) passes; an empty prerelease (such as 1.19.0-) is rejected. ## Method

- Harness: `scripts/premises/` (`run-all.sh` runs every experiment in order and rewrites `fixtures/`). Each agent runs under `env -i` with a temporary `HOME` (`CLAUDE_CONFIG_DIR` and `XDG_*` under it), a dummy API key built at run time, and `ANTHROPIC_BASE_URL` = `scripts/premises/mock_upstream.py`. The mock answers only the dummy key; a request with any other credential gets HTTP 401 and aborts the run. A request with no credential at all (Claude Code's `HEAD /api/hello` connectivity check) is recorded and answered 401 without aborting. No run read the operator's own agent config, login or memory files.
- Environment beyond the plan's isolation list (`PATH`, `TERM`, `HOME`, `CLAUDE_CONFIG_DIR`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_API_KEY`, `CLAUDE_CODE_GATEWAY_HINT_HEADERS`): OpenCode runs add `XDG_STATE_HOME` (under the temporary `HOME`), `OPENCODE_DISABLE_AUTOUPDATE=1`, `OPENCODE_CONFIG_CONTENT`, `OPENCODE_CONFIG_DIR` and `N2_OC_LOG` (the probe plugin's log directory); runs that use WebFetch add `NODE_EXTRA_CA_CERTS` (the throwaway self-signed certificate of the local HTTPS page); Q7 adds the variables under test (`ANTHROPIC_DEFAULT_{FABLE,OPUS,SONNET,HAIKU}_MODEL`, `CLAUDE_CODE_SUBAGENT_MODEL`, `DISABLE_LOGIN_COMMAND`, `DISABLE_LOGOUT_COMMAND`, `CLAUDE_CODE_MANAGED_SETTINGS_PATH`) and leaves out `ANTHROPIC_API_KEY` where `apiKeyHelper` is under test, and one run leaves out `CLAUDE_CODE_GATEWAY_HINT_HEADERS`. The isolated `.claude.json` is pre-seeded with onboarding done, the dummy key approved and the temporary repository trusted. Round 1 also set `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, which hides auxiliary requests; round 2 (2026-11-18) removed it, as a zygo launch does not set it, and re-ran every experiment.
- Mock replies are **synthetic**: the SSE files under `fixtures/claude-code/sse/` and `fixtures/opencode/sse/` were authored for these experiments by `scripts/premises/sse.py` and `steps.py`; they are not recorded model output. A request no rule matches gets a one-word `end_turn` reply, except a Claude Code compaction request, which gets a realistic `<analysis>…</analysis><summary>…</summary>` reply.
- Fixture hygiene (`scripts/premises/scrub.py`): run paths become `/home/user`, `/repo`, `/tmp/run`; the zygo checkout becomes `/zygo`; session and prompt UUIDs and OpenCode `ses_` ids become numbered placeholders; a request's `metadata.user_id` (device id) is omitted; request `system` text and tool `description` fields become `"[omitted]"`; `authorization` and `x-api-key` values and any `Bearer <word>` become `[omitted]`; e-mail addresses become `[e-mail omitted]`. `messages` are kept as captured. `fixtures/claude-code/settings-schema.json` is the upstream schema verbatim, not scrubbed; its source, date and checksum are in `fixtures/claude-code/settings-schema.source.txt`.
- `scripts/check-premises.sh` checks this file, the fixtures and the spec notes; `N2_FORBIDDEN_NAMES` (given at run time) adds a scan for names such as the operator's user name.
- Scratch: when `N2_SCRATCH` is not set, `lib.sh` (and `run-all.sh` through it) checks that `claude` and `opencode` are on `PATH`, then makes a scratch folder and prints its path; it removes the folder after exit 0 and keeps it after an error or a signal, with a `premises: kept <folder> (exit <n>)` line. Set `N2_SCRATCH` to keep the captures (isolated HOMEs, raw requests) in every case.
- tmux premises (node P1): `scripts/premises/live-tmux.sh` and `scripts/premises/live-detach.sh` use a tmux server of their own (`-S <socket in a private folder>`, `-f /dev/null`) and stop it on every exit. The header line `tmux:` is a minimum; a row's version can end in one letter (3.2a). tmux 3.2a was built from the tmux project's release file `tmux-3.2a.tar.gz` (SHA-256 `551553a4f82beaa8dadc9256800bcc284d7c000081e47aa6ecbb6ff36eacd05f`; the project publishes no checksum) into a scratch prefix. For the node E1 probes, tmux 3.4 (Ubuntu 24.04) and tmux 3.7c were built the same way (`./configure --prefix=… && make && make install`) from `tmux-3.4.tar.gz` (SHA-256 `551ab8dea0bf505c0ad6b7bb35ef567cdde0ccb84357df142c254f35a23e19aa`) and `tmux-3.7c.tar.gz` (SHA-256 `7c60cae9a0e25288e2e24750aafc9e8800fc7fd4555e447e1b29ee4201cfb3bf`) of the project's GitHub releases. `live-detach.sh` runs Claude Code on the stored login in print mode, with one allowed Bash command.
- Agent premises of workspaces (node P2): `scripts/premises/live-workspace.sh` runs Claude Code and OpenCode on the mock upstream with the dummy key and a temporary `HOME`, in panes of a tmux server of its own (`-S <socket in a private folder>`, `-f /dev/null`) and in print mode. Hook inputs are saved by `hook_log.py`; OpenCode plugin calls are saved by a probe plugin that the script writes. One sub-check (5.5) runs one print-mode turn of Claude Code on the stored login. PW9 sends SIGTERM to the agent process itself, which is the process that the zygo launcher forwards the signal to. In a fixture each agent id is `agent-id-<n>`.
- Mail premises (node ML-17): `scripts/premises/live-mail.sh --pm` (node ML-16) runs Claude Code and the OpenCode TUI on the mock upstream with the dummy key and a temporary `HOME`, in panes of a tmux server of its own (`-S <socket in a private folder>`, `-f /dev/null`); no login is read. Hook inputs are saved by `hook_log.py`; PM1 adds a probe MCP server (`mcp_probe.py`), and OpenCode plugin calls are saved by a probe plugin that the script writes. The wake line is typed with `send-keys -l`, then `Enter`. Each `LIVE` line, its fixture and its row come from one run; `docs/live-checks.md` "Mail premises (node ML-17)" has the command, bounds and side effects.
- Output-shaping premises (nodes OS-22, OS-23): `scripts/premises/live-shaping.sh po1|po2|po3|po4` runs Claude Code and OpenCode in print mode on the mock upstream with the dummy key and a temporary `HOME`; no login is read. Hook inputs are saved by `hook_log.py`; OpenCode plugin calls are saved by a probe plugin that the script writes. Part po1 makes three failing Bash calls, then `cd scratch && cargo test` on a crate with 2 failing tests; it needs rustup on `PATH` with the toolchain of `rust-toolchain.toml`, and puts that toolchain's bin folder first on the isolated `PATH`. Its `LIVE PO1` line also reports the outcome of the cargo-test call. Run it by hand: `sh scripts/premises/live-shaping.sh po1`.

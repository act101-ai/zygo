# Agent premises (node N2)

Pinned versions, one dated result per premise. A pinned agent version is a minimum (operator, 2026-11-21): Claude Code 2.1.328 or later, OpenCode 1.18.16 or later, Codex 0.172.0 or later. A prerelease of a minimum (such as 1.18.16-beta) is below it and is rejected; a prerelease of a later version (such as 1.19.0-beta) passes; an empty prerelease (such as 1.19.0-) is rejected. The header lines below give each minimum as a bare version (scripts and tests read them). An agent row's version is the minimum or a later version that the check ran on; an act-lite row's version is the release checked. ## Method

- Harness: `scripts/premises/` (`run-all.sh` runs every experiment in order and rewrites `fixtures/`). Each agent runs under `env -i` with a temporary `HOME` (`CLAUDE_CONFIG_DIR` and `XDG_*` under it), a dummy API key built at run time, and `ANTHROPIC_BASE_URL` = `scripts/premises/mock_upstream.py`. The mock answers only the dummy key; a request with any other credential gets HTTP 401 and aborts the run. A request with no credential at all (Claude Code's `HEAD /api/hello` connectivity check) is recorded and answered 401 without aborting. No run read the operator's own agent config, login or memory files.
- Environment beyond the plan's isolation list (`PATH`, `TERM`, `HOME`, `CLAUDE_CONFIG_DIR`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_API_KEY`, `CLAUDE_CODE_GATEWAY_HINT_HEADERS`): OpenCode runs add `XDG_STATE_HOME` (under the temporary `HOME`), `OPENCODE_DISABLE_AUTOUPDATE=1`, `OPENCODE_CONFIG_CONTENT`, `OPENCODE_CONFIG_DIR` and `N2_OC_LOG` (the probe plugin's log directory); runs that use WebFetch add `NODE_EXTRA_CA_CERTS` (the throwaway self-signed certificate of the local HTTPS page); Q7 adds the variables under test (`ANTHROPIC_DEFAULT_{FABLE,OPUS,SONNET,HAIKU}_MODEL`, `CLAUDE_CODE_SUBAGENT_MODEL`, `DISABLE_LOGIN_COMMAND`, `DISABLE_LOGOUT_COMMAND`, `CLAUDE_CODE_MANAGED_SETTINGS_PATH`) and leaves out `ANTHROPIC_API_KEY` where `apiKeyHelper` is under test, and one run leaves out `CLAUDE_CODE_GATEWAY_HINT_HEADERS`. The isolated `.claude.json` is pre-seeded with onboarding done, the dummy key approved and the temporary repository trusted. Round 1 also set `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, which hides auxiliary requests; round 2 (2026-11-18) removed it, as a zygo launch does not set it, and re-ran every experiment.
- Mock replies are **synthetic**: the SSE files under `fixtures/claude-code/sse/` and `fixtures/opencode/sse/` were authored for these experiments by `scripts/premises/sse.py` and `steps.py`; they are not recorded model output. A request no rule matches gets a one-word `end_turn` reply, except a Claude Code compaction request, which gets a realistic `<analysis>…</analysis><summary>…</summary>` reply.
- Fixture hygiene (`scripts/premises/scrub.py`): run paths become `/home/user`, `/repo`, `/tmp/run`, also with any `/` doubled, as in a `TMPDIR` that ends in `/` (`.../T//tmp.X`; `scrub.py:174-176`); Claude Code's dashed form of a run path becomes `-repo`, `-home-user`, `-tmp-run`, also with any `-` doubled (`--`; `scrub.py:139-142`, `175-176`); the operator's user name becomes `user`, matched in any case as a whole word (`scrub.py:286-287`); the zygo checkout becomes `/zygo`; session and prompt UUIDs and OpenCode `ses_` ids become numbered placeholders; a request's `metadata.user_id` (device id) is omitted; request `system` text and tool `description` fields become `"[omitted]"`; `authorization` and `x-api-key` values and any `Bearer <word>` become `[omitted]`; e-mail addresses become `[e-mail omitted]`. `messages` are kept as captured. With `SCRUB_FIXED=1` (as `rescrub_codex.py --check` runs it) the user name comes from `SCRUB_USER` (default `user`, which turns the user-name rule off), the host names from `SCRUB_HOSTS` (default none), and there is no rule for the home or checkout path, so the result does not depend on the machine (`scrub.py:85-86`, `111`, `136-138`). `fixtures/claude-code/settings-schema.json` is the upstream schema verbatim, not scrubbed; its source, date and checksum are in `fixtures/claude-code/settings-schema.source.txt`.
- `scripts/check-premises.sh` checks this file, the fixtures and the spec notes; `N2_FORBIDDEN_NAMES` (given at run time) adds a scan for names such as the operator's user name.
- Scratch: when `N2_SCRATCH` is not set, `lib.sh` (and `run-all.sh` through it) checks that `claude` and `opencode` are on `PATH`, then makes a scratch folder and prints its path; it removes the folder after exit 0 and keeps it after an error or a signal, with a `premises: kept <folder> (exit <n>)` line. Set `N2_SCRATCH` to keep the captures (isolated HOMEs, raw requests) in every case.
- tmux premises (node P1): `scripts/premises/live-tmux.sh` and `scripts/premises/live-detach.sh` use a tmux server of their own (`-S <socket in a private folder>`, `-f /dev/null`) and stop it on every exit. The header line `tmux:` is a minimum; a row's version can end in one letter (3.2a). tmux 3.2a was built from the tmux project's release file `tmux-3.2a.tar.gz` (SHA-256 `551553a4f82beaa8dadc9256800bcc284d7c000081e47aa6ecbb6ff36eacd05f`; the project publishes no checksum) into a scratch prefix. For the node E1 probes, tmux 3.4 (Ubuntu 24.04) and tmux 3.7c were built the same way (`./configure --prefix=… && make && make install`) from `tmux-3.4.tar.gz` (SHA-256 `551ab8dea0bf505c0ad6b7bb35ef567cdde0ccb84357df142c254f35a23e19aa`) and `tmux-3.7c.tar.gz` (SHA-256 `7c60cae9a0e25288e2e24750aafc9e8800fc7fd4555e447e1b29ee4201cfb3bf`) of the project's GitHub releases. `live-detach.sh` runs Claude Code on the stored login in print mode, with one allowed Bash command.
- Agent premises of workspaces (node P2): `scripts/premises/live-workspace.sh` runs Claude Code and OpenCode on the mock upstream with the dummy key and a temporary `HOME`, in panes of a tmux server of its own (`-S <socket in a private folder>`, `-f /dev/null`) and in print mode. Hook inputs are saved by `hook_log.py`; OpenCode plugin calls are saved by a probe plugin that the script writes. One sub-check (5.5) runs one print-mode turn of Claude Code on the stored login. PW9 sends SIGTERM to the agent process itself, which is the process that the zygo launcher forwards the signal to. In a fixture each agent id is `agent-id-<n>`.
- Codex encoder premise (node PC-12): `scripts/premises/codex/encoder.sh` serves Codex SSE that zygo's own encoder made at run time (`crates/zygo-proxy/examples/responses_encode.rs`) from authored Messages SSE (`fixtures/codex/encoder/anthropic/`); the served files are `fixtures/codex/encoder/responses/`. Its refusal cases (node RS-12) serve candidate endings made from the encoder's own `refusal-base.sse` (`responses/cand-*.sse`) and resume each case for a second turn.
- Codex premises (nodes PC-2 to PC-6, and PC-12 for the `encoder` part, K§6.3.7): `scripts/premises/run-codex.sh [<part>]` runs the parts in `scripts/premises/codex/` (`base`, `proxy`, `config`, `session`, `resume`, `encoder`) and rewrites `fixtures/codex/`. Each Codex run (`codex_env` in `scripts/premises/lib.sh`) is `env -i` with a temporary `HOME` and `CODEX_HOME` (and `XDG_*`, `TMPDIR`) under the run folder, a dummy key built at run time, `TERM=xterm-256color`, `TZ=UTC`, and a provider whose `base_url` is `scripts/premises/mock_upstream.py` directly (its `/v1/responses` SSE and `/v1/models` answers), with no zygo between. `HTTPS_PROXY`, `HTTP_PROXY` and `ALL_PROXY` point at the mock, which refuses and records each `CONNECT` and each absolute-URI request (`connect.txt` of each part under `fixtures/codex/runs/`), so a request to any other host is seen and fails; `NO_PROXY` is not set. No run uses an OpenAI or ChatGPT login; no step runs `codex login`. A TUI run passes `--no-daemon`. `codex_record` writes the part's `isolation.txt` and fails on a `HOME` or `CODEX_HOME` outside the run folder, a process or daemon socket left after the run, or a timezone other than UTC in a capture. `fixtures/codex/config.schema.json` is the pinned upstream schema (`rust-v0.172.0` tag), kept verbatim; its source and checksum are in `fixtures/codex/config.schema.source.txt`.
- Codex fixture hygiene (`scrub.py`, nodes PC-10 and PC-11), beyond the rules above: the OS name, version and architecture in a user agent, the `os_*` values and `uname -a` lines become `(os omitted)`, and so does a `Mac OS X <version>` text anywhere, not only in a user agent (`MAC_OS_X`, `scrub.py:182`, `264`); a `<timezone>` value other than a UTC form becomes `(omitted)` (`<timezone>(omitted)</timezone>`), and the UTC forms UTC, Etc/UTC, GMT, Etc/GMT, UTC+0 and UTC+00:00 (any case) are kept (`UTC_NAMES`, `scrub.py:190`, `274-275`); the platform keys `platformOs` and `platformFamily` become `(os omitted)`; the login shell becomes `(shell omitted) -lc` at the start of an exec command field (`command`, `cmd`) and `<shell>(omitted)</shell>` in an `environment_context` block, and is kept elsewhere; the macOS writable root `/private/tmp` maps as `/tmp` does (`scrub.py:282-283`); every other path under `/private/var/` (not a run path) becomes `/tmp/x` (`scrub.py:278`), as does a path under `/var/folders/` (`scrub.py:277`), while a plain `/var/…` path outside `/var/folders` is kept; Codex item ids `msg_`, `fco_` and `ctco_` + UUID, matched in any case (the same id in two cases gets one placeholder; `scrub.py:195`, `290`), become `<prefix>_placeholder<n>`, with one id map per capture folder (`SCRUB_IDMAP`: an id gets the same placeholder in every file of the folder, different ids different ones); a time-bearing ULID after a lower-case prefix (`resp_`, `msg_`, `fc_`, `rs_`) becomes a ULID of time 0 (22 zeros, then a 4-digit number) from the same map, so a response and its items stay paired; a `sandbox` value that names an OS sandbox (`seatbelt`, `landlock`, seccomp, bubblewrap, Windows sandbox names) becomes `(os omitted)`, and `marketplace-<os>-<id>` becomes `marketplace-os-omitted`; macOS `__CF*` environment names, with any `=<value>`, become `(os env omitted)`; each tool `description` in a request body, also of a tool nested in a `namespace` tool, and in a top-level tool listing (`fixtures/codex/agents/tools.json`, `fixtures/codex/mcp/tools.json`) becomes `[omitted]` (parameter descriptions are kept). The runs set no `SHELL`: Codex takes the login shell from the system user record, not from `$SHELL` (inferred from the captures, which name a login shell with no `SHELL` in the environment; not measured), so the scrub masks the shell name. `scripts/check-premises.sh` scans only these classes: over `fixtures/codex` (`cx_scan`, `scripts/check-premises.sh:350-360`), `/private/tmp`, the `seatbelt` sandbox name, the `<shell>` tag in an `environment_context` block, a login shell path at the start of an exec `command` or `cmd` field, the `platformOs` and `platformFamily` values, Codex item ids, `__CF` env names, `marketplace-<os>-` names and time-bearing ULIDs after a lower-case prefix; over `fixtures/claude-code` and `fixtures/opencode` (`env_scan`, `scripts/check-premises.sh:406-420`), the `Shell:` and `OS Version:` lines, the `x-stainless-arch` and `x-stainless-runtime-version` values and the `/cc-socks/<n>.sock` process id. Every other form in this line, among them the PC-10 forms (the user-agent OS, the `os_*` values, `uname -a` lines, a non-UTC timezone) and the other sandbox names and tool descriptions, is caught only by `python3 -I scripts/premises/rescrub_codex.py --check codex`, which fails with `scrub changes it` when `scrub.py` would change a committed file (`scripts/premises/rescrub_codex.py:240`).
- Claude Code and OpenCode fixture hygiene (`scrub.py`, node PC-13): in an environment block, the value of a `Shell:` line becomes `(omitted)` and the value of an `OS Version:` line becomes `(os omitted)`, at any line start (the text start, a line feed or carriage return, a `\n` or `\r` escape at any JSON escape depth, or a `\u000a` or `\u000d` escape); the dash form (`- Shell:`, the key in any case) for any value, the dashless form (capital first letter) only for a host value (a known shell name or its path; Darwin, Linux, Windows, macOS, Ubuntu, Debian, Fedora, FreeBSD, OpenBSD or NixOS, in any case, then a version digit; or `Windows_` or `Windows `; `OS_VAL`, `scrub.py:236`), so a YAML `shell: bash` key is kept; the `x-stainless-arch` and `x-stainless-runtime-version` values become `(arch omitted)` and `(version omitted)` (`x-stainless-os` and `Platform: darwin`, the OS family, are kept); the process id in a messaging socket path `/cc-socks/<n>.sock` becomes `<pid>`. `scripts/check-premises.sh` and `python3 -I scripts/premises/rescrub_codex.py --check claude-code` (and `--check opencode`) fail on a form left unscrubbed.
- Mail premises (node ML-17): `scripts/premises/live-mail.sh --pm` (node ML-16) runs Claude Code and the OpenCode TUI on the mock upstream with the dummy key and a temporary `HOME`, in panes of a tmux server of its own (`-S <socket in a private folder>`, `-f /dev/null`); no login is read. Hook inputs are saved by `hook_log.py`; PM1 adds a probe MCP server (`mcp_probe.py`), and OpenCode plugin calls are saved by a probe plugin that the script writes. The wake line is typed with `send-keys -l`, then `Enter`. Each `LIVE` line, its fixture and its row come from one run; `docs/live-checks.md` "Mail premises (node ML-17)" has the command, bounds and side effects.
- Output-shaping premises (nodes OS-22, OS-23): `scripts/premises/live-shaping.sh po1|po2|po3|po4` runs Claude Code and OpenCode in print mode on the mock upstream with the dummy key and a temporary `HOME`; no login is read. Hook inputs are saved by `hook_log.py`; OpenCode plugin calls are saved by a probe plugin that the script writes. Part po1 makes three failing Bash calls, then `cd scratch && cargo test` on a crate with 2 failing tests; it needs rustup on `PATH` with the toolchain of `rust-toolchain.toml`, and puts that toolchain's bin folder first on the isolated `PATH`. Its `LIVE PO1` line also reports the outcome of the cargo-test call. Run it by hand: `sh scripts/premises/live-shaping.sh po1`.
